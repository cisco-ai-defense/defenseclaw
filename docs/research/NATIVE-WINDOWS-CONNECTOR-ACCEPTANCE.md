# Native Windows connector integration acceptance

Last integration audit: **2026-07-31**

This is the combined acceptance ledger for the native-Windows connector
integration. It covers the two reference connectors (Codex and Claude Code)
and the accepted additions (Copilot CLI, Cursor, legacy Cascade, Antigravity,
OpenCode, OmniGent, and Hermes). Gemini CLI native-Windows support is excluded;
its existing non-Windows connector remains in the cross-platform registry and
is covered only by removal-regression checks.

This ledger records implementation coverage. It is not packaged, signed, live,
or certification evidence. A manual, synthetic, skipped, unrun, or
`continue-on-error` job cannot promote a connector.

Cell vocabulary:

- **I — Implemented:** the final tree has the named surface and a deterministic
  check or a concrete validation definition.
- **L — Officially limited:** the implementation stops at a documented host
  boundary and status/docs must say so.
- **N/A:** the host has no applicable surface; DefenseClaw does not emulate it.
- **B — Blocked:** code or a job definition exists, but authentic external
  evidence is not available in this integration tree.

## Validation gates driven by this ledger

The single combined validation phase must run, in this order:

1. registry/manifest/schema and Go/Python mirror parity;
2. CLI help/alias/TUI/status/Doctor contract checks;
3. Setup fresh/repair/upgrade/preservation/reconciliation/rollback/uninstall,
   deferred-cleanup and exact-restoration matrices for every included home;
4. connector event/profile/wire/fail-mode/scoped-token/v8-correlation tests;
5. PowerShell bootstrap/wizard/packaged harness definitions and JSON/YAML/docs
   validation;
6. authentic packaged or official-client jobs only when their exact binary,
   provenance, signing material and credentials are genuinely available.

Expected external blockers are recorded per connector in surface 12. A blocked
external gate keeps validation fields empty and `live: false` and must be
reported; it is never replaced with an inferred or backfilled result.

No immutable authentic packaged-Setup, official-client lifecycle,
block-visibility, or persisted release-result evidence is attached. Local
client discovery is not certification evidence. In particular, DCWIN-012
recorded no authentic Cascade event; zero counters are inconclusive and cannot
certify activation. Shared cp1252 readiness remains integration-owned. The
authentic release-validation gates therefore remain unproven; the supported
availability statuses above do not fill or imply that missing evidence.
