# IT Governed Mode — Quickstart Guide

> DefenseClaw IT Governed mode deploys a hardened AI agent (Hermes) inside a Docker
> sandbox with full guardrail enforcement, semantic model routing, and centralized
> MCP server management. One command sets everything up.

---

## Architecture

```
User query
  │
  ▼
Hermes Agent (Docker sandbox — no host FS, no network, caps dropped)
  │
  │ hooks (PreToolUse, PostToolUse, UserPromptSubmit, SessionStart, Stop)
  ▼
DefenseClaw Gateway (port 18970)
  ├── Guardrails ── regex rules (246) + sandbox-escape rules (5 CRITICAL)
  │                  mode: action — blocks prompt injection, container escape
  │
  ├── LiteLLM Proxy (port 4001)
  │   ├── LLM Models (Circuit API via deepseek/ Responses→Chat bridge)
  │   │   ├── default        → claude-sonnet-4-6
  │   │   ├── coding-model   → gpt-5-5
  │   │   ├── reasoning-model→ o3
  │   │   ├── fast-model     → gpt-4o-mini
  │   │   └── search-model   → gemini-2.5-pro
  │   │
  │   └── MCP Gateway (/mcp/)
  │       ├── Confluence / Jira   (98 tools — mcp-atlassian via uvx)
  │       ├── Outlook / Calendar  (9 tools  — Graph API via Python MCP)
  │       └── (Webex — optional, add via config)
  │
  └── Semantic Router (port 8080)
      ├── Keyword signals  (4 rules: coding, reasoning, search, simple)
      └── Embedding signals (5 rules, 38 candidates, mmBERT model)
```

Hermes sees **zero tokens or API keys**. All secrets live in DefenseClaw's `.env`
and are resolved at gateway startup into the LiteLLM config.

## Quick Setup (5 minutes)

### 1. Install DefenseClaw

```bash
# CLI
pip install defenseclaw

# Gateway binary (from release or build from source)
cp defenseclaw-gateway ~/.local/bin/
chmod +x ~/.local/bin/defenseclaw-gateway
```

### 2. Initialize

```bash
defenseclaw init
```

Creates `~/.defenseclaw/` with config, device key, and policies.

### 3. Add secrets to `~/.defenseclaw/.env`

```env
# ── Circuit API (LLM provider) ──────────────────────────────
# Base64-encoded client_id:client_secret for OAuth token endpoint
CISCO_AI_GATEWAY_AUTH=<base64 of client_id:secret>

# JWT (auto-refreshed hourly — see "JWT Refresh" section below)
CISCO_AI_JWT=<initial token from OAuth endpoint>

# ── Gateway auth (auto-generated during init) ───────────────
DEFENSECLAW_GATEWAY_TOKEN=<auto-generated>

# ── MCP Server credentials ──────────────────────────────────
# Atlassian (Confluence + Jira)
CONFLUENCE_API_TOKEN=<Atlassian API token from id.atlassian.com>
JIRA_API_TOKEN=<same token>

# Microsoft Graph (Outlook, Calendar, Contacts, Tasks)
MS_GRAPH_ACCESS_TOKEN=<Graph Explorer token or OAuth token>

# Webex (optional)
WEBEX_ACCESS_TOKEN=<bot token from developer.webex.com>

# ── Semantic Router (optional — for native SR binary) ───────
DEFENSECLAW_SR_BINARY=/path/to/semantic-router/bin/router
DEFENSECLAW_SR_LIB_PATH=/path/to/semantic-router/candle-binding/target/release

# ── LiteLLM tuning ──────────────────────────────────────────
LITELLM_DISABLE_DB_CHECKS=true
LITELLM_LOG=ERROR
LITELLM_MCP_TOOL_LISTING_TIMEOUT=120
```

### 4. Configure MCP servers

Add to `~/.defenseclaw/config.yaml` (under the top level):

```yaml
mcp_servers:
  - name: confluence
    transport: stdio
    command: uvx
    args: [mcp-atlassian]
    env:
      CONFLUENCE_URL: "https://your-company.atlassian.net/wiki"
      CONFLUENCE_USERNAME: "you@company.com"
      CONFLUENCE_API_TOKEN_ENV: CONFLUENCE_API_TOKEN
      JIRA_URL: "https://your-company.atlassian.net"
      JIRA_USERNAME: "you@company.com"
      JIRA_API_TOKEN_ENV: JIRA_API_TOKEN

  - name: outlook
    transport: stdio
    command: python3
    args: ["~/.defenseclaw/litellm/outlook_mcp.py"]
    env:
      MS_GRAPH_ACCESS_TOKEN_ENV: MS_GRAPH_ACCESS_TOKEN
```

> **Note:** Keys ending in `_ENV` are references to env var names in `.env`.
> The gateway resolves them at startup — actual secrets never appear in `config.yaml`.

### 5. Enable IT Governed mode

```bash
defenseclaw setup it-governed --yes
```

This single command:
1. Installs Hermes agent (if not present)
2. Pulls Docker sandbox image
3. Sets `deployment_mode: it_governed`
4. Configures hermes connector with action-mode guardrails
5. Provisions hardened Docker sandbox in Hermes config
6. Deploys sandbox-escape detection rules (5 CRITICAL rules)
7. Configures Hermes to use DefenseClaw LiteLLM proxy

### 6. Start the gateway

```bash
defenseclaw-gateway start
```

The gateway automatically:
- Generates LiteLLM config with models + MCP servers (secrets resolved from `.env`)
- Starts LiteLLM proxy on port 4001
- Starts Semantic Router on port 8080
- Installs DefenseClaw hooks into Hermes config
- Loads all guardrail rules

### 7. Start Hermes

```bash
hermes
```

Hermes runs inside a hardened Docker container. Ask it anything — it has
access to Jira, Confluence, Outlook, and 5 LLM models via semantic routing.

## Docker Sandbox Hardening

The Hermes Docker sandbox is configured with maximum isolation:

| Setting | Value | What it prevents |
|---------|-------|------------------|
| `docker_mount_cwd_to_workspace` | `false` | No host directory mounted |
| `docker_volumes` | `[]` | No extra bind mounts |
| `docker_forward_env` | `[]` | No host env vars leaked |
| `docker_network` | `false` | No network from container |
| `container_persistent` | `false` | No persistent storage |
| `docker_run_as_host_user` | `false` | Runs as container user |
| `home_mode` | `tmpfs` | Ephemeral home directory |
| `--cap-drop=ALL` | — | Zero Linux capabilities |
| `--security-opt=no-new-privileges` | — | No setuid/setgid escalation |
| `--pids-limit=256` | — | Fork bomb protection |

**What the agent CAN'T do:**
- Read or write any host file
- Access the host network
- See host environment variables (API keys, tokens)
- Escalate privileges
- Persist anything between sessions

**What still works:**
- LLM calls (via host-side LiteLLM proxy)
- MCP tools (Jira, Confluence, Outlook — via host-side MCP gateway)
- DefenseClaw hook inspection (runs on host)

## Sandbox-Escape Detection Rules

DefenseClaw deploys 5 CRITICAL-severity rules that detect and block escape attempts:

| Rule ID | Detects |
|---------|---------|
| `SANDBOX-CONFIG-TAMPER` | Editing `~/.hermes/config.yaml`, `hermes config set`, `TERMINAL_ENV=`, `backend: local` |
| `SANDBOX-DOCKER-ESCAPE` | `docker run --privileged`, `--cap-add`, `--network=host`, `nsenter`, `chroot` |
| `SANDBOX-ENV-OVERRIDE` | `export TERMINAL_ENV=`, `HERMES_HOME=`, modifying `.hermes/.env` |
| `SANDBOX-DEFENSECLAW-TAMPER` | Editing `.defenseclaw/config.yaml`, hooks, policies, `--disable` |
| `SANDBOX-CHFLAGS-REMOVE` | `chflags nouchg`, `xattr -d com.apple` (removing file locks) |

## Semantic Model Routing

Queries are automatically routed to the best model:

| Category | Model | Example queries |
|----------|-------|-----------------|
| Coding | gpt-5-5 | "implement binary search", "debug null pointer" |
| Reasoning | o3 | "compare microservices vs monolith", "evaluate security implications" |
| Search | gemini-2.5-pro | "search for release notes", "find documentation" |
| Math | o3 | "solve differential equation", "calculate probability" |
| Simple | gpt-4o-mini | "hello", "thanks", "what does this mean" |
| Default | claude-sonnet-4-6 | Everything else |

Routing uses keyword matching (instant) + embedding matching (mmBERT, ~35ms).

## JWT Refresh

Circuit API JWT expires every hour. Refresh manually:

```bash
GATEWAY_AUTH=$(grep CISCO_AI_GATEWAY_AUTH ~/.defenseclaw/.env | cut -d= -f2)

NEW_JWT=$(curl -s -X POST "https://id.cisco.com/oauth2/default/v1/token" \
  -H "Authorization: Basic ${GATEWAY_AUTH}=" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&scope=customscope" | \
  python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

sed -i '' "s|CISCO_AI_JWT=.*|CISCO_AI_JWT=$NEW_JWT|" ~/.defenseclaw/.env
defenseclaw-gateway stop && defenseclaw-gateway start
```

For automation, add to crontab:

```bash
# Refresh JWT every 50 minutes
*/50 * * * * /path/to/refresh-jwt.sh
```

## Lock Configs (Anti-Tampering)

After setup, lock config files to prevent modification:

```bash
sudo bash ~/.defenseclaw/lock-sandbox.sh
```

This sets macOS immutable flags (`uchg`) on:
- `~/.hermes/config.yaml`
- `~/.defenseclaw/config.yaml`
- `~/.defenseclaw/policies/guardrail/default/rules/sandbox-escape.yaml`
- `~/.defenseclaw/hooks/hermes-hook.sh`

To unlock for maintenance:

```bash
sudo chflags nouchg ~/.hermes/config.yaml ~/.defenseclaw/config.yaml
```

## Files to Transfer

When handing over to another machine, copy these files:

| File | Purpose |
|------|---------|
| `~/.defenseclaw/config.yaml` | Main config (models, routing, MCP servers, deployment mode) |
| `~/.defenseclaw/.env` | All secrets (JWTs, API tokens) — **transfer securely** |
| `~/.defenseclaw/litellm/outlook_mcp.py` | Microsoft Graph API MCP server |
| `~/.defenseclaw/litellm/sr_router.py` | Semantic Router callback for LiteLLM |
| `~/.defenseclaw/litellm/filter_empty.py` | Empty content block filter (Circuit API fix) |
| `~/.defenseclaw/policies/guardrail/default/rules/sandbox-escape.yaml` | Sandbox escape detection rules |
| `~/.defenseclaw/lock-sandbox.sh` | Config lockdown script |
| `~/.local/bin/defenseclaw-gateway` | Gateway binary |

On the new machine:
1. Install prerequisites (Docker, Python, Node.js)
2. Copy files to the same paths
3. Run `defenseclaw setup it-governed --yes`
4. Run `defenseclaw-gateway start`
5. Run `hermes`

## Adding MCP Servers

To add a new MCP server, edit `~/.defenseclaw/config.yaml`:

```yaml
mcp_servers:
  # Existing servers...

  - name: my-new-server
    transport: stdio
    command: npx
    args: ["-y", "my-mcp-package"]
    env:
      MY_API_KEY_ENV: MY_API_KEY    # References MY_API_KEY in .env
      MY_BASE_URL: "https://api.example.com"
```

Add the secret to `~/.defenseclaw/.env`:

```env
MY_API_KEY=sk-abc123...
```

Restart the gateway: `defenseclaw-gateway stop && defenseclaw-gateway start`

## Troubleshooting

| Problem | Fix |
|---------|-----|
| JWT expired (401 from Circuit API) | Run JWT refresh script above |
| Hermes hangs on "Initializing agent" | Docker image not pulled — `docker pull nikolaik/python-nodejs:python3.11-nodejs20` |
| MCP tools not loading | Wait 30s after gateway start for servers to initialize |
| Gateway won't start (EPIPE) | `pkill -9 -f 'litellm\|msgraph\|webex-mcp'` then `rm -f ~/.defenseclaw/gateway.pid` then `defenseclaw-gateway start` |
| Config locked (Operation not permitted) | `sudo chflags nouchg ~/.defenseclaw/config.yaml ~/.hermes/config.yaml` |
| "No api key passed in" on /v1/models | Harmless — Hermes probes without auth during startup |
| SR not routing (all → default) | SR config needs embedding signals — gateway regenerates without them |
| Multiple gateway processes | `pkill -9 -f defenseclaw-gateway` then `rm -f ~/.defenseclaw/gateway.pid` |

## Security Model

Three-layer defense:

| Layer | Protects against |
|-------|-----------------|
| **Docker isolation** | Agent accessing host filesystem, network, env vars, escalating privileges |
| **DefenseClaw guardrails** | Prompt injection, sandbox escape attempts, credential exfiltration |
| **Config immutability** | User/agent tampering with Docker hardening, hook scripts, guardrail rules |

All three layers are independent — compromising one does not defeat the others.
