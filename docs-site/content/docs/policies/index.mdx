A policy is what turns a finding into an action. DefenseClaw checks each prompt, model reply and tool call against a rule pack, optionally asks an LLM judge for a second opinion, and then maps the worst severity to `allow`, `alert`, `confirm` or `block`. The connector turns that action into the agent's own allow, ask or deny.

- **Rule pack.** A folder of YAML rules, judge prompts and suppressions. Three ship with DefenseClaw: `permissive`, `default` and `strict`. The pack also sets the default [block and alert levels](/docs/policies/thresholds). The balanced/default enabled catalog currently contains 239 local rules. Regexes compile during [rule-pack validation](/docs/policies/rulepack-validation); an invalid expression rejects the complete candidate.
- **Structured tool calls.** For a shell command or file write, the gateway first extracts the commands, paths and network targets, and CEL rules match those facts. A regex match on its own is recorded as detection only and does not block. See [deterministic detection](/docs/policies/deterministic-detection).
- **LLM judge.** Off until you turn it on. It reads prompts, replies and tool calls for subtle injection, personal data and exfiltration. See [set up an LLM key](/docs/guardrail/unified-llm-key).
- **Suppressions.** Three lists in the pack drop known noise from the judge. They never silence a regex or CEL rule. See [tune the LLM judge](/docs/policies/suppression-cookbook).
- **Session correlator.** Watches saved findings in one session and records a `CORR-*` finding when untrusted input, sensitive access and external egress happen in order. It is detection after the fact, not a block.
- **Admission.** Skills, MCP servers and plugins are decided separately, by scan severity and the allow and block lists. See [scanning](/docs/scanning).

## What it does not do

- A level alone does not block in observe mode. Blocking needs action mode; see [the guardrail](/docs/guardrail). One exception: an agent that changes DefenseClaw's own files, such as a copy into `~/.defenseclaw`, is blocked in every mode (rule `tamper.detector_state_write`; the permissive pack only reports it).
- A custom CEL rule cannot grant itself blocking power. A block needs complete facts and a connector that can stop the call before it runs.
- The correlator never stops the request that completes a pattern.
