DefenseClaw compiles every guardrail pattern with Go's standard `regexp` package, which is
RE2-based. The wizard's regex tester catches incompatible features before you commit. This page
explains how to write good patterns. It quotes shipped strict-pack rules where it names a rule ID;
examples marked "illustrative" use `MY-` IDs and are patterns you write.

<Callout type="info" title="Regex detection is not trusted-action proof">
Patterns remain useful for broad, portable detection. On authenticated tool
actions, however, a raw or custom regex match stays detection-only unless a
separate complete, code-owned proof for the same rule authorizes enforcement.
See the [CEL engine runtime boundary](/docs/policies/cel/engine#runtime-results).
</Callout>

<Callout type="info" title="RE2 in 30 seconds">
RE2 trades a few features for predictable, polynomial-time matching. Patterns you know from PCRE
that <strong>do not work</strong> in RE2:

- Lookarounds: `(?=…)`, `(?!…)`, `(?<=…)`, `(?<!…)`
- Backreferences: `\1`, `\2`, `\k<name>`
- Atomic groups: `(?>…)`
- Possessive quantifiers: `*+`, `++`, `?+`

If your pattern needs any of those, the wizard turns the input field red and tells you which
feature failed. Re-author with a non-capturing group and tighter quantifiers.
</Callout>

## Anatomy of a good rule

This is the shipped strict-pack rule for OpenAI project keys:

```yaml
- id: SEC-OPENAI
  pattern: 'sk-proj-[a-zA-Z0-9]{20,}'
  title: "OpenAI project key"
  severity: CRITICAL
  confidence: 0.95
  tags: [credential]
```

What makes this work:

- **Anchored prefix.** `sk-proj-` is the OpenAI project key marker. Without it the pattern would
  match every long base62 string.
- **Bounded minimum length.** `{20,}` skips short strings that only share the prefix.
- **Confidence below 1.0.** The judge and suppressions can still weigh context.
- **Self-describing tags.** Useful when you triage thousands of findings in dashboards.

## Patterns by category

### Secrets

| ID | Pattern shape | Catches | Avoids |
| --- | --- | --- | --- |
| `SEC-AWS-KEY` | `\b(?:AKIA\|ASIA)[0-9A-Z]{16}\b` | IAM, STS keys | Random base62 of similar length |
| `SEC-GITHUB-TOKEN` | `(?:ghp_\|gho_\|ghu_\|ghs_\|ghr_)[a-zA-Z0-9]{36,}` | Current GitHub token formats | Plain `gh-` strings |
| `SEC-PRIVKEY` | `-----BEGIN (?:RSA \|EC \|OPENSSH \|PGP \|DSA )?PRIVATE KEY-----` | RSA, EC, OpenSSH, PGP, DSA keys | Public certs, certificate signing requests |
| `SEC-OPENAI-V2` | `sk-[a-zA-Z0-9]{40,}` | Long-form OpenAI keys | `sk_test_` Stripe keys (underscore, not hyphen) |
| `SEC-SLACK-WEBHOOK` | `https://hooks\.slack\.com/services/T[A-Z0-9]+/B[A-Z0-9]+/[a-zA-Z0-9]+` | Slack incoming webhooks | Other Slack URLs (channels, files) |

### Prompt / tool injection

These rely on the natural-language signal more than character classes. Pair them with the LLM
judge for confirmation; the regex is the cheap pre-filter. The shipped strict pack covers this
family with `TRUST-IGNORE-PREVIOUS`, `TRUST-DISREGARD` and related `TRUST-*` rules, whose patterns
also anchor on sentence and list boundaries. A simpler illustrative rule:

```yaml
- id: MY-INJ-OVERRIDE
  pattern: '(?i)\b(ignore|disregard)\s+(all\s+)?(previous|prior|above)\s+(instructions|prompts|rules)\b'
  severity: HIGH
```

### Unicode zero-width obfuscation

The shipped rule looks for sustained insertion of zero-width characters after ASCII letters or
digits. Requiring ten insertions catches deliberately split tokens while avoiding isolated
formatting artifacts and ordinary emoji ZWJ sequences.

```yaml
- id: OBFUSC-UNICODE-ZWSP
  pattern: '(?:[A-Za-z0-9][\x{200B}\x{200C}\x{200D}\x{FEFF}][\s\S]*?){10,}'
  title: Zero-width character obfuscation
  severity: HIGH
  confidence: 0.95
  tags: [prompt-injection, obfuscation]
```

<Callout type="info" title="What counts toward the threshold">
The counted characters are U+200B (zero-width space), U+200C (zero-width non-joiner), U+200D
(zero-width joiner), and U+FEFF (byte-order mark). Each must immediately follow an ASCII
alphanumeric character. Nine insertions do not match, and a ZWJ between two emoji does not count.
</Callout>

### Exfiltration markers

When a model surfaces an out-of-band collection URL, you usually want to alert before allowing
the output downstream. The shipped strict pack has one `C2-*` rule per known service, such as
`C2-WEBHOOK-SITE`, `C2-REQUESTBIN` and `C2-NGROK`:

```yaml
- id: C2-WEBHOOK-SITE
  pattern: '(?i)(?:^|[^a-zA-Z0-9-])webhook\.site(?:[^a-zA-Z0-9.-]|$)'
  title: "webhook.site (known exfil)"
  severity: HIGH
  confidence: 0.90
  tags: [exfiltration, c2]
```

The boundary groups stop the rule from matching `notwebhook.site` or `webhook.site.example.com`.

### Enterprise data shape

Numeric-only patterns are the easiest to false-positive. Always pair them with a `condition`
in your finding suppressions (see [the suppression cookbook](/docs/policies/suppression-cookbook)).

The shipped `ENT-BULK-SSN` rule excludes invalid SSN area, group and serial ranges rather than
matching any `ddd-dd-dddd` string. Illustrative rules you might write:

```yaml
- id: MY-PII-SSN
  pattern: '\b\d{3}-\d{2}-\d{4}\b'
  severity: HIGH
- id: MY-PII-CARD
  pattern: '\b(?:4\d{3}|5[1-5]\d{2}|3[47]\d{2}|6(?:011|5\d{2}))[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}\b'
  severity: CRITICAL
```

## Patterns to avoid

- **`.*` anywhere unanchored.** It almost always matches, slowly. Pair with at least one bounded
  segment (`[A-Z0-9]{8,}`) and an anchor.
- **Greedy quantifiers under groups under quantifiers.** `(\w+)+` is the classic catastrophic
  backtracking shape. The wizard's `REGEX_REDOS` heuristic flags this on the way in.
- **Case-insensitive without `(?i)`.** Use the inline flag so the engine and your tester agree.

## Workflow

In the [Policy creator](/docs/policies/creator) Rule pack section:

1. Pick a recipe from the catalog or click "+ Rule" on the appropriate file.
2. Paste your pattern in. The wizard runs every keystroke through V8, the RE2 lint, and the
   ReDoS heuristic, plus your `should match` and `should NOT match` examples.
3. Once the pill colors line up (green for pass, amber for mismatch, red for compile error),
   review the verdict in the Live Test pane on the right — it'll show how the pattern interacts
   with the severity matrix and admission policy.
