`validate-pack` runs the same loader the gateway uses. It works offline: the gateway does not need to be running and no network request is made.

<Callout type="info" title="Enterprise deployments">
On a managed computer, `defenseclaw` runs only the commands in [Managed command availability](/docs/enterprise/managed-commands). Use `/opt/defenseclaw/bin/defenseclaw-gateway rulepack validate --dir PACK` (`/opt/cisco/defenseclaw/bin/defenseclaw-gateway` on macOS); it prints the digest to pin. See [custom rule packs](/docs/enterprise/configuration).
</Callout>

1. Validate the pack.

   ```bash
   defenseclaw guardrail validate-pack ~/.defenseclaw/policies/guardrail/default
   ```

   ```text
   Rule pack valid: "/home/alice/.defenseclaw/policies/guardrail/default"
     rules: 251/255 enabled across 7 files
     components: judges=4 judge_categories=23 local_patterns=11 suppressions=9 sensitive_tools=6
     digest: 5daac40214db7ebbb1cb21ffc76bed9ba300f2345d64cd39a4a8176ca31d35d0
     files digest: 2448bcf490dc31e9686a2ded25dbb4fde95059fa388fb294fe256b2b9afff80a (the guardrail.custom_packs pin)
   ```

   `judges=4` counts the compiled-in exfil judge and the three judge files. The full digest includes compiled defaults and can change between builds even when the files digest stays the same. Use your own run's `files digest` to pin a custom pack. You can pass a pack name instead of a path.

2. In CI, ask for JSON.

   ```bash
   defenseclaw guardrail validate-pack PATH --json
   ```

   ```json
   {"kind":"validation","summary":{"alert_only_rule_count":0,"digest":"5daac402…","enabled_rule_count":251,"files_digest":"2448bcf4…","judge_category_count":23,"judge_count":4,"local_pattern_count":11,"rule_count":255,"rule_file_count":7,"sensitive_tool_count":6,"stale_rule_count":0,"suppression_count":9},"valid":true,"wire_version":1}
   ```

3. Read a failure. A file the loader does not recognize fails the whole pack and exits `1`. The reason names the file, or the folder when a whole copy of another pack sits inside this one (for example `default/judge/injection.yaml` names `default`), and says to move it out or remove it:

   ```text
   Rule pack invalid: "/home/alice/.defenseclaw/policies/guardrail/bad"
     inventory_unexpected at correlation-patterns.yaml: unexpected YAML component: move correlation-patterns.yaml out of the rule-pack folder or remove it, then run the command or installer again
   ```

   ```json
   {"error":{"code":"inventory_unexpected","path":"correlation-patterns.yaml","reason":"unexpected YAML component: move correlation-patterns.yaml out of the rule-pack folder or remove it, then run the command or installer again"},"kind":"validation_error","valid":false,"wire_version":1}
   ```

| Exit | Meaning |
| --- | --- |
| `0` | The pack is valid. |
| `1` | The pack is invalid. The output names the file, error code and reason. |
| `2` | Validation is unavailable (gateway binary missing, untrusted, timed out or incompatible). This does not say whether the pack is valid. |

<Callout type="warn" title="Validation is fail-closed for files you provide">
Validation is all or nothing. If a recognized file is present, the whole file must parse: a malformed rule, an invalid Go regular expression or an unsupported schema version fails the pack. DefenseClaw does not silently discard the bad file or keep only the entries that parsed.
</Callout>

## CEL expression validation

Every `expression` is compiled, including on disabled rules. For the rule schema and field names, see [CEL authoring](/docs/policies/cel/authoring). The admitted language subset and limits are in the [CEL engine](/docs/policies/cel/engine) reference.

## Partial packs and fallback

A non-empty pack directory is an overlay on the compiled baseline. Missing `suppressions.yaml`, `sensitive-tools.yaml`, judge files and `rules/local-patterns.yaml` keep the baseline. Any other `rules/*.yaml` adds or replaces one category.

## Doctor checks effective connector packs

```bash
defenseclaw doctor
```
The pack also sets what a gateway outage does when you saved no fail mode: with `strict` a call is blocked while the gateway is not running, and `default` lets it run with a warning again ([Fail modes](/docs/reference/fail-modes)).


```text
  [PASS] Rule pack [codex]  -  configured rule pack "default" "/home/alice/.defenseclaw/policies/guardrail/default": 239/243 rules enabled; digest=36bc8fb6…
```

Doctor validates the pack every connector uses. It shows `FAIL` for an invalid pack and `WARN` when the validator is missing.

## Apply a validated pack

The pinned digest also covers the optional `defenseclaw-pack.json` posture file. Adding or editing that file changes the digest, so validate the pack again and pin the new digest, as for a rule file ([Thresholds](/docs/policies/thresholds#rule-pack-default-posture), [custom rule packs](/docs/enterprise/configuration#custom-rule-packs)).

A `guardrail.custom_packs` entry is checked once, when the configuration is read, and every reader (the gateway, the hooks, `defenseclaw status` and `defenseclaw doctor`) uses that one result. An entry is a config error when its path is empty, is not a readable folder, or loads no valid pack, or when its `digest` is missing or does not match the pack's files digest (a pack with no files has no usable digest). A relative `path` is read against the folder that holds `config.yaml`, not the current directory, and `~` is not expanded. While an entry has a config error, a setting that selects it runs the built-in pack of that name (`default` for any other name), `status` and `doctor` name the error, and the hook's outage behaviour follows the strict tier, so it does not open. Fix the entry, then reload.

DefenseClaw ships three rule packs: `permissive`, `default` and `strict`. A pack changes which rules run and the default block and alert levels.

| Pack | Blocks | Alerts | Pick it when |
| --- | --- | --- | --- |
| `permissive` | CRITICAL | HIGH and above | You are piloting. Pair it with observe mode and review what would have happened. |
| `default` | CRITICAL | MEDIUM and above | You want to stop obvious harm. With HITL on, eligible HIGH findings ask first. |
| `strict` | MEDIUM and above | LOW and above | Regulated work, where a missed attack costs more than an interruption. Turn the LLM judge on too. |

1. Switch every agent to the strict pack.

   ```bash
   defenseclaw guardrail use-pack strict
   ```

   Or switch one agent:

   ```bash
   defenseclaw guardrail use-pack strict --connector codex
   ```

   `use-pack` validates the pack first and writes nothing if it is invalid. A global switch removes per-agent pack overrides and lists them.

2. Check it worked.

   ```bash
   defenseclaw guardrail list-packs
   ```

   ```text
     Guardrail rule packs
     --------------------
     * built-in presets:
         - default: Balanced built-in pack - the shipped baseline.
         - strict: Tighter thresholds; blocks more aggressively.
         - permissive: Looser thresholds; favors availability over blocking.
   ```

The running gateway applies the change on its next reload. Nothing restarts.

### Move the admission policy too

`use-pack` changes the runtime rules only. The admission policy for skills, MCP servers and plugins is a separate preset:

```bash
defenseclaw policy activate strict
```

`policy activate` does not change `guardrail.rule_pack`, and `use-pack` does not change admission. Activation replaces the whole `admission:` section, so run it before any hand-tuned admission edits. See [policy defaults](/docs/policies/defaults#activate-a-preset). To block and quarantine plugins with a MEDIUM finding at install, see [block risky plugins at install](/docs/policies/defaults#block-risky-plugins-at-install).

### Undo

```bash
defenseclaw guardrail use-pack default
defenseclaw guardrail use-pack --clear --connector codex
defenseclaw policy activate default   # admission back to the default preset; also undoes the plugin edit
```
