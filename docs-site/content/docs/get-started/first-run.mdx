After the [install](/docs/get-started/download), DefenseClaw is on disk but not configured. `defenseclaw init` is the guided wizard. `defenseclaw quickstart` is the zero-prompt equivalent with safe defaults. Both run the same setup and print the same report. You do not need `init` before `quickstart`. For a guided first block, follow the [Quickstart](/docs/get-started/quickstart).

## Path A: interactive (`defenseclaw init`)

On a terminal, `init` runs local agent discovery, pre-selects every installed hook connector and configures them all in `observe` mode. It then shows one checklist, **Select connector(s) for action enforcement**; tick the agents that should block. The action-only settings (hook fail mode and human approval with its minimum severity) are asked once and shared by every agent you promote. On a new install the fail mode prompt offers `closed`. The wizard asks **Start gateway after setup?** (default yes).

Proxy connectors are detected but left out of the observe-all set, because they own the single LLM proxy port. Use `defenseclaw setup <proxy>` for them.

An agent version newer than DefenseClaw's tested versions keeps action mode and is reported as untested. A connector whose installed version has no hook contract is left out in observe and action mode, because setup refuses it in both. With other connectors selected, `init` configures them and reports the one it left out. Alone, it writes no connector config and reports `needs_attention`. `quickstart` refuses it the same way. The refusal names the version to install and the command to run after the upgrade: `defenseclaw init`, or `defenseclaw quickstart --connector <name>` for quickstart. An action connector whose version could not be read (not probed, or outside a trusted prefix) is configured in observe with a warning. See [Hook contracts](/docs/connectors/compatibility).

### Scripted `init` (no prompts)

Scripted use skips the wizard:

```bash
defenseclaw init --non-interactive --yes --observe-all --action-connectors codex
```

#### `defenseclaw init`

| Flag | What it does |
| --- | --- |
| `--connector <name>` | Pre-select a single agent. Wins over the multi-connector flags. `init` has no `--agent` alias; `quickstart` has one. |
| `--observe-all` | Configure every detected hook connector in `observe`. |
| `--action-connectors a,b` | Connectors to configure in `action`. Works with `--observe-all`. |
| `--non-interactive` | Skip every prompt. |
| `--yes` / `-y` | Accept the default for every prompt. |
| `--profile` | Protection profile (`observe` or `action`). |
| `--scanner-mode` | `local`, `remote` or `both`. |
| `--fail-mode open\|closed` | Hook fail mode. |
| `--human-approval` / `--no-human-approval` | HITL. |
| `--hilt-min-severity` | Lowest severity that asks. |
| `--with-judge` / `--no-judge` | The LLM judge. |
| `--llm-provider`, `--llm-model`, `--llm-api-key-env`, `--llm-base-url` | The unified LLM key settings. |
| `--llm-api-key` | LLM key to save into `.env`; the config stores only the env name. Other local users can see a command-line value, so prefer `DEFENSECLAW_INIT_LLM_API_KEY`. |
| `--cisco-endpoint`, `--cisco-api-key-env` | Cisco AI Defense. |
| `--cisco-api-key` | Cisco AI Defense key to save into `.env`. Prefer `DEFENSECLAW_INIT_CISCO_API_KEY`, for the same reason. |
| `--enable-guardrail` | Configure the LLM guardrail during `init`. |
| `--start-gateway` / `--no-start-gateway` | Answer the gateway prompt in advance. |
| `--verify` / `--no-verify` | Run readiness checks before exiting. |
| `--rescan-agents` | Refresh cached agent discovery. |
| `--json-summary` | Print the report as JSON. |
| `--verbose` | Show full subprocess output. |
| `--skip-install` | Skip the scanner and built-in guardrail availability checks. |

With no multi-connector flag and no `--connector`, non-interactive `init` keeps one connector found by discovery, in `observe`. `defenseclaw init --help` lists every option.

## Path B: zero prompts (`defenseclaw quickstart`)

```bash
defenseclaw quickstart --connector claudecode
```

Quickstart configures **one** connector, with the `observe` profile, the `local` scanner, no judge and no HITL. Without `--connector` it uses the single configured or detected connector. If more than one is configured or detected, it exits and asks for `--connector <name>`. On an install that already guards other connectors, `quickstart --connector <name>` exits without changes; use `defenseclaw setup <name> --yes` to add an agent, or `defenseclaw init` to change the set.

### The first-run report

<include>../../snippets/first-run-report.mdx</include>

The first line holds the `status` (`ready`, `partial` or `needs_attention`), the connector (or `connectors=N`) and the profile. **Setup** lists what the command did, **Readiness** what it checked, and **Next** up to five commands to run. A `Gateway API port` line appears in Setup when another account on the machine uses the default port.

| Exit code | Meaning |
| --- | --- |
| `0` | Status `ready` or `partial` |
| `1` | `needs_attention` |
| `2` | Stopped before changing anything, for example when it cannot tell which connector you mean |

In CI, check the `status` field of `--json-summary`, because `partial` also exits `0`.

## When to use which

| Situation | Use |
| --- | --- |
| First setup at a terminal | `defenseclaw init` |
| Installer hand-off or unattended provisioning | `defenseclaw quickstart --connector <x>` |
| CI | `defenseclaw quickstart --connector <x> --json-summary` |
| Repeatable test fixture | `defenseclaw quickstart --connector <x> --force` |
