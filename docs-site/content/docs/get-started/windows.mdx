DefenseClaw runs natively on Windows x64 for the signed-in user: a local gateway, a hook runner, the CLI, the TUI, the scanners and a managed Python runtime. The agent keeps talking to its own model service; DefenseClaw adds a hook or plugin and does not proxy model traffic on Windows.

<Callout type="warning" title="WSL is not supported">
Run DefenseClaw and the agent in the same native Windows user session. Do not install DefenseClaw in WSL, point a native agent at a WSL installation, or mix native and WSL connector homes.
</Callout>

## Requirements

| Requirement | Detail |
| --- | --- |
| Windows | Windows 10 or newer, including Windows Server 2019 and later. |
| Architecture | x64 (`amd64`) only. ARM64 is not certified, even with x64 emulation, and the installer stops. x86 is unsupported. |
| Shell | Windows PowerShell 5.1 (built in) or PowerShell 7. |
| Scope | Current user only. Running elevated works but is not needed. |
| Agent | A [supported agent](/docs/get-started/support-matrix) installed natively for the same Windows user. |
| Network | The installer downloads from GitHub. At runtime DefenseClaw listens on authenticated loopback, normally `127.0.0.1:18970`. |

Core DefenseClaw does not need Docker. The optional local observability and Local Splunk bundles need Windows x64 Pro, Enterprise or Education with Hyper-V and machine-installed Docker Desktop (Linux containers, Hyper-V backend, Compose v2). Windows Home, per-user Docker Desktop, WSL2 engines and Windows containers are not supported for these bundles.

## Install

In PowerShell, as the user who runs your agents:

```powershell
irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1 | iex
```

To guard one agent and run first-time setup in the same step, download the script first and pass parameters:

```powershell
& ([scriptblock]::Create((irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1))) -Connector codex -Quickstart
```

The installer adds `%USERPROFILE%\.local\bin` to your user `PATH`. Open a new terminal, then check:

```powershell
defenseclaw --version
defenseclaw-gateway --version
```

Parameters and exit codes are in the [installer reference](/docs/reference/commands/installer).

## Set up agents

```powershell
defenseclaw init
```

`init` asks which agents to guard. To add one later:

```powershell
defenseclaw setup codex --mode observe
```

`defenseclaw setup --add-detected --yes` adds newly installed agents without touching the others. Windows connectors: `claudecode`, `codex`, `amp`, `cursor`, `devin`, `hermes`, `opencode`, `copilot`, `antigravity` and `kiro`. Restart OpenCode after setup; fully exit and relaunch Amp. Home-folder overrides are in [Paths](/docs/reference/configuration/paths#overrides).

## How it runs

- The gateway is a background process of your account, started by `defenseclaw quickstart`, `defenseclaw setup` or `defenseclaw-gateway start`, and by a hook if it is stopped. There is no Windows service, Scheduled Task or sign-in entry.
- A hook sends each event to the gateway on loopback. In action mode the answer can block the step.
- Every decision is written to `%USERPROFILE%\.defenseclaw\audit.db`.

Details are in the [Windows security model](/docs/appendix/windows-security-model) and [Paths](/docs/reference/configuration/paths).

## Upgrade and roll back

```powershell
defenseclaw upgrade
defenseclaw rollback
```

The installer continues in a new PowerShell window. Both commands exit `0` once that window opens, before the installer has finished: read the result in the window or its log in `%USERPROFILE%\.defenseclaw\logs`, then confirm with `defenseclaw --version` and `defenseclaw doctor`. Close the TUI and other DefenseClaw commands first. In an SSH session there is no desktop for that window, so both commands change nothing, exit 1 and print the `powershell -File ... install.ps1` command to run in your terminal. See [Upgrade](/docs/get-started/upgrade) and, for a 0.8.x Setup install, [Upgrade from 0.8.x](/docs/appendix/upgrade-from-0-8#windows-moving-from-the-setup-package). To repair an install, run the install command again.

## Uninstall

```powershell
defenseclaw uninstall --all --binaries --yes
```

Without `--all` and `--binaries`, uninstall keeps your data and programs. Close agent sessions first. See [Uninstall](/docs/get-started/uninstall).

## What Windows does not support

- WSL, or a mix of native and WSL connectors.
- Windows ARM64 and x86.
- A machine-wide install, MSI or Windows service. Use [Enterprise](/docs/enterprise/install/windows); on a computer with a standalone enterprise deployment the per-user installer, `upgrade`, `rollback` and gateway refuse.
- The proxy connectors (OpenClaw, ZeptoClaw): native Windows has no guardrail proxy.
- OpenShell sandboxes. `defenseclaw sandbox` commands stop with "OpenShell sandboxes run on Linux and macOS only". Use [sandboxes](/docs/features/sandboxes) on Linux or an Apple-silicon Mac.
- An agent on another computer sending hooks to this gateway: only the same computer, same user, over loopback is tested.

Coming from WSL, do a fresh native install; do not copy WSL data, hooks, tokens or connector configuration.

## If something fails

Run these before changing anything, then see [Windows troubleshooting](/docs/troubleshooting/windows):

```powershell
defenseclaw status
defenseclaw doctor
```
