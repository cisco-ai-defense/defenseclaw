DefenseClaw installs per user with `install.ps1`, the same flow as the macOS
and Linux installer. The installer also upgrades, repairs, and rolls back.

From 1.0 this page replaces the 0.8.x `DefenseClawSetup-x64.exe` flow: that
installer is retired, and its `/repair`, `/uninstall` and `DELETEUSERDATA=1`
options do not apply to an `install.ps1` install. Re-running `install.ps1`
imports an existing Setup install (see
[Moving from the 0.8.x Setup package](#moving-from-the-08x-setup-package)). Administrator
deployments use the separate [enterprise deployment](/docs/enterprise): the
standalone [enterprise Setup](/docs/enterprise/windows) or the
[Cisco Secure Client profile](/docs/enterprise/secure-client#windows-system-service-layout).

## System requirements

| Requirement | Native Windows contract |
| --- | --- |
| Operating system | Native Windows 10-family or newer, including Windows Server 2019+. |
| Architecture | amd64/x64 only. ARM64 is not certified: releases publish no ARM64 build, so the installer refuses it. x86 is unsupported. |
| Shell | Windows PowerShell 5.1 (built in) or PowerShell 7. |
| Install scope | Current user only. Running elevated works but is not needed. |
| Agent | A [supported connector](/docs/connectors#platform-support) installed natively for the same Windows user. Do not substitute WSL or mix native and WSL connector homes. |
| Python | Provided by `uv`, which the installer installs if you do not have it. |
| Networking | The installer downloads the release from GitHub. At runtime DefenseClaw listens on authenticated loopback, normally `127.0.0.1:18970`. |

The optional Docker-backed local observability and Local Splunk bundles have a
narrower requirement: Windows x64 Pro, Enterprise, or Education; Hyper-V;
machine-installed Docker Desktop; Linux containers; a reachable daemon;
Compose v2; and a real native `docker.exe`. Windows Home, per-user Docker
Desktop, WSL2 engines, Windows containers, and command-wrapper shims are not in
that optional feature's certified path. Core DefenseClaw does not require
Docker.

## Install

```powershell
irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1 | iex
```

To choose options, download the script first and run it with parameters:

```powershell
$release = 'https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download'
$installer = irm "$release/install.ps1"
& ([scriptblock]::Create($installer)) -Connector codex -Quickstart
```

| Parameter | What it does |
| --- | --- |
| `-Yes` | Do not prompt |
| `-Version X.Y.Z` | Install a specific release (runs that release's installer) |
| `-Local DIR` | Take every release file from a directory instead of GitHub |
| `-Rollback` | Restore the install that the last upgrade replaced |
| `-Connector NAME` | First install only: the agent to guard |
| `-NoOpenclaw` | First install only: same as `-Connector none`, kept for older scripts |
| `-Quickstart` | Run `defenseclaw quickstart` afterwards when nothing is configured yet |
| `-QuickstartMode MODE` | `observe` or `action` for that quickstart (implies `-Quickstart`) |
| `-NoPersistPath` | Do not add `%USERPROFILE%\.local\bin` to your user `PATH` |
| `-CosignPath FILE` | The `cosign` to check the release signature with (default: `cosign` on `PATH`) |
| `-Help` | Show the installer's help |

`-Connector` takes `codex`, `claudecode`, `hermes`, `cursor`, `devin`,
`copilot`, `antigravity`, `opencode`, `amp`, `omnigent`, `kiro`, or `none`.

The installer checks every download against the release's `checksums.txt`
(and its Sigstore signature when `cosign` 2.0 or later is on `PATH` or given
with `-CosignPath`), prepares the new
version before changing anything, and adds `%USERPROFILE%\.local\bin` to your
user `PATH`. Open a new terminal afterwards so the `PATH` change applies, then
check:

```powershell
defenseclaw --version
defenseclaw-gateway --version
```

Run as a saved `.ps1` file, the installer exits `0` when it installed, `1`
when it did not (a previous install is restored), `3` when it installed but a
connector needs attention, and `4` when it installed but the first-run
quickstart failed.

## Configure after installation

For guided configuration, which asks which agents to guard:

```powershell
defenseclaw init
```

For a zero-prompt setup of one agent:

```powershell
defenseclaw quickstart --connector codex
```

To add one agent directly, run its setup command, for example:

```powershell
defenseclaw setup codex --mode observe
```

Each [connector page](/docs/connectors#platform-support) has the setup command
for that agent. One local gateway can guard several agents. Running a second
agent's setup asks whether to add it or switch to it; choose **Add** to keep
the first.

To set up several agents in one command, list them with `-c` (repeatable).
The list becomes the full set of guarded agents, so include the ones you
already have:

```powershell
defenseclaw setup -c codex -c claudecode -c cursor --mode observe --yes
```

The Windows connector names are `claudecode`, `codex`, `amp`, `cursor`,
`devin`, `hermes`, `omnigent`, `opencode`, `copilot`, `antigravity`, and
`kiro`. Instead of `-c`, `--detected` picks the agents installed on this
computer and `--all` picks every supported one. To add newly installed agents
without changing the others, run `defenseclaw setup --add-detected --yes`.

Setup honors the agents' own home-folder variables (`CODEX_HOME`,
`CLAUDE_CONFIG_DIR`, `COPILOT_HOME`, `OMNIGENT_CONFIG_HOME`,
`OPENCODE_CONFIG_DIR`, and `HERMES_HOME`) and remembers the folder it set up.
Repair, upgrade, and uninstall use that remembered folder, even if the
variable changes later; to move an agent's home, run its setup again. The data
root is the current profile's `.defenseclaw` unless `DEFENSECLAW_HOME` is set;
see [Supported path overrides](/docs/get-started/windows/paths-troubleshooting#supported-path-overrides).
Restart OpenCode after setup changes so it loads the updated plugin.

Amp's plugin is always
`%USERPROFILE%\.config\amp\plugins\defenseclaw.ts`. Fully exit and relaunch
Amp after setup changes. For `amp -x`, add `--plugin-ready-timeout 30` so the
plugin is loaded before the turn starts.

## Startup behavior

The gateway runs as a background process for the signed-in user and ends when
you sign out. It starts when you run `defenseclaw quickstart`,
`defenseclaw setup`, or `defenseclaw-gateway start`, and a hook starts it when
an agent calls it while it is stopped. There is no Windows service, Scheduled
Task, or sign-in entry. As on Linux and macOS, a hook does not start it after
`defenseclaw-gateway stop` (until you run `defenseclaw-gateway start`), while an
install or upgrade runs, for 60 seconds after a hook start failed, or when
`DEFENSECLAW_GATEWAY_AUTOSTART=0` is set in the agent's environment.

## Upgrade

```powershell
defenseclaw upgrade
```

The installer continues in a new PowerShell window so the running command can
release its files. It stops the gateway, keeps the current install in
`%USERPROFILE%\.defenseclaw\previous`, swaps in the new version, migrates your
configuration (a version 8 `config.yaml` becomes version 9, and the old file stays as
`config.yaml.v8.bak`), and restarts the gateway. If any step fails it restores the
previous install. Close the TUI and other DefenseClaw commands first; the
installer waits up to a minute for them and changes nothing if they stay open.

To undo the last upgrade:

```powershell
defenseclaw rollback
```

In an SSH session there is no desktop to show that window, so
`defenseclaw upgrade` and `defenseclaw rollback` change nothing, exit 1 and
print the `powershell -File ... install.ps1` command that runs the installer
in the same terminal, where it shows the result and sets the exit code.

See [Upgrade DefenseClaw](/docs/get-started/upgrade) for every option.

When an administrator sets the `DisableSelfUpdate` policy (a nonzero DWORD
under `HKLM\SOFTWARE\Policies\Cisco\DefenseClaw`), `install.ps1`,
`defenseclaw upgrade` and `defenseclaw rollback` refuse and change nothing, and
the update notice is off. Update through your managed deployment instead. A
standalone [enterprise deployment](/docs/enterprise) sets this policy when the
value is absent, unless its config sets
`enterprise.coexistence.disable_self_update: false`. On such a computer
`install.ps1`, `defenseclaw upgrade` and `defenseclaw rollback` refuse in any
case, because the
deployment's registration marks the computer as managed.

### Moving from the 0.8.x Setup package

Run the install command above. The installer imports a
`DefenseClawSetup-x64.exe` installation: it stops its gateway, removes its
program folder, sign-in entry, Add/Remove Programs entry, and `PATH` entry,
keeps your configuration and data in `%USERPROFILE%\.defenseclaw`, and keeps the
old program files in `%USERPROFILE%\.defenseclaw\previous\legacy-setup`.
Connector hooks are rewritten to the new paths when the gateway starts.

`defenseclaw rollback` cannot bring the Setup package back; it refuses and
changes nothing. To go back to it by hand, run `defenseclaw uninstall`, then
download `DefenseClawSetup-x64.exe` from the release you had and run it in
your desktop session. Your data from before the upgrade is in
`%USERPROFILE%\.defenseclaw\previous`.

You do not need the old Setup to move. To check an old
`DefenseClawSetup-x64.exe` file, compare its SHA-256
(`Get-FileHash -Algorithm SHA256`) with its entry in that release's
`checksums.txt`, after verifying the Sigstore signature of `checksums.txt`.
The 0.8.x Setup files are not Authenticode-signed, so their own `/verify`
check always fails; that does not mean the file was changed.

## Repair

Run the install command again. Reinstalling the same version rebuilds the
program files and keeps your configuration, data, and the rollback copy.

## Uninstall and preserved state

```powershell
defenseclaw uninstall              # remove connector integrations; keep data and programs
defenseclaw uninstall --binaries   # also remove the programs in %USERPROFILE%\.local\bin
defenseclaw uninstall --all --binaries --yes   # remove everything, including %USERPROFILE%\.defenseclaw
```

For a machine-wide deployment managed by Intune or another MDM, see
[enterprise deployment](/docs/enterprise). The Cisco Secure Client profile is
described in
[Secure Client managed deployment](/docs/enterprise/secure-client).
