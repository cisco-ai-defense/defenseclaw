DefenseClaw installs per user with `install.ps1`, the same flow as the macOS
and Linux installer. The installer also upgrades, repairs, and rolls back.

From 1.0 this page replaces the 0.8.x `DefenseClawSetup-x64.exe` flow: that
installer is retired, and its `/repair`, `/uninstall` and `DELETEUSERDATA=1`
options do not apply to an `install.ps1` install. Re-running `install.ps1`
imports an existing Setup install (see
[Moving from the 0.8.x Setup package](#moving-from-the-08x-setup-package)). Administrator
deployments use the separate [enterprise deployment](/docs/enterprise): the
standalone [enterprise Setup](/docs/enterprise/windows) or the
[Cisco Secure Client profile](/docs/setup/enterprise-deployment#windows-system-service-layout).

## System requirements

| Requirement | Native Windows contract |
| --- | --- |
| Operating system | Native Windows 10-family or newer, including Windows Server 2019+. |
| Architecture | amd64/x64 only. ARM64 is not certified: releases publish no ARM64 build, so the installer refuses it. x86 is unsupported. |
| Shell | Windows PowerShell 5.1 (built in) or PowerShell 7. |
| Install scope | Current user only. Running elevated works but is not needed. |
| Agent | A [supported connector](/docs/connectors#platform-support) installed natively for the same Windows user. Do not substitute WSL or mix native and WSL connector homes. |
| Python | Provided by `uv`, which the installer installs if you do not have it. |
| Networking | The installer downloads the release from GitHub. At runtime DefenseClaw listens on authenticated loopback, normally `127.0.0.1:18970`. |

The optional Docker-backed local observability and Local Splunk bundles have a
narrower requirement: Windows x64 Pro, Enterprise, or Education; Hyper-V;
machine-installed Docker Desktop; Linux containers; a reachable daemon;
Compose v2; and a real native `docker.exe`. Windows Home, per-user Docker
Desktop, WSL2 engines, Windows containers, and command-wrapper shims are not in
that optional feature's supported path. Core DefenseClaw does not require
Docker.

## Install

```powershell
irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1 | iex
```

To choose options, run the script block with parameters:

```powershell
& ([scriptblock]::Create((irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1))) -Connector codex -Quickstart
```

| Parameter | What it does |
| --- | --- |
| `-Yes` | Do not prompt |
| `-Version X.Y.Z` | Install a specific release |
| `-Local DIR` | Take every release file from a directory instead of GitHub |
| `-Rollback` | Restore the install that the last upgrade replaced |
| `-Connector NAME` | First install only: the agent to guard |
| `-NoOpenclaw` | Same as `-Connector none` |
| `-Quickstart` | First install only: run `defenseclaw quickstart` afterwards |
| `-QuickstartMode observe\|action` | Mode for `-Quickstart`; implies `-Quickstart` |
| `-NoPersistPath` | Do not add `%USERPROFILE%\.local\bin` to your user `PATH` |
| `-CosignPath FILE` | Use this `cosign` binary to verify the release signature |

The installer checks every download against the release's `checksums.txt`
(and its Sigstore signature when `cosign` 2.0 or later is installed), prepares the new
version before changing anything, and adds `%USERPROFILE%\.local\bin` to your
user `PATH`. Open a new terminal afterwards so the `PATH` change applies, then
check:

```powershell
defenseclaw --version
defenseclaw-gateway --version
```

## Configure after installation

For guided configuration:

```powershell
defenseclaw init
```

For explicit supported connectors:

```powershell
defenseclaw setup codex --mode observe
defenseclaw setup claude-code --mode observe
defenseclaw setup amp --mode observe
defenseclaw setup cursor --mode observe
defenseclaw setup devin --mode observe
defenseclaw setup hermes --mode observe
defenseclaw setup omnigent --mode observe
defenseclaw setup opencode --mode observe
defenseclaw setup copilot --mode observe
defenseclaw setup antigravity --mode observe
defenseclaw setup kiro --mode observe
```

One local gateway can host all eleven native lifecycle connectors. Add connectors without removing the
first:

```powershell
defenseclaw setup `
  --connector codex `
  --connector claudecode `
  --connector amp `
  --connector cursor `
  --connector devin `
  --connector hermes `
  --connector omnigent `
  --connector opencode `
  --connector copilot `
  --connector antigravity `
  --connector kiro `
  --mode observe `
  --restart `
  --yes
```

Setup follows the same rules for every connector:

1. If you set a connector home variable (`CODEX_HOME`, `CLAUDE_CONFIG_DIR`,
   `COPILOT_HOME`, `OMNIGENT_CONFIG_HOME`, `OPENCODE_CONFIG_DIR` or
   `HERMES_HOME`), setup records that path. Otherwise it uses the default home.
2. Antigravity uses `%USERPROFILE%\.gemini\config`, Cursor uses its default
   configuration home, and Devin uses `%APPDATA%\devin`.
3. Repair and upgrade keep using the recorded home, even if you later change the
   environment variable. Run `defenseclaw setup <connector>` again to move it.
4. Restart OpenCode after setup changes so it loads the new plugin state.

The data root is `%USERPROFILE%\.defenseclaw` unless `DEFENSECLAW_HOME` is set;
see [Path and override rules](/docs/get-started/windows/paths-troubleshooting#supported-path-overrides).

Amp has no connector-home override: its system plugin uses
`%USERPROFILE%\.config\amp\plugins\defenseclaw.ts`. Fully exit and relaunch Amp
after setup changes; headless execute mode must use `--plugin-ready-timeout 30`
so the policy plugin is ready before the turn begins.

## Startup behavior

The gateway runs as a background process for the signed-in user. It starts
when you run `defenseclaw quickstart`, `defenseclaw setup`, or
`defenseclaw-gateway start`, and a hook starts it when an agent calls it while
it is stopped. There is no Windows service, Scheduled Task, or sign-in entry.

## Upgrade

```powershell
defenseclaw upgrade
```

The installer continues in a new PowerShell window so the running command can
release its files. It stops the gateway, keeps the current install in
`%USERPROFILE%\.defenseclaw\previous`, swaps in the new version, migrates your
configuration, and restarts the gateway. If any step fails it restores the
previous install. Close the TUI and other DefenseClaw commands first; the
installer waits up to a minute for them and changes nothing if they stay open.

To undo the last upgrade:

```powershell
defenseclaw rollback
```

See [Upgrade DefenseClaw](/docs/get-started/upgrade) for every option and the
[CLI reference](/docs/reference/cli#upgrade) for flags.

When an administrator sets the `DisableSelfUpdate` policy (a nonzero DWORD
under `HKLM\SOFTWARE\Policies\Cisco\DefenseClaw`), `install.ps1`,
`defenseclaw upgrade` and `defenseclaw rollback` refuse and change nothing, and
the update notice is off. Update through your managed deployment instead. A
standalone [enterprise deployment](/docs/enterprise) sets this policy when the
value is absent, unless its config sets
`enterprise.coexistence.disable_self_update: false`. On such a computer
`install.ps1`, `defenseclaw upgrade` and `defenseclaw rollback` refuse in any
case, because the
deployment's registration marks the computer as managed.

### Moving from the 0.8.x Setup package

Run the install command above. The installer imports a
`DefenseClawSetup-x64.exe` installation: it stops its gateway, removes its
program folder, sign-in entry, Add/Remove Programs entry, and `PATH` entry,
keeps your configuration and data in `%USERPROFILE%\.defenseclaw`, and keeps the
old program files in `%USERPROFILE%\.defenseclaw\previous\legacy-setup`.
Connector hooks are rewritten to the new paths when the gateway starts.

You do not need to run the old Setup to move.

<Accordions>
<Accordion title="Checking an old 0.8.x Setup file">

The published 0.8.x `DefenseClawSetup-x64.exe` files are not Authenticode
signed, so `/verify` on them exits `1`. That is their signing state, not a sign
of tampering. To check such a file, verify the Sigstore signature of the
release's `checksums.txt`, then compare the file's SHA-256
(`Get-FileHash -Algorithm SHA256`) with its entry there.

</Accordion>
</Accordions>

## Repair

Run the install command again. Reinstalling the same version rebuilds the
program files and keeps your configuration, data, and the rollback copy.

## Uninstall and preserved state

```powershell
defenseclaw uninstall              # remove connector integrations; keep data and programs
defenseclaw uninstall --binaries   # also remove the programs in %USERPROFILE%\.local\bin
defenseclaw uninstall --all --binaries --yes   # remove everything, including %USERPROFILE%\.defenseclaw
```

For a machine-wide deployment managed by Intune or another MDM, see
[enterprise deployment](/docs/enterprise). The Cisco Secure Client profile is
described in
[Enterprise hardening and deployment](/docs/setup/enterprise-deployment).
All uninstall flags are in the [CLI reference](/docs/reference/cli#uninstall).
