title: Windows managed enterprise guidance moved
description: The Windows managed-enterprise guidance now lives in the enterprise deployment section (standalone profile) and the enterprise hardening guide (Cisco Secure Client profile).

<Callout title="Deploying to managed Windows computers?">
Start with [Deploy to a fleet](/docs/enterprise/get-started): six steps from
choosing a profile to a ringed rollout, for Intune, Configuration Manager,
Workspace ONE or any other MDM.
</Callout>

Windows managed enterprise has two profiles. The standalone profile, for
Intune or any other MDM, is documented in
[Windows standalone deployment](/docs/enterprise/windows). The Cisco Secure
Client profile's service, guardian, policy, repair, upgrade, and removal
lifecycle lives in [Secure Client managed deployment](/docs/setup/enterprise-deployment#windows-system-service-layout).
This route remains as a compatibility pointer for existing bookmarks.

<Cards>
  <Card title="Standalone profile (any MDM)" href="/docs/enterprise/windows" description="Install the four standalone services with PowerShell 7, detect them with Intune, and converge with ensure." />
  <Card title="Windows system-service layout" href="/docs/setup/enterprise-deployment#windows-system-service-layout" description="Start with the Windows architecture, qualified connectors, policy, and target manifest." />
  <Card title="Install Windows services" href="/docs/setup/enterprise-deployment#install-the-windows-services" description="Run the administrator-owned installer and verify all five Secure Client SCM services." />
  <Card title="Reconcile and verify targets" href="/docs/setup/enterprise-deployment#reconcile-and-verify-windows-targets" description="Repair enrolled per-user connector hooks and read back readiness." />
  <Card title="Repair, upgrade, and remove" href="/docs/setup/enterprise-deployment#windows-repair-upgrade-and-removal" description="Use the transactional managed lifecycle rather than the per-user Setup." />
</Cards>

The ordinary per-user Windows package remains separate and never installs a
service. Use [Install and maintain](/docs/get-started/windows/install-lifecycle)
for that package.
