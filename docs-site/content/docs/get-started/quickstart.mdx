Install DefenseClaw, guard one agent and watch a test command get blocked, in about five minutes. This uses Claude Code. For another agent, replace `claudecode` with its connector name (`codex`, `copilot`, `cursor`, `devin`, `antigravity`, `kiro`, `opencode`, `amp` or `hermes`). The [support matrix](/docs/get-started/support-matrix) shows which agents can block on your OS.

The block comes from a one-rule test pack that matches only `echo defenseclaw-demo-marker`. Agents refuse the destructive commands the default rules target, so a harmless marker is the reliable way to see a block.

## Block a tool call

<Steps>

<Step>

### Install

<include>../../snippets/install-commands.mdx</include>

The installer asks which agent to guard: type `claudecode`. Requirements and options are on [Install](/docs/get-started/install).

</Step>

<Step>

### Run `defenseclaw init`

```bash
defenseclaw init --connector claudecode
```

Press Enter through the prompts. Claude Code starts in **observe** mode: DefenseClaw logs what the agent does and blocks nothing yet. At **Select connector(s) for action enforcement**, leave the box unchecked. `init` starts the gateway and prints a first-run report. This sample comes from `defenseclaw quickstart --skip-gateway`, which prints the same report, so its Sidecar row says not started where yours says started:

<include>../../snippets/first-run-report.mdx</include>

`✓` is done and `-` is optional or skipped. You need no LLM key for this guide. If the report says `partial`, it names what needs attention; `defenseclaw doctor` explains the rest. Options are in the [init reference](/docs/reference/commands/first-run).

Quit and reopen Claude Code so it loads the hooks, ask it to list the files in the directory, then run `defenseclaw status`. The agent, its mode and the new events appear within a second or two.

</Step>

<Step>

### Turn on blocking for Claude Code

```bash
defenseclaw guardrail mode action --connector claudecode
```

This switches only Claude Code to **action** mode, which enforces the rules. The running gateway applies it without a restart. The hook fail mode is `closed` on a new install: if the gateway is down, tool calls are blocked ([fail modes](/docs/reference/configuration/fail-modes)).

</Step>

<Step>

### Add the demo rule

Copy the default rule pack, add one CRITICAL rule that matches only `defenseclaw-demo-marker`, and point Claude Code at the copy:

{/* regression-check: the PowerShell tab below is pending a native Windows run. */}

<Tabs items={['macOS / Linux', 'Windows (PowerShell)']}>

<Tab value="macOS / Linux">

```bash
PACK=~/.defenseclaw/policies/guardrail/first-guardrail
cp -R ~/.defenseclaw/policies/guardrail/default "$PACK"
cat > "$PACK/rules/first-guardrail.yaml" <<'EOF'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
EOF
defenseclaw guardrail validate-pack "$PACK"
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

<Tab value="Windows (PowerShell)">

```powershell
$Pack = "$HOME\.defenseclaw\policies\guardrail\first-guardrail"
Copy-Item -Recurse "$HOME\.defenseclaw\policies\guardrail\default" $Pack
Set-Content -Path "$Pack\rules\first-guardrail.yaml" -Encoding ascii -Value @'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
'@
defenseclaw guardrail validate-pack $Pack
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

</Tabs>

The copy keeps every default rule. `use-pack` pins the pack's digest in `guardrail.custom_packs.first-guardrail` and switches Claude Code to it. Nothing restarts.

</Step>

<Step>

### Ask the agent to run the marker

In Claude Code, ask:

> Please run `echo defenseclaw-demo-marker`.

The command does not run. Claude Code tells you DefenseClaw blocked it:

> DefenseClaw policy blocked this action (rule DEMO-MARKER-BLOCK: First-guardrail demo marker). Do not retry it in another form.

In another terminal, list the latest alerts:

```bash
defenseclaw alerts --limit 5
```

The block is the newest row. `defenseclaw alerts --show 1` prints the whole record:

```text
Alert #1
  Severity:  CRITICAL
  Action:    scan-finding
  Target:    claudecode:PreToolUse
  Decision:  blocked
  Connector: claudecode
  Rule:      DEMO-MARKER-BLOCK: First-guardrail demo marker
  Scanner:   hook-rules
```

The same alert is in the **Alerts** panel of `defenseclaw tui` (press `2`).

![The Alerts panel of defenseclaw tui showing one CRITICAL scan-finding alert for claudecode:PreToolUse with rule DEMO-MARKER-BLOCK](/images/get-started/tui-alerts-demo-block.png)

</Step>

<Step>

### Undo the demo

```bash
defenseclaw guardrail use-pack --clear --connector claudecode   # back to the default pack
defenseclaw guardrail mode --clear --connector claudecode       # back to observe
```

Delete the `first-guardrail` folder under `~/.defenseclaw/policies/guardrail/`. Skip the second command to keep enforcing the default rules.

</Step>

</Steps>

## If it did not block

- The agent was open before `init`: quit and reopen it.
- `defenseclaw doctor` shows a failing hook or gateway row: see [Troubleshooting](/docs/troubleshooting).
- Still in observe mode: run `defenseclaw guardrail status`.
