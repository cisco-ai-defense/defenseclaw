After the [install](/docs/get-started/install), DefenseClaw is on disk but not yet configured. Run **one** first-run command. Both write the config, seed the audit database and set up the guardrail for your agent.

On native Windows, first check the [connector platform table](/docs/connectors#platform-support).

<Cards>
  <Card title="defenseclaw init" description="Interactive wizard. Asks about connector, profile, scanner mode, judge, HITL. Recommended the first time." />
  <Card title="defenseclaw quickstart" description="Zero-prompt equivalent with safe defaults. Recommended for CI, scripts, and demos." />
</Cards>

<Callout>
You do **not** need to run `init` before `quickstart`. Pick one. They differ in one way that matters: `quickstart` starts the gateway unless you pass `--skip-gateway`. Interactive `init` asks whether to start it. Non-interactive `init` starts the gateway only with `--start-gateway`.
</Callout>

## Path A interactive init [#path-a-interactive-defenseclaw-init]

The recommended first run for a human at a terminal. The wizard walks you through every choice, shows defaults, and explains the trade-offs.

```bash
defenseclaw init
```

On a terminal, `init` runs the guided wizard. It runs local agent discovery, **pre-selects every installed hook connector**, and configures them **all in `observe` (log-only) mode** by default — pressing Enter through the connector prompt brings up everything you have. Rather than asking observe-vs-action for each one, it asks a single question, **"Action-mode connector(s)"**, naming the subset that should enforce. Leave it blank and every connector stays in observe.

The action-only policy knobs — hook fail-mode (`open`/`closed`) and HITL human-approval plus its minimum severity — are asked **once** and shared across every connector you promote to action; observe connectors never see them. Proxy connectors (`openclaw`, `zeptoclaw`) are detected but excluded from the observe-all set — they own the single LLM proxy port and can't be multi-connector peers — so the wizard prints a one-line note pointing you to `defenseclaw setup <proxy>` for them.

<Callout type="warn">
An action connector whose installed version doesn't map to a known hook contract is **downgraded to observe** with a warning — the same gate the gateway applies at boot. Override only for exploratory testing with `DEFENSECLAW_ALLOW_HOOK_CONTRACT_DRIFT=1`.
</Callout>

### Scripted `init` (no prompts)

To skip the wizard — including inside a session that *is* a TTY (CI on a pty, scripted demos) — `defenseclaw init` exposes two **init-only** multi-connector flags. These do **not** exist on `quickstart`:

```bash
# Observe every detected hook connector, enforce on codex, start the gateway:
defenseclaw init --non-interactive --yes --observe-all --action-connectors codex --start-gateway
```

| Flag (`init` only) | Effect |
| --- | --- |
| `--observe-all` | Configure every detected hook connector in `observe` mode. |
| `--action-connectors codex,claudecode` | Comma-separated connectors to configure in `action` mode. Composable with `--observe-all` (everything else stays observe); the named connectors are configured even on their own. |
| `--non-interactive` | Skip every prompt. |
| `--yes` / `-y` | Auto-accept every confirmation. |
| `--connector <x>` | Pre-select a single agent. Single-connector path — wins over the multi flags. |
| `--start-gateway` | Start the gateway after setup. Without it, non-interactive `init` does not start the gateway. |

With neither multi flag nor `--connector`, non-interactive init keeps the single-connector default: one discovery-backed connector in `observe`. An explicit `--connector` always wins.

## Path B zero-prompt quickstart [#path-b-zero-prompts-defenseclaw-quickstart]

The scripted equivalent. No prompts, and safe defaults: `observe` profile, `local` scanner, no LLM judge, no HITL.

<Steps>

<Step>

### Run it

```bash
defenseclaw quickstart --connector claudecode
```

Replace `claudecode` with the setup name for the agent you use. On native
Windows, pick a connector that the [platform table](/docs/connectors#platform-support)
lists as supported; `quickstart` rejects the others before it writes anything.
`quickstart` configures **one** connector. If you
skip `--connector`, it uses the single configured or detected connector; if
more than one connector is configured/detected, or the installer hint disagrees
with the detected connector, it exits and asks you to rerun with `--connector
<name>`.

</Step>

<Step>

### Watch the report

The command prints a one-screen first-run report. This sample is illustrative; the steps, paths and hints depend on your machine:

```text
  DefenseClaw First-Run
  status=ready connector=claudecode profile=observe
  ────────────────────────────────────────────────────────

  Setup
  ✓ Config  created defaults
  ✓ Bootstrap  ~/.defenseclaw
  ✓ Skill scanner  ~/.local/bin/skill-scanner
  ✓ MCP scanner  ~/.local/bin/mcp-scanner
  ✓ Guardrail  claudecode, mode=observe
  ✓ Sidecar  started

  Readiness
  ✓ Config file  ~/.defenseclaw/config.yaml
  ✓ Audit database  ~/.defenseclaw/audit.db
  ✓ Device key  ~/.defenseclaw/device.key

  Next
  defenseclaw doctor
  defenseclaw keys list
  Adding another agent later: defenseclaw setup <connector>
  Running coding agents in OpenShell sandboxes: defenseclaw sandbox setup
```

The `status` is `ready`, `partial` (a step warned) or `needs_attention` (a step failed). The Next list can also show `Unguarded ACP agents found (...): defenseclaw setup acp` when an ACP editor agent is not guarded yet.

If `status` is `needs_attention`, the command exits non-zero. The failed steps and the Next list show the command to run.

</Step>

<Step>

### Drive the agent

Open Claude Code (or whichever connector you picked). DefenseClaw now receives
the lifecycle events and interception surfaces supported by that connector.
Watch the resulting decisions land in the live dashboard:

```bash
defenseclaw tui
```

Or take a scriptable snapshot from mandatory SQLite event history:

```bash
defenseclaw-gateway audit export --output - | tail -n 200 | jq .
```

JSONL is no longer an implicit mirror. If you need a continuous external file,
configure an explicit v8 `kind: jsonl` destination with the buckets, signals,
and redaction profile that file is allowed to receive.

</Step>

</Steps>

## When to use which

| Situation | Use |
| --- | --- |
| First-time setup at a terminal | `defenseclaw init` |
| You want to be asked questions and shown defaults | `defenseclaw init` |
| Installer hand-off / unattended provisioning | `defenseclaw quickstart --connector <x>` |
| CI pipeline (no TTY, deterministic config) | `defenseclaw quickstart --connector <x> --non-interactive --yes --json-summary` |
| Scripted demo / repeatable test fixture | `defenseclaw quickstart --connector <x> --force` |
