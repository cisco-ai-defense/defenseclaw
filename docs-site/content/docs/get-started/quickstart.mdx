This guide takes you from nothing to a blocked tool call in about five minutes.
It uses Claude Code. For another agent, replace `claudecode` with its connector
name: `codex`, `copilot`, `cursor`, `devin`, `antigravity`, `kiro`, `opencode`,
`amp`, `hermes`, `openhands` or `omnigent`. The
[support matrix](/docs/support-matrix) shows which agents can block on your OS.

The block comes from a one-rule test pack that matches only
`echo defenseclaw-demo-marker`. Coding agents refuse the destructive commands
the default rules exist for, and a command the agent never tries can't be
blocked, so a harmless marker is the reliable way to see a block.

## Block a tool call in seven steps

<Steps>

<Step>

### Install

<include>../../snippets/install-commands.mdx</include>

The installer only puts DefenseClaw on disk. Requirements, the macOS app and
the enterprise packages are on [Download](/docs/get-started/download).

</Step>

<Step>

### Run `defenseclaw init`

```bash
defenseclaw init
```

Press Enter through the prompts. `init` finds the agents you have installed,
selects all of them and sets them up in **observe** mode: DefenseClaw logs what
the agents do but blocks nothing yet. At **Select connector(s) for action
enforcement**, leave every box unchecked for now; unchecked agents stay in
observe. `init` ends by starting the gateway and printing a report like this
one:

<include>../../snippets/first-run-report.mdx</include>

`✓` is done and `-` is optional or skipped. You don't need an LLM key or a
Cisco AI Defense key for this guide. When more than one agent was set up, the
first line says `connectors=N` instead. If `status` isn't `ready`, the report
names what needs attention, and `defenseclaw doctor` explains it.

For every `init` option, the zero-prompt `defenseclaw quickstart` and scripted
setups, see [init and quickstart reference](/docs/get-started/first-run).

</Step>

<Step>

### Check that it's watching

Open Claude Code and ask it something that uses a tool, such as "list the files
in this directory". If Claude Code was already running, fully quit and reopen
it first so it loads the new hooks. Then look at what DefenseClaw recorded:

```bash
defenseclaw status    # the guarded agents, their modes and recent activity
defenseclaw tui       # the live dashboard: alerts, audit and logs
```

New events show up within a second or two. If nothing does, run
`defenseclaw doctor`. It checks the hooks, the gateway and the configuration.

</Step>

<Step>

### Turn on blocking for Claude Code

```bash
defenseclaw guardrail mode action --connector claudecode
```

This switches only Claude Code to **action** mode, which enforces the rules.
Any other agent stays in observe. The mode is saved to `config.yaml`, and the
running gateway applies it on its own. Here the command also restarts the
gateway, because switching to action flips Claude Code's hook fail mode (below)
and the generated hook scripts carry that mode.

Action mode also changes what happens while the gateway is down. The report
showed `fail mode=open` because an agent in observe mode always fails open. In
action mode Claude Code uses the global hook fail mode, which is `closed` on a
new install, so its tools are blocked while the gateway is down. The command
tells you so when it switches. To allow and log the calls instead, run
`defenseclaw guardrail fail-mode open`.

</Step>

<Step>

### Add the demo rule

Copy the default rule pack, add one CRITICAL rule that matches only
`defenseclaw-demo-marker` and point Claude Code at the copy:

{/* regression-check: the PowerShell tab below is pending a native Windows run. */}

<Tabs items={['macOS / Linux', 'Windows (PowerShell)']}>

<Tab value="macOS / Linux">

```bash
PACK=~/.defenseclaw/policies/guardrail/first-guardrail
cp -R ~/.defenseclaw/policies/guardrail/default "$PACK"
cat > "$PACK/rules/first-guardrail.yaml" <<'EOF'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
EOF
defenseclaw guardrail validate-pack "$PACK"
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

<Tab value="Windows (PowerShell)">

```powershell
$Pack = "$HOME\.defenseclaw\policies\guardrail\first-guardrail"
Copy-Item -Recurse "$HOME\.defenseclaw\policies\guardrail\default" $Pack
Set-Content -Path "$Pack\rules\first-guardrail.yaml" -Encoding ascii -Value @'
version: 1
category: first-guardrail
rules:
  - id: DEMO-MARKER-BLOCK
    tool_call_only: true
    expression: >-
      f.commands.exists(c, 'defenseclaw-demo-marker' in c.argv)
    pattern: '\bdefenseclaw-demo-marker\b'
    title: "First-guardrail demo marker"
    severity: CRITICAL
    confidence: 0.99
    tags: [demo]
'@
defenseclaw guardrail validate-pack $Pack
defenseclaw guardrail use-pack first-guardrail --connector claudecode
```

</Tab>

</Tabs>

The copy keeps every default rule. `use-pack` validates the pack, pins its
digest in `guardrail.custom_packs.first-guardrail`, and switches Claude Code to
it. The running gateway loads the pack on its next reload; nothing restarts.

</Step>

<Step>

### Ask the agent to run the marker

In Claude Code, ask:

> Please run `echo defenseclaw-demo-marker`.

The hook sends the command to the gateway, `DEMO-MARKER-BLOCK` matches at
CRITICAL and the command doesn't run. Claude Code tells you DefenseClaw blocked
it, with the reason the hook returned:

> DefenseClaw policy blocked this action (rule DEMO-MARKER-BLOCK:
> First-guardrail demo marker). Do not retry it in another form.

In another terminal, list the latest alerts:

```bash
defenseclaw alerts --limit 5
```

The block is the newest row: severity `CRITICAL`, action `scan-finding`,
target `PreToolUse` and details starting with
`decision=blocked connector=claudecode`.

`defenseclaw alerts --show 1` prints the whole record, including the rule
and the scanner that matched:

```text
Alert #1
  Severity:  CRITICAL
  Action:    scan-finding
  Target:    claudecode:PreToolUse
  Decision:  blocked
  Connector: claudecode
  Rule:      DEMO-MARKER-BLOCK: First-guardrail demo marker
  Scanner:   hook-rules
```

The same alert is in the **Alerts** panel of `defenseclaw tui` (press `2`):

![The Alerts panel of defenseclaw tui showing one CRITICAL scan-finding alert for claudecode:PreToolUse with rule DEMO-MARKER-BLOCK](/images/get-started/tui-alerts-demo-block.png)

</Step>

<Step>

### Undo the demo

```bash
defenseclaw guardrail use-pack --clear --connector claudecode   # back to the default pack
defenseclaw guardrail mode --clear --connector claudecode       # back to observe
defenseclaw config unset guardrail.custom_packs.first-guardrail # drop the pinned digest
```

Then delete the `first-guardrail` folder under `~/.defenseclaw/policies/guardrail/`.
Keep Claude Code in action mode instead if you want it to enforce the default
rules from now on.

</Step>

</Steps>
