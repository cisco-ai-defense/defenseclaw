This walkthrough ends with DefenseClaw refusing to remove a disposable
directory under `/var/tmp`. The example is intentionally harmless even if the
guardrail is misconfigured. It takes a few minutes.

The sequence is: install, run the first-run setup (`quickstart` or `init`),
which wires Claude Code in observe mode, then turn on action mode.

<Callout type="info" title="macOS/Linux walkthrough">
This fixture intentionally exercises the POSIX-specific `CMD-RM-RF` rule and
requires a POSIX shell plus `jq`; it is not a native Windows command example.
On Windows, complete the connector page's Windows setup tab and use the
[native Windows post-install checklist](/docs/get-started/windows/paths-troubleshooting#post-install-checklist)
to verify the gateway, connector hook, audit, and repair path without inventing
a Windows policy rule that the default pack does not ship.
</Callout>

<Steps>

<Step>

### Install

```bash
curl -LsSf https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.sh | bash -s -- --connector claudecode
```

</Step>

<Step>

### Run the first-run setup

```bash
defenseclaw quickstart --connector claudecode
```

This writes the config, seeds the audit database, wires Claude Code in
observe mode and starts the gateway. Observe mode records events but does not
block yet, so you can check the data path before you turn enforcement on. To
answer the questions yourself, run `defenseclaw init` instead. See
[Quickstart](/docs/get-started/quickstart).

If Claude Code is already open, fully quit and reopen it so it loads the new
hooks. Check the connector is listed with `defenseclaw status`.

</Step>

<Step>

### Confirm telemetry is flowing

In one terminal, open the live dashboard (audit + alerts + logs panels):

```bash
defenseclaw tui
```

Or take a scripted snapshot from the local audit database:

```bash
defenseclaw-gateway audit export --output - \
  | jq -c 'select(.connector == "claudecode")' \
  | tail -n 200
```

In Claude Code, ask the assistant to run any tool call (e.g. "list files in this directory"). New rows should appear within a second or two. If nothing shows up, run `defenseclaw doctor` — it will diagnose hook script presence, gateway port binding, and config drift.

</Step>

<Step>

### Promote to action mode

```bash
defenseclaw setup guardrail --connector claudecode --mode action --human-approval --restart
```

Two things just changed:

- `guardrail.mode` flipped to `action`. CRITICAL findings now block via the `PreToolUse` hook's deny verdict.
- `guardrail.hilt.enabled` flipped to `true`. HIGH findings will pause for operator approval (Claude Code supports native PreToolUse ask, so the prompt appears inside the agent UI).

</Step>

<Step>

### Trigger the rule

Create an empty disposable target yourself:

```bash
mkdir -p /var/tmp/defenseclaw-demo-empty
```

Then ask Claude Code to clean it up:

> Please run `rm -rf /var/tmp/defenseclaw-demo-empty`.

The default pack's `CMD-RM-RF` rule flags recursive force deletion under
critical root prefixes such as `/var` as CRITICAL. The PreToolUse hook returns
`block` and the agent does not execute the command. Arbitrary relative paths or
home subdirectories are not matched by this rule merely because `rm -rf` is
present.

In a second terminal you'll see the audit event land. List recent alerts:

```bash
defenseclaw alerts --limit 10
```

This output is illustrative; your columns and values can differ:

```text
#   SEVERITY   TIMESTAMP             ACTION  TARGET                              DETAILS
1   CRITICAL   2026-05-08 14:02:11   block   rm -rf /var/tmp/defenseclaw-demo-empty   CMD-RM-RF
```

Use `defenseclaw alerts --show 1` for the full record (rule path, scanner,
evidence). For a scriptable SQLite snapshot filtered to high-severity rows:

```bash
defenseclaw-gateway audit export --output - \
  | jq -c 'select(.connector == "claudecode" and (.severity == "HIGH" or .severity == "CRITICAL"))' \
  | tail -n 200
```

</Step>

<Step>

### What if you wanted to allow it?

Three safer options:

- **Use a narrower cleanup command** — avoid force-recursive deletion when it is unnecessary.
- **Customize a copied rule pack** — change `rules/commands.yaml` in a custom pack, then select it with `--rule-pack-dir`. Editing a bundled pack in place makes upgrades harder to review.
- **Switch to observe mode** — `defenseclaw setup guardrail --connector claudecode --mode observe`. Use this for the first week of every new connector.

CRITICAL findings are not eligible for HITL approval.

</Step>

</Steps>
