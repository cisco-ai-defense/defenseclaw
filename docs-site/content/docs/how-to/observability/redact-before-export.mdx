A new install exports full content. This page sets a profile on one destination so it receives less, and leaves local history unredacted.

The four profiles are `none`, `sensitive`, `content` and `strict`. [Redaction](/docs/reference/observability/redaction#built-in-profiles) says what each removes.

## Before you start

- A destination is configured ([Send to an OTLP collector](/docs/how-to/observability/send-to-an-otlp-collector)).
- You know which buckets the destination needs. A global or bucket profile also redacts local history; a destination profile does not.

## Steps

1. See what is unredacted now.

   ```bash
   defenseclaw setup redaction status
   ```

   ```text
   Destinations
     local-sqlite: signals=logs redaction=unredacted (none)
     engineering: signals=logs,traces,metrics redaction=unredacted (none)

   Buckets
     BUCKET                   SIGNALS                PROFILE
     compliance.activity      logs,traces,metrics    none
     security.finding         logs,traces,metrics    none
   …
   Every bucket uses profile 'none', so collected telemetry is sent unredacted.
   ```

2. Preview a profile on one destination.

   ```bash
   defenseclaw setup redaction destination send engineering \
     --signal logs --bucket security.finding --profile strict --dry-run
   ```

   ```text
   Redaction policy preview
     Scope: configurable observability log/trace projections only
     Effective legs changed: 29
     Newly unredacted: 0
     engineering/send security.finding logs: not-delivered -> strict
   …
   ```

   This also narrows `engineering` to the one bucket and signal you named. Everything else stops going to it.

3. Apply it. Replace `--dry-run` with `--yes`.

   ```bash
   defenseclaw setup redaction destination send engineering \
     --signal logs --bucket security.finding --profile strict --yes
   ```

   ```text
   Configuration updated and verified.
   Backup: ~/.defenseclaw/backups/config.yaml.before-redaction-1792566544163000669
   The gateway will hot-reload supported policy changes; restart if required by the plan.
   ```

To apply one profile to every destination and to local history instead, run `defenseclaw setup redaction apply --scope all-configurable --profile sensitive --yes`. Run `defenseclaw setup redaction` with no arguments for the guided editor, or open **Setup → Guardrail & scanning → Redaction** in the TUI.

## Check it worked

```bash
defenseclaw observability plan --bucket security.finding --signal logs
```

```text
BUCKET            SIGNAL  COLLECT  DESTINATION   DECISION  ROUTE                                   REDACTION
security.finding  logs    yes      local-sqlite  send      all-collected-logs-and-mandatory-floor  none
security.finding  logs    yes      engineering   send      send                                    strict
```

The destination should show the profile you chose. Local history keeps `none`.

## Undo

Every change writes a backup. Restore it, or hand the destination back to the defaults:

```bash
defenseclaw setup redaction destination inherit engineering --yes
```

To turn redaction off everywhere, run `defenseclaw setup redaction remove-all --yes`. Prompts, responses, tool data and paths then reach every destination as recorded.
