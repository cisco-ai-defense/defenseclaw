An OTLP destination receives logs, traces and metrics from the gateway. Use it for Datadog, Honeycomb, New Relic, Grafana Cloud or your own collector.

## Before you start

- The collector address, and a header or token if it needs one.
- Store the token in an environment variable, not in a command line. Command-line values are visible to other users in `ps`.

## Steps

1. Add the destination.

   ```bash
   defenseclaw setup observability add otlp \
     --name engineering \
     --endpoint otel.example.com:4317 \
     --protocol grpc \
     --non-interactive
   ```

   ```text
     Generic OTLP: added as destination 'engineering'
     Test it with: defenseclaw setup observability test engineering
     Saved. The gateway isn't running; it loads this destination when it starts (defenseclaw-gateway start).
   ```

   For a collector on this computer or a private network, add `--allow-private-networks`. If it has no TLS, add `--plaintext` too. Use `--environment <name>` to tell computers with the same host name apart.

2. Narrow what it receives. With no filter, it gets every bucket and every signal. This sends only security logs and traces:

   ```yaml
   observability:
     destinations:
       - name: engineering
         kind: otlp
         protocol: grpc
         endpoint: otel.example.com:4317
         send:
           signals: [logs, traces]
           buckets: [security.finding, enforcement.action]
   ```

   Edit `~/.defenseclaw/config.yaml`, then run `defenseclaw config validate`. A running gateway applies a valid edit by itself. For filters by connector, action or severity, see [routes and selectors](/docs/reference/observability#routes-and-selectors).

3. Review the result.

   ```bash
   defenseclaw observability plan --bucket security.finding --signal logs
   ```

   ```text
   BUCKET            SIGNAL  COLLECT  DESTINATION   DECISION  ROUTE                                   REDACTION  …
   security.finding  logs    yes      local-sqlite  send      all-collected-logs-and-mandatory-floor  none       …
   security.finding  logs    yes      engineering   send      send                                    none       …
   ```

## Check it worked

```bash
defenseclaw observability destination test engineering
```

Add `--write-probe` to send one marked, content-free record. The test connects from your shell, while the gateway delivers through the proxy it was started with. If the test passes but `defenseclaw doctor` reports `delivery_failed`, look for `export failed` lines in the gateway log.

## Undo

```bash
defenseclaw setup observability disable engineering
```

`disable` keeps the entry. `defenseclaw setup observability remove engineering` deletes it.
