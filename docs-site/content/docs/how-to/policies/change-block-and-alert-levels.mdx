title: Change block and alert levels

`block_at` is the lowest severity DefenseClaw blocks. `alert_at` is the lowest it alerts on. Both take `CRITICAL`, `HIGH`, `MEDIUM` or `LOW`.

Before you start: the levels apply in action mode. In observe mode a finding at or above `block_at` is logged and nothing is stopped. See [turn on blocking](/docs/how-to/guardrail/turn-on-blocking).

1. Set the global block level.

   ```bash
   defenseclaw guardrail block-at HIGH
   ```

   ```text
     OK The global block level is now HIGH: tool calls, prompts and LLM traffic are blocked at HIGH+ unless a connector has its own. The gateway isn't running; it loads this when it starts.
       The global mode is observe, so connectors that follow it only log; the levels apply once they're in action mode.
   ```

   With a running gateway the message ends `The running gateway applies it now.` and the next decision uses the new level.

2. Set the alert level for one agent.

   ```bash
   defenseclaw guardrail alert-at MEDIUM --connector codex
   ```

   ```text
     OK Codex (codex) now alerts on tool calls, prompts and LLM traffic at MEDIUM+. The gateway isn't running; it loads this when it starts.
   ```

3. Give a profile its own level. The commands above have no `--profile` option, so use `config set` (see [group policies](/docs/how-to/policies/give-a-group-its-own-policy)).

   ```bash
   defenseclaw config set guardrail.profiles.contractors.block_at MEDIUM
   ```

## Check it worked

```bash
defenseclaw config get guardrail.block_at --effective
defenseclaw config get guardrail.alert_at --effective
```

```text
(source: config:guardrail.block_at)
HIGH
(source: pack-default:default)
MEDIUM
```

The `source` line shows where the value comes from. `pack-default:default` means nothing is set and the rule pack decides. `defenseclaw guardrail status` shows the result for each agent in its Block/alert column (`HIGH+/MEDIUM+`).

```bash
defenseclaw guardrail profile explain --connector codex
```

## Undo

Clear a level so the agent inherits the global one, or remove a profile key:

```bash
defenseclaw guardrail block-at inherit --connector codex
defenseclaw config unset guardrail.profiles.contractors.block_at
```

```text
  OK Codex (codex) follows the global block level again: HIGH+. The gateway isn't running; it loads this when it starts.
```

<Callout type="warn" title="Managed devices refuse local changes">
On a device managed by MDM or a management plane, `config set` and the `guardrail` commands exit with status 3. Change the levels in the admin config.
</Callout>
