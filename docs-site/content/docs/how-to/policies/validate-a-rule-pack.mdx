`validate-pack` runs the same loader the gateway uses. It works offline: the gateway does not need to be running and no network request is made.

1. Validate the pack.

   ```bash
   defenseclaw guardrail validate-pack ~/.defenseclaw/policies/guardrail/default
   ```

   ```text
   Rule pack valid: "/home/alice/.defenseclaw/policies/guardrail/default"
     rules: 239/243 enabled across 7 files
     components: judges=4 judge_categories=23 local_patterns=11 suppressions=9 sensitive_tools=6
     digest: 2d47f157e50f886c9a042b476be766af8d458788ee29a5fd611438361a8d9b18
     files digest: a86e6eca3acb787b98aa0c51cd8e46da435a645dcbd667ea675b8bd70fb6314d (the guardrail.custom_packs pin)
   ```

   `judges=4` counts the compiled-in exfil judge and the three judge files. The full digest includes compiled defaults and can change between builds even when the files digest stays the same. Use your own run's `files digest` to pin a custom pack. You can pass a pack name instead of a path.

2. In CI, ask for JSON.

   ```bash
   defenseclaw guardrail validate-pack PATH --json
   ```

   ```json
   {"kind":"validation","summary":{"alert_only_rule_count":0,"digest":"2d47f157…","enabled_rule_count":239,"files_digest":"a86e6eca…","judge_category_count":23,"judge_count":4,"local_pattern_count":11,"rule_count":243,"rule_file_count":7,"sensitive_tool_count":6,"stale_rule_count":0,"suppression_count":9},"valid":true,"wire_version":1}
   ```

3. Read a failure. A file the loader does not recognize fails the whole pack and exits `1`:

   ```text
   Rule pack invalid: "/home/alice/.defenseclaw/policies/guardrail/bad"
     inventory_unexpected at correlation-patterns.yaml: unexpected YAML component
   ```

   ```json
   {"error":{"code":"inventory_unexpected","path":"correlation-patterns.yaml","reason":"unexpected YAML component"},"kind":"validation_error","valid":false,"wire_version":1}
   ```

| Exit | Meaning |
| --- | --- |
| `0` | The pack is valid. |
| `1` | The pack is invalid. The output names the file, error code and reason. |
| `2` | Validation is unavailable (gateway binary missing, untrusted, timed out or incompatible). This does not say whether the pack is valid. |

Validation is all or nothing. If a recognized file is present, the whole file must parse: a malformed rule, an invalid Go regular expression or an unsupported schema version fails the pack. DefenseClaw does not silently discard the bad file or keep only the entries that parsed. Every `expression` is compiled, including on disabled rules. The pinned digest also covers the optional `defenseclaw-pack.json` posture file.

## Partial packs

A non-empty pack directory is an overlay on the compiled baseline. Missing `suppressions.yaml`, `sensitive-tools.yaml`, judge files and `rules/local-patterns.yaml` keep the baseline. Any other `rules/*.yaml` adds or replaces one category.

## Check it worked in doctor

```bash
defenseclaw doctor
```

```text
  [PASS] Rule pack [codex]  -  configured rule pack "default" "/home/alice/.defenseclaw/policies/guardrail/default": 239/243 rules enabled; digest=2d47f157…
```

Doctor validates the pack every connector uses. It shows `FAIL` for an invalid pack and `WARN` when the validator is missing.

## Managed hosts

On a managed computer, `defenseclaw` runs only `sandbox` commands. Use `defenseclaw-gateway rulepack validate --dir PACK`; it prints the digest to pin. See [custom rule packs](/docs/enterprise/configure/configuration#custom-rule-packs).
