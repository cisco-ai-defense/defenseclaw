Pick the sandbox pack that fits your project, add your own hosts, and lock a project to the sites its sandbox reached. A pack is one YAML file that sets web access, how connection requests are approved, live mount or copy, hidden secret files and skip-permissions mode.

| Pack | Web access | Your project | Skip-permissions |
| --- | --- | --- | --- |
| `open` (default) | Any site by name, except the blocklist, private networks and this machine | Mounted live | On |
| `balanced` | A curated developer allowlist | Mounted live | On |
| `strict` | None, only the model provider | Copied | Off |

Every setting of each pack is in [Sandbox policy](/docs/reference/sandboxes/policy#built-in-packs). Sandboxes must be set up first.

## Pick a built-in pack

For one run:

```bash
defenseclaw sandbox run claude --pack balanced
```

For every run, set `openshell.pack: balanced` in `~/.defenseclaw/config.yaml`. `defenseclaw sandbox pack list` lists the packs with their digests.

## Extend a pack

A custom pack starts from nothing unless it names a parent. Create `~/.defenseclaw/policies/sandbox/team-web/pack.yaml`. The directory name must match `name`.

```yaml
version: 1
name: team-web
extends: balanced
egress:
  allow:
    - artifacts.example.com
    - docs.example.com
  ports: [443]
```

Lists such as `egress.allow` add to the parent's. Every other key replaces the parent's value ([rules](/docs/reference/sandboxes/policy#extend-a-pack)). Validate it, then use it:

```bash
defenseclaw sandbox pack validate ~/.defenseclaw/policies/sandbox/team-web/pack.yaml
defenseclaw sandbox run claude --pack team-web
```

A bad key stops validation with the file, the key and the reason:

```text
sandbox pack /home/dev/.defenseclaw/policies/sandbox/team-web/pack.yaml: egress.ports[1]: port 70000 must be between 1 and 65535
```

## Add one host at a time

```bash
defenseclaw sandbox policy allow artifacts.example.com
defenseclaw sandbox policy test --host artifacts.example.com
```

```text
  pack balanced · profile balanced · network allowlist
DESTINATION             DECISION  RULE                      SOURCE
registry.npmjs.org:443  allowed   allow registry.npmjs.org  DefenseClaw's curated allowlist (pack balanced)
```

`policy block HOST` does the opposite. `policy test` says which rule decides and why.

## Record, then lock

Run a few sessions on the default `open` pack. DefenseClaw keeps every destination a sandbox reached or tried to reach (`defenseclaw sandbox destinations NAME`). Then preview and write a pack from them:

```bash
defenseclaw sandbox policy suggest --sandbox myapp-claude --diff
defenseclaw sandbox policy suggest --sandbox myapp-claude \
  --pack-out ~/.defenseclaw/policies/sandbox/myapp/pack.yaml
```

```text
  ✓ wrote /home/user/.defenseclaw/policies/sandbox/myapp/pack.yaml: pack myapp, extends balanced, 1 host to allow
```

The pack extends `balanced` and allows each host the sandbox reached that balanced does not cover, with a comment naming the programs that reached it. Hosts only ever refused, shadow AI hosts and the model provider are listed as comments, not allowed. Review every host, then lock the project:

```bash
defenseclaw sandbox run claude --pack myapp
```

To keep it locked in CI, run `defenseclaw sandbox policy test --pack FILE --fixture egress-expectations.yaml`. It exits 1 when a decision does not match. A project can also ask for a stricter sandbox with a [`.defenseclaw/sandbox.yaml`](/docs/reference/sandboxes/policy#repository-policy).

## Undo

Remove `--pack`, or delete `openshell.pack` from `config.yaml`, to return to `open`. Delete the pack directory to remove a custom pack.
