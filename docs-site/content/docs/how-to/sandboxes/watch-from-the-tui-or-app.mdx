Watch the live feed, answer asks, unblock sites, and stop, pull or undo a sandbox from the TUI or the macOS app. Both read the DefenseClaw daemon, so a sandbox started from the command line shows up in both. Sandboxes must be set up and the daemon running. On Windows the panel only says that OpenShell sandboxes run on Linux and macOS.

| Task | Command line | TUI (`7`) | macOS app |
| --- | --- | --- | --- |
| Start a run | `sandbox run claude` | `n` | **Copy run command** |
| Watch the feed | `sandbox activity -f` | `t` for **Activity** | **Activity**, plus notifications |
| Unblock a site | `sandbox unblock HOST` | `u` | **Unblock** |
| Answer an ask | `sandbox approve NAME ID` | `a`, `A`, `x` in **Asks** | **Approve**, **Always…**, **Reject** |
| Bring back a copy | `sandbox pull NAME --apply` | `P` | **Pull to branch** |
| Undo | `sandbox undo NAME` | `U` | **Undo…** |

## Use the TUI

```bash
defenseclaw tui
```

Press `7` for the Sandboxes panel. The header shows the state (`READY`, `OFF`, `WAITING`, `UNAVAILABLE` or `UNREACHABLE`), how many sandboxes run, how many asks wait, and the gateway with its driver. `OFF` points to the setup wizard. `UNAVAILABLE` gives the daemon's reason.

Press `t` to switch views: **Sandboxes** (one row per sandbox), **Activity** (the live feed, newest first) and **Asks** (waiting for you). `Enter` opens details, `Esc` closes them.

![DefenseClaw TUI Activity view on Linux: the feed of one sandbox, newest first, with allowed sites, two shadow AI warnings, a paste site refused with the key that unblocks it, a blocked tool call and the sandbox's lifecycle lines](/images/sandboxes/screens/tui-sandboxes-activity.png)

| Key | Action |
| --- | --- |
| `n` | Start a new sandboxed run |
| `c` | Connect: start a stopped sandbox and attach its harness |
| `s` / `d` | Stop (kept) or delete the sandbox, after asking |
| `R` / `P` | Review changed files (live mount), or pull a copy's work |
| `U` | Undo the pre-session snapshot, or the last pull on a copy |
| `u` | Unblock a blocked site, for this sandbox or all |
| `a` / `A` / `x` | Approve an ask once, always, or reject it |
| `w` | Turn the shell wrapper on or off per harness |

The KEYS line at the bottom lists the keys that apply to the selected row. Blocks of private networks, metadata addresses and your organization's block lists cannot be lifted here.

`n` opens the launch dialog: harness, project folder, optional name, network profile, work on a copy (ticked and locked on a Mac), and keep the harness's prompts (`--safe`). `Ctrl+S` starts it and the TUI hands over your terminal until the harness exits.

![DefenseClaw TUI New sandboxed run dialog on a Mac: harness, project folder, name, network profile, work on a copy, keep the harness's own permission prompts](/images/sandboxes/screens/tui-sandbox-launch.png)

## Use the macOS app

The [macOS app](/docs/features/macos-app) shows sandboxes in the Sandboxes view (under **Govern**, or `⌘⇧B`), the menu bar and notifications. It refreshes every few seconds. The view has a table of sandboxes, a list of waiting asks and the 60 newest events, and each selected sandbox offers **Stop…**, **Copy pull command**, **Pull to branch**, **Review changes**, **Undo…** and **Copy connect command**. The app has no launch dialog: start runs in Terminal.

With **Notify on sandbox blocked destinations and asks** on in the app's settings, you get a notification for a blocked site (**Unblock for this sandbox**), an ask, a new git repository in a mounted project, and hooks that cannot reach DefenseClaw. At most one arrives per sandbox and site per minute. Unblocking a site everywhere is a confirmed choice in the Sandboxes view.

## Check it worked

Run `defenseclaw sandbox run claude` in a terminal. The sandbox appears in the TUI Sandboxes panel or the app within a few seconds, and its sites appear in **Activity**.
