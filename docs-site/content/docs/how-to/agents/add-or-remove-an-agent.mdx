One gateway guards several agents at once, each with its own mode. Adding, replacing or removing an agent never deletes audit history: each audit row keeps the connector that produced it.

## Before you start

- DefenseClaw is set up for one agent.
- The new agent is a hook agent. OpenClaw and ZeptoClaw run through a proxy and cannot sit next to hook agents (see Replace below).

## The questions setup asks

`defenseclaw setup <agent>` asks these questions in this order. The first one is the enforcement mode,
answered with a number:

```text
  Enforcement mode for Codex
  ──────────────────────────
    [1] observe — scan and report findings, never block (recommended to start)
    [2] action  — scan and block/confirm when policy requires (PreToolUse deny)
  Select mode (1, 2) [1]:
```

Type `1` (observe) or `2` (action), or press Enter for the default. Letters are
rejected here. Passing `--mode observe` or `--mode action` answers this question,
so setup does not ask it.

If another connector is already wired (here, `claudecode`), setup prints what it
will change and then asks how to combine them:

```text
  DefenseClaw is already configured for: claudecode
  You are setting up: codex
    [a] Add     — run it alongside the existing connector(s) (multi-connector)
    [r] Replace — switch to only this connector
    [c] Cancel  — make no changes
  Choose (a, r, c) [a]:
```

Type `a` to keep both active. Type `r` only when you want DefenseClaw to tear
down the previous connector's agent-side files before wiring the new one. `c`
makes no changes.

If you chose action mode, setup then offers the LLM judge:

```text
  Add LLM judge on top of rule scanning? [y/N]:
```

Press Enter or type `n` to keep rule scanning only, or `y` to add the judge
(configure its model with `defenseclaw setup llm`). Observe mode skips this
question. `--enable-judge` or `--no-enable-judge` answers it.

To replace instead of add, pass `--replace`. Setup then asks a yes/no question
in place of the Add/Replace/Cancel choice, followed by the judge question in
action mode:

```bash
defenseclaw setup claude-code --replace --mode action
```

```text
  Replace codex with claudecode? This removes the other connector(s). [y/N]: y
  Add LLM judge on top of rule scanning? [y/N]: n
```

## Add an agent

1. Run the agent's setup command. If another agent is already guarded, setup asks.

   ```bash
   defenseclaw setup codex
   ```

   ```text
     DefenseClaw is already configured for: claudecode
     You are setting up: codex
       [a] Add     — run it alongside the existing connector(s) (multi-connector)
       [r] Replace — switch to only this connector
       [c] Cancel  — make no changes
     Choose (a, r, c) [a]: a
     …
     OK Desired roster staged for 'codex' - 2 connectors selected: claudecode, codex
     OK codex mode=observe
   ```

   Add is the default, also with `--yes`. The new agent starts in observe mode. Add `--mode action` to block from the start.

2. Check both agents.

   ```bash
   defenseclaw guardrail status
   ```

   ```text
     * enabled:    yes
         Connector    Key         State    Mode     Fail    Rule pack  Block/alert       HILT  Scan        Judge
         -----------  ----------  -------  -------  ------  ---------  ----------------  ----  ----------  -----
         Claude Code  claudecode  enabled  observe  closed  default    CRITICAL/MEDIUM+  off   regex_only  off
         Codex        codex       enabled  observe  closed  default    CRITICAL/MEDIUM+  off   regex_only  off
   ```

3. Give one agent its own settings. Add `--connector` to any guardrail command.

   ```bash
   defenseclaw guardrail mode action --connector codex
   defenseclaw guardrail hilt on --min-severity HIGH --connector claudecode
   ```

   The [per-connector overrides](/docs/reference/commands/guardrail-setup#per-connector-overrides) table lists what each agent can override.

## Replace an agent

Replace tears down the old agent's files and leaves only the new one.

```bash
defenseclaw setup claude-code --replace --mode action
```

Setup names the agents it removes and asks first (`--yes` skips the question). The same flag switches between a hook agent and a proxy agent (`defenseclaw setup openclaw --replace`) on Linux and macOS. Native Windows has no guardrail proxy, so OpenClaw and ZeptoClaw replacement is unsupported there. Without `--replace`, setup refuses and changes nothing.

## Remove an agent

```bash
defenseclaw setup remove codex
```

```text
  OK Removed connector 'codex'
  OK Remaining connector(s): claudecode

  Restarting gateway so the removed connector's hooks are torn down...
```

`--yes` skips the question and `--no-restart` restarts later. Removing the last agent needs `--force`. DefenseClaw stays installed; `defenseclaw uninstall` removes it.

## Check it worked

`defenseclaw guardrail status` lists only the agents you kept, and `defenseclaw doctor` reports no leftover hooks.
