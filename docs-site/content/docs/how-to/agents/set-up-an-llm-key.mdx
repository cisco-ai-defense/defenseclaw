One key, `DEFENSECLAW_LLM_KEY`, powers the LLM judge and the skill, MCP and plugin scanners. Set it once. Override it per component only if you need separate billing or rate limits ([LLM providers](/docs/reference/configuration/llm-providers#per-component-overrides)).

## Before you start

- An API key for a provider such as Anthropic or OpenAI. For Bedrock, Vertex AI or Azure OpenAI, see the table at the end.

## Steps

1. Pick the provider and model. This writes the top-level `llm:` block that the judge and scanners inherit.

   ```bash
   defenseclaw setup llm --provider anthropic --model claude-sonnet-4-5 --api-key-env DEFENSECLAW_LLM_KEY
   ```

   ```text
     OK Saved to /home/alice/.defenseclaw/config.yaml
       llm.provider:                  anthropic
       llm.model:                     claude-sonnet-4-5
       llm.api_key_env:               DEFENSECLAW_LLM_KEY = (not set)

     Config updated. The running gateway applies it without a restart.
   ```

2. Store the key. The prompt is hidden and the value goes to `~/.defenseclaw/.env` (`%USERPROFILE%\.defenseclaw\.env` on Windows), readable only by you.

   ```bash
   defenseclaw keys set DEFENSECLAW_LLM_KEY
   ```

   ```text
     OK Saved DEFENSECLAW_LLM_KEY to /home/alice/.defenseclaw/.env (value hidden)
       The running gateway keeps the DEFENSECLAW_LLM_KEY it loaded at start; apply the change with: defenseclaw-gateway restart
   ```

   In scripts, read the value from standard input so it stays out of `ps` and shell history:

   <Tabs items={['macOS / Linux', 'Windows PowerShell']}>
   <Tab value="macOS / Linux">

   ```bash
   printf '%s\n' "$LLM_KEY" | defenseclaw keys set DEFENSECLAW_LLM_KEY --value-stdin
   ```

   </Tab>
   <Tab value="Windows PowerShell">

   ```powershell
   $env:LLM_KEY | defenseclaw keys set DEFENSECLAW_LLM_KEY --value-stdin
   ```

   </Tab>
   </Tabs>

3. Restart the gateway so it loads the key.

   ```bash
   defenseclaw-gateway restart
   ```

4. Turn on the judge. In action mode, the wizard offers the LLM you configured instead of asking again.

   ```bash
   defenseclaw setup guardrail --non-interactive --connector claudecode --mode action \
     --detection-strategy regex_judge \
     --judge-model anthropic/claude-sonnet-4-5 \
     --judge-api-key-env DEFENSECLAW_LLM_KEY
   ```

   ```text
       guardrail.judge.enabled:       true
       guardrail.judge.llm.model:     anthropic/claude-sonnet-4-5
       judge credentials:             DEFENSECLAW_LLM_KEY
       guardrail.judge.hook_connectors: all
   ```

## Check it worked

```bash
defenseclaw keys check
```

```text
  1/1 required credentials set.
  OK all required credentials present
```

`keys check` exits 0 when every required key is set, so you can use it as a CI gate. `defenseclaw keys list` shows each key, whether the current config needs it, and where it was found (`env`, `dotenv` or `unset`). `defenseclaw setup llm --show` prints the resolved settings with the key masked to its last four characters. Add `--ping` to `setup llm` to send a one-token test call.

## Other providers

| Provider | Extra settings | Details |
| --- | --- | --- |
| AWS Bedrock | Region and auth mode (`api_key`, `iam_credentials`, `profile`, `instance_role`) | [Bedrock](/docs/reference/configuration/llm-providers#aws-bedrock) |
| Google Vertex AI | Project, region, auth mode | [Vertex AI](/docs/reference/configuration/llm-providers#google-vertex-ai) |
| Azure OpenAI | Endpoint, API version, deployment aliases | [Azure OpenAI](/docs/reference/configuration/llm-providers#azure-openai) |
| Ollama, vLLM, LM Studio | A `base_url`; no key | [Provider catalog](/docs/reference/configuration/llm-providers#provider-catalog) |

DefenseClaw reads keys from the process environment first, then `~/.defenseclaw/.env`. It does not use the OS keychain or an external secret manager.

## Undo

Remove the line from `~/.defenseclaw/.env` and run `defenseclaw setup guardrail --detection-strategy regex_only` to turn the judge off.
