---
title: Turn on blocking
description: Switch one agent, or all agents, from observe mode to action mode so the guardrail blocks, and switch back.
keywords:

---

Observe mode records findings and blocks nothing. Action mode blocks at the levels in [Guardrail](/docs/features/guardrail#block-and-alert-levels). Run observe for about a week on a new agent before you switch.

## Before you start

- DefenseClaw is installed and an agent is set up ([Quickstart](/docs/get-started/quickstart)).
- You have read `defenseclaw alerts` for a while and the findings look right.

## Steps

1. Check the current mode.

   ```bash
   defenseclaw guardrail status
   ```

   ```text
     Guardrail status
     ----------------
     * enabled:    yes
         Connector    Key         State    Mode     Fail    Rule pack  Block/alert       HILT  Scan        Judge
         -----------  ----------  -------  -------  ------  ---------  ----------------  ----  ----------  -----
         Claude Code  claudecode  enabled  observe  closed  default    CRITICAL/MEDIUM+  off   regex_only  off
     …
   ```

2. Switch the agent to action mode. Leave out `--connector` to change the global mode that agents without their own mode follow.

   ```bash
   defenseclaw guardrail mode action --connector claudecode
   ```

   ```text
     OK Claude Code is now in action mode: it blocks findings at or above the block-at severity.
   ```

   The running gateway applies the change on its next reload. No restart is needed.

3. Run a command a default rule blocks. `CMD-RM-RF` blocks a recursive force delete of `/` or a top-level directory such as `/etc` or `/proc`. Many models refuse to run `rm -rf /proc` themselves, so no tool call is made; if that happens, use the harmless test rule in [Block a destructive command](/docs/how-to/guardrail/block-a-destructive-command).

## Check it worked

```bash
defenseclaw alerts --limit 5
```

```text
                         Security Alerts (last 2)
+------------------------------------------------------------------------+
| # | Severity | Time  | Action       | Target      | Details [--show #] |
|---+----------+-------+--------------+-------------+--------------------|
| 1 | CRITICAL | 06:59 | scan-finding | ...eToolUse | decision=blocke... |
…
```

`decision=blocked` means the agent received a deny.

## Undo

```bash
defenseclaw guardrail mode observe --connector claudecode
```

To drop the agent's own mode and follow the global mode again, run `defenseclaw guardrail mode --connector claudecode --clear`.
