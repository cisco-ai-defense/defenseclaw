Pick the narrowest option that works. All of them take effect on the next gateway reload, with no restart.

## Choose one

| You want to | Use |
| --- | --- |
| Allow one call, once | Human approval ([Ask before risky calls](/docs/how-to/guardrail/ask-before-risky-calls)). Works for findings below the block level only. |
| Turn a rule off for one agent | `guardrail rule disable` |
| Silence one false positive but keep the rule | `guardrail suppress add` |
| Skip the scan for a tool you vetted | `tool allow` |
| Log instead of block while you tune | `guardrail mode observe` |

CRITICAL findings cannot be approved. Change the rule, not the call.

## Steps

1. Find the rule id of the finding.

   ```bash
   defenseclaw alerts --show 1
   ```

   The `Rule:` line names it, for example `C2-WEBHOOK-SITE`.

2. Turn the rule off for one agent.

   ```bash
   defenseclaw guardrail rule disable C2-WEBHOOK-SITE --connector claudecode
   ```

   ```text
     OK Rule C2-WEBHOOK-SITE is turned off for Claude Code. Saved (config generation 18). The running gateway applies it on its next reload.
   ```

   Or suppress only the matching finding, with a recorded reason:

   ```bash
   defenseclaw guardrail suppress add webhook-demo \
     --finding C2-WEBHOOK-SITE \
     --reason "Documentation example, sends no data" \
     --connector claudecode
   ```

   ```text
     OK Suppression WEBHOOK-DEMO added for Claude Code. Saved (config generation 19). The running gateway applies it on its next reload.
   ```

3. Or allow a vetted tool. An allowed tool skips rule scanning, so allow only what you reviewed. Write tools still get a code check.

   ```bash
   defenseclaw tool allow Bash --connector claudecode --reason "vetted"
   ```

   ```text
   [tool] 'Bash' (connector 'claudecode') added to allow list
   ```

## Check it worked

Run the same call again. No alert appears for it, and `defenseclaw alerts --limit 5` shows no new row for the rule.

## Undo

```bash
defenseclaw guardrail rule enable C2-WEBHOOK-SITE --connector claudecode
defenseclaw guardrail suppress remove WEBHOOK-DEMO --connector claudecode
defenseclaw tool unblock Bash --connector claudecode
```

## Change what a rule matches

To change what a bundled rule matches, copy the pack, edit it, validate it and select it. Do not edit a bundled pack in place.

```bash
cp -R ~/.defenseclaw/policies/guardrail/default ~/my-guardrail-pack
defenseclaw guardrail validate-pack ~/my-guardrail-pack
defenseclaw guardrail use-pack ~/my-guardrail-pack --connector claudecode
```

```text
Rule pack valid: "/home/alice/my-guardrail-pack"
  rules: 239/243 enabled across 7 files
  …
  files digest: a86e…b6314d (the guardrail.custom_packs pin)
```

`use-pack` pins the pack by digest. If you edit the pack later, the gateway keeps the old policy and `defenseclaw doctor` fails the Policy row until you pin the new digest. [Rules and custom packs](/docs/reference/policy/rules) has the details.
