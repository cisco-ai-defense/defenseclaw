Put a skill, MCP server, plugin or tool on the block list or the allow list. A blocked name is refused without a scan. An allowed name skips the scan.

## Before you start

- The gateway should be running so the change is audited. With it stopped, the commands still write `config.yaml` and warn that no audit event was recorded.
- This is a per-user command. On a managed device the commands are refused (exit code 3) and the rules go in the admin config.

## Steps

1. Block by name.

   ```bash
   defenseclaw skill block risky-skill --reason "unvetted vendor skill"
   ```

   ```text
   [skill] Blocked 'risky-skill' (every connector).
   ```

   The same works for `mcp`, `plugin` and `tool`. Add `--connector claudecode` to limit a rule to one connector.

2. Allow a reviewed asset.

   ```bash
   defenseclaw skill allow ok-skill --reason reviewed
   ```

   ```text
   [skill] 'ok-skill' added to allow list
     Note: this rule matches the name only: any skill named 'ok-skill' on any connector skips the scan.
   ```

   When the asset is installed, `allow` pins the rule to that copy's path, so a different folder with the same name is still scanned. For an MCP server, `mcp allow` pins the rule to its URL or command.

3. Edit the lists for anything the commands do not cover, such as URL or command rules.

   ```bash
   defenseclaw config set asset_policy.mcp.denied --json '[{"url":"https://mcp.example.net/v1","reason":"unknown vendor"}]'
   ```

4. Remove a rule.

   ```bash
   defenseclaw skill unblock risky-skill
   ```

   ```text
   [skill] Unblocked 'risky-skill' (every connector).
     It will be scanned on the next check.
   ```

   `unblock` removes the block or allow rule and clears the runtime state. It does not restore files; use `defenseclaw skill restore`.

## Which rule wins

1. A rule scoped to the asset's connector beats an unscoped rule.
2. At the same scope, `denied` beats `allowed`.
3. After the lists, the first-party list can skip the scan, then the scan result decides.

A block does not touch an asset that is already running. Use `disable` or `quarantine` for that.

## Check it worked

```bash
defenseclaw config get asset_policy.skill
defenseclaw-gateway policy evaluate --target-type skill --target-name risky-skill
```

The dry run prints `"verdict": "blocked"` for a blocked name.
