Subscribe to a catalog of skills or MCP servers. DefenseClaw fetches it, scans each entry and promotes clean entries into `asset_policy`. A registry is the approved catalog. It does not replace your block and allow lists.

## Before you start

- A catalog URL, or an absolute path to a manifest file. Kinds: `clawhub`, `smithery`, `skills_sh`, `http_yaml`, `http_json`, `git`, `file`. See [Registries reference](/docs/reference/scanning/registries).
- For `http_yaml`, `http_json`, `git` and `file`, every entry's `source_url` needs a SHA-256.

## Steps

1. Add the source. `--auth-env` takes the name of an environment variable that holds a token, never the token.

   ```bash
   defenseclaw registry add corp-skills --kind http_yaml --url https://catalog.example.com/skills.yaml --content skill --auth-env CORP_CATALOG_TOKEN --non-interactive
   ```

   ```text
     OK Registered registry source 'corp-skills'.
     Run `defenseclaw registry sync corp-skills` to fetch + scan + promote entries.
   ```

2. Dry-run the fetch. Nothing is written.

   ```bash
   defenseclaw registry test corp-skills
   ```

3. Sync. Each entry goes through the skill or MCP scanner. Clean entries are promoted.

   ```bash
   defenseclaw registry sync corp-skills
   ```

   Stdio MCP entries start the publisher's package on your machine. They stay `pending` unless you pass `--scan-stdio`.

4. Look at what landed, then approve or reject held entries.

   ```bash
   defenseclaw registry list
   defenseclaw registry entries corp-skills --status warning
   defenseclaw registry approve corp-skills my-skill --type skill
   ```

   ```text
     Registry sources
     ID            KIND  CONTENT  ON  ENTRIES  LAST SYNC  URL
     corp-skills   file  skill    yes -        -          /path/to/m.yaml
     ENTRIES column: total (clean/warning/blocked/error/rejected)
   ```

5. Optional: refuse anything the catalog does not list.

   ```bash
   defenseclaw registry require --type skill --enabled --enforce
   ```

   `--enforce` turns on `asset_policy.enabled` and sets `asset_policy.mode` to `action`. Without it nothing is blocked, and the CLI says so.

## Keep it fresh

Sync is on demand. Schedule it as the user who runs DefenseClaw, for example `0 * * * * defenseclaw registry sync --all` in that user's crontab. Keep the gateway running so the sync is audited.

## Undo

`defenseclaw registry remove corp-skills` removes the source and every rule it promoted.
