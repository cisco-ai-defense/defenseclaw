**An actor holds no secret value.** There are no API keys in its environment, its files or its snapshots. The agent sends a placeholder, and Substrate's egress gateway swaps in the real value on the way out, only for the hosts the secret is bound to. If the agent is tricked into sending the placeholder somewhere else, nothing real leaves.

## Kinds of secret

| Kind | Where it is stored | How it is used |
|---|---|---|
| Model keys | A Secret in the DefenseClaw namespace, or Substrate's credential provider | Added by the DefenseClaw guardrail proxy. The actor has placeholders only. The model provider hosts are never in an actor's allow list |
| Service credentials (git push, registries, internal APIs, remote MCP servers) | `ate-secret://` references through the Kubernetes, Vault, AWS or GCP credential providers | The egress gateway replaces the placeholder **only on bound hosts**, on inspected rules |
| Per-person (`secrets set --mine`) | A Secret or Vault path keyed by your OIDC subject | Bound only to your actors |
| Values a program inside the actor must read | Off by default | A profile's `actor_secrets` gives a short-lived value, marked as exposed, with exact-value matching on prompts and egress |
| DefenseClaw's own credentials | `defenseclaw-system` Secrets (admin RBAC only) or the Secrets Store CSI driver | Never leave the namespace |

## Bind a secret to hosts

```yaml
# defenseclaw-values.yaml
config:
  substrate:
    secrets:
      - name: github-push
        source: vault://kv/ci/github-app
        inject:
          hosts: [github.com, api.github.com]
          header: Authorization
          prefix: "Bearer "
          placeholder: DC_SECRET_GITHUB
        scope: shared            # or per_person
        profiles: [eng-*]
```

- The secret is injected only on the listed hosts and only for actors whose profile matches.
- A host listed in `allow_passthrough_for` is not inspected, so a secret is never bound to it.
- Rotation happens at request time. There is no restart.
- Every injection is recorded with the secret **name**, the host, the actor and the person (`log.secret.injected`). The value, a prefix of it and its placeholder are never recorded.

## Manage them

```bash
defenseclaw substrate secrets list --mine
defenseclaw substrate secrets set github-push --mine
defenseclaw substrate secrets test github-push
defenseclaw substrate secrets rm github-push --mine
```

You see only the names of your own entries. `secrets test` checks that the secret resolves and the bound hosts accept it, without printing the value.

## Things to know

- **Hosts that echo tokens.** Some services return the token they were given. The callout checks responses in body mode where it can, and these hosts are listed in the [troubleshooting](/docs/substrate/troubleshooting) page.
- **Subscription sign-ins** put tokens in an actor's snapshots. Managed profiles refuse them; open source warns.
- **Snapshots hold everything the actor held.** Check the snapshot bucket's encryption and access with `doctor`, and use `delete` to remove an agent's snapshots.
