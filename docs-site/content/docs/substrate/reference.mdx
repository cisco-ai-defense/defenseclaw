`defenseclaw substrate` runs on your laptop or in CI. It needs no `config.yaml` on the laptop: every command except the admin ones reads a small context file.

## Commands

| Command | What it does |
|---|---|
| `login`, `logout`, `whoami` | Sign in with your organization's OIDC provider (device flow; `--no-browser` prints the code), in CI with `--workload` and `--workload-token-file`, or with `--kube` on an open-source cluster that has no OIDC provider (your current kubeconfig; the gateway verifies it with a TokenReview). `login` saves a context: `--admin-url`, `--issuer`, `--client-id`, the CA files (`--admin-ca-file`, `--issuer-ca-file`), `--default-profile`, `--default-template`, `--name`. `--kube-context` and `--kubeconfig` choose the Kubernetes identity for `--kube`; `--workload-audience` names the audience of a CI token. Tokens go in the operating system keychain |
| `run <agent> [-- args]` | Start an agent in an actor and attach. `--task "..."` runs headless, `--detach` doesn't attach, `--batch FILE --parallel N` runs one actor per task, `--clone URL --ref REF` starts from a repository instead of a copy of the folder, `--unmask` and `--exclude` change what is uploaded, `--secret NAME`, `--profile`, `--template`, `--keep`, `--no-upload`, `--max-upload-mb` |
| `connect <name>` | Attach to an actor, resuming it first if it is suspended. `--no-asks` leaves asks for `approvals`; `--transport` picks the relay transport |
| `list` | Your actors with state, last activity, checks and asks. `--all` (admins), `--batch` |
| `status [name]` | One actor, or a batch (`--batch`). `status --cluster` is the cluster and fleet document for admins (`--json`) |
| `verify` | Checks the cluster side against the install file; `--json` follows the management contract |
| `logs <name> [-f]` | The agent's output; `--task` picks a task |
| `pull <name>` | See the changed files, flagged for risk (`--diff`), then `--apply`, `--branch NAME` or `--patch-out FILE` |
| `checkpoint <name> [--every D]` | Save the whole actor, files and memory |
| `undo <name> [--to ID]` | Return the actor to its last checkpoint, or to a given one |
| `delete <name>... \| --batch ID` | Delete actors, their allow lists and their snapshots |
| `migrate <name>` | Move an actor with an old kit to a rebuilt template |
| `approvals`, `approve <id> [--always]`, `reject <id> [--reason]` | Answer asks, including for detached and unattended runs |
| `usage [--batch ID]` | Your own usage and cost. Admins can read the fleet |
| `secrets list [--mine]`, `set NAME (--stdin \| --from-env VAR)`, `rm NAME`, `test NAME` | Names of your secrets and their bindings. Values are never shown |
| `policy explain NAME`, `show`, `test NAME` | Your own effective policy and where each value comes from; `test` asks whether a host, method or tool would be allowed |
| `policy reset ATESPACE/NAME [--reason TEXT] [--yes]` | Administrators: clear a `policy_conflict` once the other writer is stopped. The controller writes the policy again and starts reverting changes again. Audited under your own name |
| `doctor` | Checks the cluster side (`--cluster`, `--namespace`, `--kube-context`, `--install-file`). Ends with `ready for agents` |
| `setup` | Writes the Substrate install overlay. `--plan` and `--dry-run` show it, `--remove` takes the callout out, `--print-access-policies` prints the access policies, `--capability` tells it what your Substrate supports |
| `template build\|verify\|scan\|publish\|keygen` | Administrators: build an agent image with the kit and a signed attestation, check or scan it, publish it to the cluster's registry, make the signing key. These run on this computer and need no sign-in |

Every read command has `--output text|json` and `--json`, and every command takes `--context` to pick a saved cluster. Errors say what failed and how to fix it. `--yes` answers questions.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Done |
| 1 | The command failed |
| 2 | Usage error |
| 3 | Unsupported or refused (a profile or setting forbids it) |
| 4 | Not signed in; run `defenseclaw substrate login` |
| 75 | The cluster is unreachable (`verify`, `status --cluster`) |

### Environment variables

| Variable | Meaning |
|---|---|
| `DEFENSECLAW_SUBSTRATE_CONTEXT` | Which saved cluster to use |
| `DEFENSECLAW_SUBSTRATE_ADMIN_URL`, `DEFENSECLAW_SUBSTRATE_ISSUER`, `DEFENSECLAW_SUBSTRATE_CLIENT_ID`, `DEFENSECLAW_SUBSTRATE_PROFILE`, `DEFENSECLAW_SUBSTRATE_TEMPLATE` | Override the saved context, for CI |
| `DEFENSECLAW_SUBSTRATE_KUBE`, `DEFENSECLAW_SUBSTRATE_WORKLOAD_TOKEN_FILE`, `DEFENSECLAW_SUBSTRATE_WORKLOAD_AUDIENCE` | Sign in with the Kubernetes identity, or as a CI workload, without flags |
| `DEFENSECLAW_SUBSTRATE_TOKEN_STORE=file` | Keep tokens in a 0600 file instead of the keychain (headless Linux and CI). The launcher never falls back to this on its own; it says so and names the variable |

### Files

`substrate/contexts.json` under the DefenseClaw state directory holds your contexts: addresses, issuer, client ID and the CA files. It has no secrets and mode 0600. Tokens live in the keychain (macOS Keychain, Windows Credential Manager, Linux Secret Service). On macOS the key that seals them is an item only the DefenseClaw program may read without asking; macOS asks once after you install a new DefenseClaw build, and over SSH the keychain must be unlocked (`security unlock-keychain`).

## Configuration

The `substrate` section of the DefenseClaw configuration. On a cluster it comes from the chart's `config:` values.

| Key | Default | Meaning |
|---|---|---|
| `substrate.enabled` | `false` (the chart sets `true`) | Turns the Substrate components on |
| `substrate.api.address`, `.ca_file`, `.auth` | `api.ate-system:443`, in-cluster CA, `serviceaccount` | How DefenseClaw reaches the Substrate control API |
| `substrate.supported_versions` | `>=1.0.0 <1.1.0` | The Substrate versions `doctor` accepts |
| `substrate.identity.issuer` | `https://idp.ate-system.svc` | Issuer of the actor tokens. Make it unique per cluster |
| `substrate.identity.audience` | `defenseclaw` | Audience of actor tokens |
| `substrate.identity.token_lifetime_seconds` | `300` | Lifetime of the token the egress gateway adds. Fixed at 300 s: egress caches the token by actor name, so a recreated actor with the same name is refused until the old token expires. |
| `substrate.identity.oidc.issuer`, `.client_id`, `.groups_claim` | none, none, `groups` | The OIDC provider people sign in with. Unset on an open-source cluster to accept Kubernetes identities (`login --kube`) instead. Managed installs require it |
| `substrate.identity.workload_oidc` | `[]` | Issuers accepted for CI workloads: `issuer`, `audience` |
| `substrate.services.actor`, `.admin` | `defenseclaw-actor...svc`, `defenseclaw-admin...svc` | Service names (the chart fills them) |
| `substrate.launcher_atespaces` | `{}` | Profile name to the atespaces the launcher may create actors in. Only DefenseClaw edits these |
| `substrate.require_attested_templates` | `true` | Actors from unattested templates get no network |
| `substrate.default_sandbox_class` | `gvisor` | `gvisor` or `microvm` |
| `substrate.idle_suspend_after` | `30m` | Idle time before DefenseClaw suspends an actor. `--task` runs are exempt unless the profile says so |
| `substrate.unattended.asks` | `deny` | What an unattended run does with an ask |
| `substrate.unattended.ask_timeout` | `30m` | How long an allowed ask waits for a person |
| `substrate.unattended.telemetry_sampling` | `1.0` | Fraction of routine events kept for `--task` runs. Blocks and lifecycle records are never sampled |
| `substrate.rate_limits.per_actor_rps`, `.per_atespace_rps` | `20`, `500` | Fair-share limits. Over budget answers `429` with `Retry-After` |
| `substrate.extproc.enabled` | `true` | The egress callout |
| `substrate.extproc.failure_mode` | `closed` | What the egress gateway does when the callout fails |
| `substrate.extproc.body_inspection` | `auto` | Read bodies of POSTs to MCP and listed hosts when Substrate supports it |
| `substrate.extproc.body_max_bytes` | `1048576` | Largest body the callout reads |
| `substrate.extproc.mcp_hosts` | `[]` | Hosts whose bodies are read as MCP calls |
| `substrate.llm.providers` | all the gateway proxy serves | Providers actors may reach, only through the proxy |
| `substrate.llm.credential.provider_uri` | none | Where the model key comes from (`ate-secret://...`) |
| `substrate.secrets` | `[]` | See [Secrets](/docs/substrate/secrets) |
| `substrate.allow_passthrough_for` | `[]` | Hosts that are not inspected. Never given a secret |

Profile keys for Substrate: `profile_assignments[].match.substrate` (`atespaces`, `templates`, `workloads`). The `sandbox` section of a profile is the same as for OpenShell (`required_for`, `allowed_harnesses`, `egress_allow_only`, `allow_unblock`, `user_approvals` and the rest). See [Managed enterprise](/docs/substrate/enterprise).

Keys of the `sandbox` section (and of `substrate.admin`) for the runtime:

| Key | Values | Meaning | How a profile tightens `substrate.admin` |
|---|---|---|---|
| `runtimes` | `[openshell, substrate]` | Where the profile's agents may run. Left out: both. Without `substrate`, its actors get no policy | Intersection |
| `sandbox_class` | `gvisor`, `microvm` | The weakest isolation an actor may run in. Unset: `substrate.default_sandbox_class` | `microvm` wins |
| `idle_suspend_after` | Go duration, 1m or more | Replaces `substrate.idle_suspend_after` | The minimum |
| `unattended_asks` | `deny`, `queue` | What an unattended run's ask does. Unset: `substrate.unattended.asks` | `deny` wins |
| `ask_timeout` | Go duration, 1m to 24h | How long a queued ask waits before it is denied. Unset: `substrate.unattended.ask_timeout` | The minimum |
| `actor_secrets` | key names | Values a program inside the actor may read, keys of the Secret in `callout.actorSecrets.secretName`. Matched by exact value on prompts and egress | Intersection |

`openshell.admin` refuses `sandbox_class`, `idle_suspend_after`, `unattended_asks`, `ask_timeout` and `actor_secrets`. `substrate.admin` refuses `allow_mount`, `allow_host_ports`, `process_tree`, `driver_fallback`, `require_copy_for` and locked `workdir.*` keys.

## Chart values

The signed chart is `oci://ghcr.io/cisco-ai-defense/charts/defenseclaw-substrate`. Every value is checked by its schema. The ones you will set:

| Value | Meaning |
|---|---|
| `config` | The DefenseClaw configuration, rendered into one ConfigMap |
| `bootstrap.ownerTokenSecret` | A Substrate global owner's token for the one-time access-policy bootstrap |
| `managedAtespaces` | Other atespaces DefenseClaw writes policy in |
| `substrate.namespace`, `substrate.apiAddress` | Where Substrate runs |
| `gateway.hpa.*`, `gateway.pdb.*` | Scaling and disruption budget of the gateway |
| `leader.store.size`, `leader.store.keepOnUninstall` | The leader's volume |
| `callout.judge.tokenSecret` | The callout's token for the MCP tool-rules route. Default `defenseclaw-callout-judge`, which the chart creates. `""` turns the route off: MCP tool calls then raise an alert, and a managed install refuses them |
| `networkPolicy.adminFrom`, `adminIngress.*` | Who can reach the admin Service |
| `metrics.prometheusRule.enabled` | Install the alert rules |
| `observability.local.enabled` | A local collector for trying the chart |
