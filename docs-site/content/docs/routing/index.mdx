Model routing lets the gateway pick the model for a call after it reads the request and before it forwards it. A classifier names the kind of work, for example coding or summarize, and the model you mapped to that kind answers. The guardrail, administrator rules and budgets still apply to the model that is picked. If the classifier fails, the original request goes through unchanged.

Routing is off until you turn it on.

## The commands

```bash
defenseclaw routing setup          # choose a classifier and map kinds of work to models
defenseclaw routing test "refactor this function"   # a dry run: no model is called
defenseclaw routing status         # what routing is doing now
defenseclaw routing usage          # what calls used (needs observability.tokenomics)
```

`defenseclaw routing enable --connector claudecode` (or `codex`) turns on route-only mode for that agent. `defenseclaw routing disable --connector NAME` puts the agent's own settings back. See [Semantic model routing](/docs/routing/semantic-routing) for the flags.
