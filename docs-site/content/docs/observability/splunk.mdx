DefenseClaw ships a single command — `defenseclaw setup splunk` — with three independent pipelines you can mix and match:

<Callout type="warning" title="Native Windows local mode is optional and narrowly certified">
Remote HEC and Splunk Observability destinations do not require Docker. The
local Windows Docker mode requires native x64 Windows Pro, Enterprise, or
Education; Hyper-V; machine-installed Docker Desktop using Linux containers;
Compose v2; and a real `docker.exe`. WSL2/per-user engines, Windows containers,
and command-wrapper shims are outside that certification.
</Callout>

| Pipeline | Use case | What it does |
| --- | --- | --- |
| `--logs` | Local demo / dev | Starts Splunk in Docker in Free mode, installs the bundled local-mode app, and sends events through HEC |
| `--enterprise` | Production SIEM | Configures the gateway's HEC destination to point at *your* Splunk; no Docker, no install |
| `--o11y` | Splunk Observability Cloud | Sends OTLP traces and metrics (logs optional) to your realm |

You can run more than one. In config v8, HEC and O11y become independent
entries under `observability.destinations`, so adding one never replaces another.

## Local mode (`--logs`)

The fastest path to a working Splunk demo. One command starts Splunk 10.x in Docker in Free mode (the bundle pins `splunk/splunk-claw-bridge:10.2.0`), installs the bundled `defenseclaw_local_mode` app, and points the gateway's HEC destination at it.

```bash
defenseclaw setup splunk --logs --accept-splunk-license
```

What happens:

<Steps>
  <Step>
    **License check.** Without `--accept-splunk-license` the CLI prompts you interactively. Use `--non-interactive` for CI.
  </Step>
  <Step>
    **Docker preflight.** Verifies Docker is running and that ports `8000` (Splunk Web) and `8088` (HEC) are free.
  </Step>
  <Step>
    **Bridge bootstrap.** `splunk-claw-bridge up` (shipped in `bundles/splunk_local_bridge/`) launches the container, waits for `/services/server/info`, and provisions an HEC token.
  </Step>
  <Step>
    **Destination wiring.** Writes a logs-capable `kind: splunk_hec` v8 destination pointing at `http://127.0.0.1:8088/services/collector/event`, index `defenseclaw_local`, sourcetype `defenseclaw:json`. The reviewed private-network opt-in applies only to this local destination.
  </Step>
  <Step>
    **App install.** Copies the bundled `defenseclaw_local_mode` app into the container: its dashboards, shared SPL macros, and `props.conf` field extraction.
  </Step>
</Steps>

Open Splunk at [http://localhost:8000](http://localhost:8000). The bundled app
shows up as **DefenseClaw Local Mode**. The generated HEC token and bootstrap
secret stay hidden unless you pass `--show-credentials`; keep them out of
diagnostics and support output.

### Bundled dashboards

The app opens on a home page and groups its views into four menus:

| Menu | Views |
| --- | --- |
| **Investigate** | Audit and security, runs and sessions, queue and runtime health |
| **Observe** | Gateway health, gateway logs, model usage and cost |
| **Demo Dashboards** | Agent Tokenomics Overview, Executive Agent Watch Overview, AI Discovery Inventory, AI Runtime Planes, Connector Activity, Policy Decisions, Findings and HITL |
| **Operate** | Alerts and saved searches, search and drill-down |

The demo dashboards below are the ones you would build by hand for a production
deployment, pointed at the local index for a self-contained demo.

#### Executive Agent Watch Overview

The CISO-friendly landing page: high-attention sessions, blocked actions, scanner heat, HITL backlog.


#### AI Discovery Inventory

What agents are running, which models they call, and which scanners have evaluated them. Useful as the "first thing the SOC sees" panel.


#### Connector Activity

Per-connector throughput, error rate, and policy hit ratios over time. Helps catch a connector that suddenly starts triggering rules.

On multi-connector installs, this is the fastest dashboard for comparing hook volume, errors, and policy hits across the active roster.


#### Policy Decisions

Every guardrail verdict, broken down by rule, severity, and outcome. The "did this actually fire?" view when you tune a rule pack.


#### Findings and HITL

Open scanner findings plus HITL request/decision history. This is an
observability view, not a resumable approval queue; live approval happens only
on connector events with a native ask surface.


### What the dashboards query

The views read from a shared set of SPL macros in the app's `default/macros.conf`, scoped to `index=defenseclaw_local`. The macros normalize the gateway's JSON envelope so the dashboards don't have to repeat field extractions.

The v8 Splunk adapter wraps the already-selected, already-redacted canonical log
projection and derives compatibility aliases only from those immutable bytes. A
removed field never reappears through a raw fallback. The canonical bucket,
family/event name, action, source, connector, severity, trace/span IDs, and
structured body remain available for new SPL, while documented v7 aliases remain
available only during their compatibility window.

Useful starting queries:

```spl title="Codex hook activity in the last hour"
index=defenseclaw_local sourcetype=defenseclaw:json bucket="agent.lifecycle" connector="codex"
| stats count by event_name, action, outcome
| sort -count
```

```spl title="Blocked guardrail actions, broken down by connector"
index=defenseclaw_local sourcetype=defenseclaw:json bucket="enforcement.action" action="block"
| stats count by connector, source, severity
| sort -count
```

```spl title="Hook throughput per connector (spot a noisy agent)"
index=defenseclaw_local sourcetype=defenseclaw:json bucket="agent.lifecycle"
| timechart span=5m count by connector
```

## Enterprise mode (`--enterprise`)

Send events to an existing Splunk deployment. No Docker, no app install — just
configure the logs-only HEC destination.

```bash
read -rs DEFENSECLAW_SETUP_SPLUNK_HEC_TOKEN && export DEFENSECLAW_SETUP_SPLUNK_HEC_TOKEN

defenseclaw setup splunk --enterprise --non-interactive \
  --hec-endpoint https://splunk.example.com:8088/services/collector/event \
  --index defenseclaw \
  --sourcetype _json
```

The token comes from the environment, because a `--hec-token` value on the
command line is visible to other local users in `ps`.

| Flag | Purpose |
| --- | --- |
| `--hec-endpoint` | Full HEC URL, including `https://` and `/services/collector/event`. It is used exactly as given. |
| `--hec-token` | HEC token. Prefer `DEFENSECLAW_SETUP_SPLUNK_HEC_TOKEN`; `DEFENSECLAW_SPLUNK_HEC_TOKEN` is also read when neither is given. |
| `--index` | Defaults to `defenseclaw`. Create it ahead of time. |
| `--source` | HEC `source` field. Defaults to `defenseclaw`. |
| `--sourcetype` | Defaults to `_json`. Use `defenseclaw:json` if you've installed the `props.conf` stanza below. |
| `--skip-test` | Skip the live HEC probe (useful in air-gapped CI). |

The CLI runs a one-shot probe by default — it sends a test event and confirms HEC returns 200 before persisting the config. If your HEC is behind a VPN, pass `--skip-test`.

### Field mapping in your Splunk

The events arrive as v8 canonical log projections inside the HEC adapter envelope
described in [Observability](/docs/observability). For Splunk Cloud or Splunk
Enterprise without the bundled app, you'll typically want:

```ini title="props.conf"
[defenseclaw:json]
KV_MODE = json
SHOULD_LINEMERGE = false
TIME_FORMAT = %Y-%m-%dT%H:%M:%S
MAX_TIMESTAMP_LOOKAHEAD = 30
TRUNCATE = 0
```

This is the stanza the bundled local-mode app ships in its
`default/props.conf`. DefenseClaw does not ship a separate add-on for Splunk
Cloud or Enterprise; copy the stanza and any macros you need from the app.

## Splunk Observability Cloud (`--o11y`)

For organizations standardized on Splunk O11y instead of Splunk Enterprise, the
gateway sends OTLP over HTTP to your realm's ingest endpoint:

```bash
read -rs DEFENSECLAW_SETUP_SPLUNK_ACCESS_TOKEN && export DEFENSECLAW_SETUP_SPLUNK_ACCESS_TOKEN

defenseclaw setup splunk --o11y --non-interactive \
  --realm us1 \
  --traces --metrics --logs-export
```

This writes an OTLP destination under `observability.destinations`, pointed at
`ingest.us1.observability.splunkcloud.com`. Traces and metrics are on by
default and logs are off; `--logs-export` adds logs. Turn a signal off with
`--no-traces`, `--no-metrics`, or `--no-logs-export`. The destination is named
after `--app-name` (default `defenseclaw`), which is also the OTel service
name. Apply a [redaction profile](/docs/observability/redaction) when the realm
must not receive full content.

Do not pass `--logs` here: in this command `--logs` starts the local Splunk
container.

## Disable

```bash
defenseclaw setup splunk --disable --logs
defenseclaw setup splunk --disable --enterprise
defenseclaw setup splunk --disable --o11y
```

`--disable` disables the matching named destination (and stops the local container
if you ran `--logs`). It does not touch other destinations.

## Verify

```bash
defenseclaw doctor

defenseclaw observability plan
defenseclaw setup observability list
```

`doctor` confirms destination health without exposing credentials or response
bodies. The plan shows the exact selected buckets/signals and effective profile.
Local SQLite remains the durable log history. Configure a separate `kind: jsonl`
destination only when a file stream is also required; it is not an implicit mirror
of the Splunk projection.

## Troubleshooting

<Accordions>
  <Accordion title="Local Splunk container won't start (port 8000 in use)">
    Stop the conflicting service or run `defenseclaw setup splunk --disable --logs` and re-run after freeing the port. There's no `--port` flag today; ports `8000` and `8088` are checked at boot.
  </Accordion>
  <Accordion title="Enterprise HEC returns 403">
    Token is wrong or HEC isn't enabled on that Splunk endpoint. Test with curl: `curl -k $HEC_ENDPOINT -H "Authorization: Splunk $TOKEN" -d '{"event":"test"}'`. The CLI's `--skip-test` skips this same probe.
  </Accordion>
  <Accordion title="Events arriving but no extracted fields">
    Make sure your sourcetype is `_json` (auto-extract) or that you've installed the bundled macros / props.conf snippet above for `defenseclaw:json`.
  </Accordion>
  <Accordion title="O11y traces but no logs">
    Logs are off unless you passed `--logs-export`, and Splunk O11y log ingest is a separate entitlement, so the realm may not accept them. Rerun with `--no-logs-export` if you only have traces and metrics.
  </Accordion>
</Accordions>
