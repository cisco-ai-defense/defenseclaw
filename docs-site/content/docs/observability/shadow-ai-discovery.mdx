The Shadow AI Discovery Board displays endpoint detections from a separately
managed sensor beside DefenseClaw telemetry. Both producers contribute
OpenTelemetry to the bundled local observability stack while keeping separate
identities:

```text
DefenseClaw gateway ── OTLP/gRPC ──┐
                                  ├─> DefenseClaw Collector ─> Loki ─> Grafana
Endpoint sensor    ── OTLP/HTTP ───┘
```

This is the Phase 1 integration boundary. It provides co-deployment, shared
transport, and the bundled Shadow AI Discovery Board. It does not yet bind a
DefenseClaw session or policy decision to an endpoint PID, and it does not let
the endpoint sensor enforce DefenseClaw policy.

## Prerequisites

- Install DefenseClaw and bring up its
  [local observability stack](/docs/observability/local-observability).
- For the current producer profile, install ShadowClaw 1.4.1 or newer by
  following the [ShadowClaw installation guide](https://gatekeeper454.github.io/ShadowClaw/get-started/install.html).
- Run only DefenseClaw's Collector on `127.0.0.1:4317` and `127.0.0.1:4318`.
  The endpoint sensor's optional standalone Collector uses the same ports and
  must stay stopped for this integration.

## Start the shared stack

```bash
defenseclaw setup local-observability up
defenseclaw setup local-observability status
```

From the endpoint-sensor checkout, start it with the DefenseClaw profile:

```bash
sudo python3 -m shadowclaw \
  --config config/shadowclaw.defenseclaw.json \
  --dns-sniffer
```

The profile sends logs and metrics to `http://127.0.0.1:4318`. The Collector
already accepts OTLP/HTTP there, so no DefenseClaw destination or Collector
configuration needs to be added.

Open [Grafana](http://localhost:3000) and select **Shadow AI Discovery Board**.
DefenseClaw provisions the dashboard with the rest of the local stack; a
separate Grafana import is not required.

## Verify both producers

The Collector debug stream shows the raw OTLP envelopes received from both
products:

```bash
defenseclaw setup local-observability logs \
  --service otel-collector \
  --follow
```

For an end-to-end log check, query Loki:

```bash
curl -sG http://127.0.0.1:3100/loki/api/v1/query \
  --data-urlencode 'query=sum(count_over_time({service_namespace="shadowclaw"}[15m]))'
```

A positive result proves that endpoint telemetry reached the shared Loki.
DefenseClaw records remain under `service.namespace=defenseclaw`; external
sensor records remain under `service.namespace=shadowclaw`. The Collector's
resource processor uses `insert`, so it fills a missing namespace without
overwriting an external producer's declared namespace.

## Security and data handling

The local Collector is unauthenticated and bound to loopback by default. Do not
publish ports `4317` or `4318` beyond the host without adding an authentication
and network access-control boundary.

Endpoint telemetry can include process identity, executable paths, endpoints,
and host activity evidence. DefenseClaw's outbound v8 redaction profiles do not
rewrite records sent directly from an external producer to the Collector.
Configure the sensor's own collection and export policy for the destination's
trust boundary.

## Stop the integration

Press `Ctrl+C` in the endpoint-sensor terminal, then stop the optional
DefenseClaw stack when it is no longer needed:

```bash
defenseclaw setup local-observability down
```

Stopping the stack does not remove its persisted Grafana, Loki, Tempo, or
Prometheus volumes.
