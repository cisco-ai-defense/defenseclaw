A **registry source** is a manifest of skills, MCP servers or both that DefenseClaw fetches when you sync. Public catalogs (clawhub, smithery, skills.sh), internal HTTPS YAML or JSON files, git repositories and local files are supported. Synced entries go through the skill and MCP scanners. Clean ones land in `asset_policy.{skill,mcp}.registry`, so an admission decision can name the registry that approved it.

<Callout title="Why registries matter">
Without a registry, each new skill or MCP server is checked against hand-written rules. With a registry, the catalog drives admission: clean entries are promoted, suspicious ones wait for review, and `registry_required` denies anything the catalog has not approved.
</Callout>

## What you just saw

An **on-demand** registry sync verified source integrity, routed an entry through its existing scanner, and selected a deterministic outcome: promote a clean entry, hold a warning for review, or deny an unknown asset when `registry_required=true`. Stored sync settings do not create a runtime poller.

## Three worked examples

<Tabs items={['Public clawhub', 'Internal http_yaml mirror', 'smithery MCPs']}>

<Tab value="Public clawhub">

The simplest source. No URL and no auth:

```bash
defenseclaw registry add clawhub \
  --kind clawhub \
  --content skill \
  --non-interactive

defenseclaw registry sync clawhub
```

The first sync downloads the manifest, runs the skill scanner on every entry, and promotes the clean ones into `asset_policy.skill.registry`.

</Tab>

<Tab value="Internal http_yaml mirror">

For a curated mirror on your own network:

```bash
defenseclaw registry add corp-skills \
  --kind http_yaml \
  --url https://catalog.corp.example.com/skills.yaml \
  --content skill \
  --auth-env CORP_CATALOG_TOKEN \
  --non-interactive

defenseclaw registry test corp-skills -e           # fetch + parse, list entries, no writes
defenseclaw registry sync corp-skills              # fetch + scan + promote
```

Set `CORP_CATALOG_TOKEN` in the environment before `test` and `sync`. `--auth-env` takes the **name** of the variable, so the token never lands in `config.yaml`. Every entry's `source_url` needs a SHA-256 for the `http_yaml`, `http_json`, `git` and `file` kinds; the manifest publisher adds it.

</Tab>

<Tab value="smithery MCPs">

For the smithery.ai public MCP catalog:

```bash
defenseclaw registry add smithery-public \
  --kind smithery \
  --content mcp \
  --non-interactive

defenseclaw registry sync smithery-public
```

Each entry goes through the MCP scanner. Clean ones land in `asset_policy.mcp.registry`, so admission records which registry approved the server. `sync` skips stdio entries by default, because scanning one starts the publisher's package. Add `--scan-stdio` only for a catalog you trust.

</Tab>

</Tabs>

## Require registry approval

`asset_policy.<type>.registry_required` makes an asset class **deny by default**:

```bash
defenseclaw registry require --type skill --enabled
defenseclaw registry require --type mcp   --enabled
```

Without `--connector`, the command updates the global default and clears the
`registry_required` override on every active connector, so an old override
cannot keep enforcement off. Other per-connector fields and the global rule
lists do not change. `--connector <name>` changes only that connector's
override. Overrides for inactive connectors are kept.

When `registry_required=true`:

- An asset whose name matches a rule in `asset_policy.<type>.registry` follows that rule.
- An asset whose name does **not** match any rule falls through to the configured `registry_empty_action` (default `deny`).
- An empty registry list with `require=on` blocks **every** asset of that class by default until the next `sync` populates it. Setting `registry_empty_action: warn` or `allow` relaxes only this empty-registry gate and falls through to the type default; `warn` is non-blocking. The CLI warns you when you turn on `require` for an empty list.

The gateway tags every admission decision with `Reason="registry:<id>"` (or
`"registry:operator-approved"` for manually approved entries). Inspect the TUI
or run `defenseclaw-gateway audit export --output -` to see which catalog won;
an optional JSONL destination contains only the records its v8 route selects.

## Auth, private networks and SHA-256

| Knob | Default | Purpose |
| --- | --- | --- |
| `--auth-env <ENV>` | `""` | Name of an env var holding a bearer token sent on every fetch. The CLI rejects values that look like literal secrets. |
| `--allow-private` (`test` and `sync` only) | off | Permit RFC1918 and ULA destinations, for an internal mirror on a private subnet. `add` has no such flag. |
| `--non-interactive` | off | Use flags only. A missing required flag exits nonzero with an error. |
| SHA-256 on `source_url` | required for `http_yaml` / `http_json` / `git` / `file` | Per-entry integrity; the scanner refuses to download an entry whose computed digest does not match. |

Registry fetches use the same hardened URL path in `test` and `sync`: loopback, link-local, cloud-metadata, and private-network destinations are refused by default, including DNS resolutions that rebind into a reserved range. Use `--allow-private` only for a registry mirror you intentionally run on an internal network. Local `file` registries must use absolute paths, and remote entry downloads must pass the per-entry SHA-256 check before scanner promotion can happen.

## Inspect what landed

```bash
defenseclaw registry list                              # one row per source, with cached counts
defenseclaw registry show corp-skills                  # full detail + verdict summary
defenseclaw registry entries corp-skills --status warning
defenseclaw registry approve corp-skills my-skill --type skill
defenseclaw registry reject  corp-skills evil-skill --type skill
```

`approve` and `reject` re-promote against the cached manifest immediately by default, so the new rule lands without a network round-trip. Pass `--no-repromote` if you want to defer the change to the next `registry sync`.

## Sync schedules

Syncing is **on demand**. The `--auto-sync` and `--sync-interval-hours` flags on `add` and `edit` are reserved and ignored; nothing polls. Run `registry sync --all` from cron, a systemd timer or a CI schedule:

```bash
# /etc/cron.d/defenseclaw-registry
0 * * * * defenseclaw registry sync --all
```

## Common gotchas

<Accordions>

<Accordion title="`--url for kind=file must be an absolute path`">

The `file` kind rejects relative paths because the working directory at sync time may differ. Use `$PWD/manifest.yaml` or another absolute path.

</Accordion>

<Accordion title="Sync errors out with `sha256 is required for registry-managed http(s) skill source_url`">

The catalog publisher must include the SHA-256 in the manifest. It is required for the `http_yaml`, `http_json`, `git` and `file` kinds. Without it, anyone who controls the download endpoint could swap the skill payload.

</Accordion>

<Accordion title="Removing a source removes its rules too">

`remove` deletes every `asset_policy.{skill,mcp}.registry` rule whose `Reason="registry:<id>"`, because the registry is the source of those rules. Use `--keep-cache` to keep the cached manifest on disk for a later re-add.

</Accordion>

<Accordion title="My MCP scanner / skill scanner is not installed">

The skill scanner is an unconditional runtime dependency. If it is missing,
affected skill scans fail and those entries are marked `error`. The MCP scanner
is declared only on Python 3.11 and newer; any Python 3.10 runtime, including a
managed POSIX install that selected 3.10, legitimately omits it. When the MCP
SDK is unavailable, MCP entries are fetched but remain `pending` because no
verdict is computed.

Do not repair a packaged runtime with `pip`. Use the
[supported install or repair path](/docs/get-started/install), then rerun
`defenseclaw registry sync --all`. Source contributors should run `uv sync`
from the checkout. Use Python 3.11 or newer when MCP scanning is required.

</Accordion>

</Accordions>
