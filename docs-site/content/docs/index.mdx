DefenseClaw enforces one rule: untrusted agent capabilities are scanned,
governed, logged, and blocked when policy says they are unsafe.

## What you just saw

The demo sends one synthetic Claude Code `PreToolUse` event with a HIGH finding
through three modes:

- **Observe** lets the call run and records the evidence.
- **Action** blocks it. The demo sets the block level to HIGH with
  `defenseclaw guardrail block-at HIGH`. With the shipped default, action mode
  blocks CRITICAL findings and only alerts on HIGH.
- **Action + HITL** pauses the call and asks you inside Claude Code, because
  Claude Code's `PreToolUse` hook supports a native approval prompt.

CRITICAL findings always block, with or without HITL.

## How it works

DefenseClaw has three parts: the `defenseclaw` CLI, which sets everything up and
shows you what happened; the `defenseclaw-gateway` sidecar, which makes every
decision and records it; and a connector for each agent, the hooks or plugin
that send the agent's prompts and tool calls to the gateway.
[What is DefenseClaw?](/docs/get-started/what-is-defenseclaw) shows the
architecture and explains what DefenseClaw doesn't protect against.
