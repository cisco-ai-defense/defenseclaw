DefenseClaw is the **Cisco** governance layer for AI coding agents. It enforces one rule: untrusted agent capabilities are scanned, governed, logged, and blocked when policy says they are unsafe.

<DefenseClawDemo scenario="modes-same-event" variant="hitl" />

## What you just saw

The same synthetic Claude Code `PreToolUse` event produces three deliberately different results. **Observe** allows execution and records evidence. **Action** blocks the event. **Action + HITL** returns a native pause because Claude Code exposes an approval-capable pre-execution hook. CRITICAL findings always block, regardless of HITL.

Action mode blocks CRITICAL findings by default and alerts on MEDIUM and above. Tune it with `defenseclaw guardrail block-at`. See [Setup Guardrail](/docs/setup/guardrail).

```bash
curl -LsSf https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.sh | bash
```

## Three jobs, one runtime

| Govern | Inspect | Prove |
| --- | --- | --- |
| Skills, MCP servers, plugins, and generated code before they run | Prompts, completions, and tool calls at runtime | SQLite audit history, JSONL, OTLP, Splunk, webhooks, and TUI views |

DefenseClaw combines a **Python operator CLI** and a **Go gateway sidecar**. The CLI configures and inspects. The gateway runs the data path and applies policy. A connector wires each agent to the gateway.

## Architecture

Every agent reaches the gateway through a connector. There are three connector types:

- **Hook connectors** register the agent's native lifecycle hooks, such as Claude Code `PreToolUse`. Most connectors use hooks.
- **Policy plugin connectors** load a small DefenseClaw plugin inside the agent, such as the Amp policy plugin.
- **Proxy connectors** route model traffic through the gateway's guardrail proxy. OpenClaw and ZeptoClaw use the proxy.

## Scope and limitations

DefenseClaw improves safety by combining scanner results, runtime inspection, policy decisions, and audit trails. It does **not** prove that an agent, skill, plugin, or model interaction is risk-free.

<Callout type="warn">
High-risk deployments should pair DefenseClaw with human review, least-privilege credentials, sandboxing, CI gates, and production monitoring. In observe mode, findings are logged without blocking. Action mode blocks CRITICAL findings by default and alerts on MEDIUM and above. Tune it with `defenseclaw guardrail block-at`.
</Callout>
