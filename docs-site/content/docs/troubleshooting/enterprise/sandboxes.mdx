Sandbox setup problems (`openshell_prerequisite_missing`, `sandbox_subject_changed`, a required agent that says sandboxes are not available) are in [Sandboxes on managed computers](/docs/enterprise/runtime/sandbox-reference/). The sensor warning codes are in [Kernel sensor warnings](/docs/troubleshooting/enterprise#kernel-sensor-warnings). Problems on a user's own sandbox are in [Sandbox troubleshooting](/docs/troubleshooting/sandboxes).

## An agent reports `Operation not permitted` on a Linux computer that runs Tetragon

One of DefenseClaw's two kernel controls (an SSH private key open, or an in-place write of a shell profile or autostart entry), or one of your own enforcing Tetragon policies, denied the open. Only processes below an enrolled user's command-line agent are affected.

**Fix.** Run `enterprise linux tetragon status --user <name>`, then `audit export`. `enterprise linux tetragon pause` unblocks now. See [the help-desk runbook](/docs/enterprise/runtime/tetragon#when-a-control-blocks-something).

**Check.** The agent's open succeeds, and `tetragon status` no longer reports a would-block for the user.

## `tetragon status` says Tetragon is not reachable, or no would-block appears for an enrolled agent

Plane C is off (`ai_discovery.runtime.enable_host_plane`), the helper cannot reach the socket, or the user has no anchored agent.

**Fix.** Run `enterprise linux tetragon verify --ready-for consume`. See [Tetragon on a Linux fleet](/docs/enterprise/runtime/tetragon-reference#troubleshooting).

**Check.** The command reports ready.
