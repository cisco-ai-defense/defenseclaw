---
title: Routing rules and budgets
description: Limit which models each group may use and cap model spend per user, group or connector, on one device or across the fleet with the opt-in budget store.
---

Routing rules and budgets are part of `routing.admin` in config.yaml. On a standalone managed device they come from the signed bundle and users cannot change them. On other installs a deny is reported, never enforced.

Rules and budgets need routing on (`routing.enabled: true`) and DefenseClaw 1.0.10 or later. Sign the bundle with `--min-product-version 1.0.10`.

## Rules

```yaml
routing:
  admin:
    rules:
      - id: secrets-stay-local
        match: {severity_at_least: HIGH}
        allow: [local]
        default: local
      - id: contractors-no-cloud
        match: {groups: ["DCLAB\\contractors"]}
        action: deny
        message: "Contractors may not use cloud models. Contact IT."
```

- Every matching rule applies. A deny wins, `allow` lists intersect, and the first matching `default` that is allowed is used.
- `allow` also binds a request that is not routed: its own model must be one of the allowed models.
- `match` keys: `groups`, `users`, `connectors`, `agents`, `categories`, `severity_at_least`. Keys combine with AND, values of one key with OR.
- Groups and users match only a verified caller, with the same proof rules as profile assignments. On a managed device, when DefenseClaw cannot confirm a fact, a constraining rule applies and a deny rule refuses.
- While the classifier is down, every category rule applies on a managed device, so their `allow` lists must share a model.
- Route-only connectors run no guardrail scan, so severity rules never apply to them.

## Budgets

```yaml
routing:
  admin:
    budgets:
      - id: per-user-daily
        scope: user        # user, group or connector
        subject: "*"       # each user has their own limit
        period: day        # day, week (from Monday), month; UTC
        limit_usd: 20
        on_exceed: downgrade:fast
```

- `on_exceed` is `warn`, `deny` (managed devices only) or `downgrade:<model>[,<model>]`.
- Budgets count the computed cost of agent calls: tokens times `observability.pricing`. A cost the agent reports is never counted. Judge and decision-model calls are not counted.
- Budgets need `observability.tokenomics.enabled: true` with cost computed and the agent role recorded. On a managed device also set `observability.pricing.unknown_model: fallback`, so every model has a price.
- Calls already running when a limit is reached still finish.

## Spend across devices: the budget store (optional)

Without a store, each device counts its own spend; a user with two devices has two limits. The opt-in budget store sums spend across devices. Each device gets its own credential, which names only that device's users and the budgets they are in.

1. On an administrator workstation, create a tenant secret once and keep it there (`openssl rand -base64 32 > tenant-secret; chmod 600 tenant-secret`). No device and no store holds it.
2. Run the store as its own service account with a TLS certificate. Copy the bundle's `routing.admin.budgets` into its config, so it knows the group and connector limits:

   ```yaml
   # config.yaml on the store host
   config_version: 9
   routing:
     admin:
       budgets: []   # the same budgets as the device bundle
       budget_store:
         server:
           listen: 0.0.0.0:8443
           tls_cert_file: /etc/defenseclaw-budget-store/cert.pem
           tls_key_file: /etc/defenseclaw-budget-store/key.pem
           db_path: /var/lib/defenseclaw-budget-store/store.db
           device_daily_cap_usd: 500   # the most one device may add per UTC day
   ```

   ```bash
   defenseclaw-gateway budget-store serve --config /etc/defenseclaw-budget-store/config.yaml
   ```

3. Issue a credential for each device, naming its users (UPN or SID) and the groups of theirs that budgets name:

   ```bash
   defenseclaw-gateway budget-store device issue --config bundle-config.yaml --secret-file ./tenant-secret \
     --user alice@example.com --group "EXAMPLE\\eng" \
     --credential-out laptop-17.cred --record-out laptop-17.record
   ```

   Install `laptop-17.cred` on the device as the protected credential `routing-budget-store-device` with your MDM. Copy `laptop-17.record` to the store host and register it:

   ```bash
   defenseclaw-gateway budget-store device add --config /etc/defenseclaw-budget-store/config.yaml --record laptop-17.record
   ```

   Delete both files after. When a device's users or groups change, issue a new credential, add it, and revoke the old one.

4. In the device bundle:

   ```yaml
   routing:
     admin:
       budget_store:
         url: https://budgets.example.internal:8443
         ca_file: /etc/defenseclaw/budget-store-ca.pem   # recommended with a private CA
   ```

Manage devices and read fleet totals on the store host:

```bash
defenseclaw-gateway budget-store device list   --config /etc/defenseclaw-budget-store/config.yaml
defenseclaw-gateway budget-store device revoke --config /etc/defenseclaw-budget-store/config.yaml d3f1...
defenseclaw-gateway budget-store report        --config /etc/defenseclaw-budget-store/config.yaml --since 2026-11-01
```

What the store sees:

| Sent | Not sent |
| --- | --- |
| Device id, budget id, a keyed hash for each user, group and named user, connector names, UTC days, dollar amounts | User, group, device or host names, prompts, models |

What a device may do:

- Add spend only for its own users and the budgets its credential names. Anything else is refused.
- Read the fleet spend of its own users. For a group or connector budget it learns only whether the limit is reached, never the total.
- Group and connector totals and every device's spend are read on the store host only (`report`); the store has no network API for them.
- A revoked device is refused within 10 seconds. Its spend so far stays counted.
- One device adds at most `device_daily_cap_usd` per UTC day (or its own `--cap-usd`); `device list` shows the days a device reached it.

More:

- Every request and every answer is signed with the device's key, over HTTPS. The device refuses plain HTTP, redirects, proxies from the environment and answers the store did not sign (for example rewritten by a TLS-inspecting proxy).
- Set `ca_file` to your private CA. Without it the device trusts the system roots, including any TLS-inspection root on the device.
- When the store is down or refuses, budgets keep counting this device only. `defenseclaw routing budgets list` and `doctor` say so, and the fleet total comes back when the store answers.
- A user the device's credential does not name, or with no verified SID or UPN, is counted on that device only.
- A local administrator of a device can read and add spend for that device's users and its groups, up to its daily cap; revoke the device to stop it. They cannot reach other users.
- New network traffic: each managed device's gateway connects to the store URL every `sync_interval` (30 seconds by default) and when a new user starts an agent. Allow it in your firewall, and expose the store only to the devices' network. The store sees each device's address and when it sends.
- If the tenant secret leaks, the hashes of names can be computed: make a new secret and issue every device again. Spend counted under the old secret no longer adds up.
- Budget ids and connector names reach the store as they are: do not put a person's name in a budget id.
- Turning the store on in the middle of a period starts per-user, group and named-user budgets again on each device.
- Devices behind one NAT address share a high request limit (20 times `rate_limit_per_minute`); a busy host on that address can push them to per-device counting for a minute.
- After a gateway restart, a user's spend on other devices is read within seconds; calls made in those seconds see only this device's spend.
- The TLS key must be owned by the account that runs the store and readable only by it. It may be a link, for example into `/etc/letsencrypt/live`, when the file it points to meets that rule.
- A stream the user stops after the answer started has no final token count: the user's own budget reads as unknown for 10 minutes (a deny budget then refuses on a managed device).

## Check it

```bash
defenseclaw routing rules list      # rules and notes on rules that do less than they look
defenseclaw routing budgets list    # spend this period, and whether it is the fleet or this device only
defenseclaw routing test "write a parser" --as-user DCLAB\\alice   # administrators: which model, which rule
```
