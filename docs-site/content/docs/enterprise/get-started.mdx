Deploy the standalone profile in six steps. You need an MDM, configuration-management
tool or administrator shell that runs commands as SYSTEM on Windows and as root on
Linux and macOS. [Concepts](/docs/enterprise/plan/concepts) defines *profile*,
*lifecycle* and *ensure*. Not sure you need this? Read
[Is this for you?](/docs/enterprise#is-this-for-you).

## 1. Pick the profile

Use **standalone** unless you run Cisco Secure Client and want DefenseClaw as one of
its modules ([Secure Client](/docs/enterprise/install/secure-client)). On Windows and
macOS the profile defaults to Secure Client, so set `enterprise.profile: standalone`
([Two profiles](/docs/enterprise#two-profiles)).

## 2. Pick the agents

Each agent you protect is a key under `guardrail.connectors` in the config. Nothing
is protected until you list one.

| Route | Agents |
| --- | --- |
| [Machine policy](/docs/enterprise/plan/concepts#machine-policy-connector): hooks in the vendor's administrator-owned policy files | Claude Code, Codex, Cursor, GitHub Copilot, OpenCode (with the managed plugin) |
| [Per-user](/docs/enterprise/plan/concepts#per-user-connector): the guardian writes and repairs the hook in each enrolled user's config | Devin, Antigravity, Hermes, Amp, Kiro |

OpenClaw and ZeptoClaw are not supported here. The verified combinations are in the
[enterprise route table](/docs/get-started/support-matrix#enterprise); how to list
agents and users is in [Plan a rollout](/docs/enterprise/plan/rollout#step-1-choose-the-agents).

ACP (Agent Client Protocol) editors are a separate route, in preview, and not a
`guardrail.connectors` key. The central config needs `acp.enabled: true`, a
binding for each editor and agent pair, and an ACP profile that allows both
([ACP configuration](/docs/reference/apis/acp-guard#configuration)). Then enroll each
user with `defenseclaw-gateway enterprise acp enroll --user --client --agent
--profile` ([Managed computers](/docs/reference/apis/acp-guard#managed-computers)).
Enrollment refuses a pair the config does not allow.

## 3. Pick your MDM

Every recipe follows the same [MDM contract](/docs/enterprise/mdm) and uses the
scripts in [`packaging/mdm`](https://github.com/cisco-ai-defense/defenseclaw/tree/main/packaging/mdm).

| Tool | What you push |
| --- | --- |
| [Intune on Windows](/docs/enterprise/mdm/intune/windows) | A Win32 app that wraps the Setup and your config, plus a PowerShell 7 app |
| [Intune on macOS](/docs/enterprise/mdm/intune/macos), [Linux](/docs/enterprise/mdm/intune/linux) | One root script: the kit wrapper |
| [Jamf Pro](/docs/enterprise/mdm/jamf), [Iru (Kandji)](/docs/enterprise/mdm/kandji) | The `.pkg` and kit scripts |
| [Workspace ONE UEM](/docs/enterprise/mdm/workspace-one) | A Win32 app or the `.pkg`, with scripts and sensors |
| [Configuration Manager](/docs/enterprise/mdm/configmgr) | An application with the Setup and your config |
| [Linux configuration management](/docs/enterprise/mdm/linux-config-management) | The `.deb` or `.rpm` through Ansible, Puppet, Chef, Salt, apt or dnf |
| Any other tool | The kit wrapper, run as SYSTEM or root ([What you deliver](/docs/enterprise/mdm#what-you-deliver)) |

The release files: `DefenseClawSetup-Enterprise-Standalone-x64.exe` on Windows,
`defenseclaw-enterprise-<version>-linux-<arch>.deb`, `.rpm` or `.tar.gz` on Linux,
and `defenseclaw-enterprise-<version>-darwin-arm64.pkg` on macOS. Verify the
signed `checksums.txt` once and pin each file by its SHA-256.

## 4. Deliver the config and the AI Defense key

The config is one YAML file only administrators can change. It is the only policy
the host enforces ([Policy changes on a managed host](/docs/enterprise/plan/managed-policy)).
The lifecycle installs it at `C:\ProgramData\Cisco\DefenseClaw\etc\config.yaml`
(Windows), `/etc/defenseclaw/config.yaml` (Linux) or
`/opt/cisco/defenseclaw/etc/config.yaml` (macOS). Start from
[A minimal config](/docs/enterprise#a-minimal-config). A first install on Windows
needs a config; on Linux and macOS an install without one protects no agents. How
each wrapper takes it: [Deliver the config](/docs/enterprise/mdm#deliver-the-config).

The Cisco AI Defense key is optional. It never goes in the config, an MDM script or
a command line; store it with `enterprise secret set`
([Deliver the AI Defense key](/docs/enterprise/mdm#deliver-the-ai-defense-key)).

## 5. Run ensure and read the result

`ensure` is the one action your MDM runs. It installs, upgrades, repairs drift and
applies a changed config; when the host already matches it reports `"noop": true`,
so it is safe on every check-in. Exit codes: success `0` (Windows and Unix), failed
and rolled back `1603` or `1`, busy `1618` or `75`, invalid arguments `1639` or `2`
([Exit codes](/docs/enterprise/mdm#exit-codes)). Check a host by hand:

```bash
sudo /opt/defenseclaw/bin/defenseclaw-gateway enterprise linux status --json
```

```json title="Output (healthy, trimmed)"
{
  "ok": true,
  "action": "status",
  "profile": "standalone",
  "installed": true,
  "readiness": { "gateway": true, "guardian": true, "enumerator": true, "sensor_helper": true },
  "coverage_complete": true,
  "security_complete": false,
  "warnings": [{ "code": "hook_process_fail_open", "message": "Codex can run a tool after its PreToolUse hook is killed or times out" }],
  "errors": []
}
```

On macOS use `/opt/cisco/defenseclaw/bin/defenseclaw-gateway enterprise macos status --json`.
On Windows, from an elevated prompt:
`& 'C:\Program Files\Cisco\DefenseClaw\bin\defenseclaw.exe' enterprise windows status --profile standalone --json`.
Read `coverage_complete` and `security_complete` ([Health fields](/docs/enterprise/operate/operations#health-fields)).
With Codex or Claude Code enabled, installed hooks can provide complete coverage
while `security_complete` remains `false`: the agent can continue after a stopped
or timed-out hook. `hook_process_fail_open` names that residual risk.

## 6. Pilot in observe mode, then expand in rings

Deploy a pilot ring with `guardrail.mode: observe`. It records every decision,
including what DefenseClaw would have blocked, without blocking on policy verdicts.
When the pilot is healthy and you have reviewed the decisions, set
`guardrail.mode: action` and deliver the config again. Then grow in rings (pilot,
early, broad, everyone). [Plan a rollout](/docs/enterprise/plan/rollout#step-5-expand-in-rings)
has ring sizes and exit criteria.
