DefenseClaw tracks hook connector compatibility in a packaged manifest, `cli/defenseclaw/inventory/hook_contracts.json`. It maps each agent version range to the hook contract DefenseClaw knows how to install, parse, evaluate and answer. A contract says DefenseClaw understands an agent version's hooks. It does not say the connector runs on every OS: see the [support matrix](/docs/get-started/support-matrix).

For pre/post tool-call pairing and outcome tiers per connector, see the [stateful connector lifecycle](/docs/reference/policy/cel/tool-call-state/#connector-outcome-and-identity-matrix).

- **Kiro.** Per-user installs are not version-gated. Kiro IDE and `kiro-cli --v3` read `.kiro/hooks/*.json`, and bare `kiro-cli` (2.x) reads its agent config. Managed Windows pins `kiro-cli-windows-managed-hooks-v1` (kiro-cli `>=2.24.1`) or `kiro-ide-windows-managed-hooks-v1` (Kiro IDE `>=1.0.182`).
- **Cursor.** The range `>=2.4.0, <4.0.0` is the Cursor Desktop application version; from `4.0.0` on it runs as an untested newer version. The Agent CLI is covered only at the reviewed exact build `2026.07.23-e383d2b`. A later Agent build runs as an untested newer version, and a build with the same date but another build ID has no contract. The `cursor_version` field in hook payloads is the Desktop application version.
- **Codex.** `0.133.0` to `0.134.x` use the ten-event `codex-hooks-v3` contract with selective local-function tool payloads. `0.135.0` to `0.144.x` keep the event matrix and expand to generic local function tools (`codex-hooks-v3-generic`). `0.145.0` adds `SessionEnd` (`codex-hooks-v4`). Per-user setup also needs Codex `0.136.0` or newer for its app-server command, and checks this before it changes anything.
- **Claude Code.** v1 covers `>=2.1.154, <2.1.219` with 28 events. v2 starts at `2.1.219` with 29 events and adds the observation-only `DirectoryAdded`.
- **Antigravity (`agy`).** The contract starts at `>=1.1.8`. The OpenShell sandbox image installs agy `1.2.12`.
- **Amp.** `0.0.1785334225` is DefenseClaw's contract snapshot and certification floor for the five-event plugin API (`amp-plugin-v1`, plugin script `v2`). Amp does not declare it as the upstream minimum.
- **Hermes.** A git install that prints only its release date, such as `Hermes Agent vunknown (2026.9.24)`, is matched by the date tags in the table. An earlier date has no contract and a later one is an untested newer version.
- **Hermes 0.19.0 to 0.21.0 run their TUI without the hooks.** Their TUI (`hermes --tui`) and dashboard chat run tools without the shell hooks DefenseClaw registers, so a terminal call there is neither checked nor recorded ([upstream fix](https://github.com/NousResearch/hermes-agent/commit/3094cde5138bd2bc28134d060345081ab5099d25)). Their classic interface, cron, ACP and messaging gateway run the hooks, so DefenseClaw sets these releases up (also the release dates `2026.7.20` up to `2026.9.7`, and a git build that prints one of those dates), and setup, `defenseclaw doctor` and the gateway log warn about the TUI. Use the classic interface, or update Hermes to 0.21.1 or later (`hermes update`). The pinned Hermes in the OpenShell image is not refused either; the sandbox refuses its TUI, dashboard chat and `hermes serve` instead. See [Hermes](/docs/reference/connectors/hermes).

Open-ended contracts leave `max_exclusive` empty until an upstream release publishes a breaking hook change. A bounded contract records how far DefenseClaw tested a connector, not where it stops working.

## Version policy

DefenseClaw assumes a connector version works unless it knows otherwise.

| Case | What happens |
| --- | --- |
| Untested newer version: above every tested range, or between two exact pins of one contract | Uses the newest contract. Setup keeps your mode. Doctor and setup print an informational "untested newer version" line. |
| Below the lowest tested version, in a gap between ranges, or the same version as an exact-build pin with another build ID | No contract. Setup refuses the connector in observe and action mode and changes nothing. |
| Known broken: listed in `known_broken_versions` with a reason and an issue link | Treated like a version below the floor, and the refusal names the reason. An entry with `warn_only` is not refused: the version keeps its contract, and setup and doctor warn with the reason. Today the list holds one warning: Hermes 0.19.0 to 0.21.0 on the host (see above). |
| Compatible update after setup | Doctor reports information. `defenseclaw setup <connector>` or the next gateway start refreshes the lock. |
| Enterprise standalone profile | Same rules. A version with no contract gets no hooks in any guardrail mode, and `status` and `verify` report `hook_contract_unverified` with `coverage_complete: false`. |

## Setup-time checks

Every `defenseclaw setup` path that chooses a connector refreshes agent discovery, reads the installed version and checks it against the manifest before it writes config.

- A version with no contract is refused in observe and action mode before any change, with the version to upgrade to. `defenseclaw init` and `quickstart` leave such a connector out in both modes too. Upgrade the agent, then run `defenseclaw setup <connector>` again. `DEFENSECLAW_ALLOW_HOOK_CONTRACT_DRIFT=1` skips this check for exploratory testing only.
- OpenCode is refused the same way. A detected version with no contract is below `1.18.10` or known broken; its plugin and contract lock must change together.
- If the agent is not installed on the host, action mode accepts the harness image DefenseClaw built for it. The image must be the one a sandbox would run now: built by this release for this user from the current `openshell.image` settings, hook-fire verified, and with a harness version that resolves to a known contract. Run `defenseclaw sandbox image build <harness>` if it is refused.
- If the version cannot be read because the binary is outside a trusted install prefix, interactive setup offers to trust the directory. Non-interactive runs print `defenseclaw setup trusted-paths add <dir>`. Trusting a path never bypasses the version gate.

The gateway checks the version again when it starts. `DEFENSECLAW_ALLOW_HOOK_CONTRACT_DRIFT=1` skips both checks.

- With one connector, a version with no contract is refused in observe and action mode for every hook connector, and the gateway does not start. A version that could not be read is refused in action mode. This check is skipped when the enterprise hook guardian owns the hooks (a managed enterprise computer).
- With several connectors, a version with no contract is refused in action mode, and OpenCode in both modes. A version that could not be read is refused in action mode. The guardian does not skip this check. In observe mode a version with no contract gets a warning in the gateway log; Claude Code and Codex then fail their setup, because they build their hooks from the contract, and other connectors install their hooks.
- A refused or failed connector that this gateway did not guard before is skipped, and the other connectors keep running. One it already guarded, as after an upgrade of DefenseClaw or of the agent, stops the start: the gateway restores the earlier connector state and does not start, except on a managed computer. If every connector is refused, the gateway does not start.

Proxy connectors are recorded in the manifest as `not-gated`, because their enforcement surface is the proxy.

## Runtime lock

After gateway setup, DefenseClaw writes `hook_contract_lock.json` in the data directory.

| Field | Purpose |
| --- | --- |
| `raw_agent_version` | The exact version string discovered locally. |
| `normalized_agent_version` | The semver-like value used for range matching. |
| `contract_id` | The contract selected for this connector. |
| `hook_script_version` | The hook script generation installed on disk. |
| `hook_script_digests` | Hashes of installed hook scripts, for drift detection. |
| `defenseclaw_version` | The DefenseClaw build that wrote the lock. |

`defenseclaw doctor` compares the lock with the current discovery cache, so upgrades, contract changes and script drift show up before action-mode enforcement depends on them.
