This page answers "can this connector do X?" for every connector. The table is checked against the connector code on every change. For what works on your operating system, see the [support matrix](/docs/get-started/support-matrix).

<CapabilityMatrix />

## Columns

| Column | Meaning |
| --- | --- |
| Family | `proxy`: DefenseClaw sits in the model data path. `hooks`: DefenseClaw uses the agent's hooks or plugin and the agent talks to its upstream directly. |
| Tool inspection | When DefenseClaw sees a tool call. `pre-execution + response-scan` scores it before it fires and again when it returns. |
| Subprocess policy | `shims`: setup installs PATH shims for `curl`, `wget`, `ssh`, `nc`, `pip` and `npm` that ask the gateway before running the real binary. They do not isolate the process. `none`: the agent runs commands itself. |
| Block | Whether the connector's hooks can return a block decision at all. |
| Native ask | Whether the hooks can prompt you inside the agent. Without it, a confirm verdict becomes an alert, allow or context message that the TUI can show but cannot resume. |
| Fail-closed | Whether DefenseClaw can deny a delivery failure in mode `closed`. A note marks agents that can still allow a call if the hook cannot start or times out. |
| OpenShell sandbox | Tamper tier and verification of the harness image. See below. |
| HITL | How human approvals reach you on that connector. |

Two rules sit on top of the columns.

- **Prompt rules block only where the agent can block a prompt.** Claude Code, Codex, Cursor and Devin can. Kiro blocks a prompt only in Kiro IDE. Copilot CLI, Hermes, OpenCode, Amp and Antigravity have no such hook, so a matching prompt reaches the model. Tool-call rules still block there.
- **Antigravity asks and blocks only on `PreToolUse`.** `PreInvocation` and `PostInvocation` only change context, `PostToolUse` only observes, and `Stop` is always allowed.

## Common questions

### Which connector gives the most safety on its own?

One with **Block**, **Native ask** and **Fail-closed** all yes, and a managed-tier sandbox verified end to end. Of the current connectors that is [Claude Code](/docs/connectors/claudecode): it asks inside the agent, and in a sandbox its hooks sit in a root-owned policy file.

### Which connectors enforce through the agent's own hooks?

[Claude Code](/docs/connectors/claudecode), [Codex](/docs/connectors/codex), [Cursor](/docs/connectors/cursor), [Hermes](/docs/connectors/hermes), [Devin](/docs/connectors/devin), [Copilot CLI](/docs/connectors/copilot), [Antigravity](/docs/connectors/antigravity), [OpenCode](/docs/connectors/opencode) and [Kiro](/docs/connectors/kiro). [Amp](/docs/connectors/amp) uses a policy plugin. None of them can block a request the agent has not yet shown to its hook or plugin surface.

### Which connectors can ask me inside the agent?

Claude Code (`PreToolUse`, in Manual mode only; other permission modes block), Copilot CLI (`preToolUse`), Antigravity (`PreToolUse` only), Amp (`tool.call` and model-bound `tool.result` in the active foreground thread) and OpenClaw. Cursor is not counted: DefenseClaw does not turn on its native ask. Every other confirm verdict takes a connector-specific fallback, and there is no TUI approval queue.

### Which connectors fail closed?

Use the [gateway outage table](#gateway-outage). The first table's Fail-closed column also marks agents that can run a call when a hook cannot start or times out.

## Gateway outage

The default is `closed` everywhere except Secure Client. On a managed standalone host, only an administrator can choose `open`. An administrator's `open` applies only when the gateway is proven not running. On Linux and macOS, a missing socket in a trusted directory proves the gateway is not running. An existing socket that refuses a connection or disappears while dialing blocks even under `open`. On Windows, a stopped service with no listener proves the gateway is not running; a running service with no listener blocks even under `open`. A stopped Windows service whose listener table cannot be read, or with another listener on its port, blocks. A connected listener owned by another process also blocks. When the service is running and the listener table cannot be read, the hook dials and verifies the connected peer. `enterprise_managed_gateway_restarting` and `enterprise_managed_gateway_no_answer` block even under `open` on every OS. A foreign-hook guard that cannot verify the gateway's session record blocks the call too. Rate limits (HTTP 429, including unanswered resends), a deadline spent by local hook work, failed identity or credential checks, oversized input and complete but unusable answers block. The environment never selects the installed mode. [Fail modes](/docs/reference/configuration/fail-modes) explains how to set and inspect it.

### Default-guard outage class

With `foreign_hooks: remove`, these guarded tool calls have the following outcome under administrator `open` at a proven stopped gateway. The capability rows above are the source for each OS. A restarting or unanswered gateway blocks every managed standalone tool call, even under `open`.

| Connector ID | Linux | macOS | Windows |
| --- | --- | --- | --- |
| `copilot` | Blocks | Blocks | Blocks |
| `cursor` | Blocks | Blocks | Blocks |
| `devin` | Blocks | Blocks | Blocks |
| `opencode` | Blocks | Blocks | Blocks |
| `amp` | Blocks | Blocks | Runs |
| `hermes` | Blocks | Blocks | Runs |

- **Managed tool calls default to closed.** The managed column shows the administrator's explicit `open` for a proven stopped gateway under the default foreign-hook guard; the table above makes the guarded class explicit for each OS. A restart or missing answer blocks even under `open` on every OS. With `foreign_hooks: report` or `allow`, Copilot's and OpenCode's machine-policy routes follow the installed mode for a proven stopped gateway on every OS; their per-user routes still block on Linux and macOS. Windows Amp keeps its guard session locally; its plugin's outage result is given in the managed column. `status --json` and `verify --json` report the mode of the installed route.
- **The foreign-hook guard can still block.** With `foreign_hooks: remove` (the default), the foreign-hook guard checks the connectors in the table above. Except for Windows Amp, a guarded tool call needs the gateway's session record. A stopped, restarting or unanswered gateway leaves that check unproven, so the guarded call blocks even under administrator `open`. Windows has no Hermes foreign-hook guard; its hook can follow administrator `open` only for a proven stopped gateway. Start the gateway, then restart the agent if its session still fails the check. See [Foreign-hook guard](/docs/enterprise/configure/foreign-hook-guard#gateway-outages).
- **A hook must run to deny.** Claude Code, Codex, Devin, Kiro, Copilot CLI, Antigravity and Hermes can run a call when a hook cannot start or times out. Cursor writes `failClosed: true` in action mode and `false` in per-user observe mode. A loaded Amp or OpenCode plugin denies a tool call it cannot check in mode `closed`.
- **Vendor limits still apply.** Antigravity does not document non-zero hook exit status as enforcement; DefenseClaw sends its native deny on `PreToolUse`. Hermes accepts a valid block answer and, from 0.21, exit 2; other exits, a killed hook or a timeout can let a call run. Kiro CLI 2.24.1 ran a tool after a 12-second `preToolUse` hook exceeded its default timeout. DefenseClaw registers a 30-second timeout.
- **Cursor CLI has an outage display limit.** Builds without `beforeSubmitPrompt` can send the prompt without a hook check. In action mode a refused prompt can disappear without a displayed reason, although tool refusals show their reason. Run `defenseclaw-gateway status`; on a per-user install, `defenseclaw-gateway start` restores a stopped gateway.
- **Strict availability only tightens.** Where the table says Read, `DEFENSECLAW_STRICT_AVAILABILITY=1` closes an outage without changing the installed or reported mode. Amp does not read it.
- **Secure Client keeps its existing delivery.** Its unset mode is `open`; an explicit `closed` is kept where the connector supports it, as shown in the table. Only its Antigravity, Devin, Hermes and Kiro shell hooks retain the legacy `DEFENSECLAW_FAIL_MODE` override. Hooks rendered by 1.0.3 or earlier keep their legacy input until upgrade renders them again.
- **Stop events let a turn end.** Once a stop or session-end event is identified, an outage gets a neutral response. Codex prompt and tool-result hooks remain closed on managed hosts even under administrator outage `open`. Per-user fail-open calls are recorded and later reported as `guardrail-degraded` alerts; see [diagnosis](/docs/reference/configuration/fail-modes#reporting-and-diagnosis).

### I want to run the agent in an OpenShell sandbox

`defenseclaw sandbox run <harness>` runs a coding agent in an NVIDIA OpenShell sandbox that sees only your project folder, on Linux or in a MicroVM on an Apple-silicon Mac ([how](/docs/how-to/sandboxes/set-up-on-macos)). DefenseClaw builds images for the harnesses below. Every other connector is pending.

<SandboxHarnessTable />

| Term | Meaning |
| --- | --- |
| Managed tier | The hooks are in a root-owned policy file that user and project settings cannot switch off. |
| User tier | The agent can edit its hook file, or code it or a repository adds runs beside the hooks. DefenseClaw reports a sandbox whose hooks go silent while the harness is active. |
| Verified | The image passed a hook check against a mock model, and the harness ran end to end in a live sandbox with the daemon: a blocked command stayed blocked and the egress block list held. |
| Unverified | The harness needs a vendor account before its first turn, so no mock model can drive it. `sandbox run` builds the image, then refuses it. |
| Not tested live | A sign-in path no live run exercised. The connector's reference page says which sign-ins `sandbox run` shares. |

`openshell.harnesses` (Claude Code and Codex when empty) decides which images `defenseclaw sandbox setup` and a bare `defenseclaw sandbox image build` build, and which `defenseclaw sandbox doctor` checks. `sandbox setup --harness` (repeatable) replaces that list, so name every harness you want. `sandbox image build <harness>` builds what you name without changing the list, and `sandbox run` builds a missing image on first use. Every sandbox hook fails closed.

## Sandbox failure records

Sandbox shell hooks record failures at `/sandbox/.defenseclaw/logs/hook-failures.jsonl`, including neutral stop responses and closed prompt or tool-call failures. The Amp and OpenCode sandbox plugins write no record. They block a tool call they cannot check and do not block prompts. The next tool call is blocked as before, and so is the next prompt where the hook can block one.
