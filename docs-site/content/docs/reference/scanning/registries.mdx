A registry source is a fetchable manifest of skills or MCP servers. Synced entries go through the skill or MCP scanner, and clean ones are promoted into `asset_policy.{skill,mcp}.registry`. A registry is the approved catalog. It is not the block or allow list: those are the `denied` and `allowed` rules in [Admission](/docs/reference/scanning/admission), and they always apply. To set one up, see [Subscribe to a registry](/docs/how-to/scanning/subscribe-to-a-registry).

## Promote and require

Once entries are flowing in, `asset_policy.<type>.registry_required` flips the corresponding asset class to **deny-by-default**:

```bash
defenseclaw registry require --type skill --enabled
defenseclaw registry require --type mcp   --enabled --enforce
```

`registry_required` is an asset policy rule, so unlike the `denied` and
`allowed` lists it follows `enabled` and `mode`. The requirement is enforced
only while asset policy is on: `asset_policy.enabled: true` and
`asset_policy.mode: action`. A per-user
install starts with `enabled: false` and `mode: observe`, so a `require` rule
does not take effect until asset policy is enabled for action; the CLI says so.
Add `--enforce` to turn both on in the same
save, or set them in the TUI config editor (Setup → `c` → Asset Policy). In
`observe` mode an unregistered asset is logged, not blocked. To turn
enforcement back off, run
`defenseclaw registry require --type mcp --disabled --no-enforce`
(`--no-enforce` sets `mode: observe`).

A registry rule that pins `transport` treats `http` and `streamable-http` as
the same HTTP transport, and a URL server added without `--transport` counts as
`http`.

An unscoped operation is broad operator intent: it updates the global default
and clears only the targeted `registry_required` override on every active
connector, so stale opposite overrides cannot keep enforcement disabled. All
other per-connector fields and the global registry rule/filter lists remain
unchanged. `--connector <name>` changes only that connector's explicit
override. Known but inactive connector overrides are preserved so future
activation does not silently inherit a weaker or stronger posture than the one
previously saved.

When `registry_required=true`:

- An asset whose name matches a rule in `asset_policy.<type>.registry` follows that rule.
- An asset whose name does **not** match any rule falls through to the configured `registry_empty_action` (default `deny`).
- An empty registry list with `require=on` blocks **every** asset of that class by default until the next `sync` populates it. Setting `registry_empty_action: warn` or `allow` relaxes only this empty-registry gate and falls through to the type default; `warn` is non-blocking. The CLI warns you in colour when you flip `require=on` against an empty list — read the warning carefully.

The Go gateway tags every admission decision with `Reason="registry:<id>"` (or
`"registry:operator-approved"` for manually approved entries). Inspect the TUI
or run `defenseclaw-gateway audit export --output -` to see which catalog won;
an optional JSONL destination contains only the records its v8 route selects.


## Flags and integrity checks

| Knob | Default | Purpose |
| --- | --- | --- |
| `--auth-env <ENV>` | `""` | Name of an env var holding a bearer token sent on every fetch. The CLI rejects values that look like literal secrets. |
| `--allow-private` | off | A `registry test` and `registry sync` flag (not `add`). Permits RFC 1918 / ULA destinations: off in production, on for an internal mirror on a private subnet. |
| `--scan-stdio` | off | A `registry sync` flag. Also scans stdio MCP entries, which starts each publisher-controlled package on this machine. |
| `--non-interactive` | off | Required for CI; missing required flags exit non-zero with a clear `error: --foo is required`. |
| SHA-256 on `source_url` | required for `http_yaml` / `http_json` / `git` / `file` | Per-entry integrity; the scanner refuses to download an entry whose computed digest does not match. |

Registry fetches use the same hardened URL path in `test` and `sync`: loopback, link-local, cloud-metadata, and private-network destinations are refused by default, including DNS resolutions that rebind into a reserved range. Use `--allow-private` only for a registry mirror you intentionally run on an internal network. Local `file` registries must use absolute paths, and remote entry downloads must pass the per-entry SHA-256 check before scanner promotion can happen.


## Inspect what landed

This is a real `file` source with two stdio MCP entries, synced without
`--scan-stdio`, so both entries are still `pending`:

```text title="defenseclaw registry list"

  Registry sources
  ────────────────
  ID                       KIND         CONTENT  ON  ENTRIES            LAST SYNC              URL
  ------------------------ ------------ -------- --- ------------------ ---------------------- ------------------
  corp-mcp                 file         mcp      yes 2 (0/0/0/0/0)      2026-10-06T18:27:26Z   /tmp/corp-mcp.yaml

  ENTRIES column: total (clean/warning/blocked/error/rejected)
```

```text title="defenseclaw registry entries corp-mcp --status pending"

  Entries for corp-mcp
  ────────────────────
  NAME                             TYPE   STATUS     SEV      A/R
  -------------------------------- ------ ---------- -------- ---
  context7                         mcp    pending    -        --
  filesystem                       mcp    pending    -        --
```

`ENTRIES` reads the total, then the clean, warning, blocked, error and
rejected counts; a dash means the source was never synced. `A/R` shows whether
you approved or rejected an entry.

```bash
defenseclaw registry list                              # one row per source, with cached counts
defenseclaw registry show corp-skills                  # full detail + verdict summary
defenseclaw registry entries corp-skills --status warning
defenseclaw registry approve corp-skills my-skill --type skill
defenseclaw registry reject  corp-skills evil-skill --type skill
```

`approve` and `reject` re-promote against the cached manifest immediately by default, so the new rule lands without a network round-trip. Pass `--no-repromote` if you want to defer the change to the next `registry sync`. `--type` is optional when the source holds one content type (`--content skill` or `--content mcp`) or the entry name exists under one type only.


## Sync schedules

Syncing is on demand. Stored sync settings do not start a poller. Run `registry sync --all` on a schedule (cron, a systemd timer or a CI schedule).

DefenseClaw configuration is per user, so schedule the sync as the user who
runs DefenseClaw, for example in that user's crontab (`crontab -e`):

```bash
0 * * * * defenseclaw registry sync --all
```

Keep the gateway running: with it stopped, `registry sync` still fetches, scans
and promotes, but it warns that the audit event was not recorded. Use the full
path to `defenseclaw` if cron's `PATH` does not include it.


## Common gotchas

<Accordions>

<Accordion title="`--url for kind=file must be an absolute path`">

The `file` adapter rejects relative paths because `~/.defenseclaw/` and the operator's CWD are not guaranteed to line up at admission. Use `$PWD/manifest.yaml` or a fully qualified path.

</Accordion>

<Accordion title="Sync errors out with `sha256 is required for registry-managed http(s) skill source_url`">

The catalog publisher needs to compute and include the SHA-256 in their manifest. This is a hard requirement for `http_yaml`, `http_json`, `git`, and `file` kinds — without it, an attacker who compromises the registry HTTPS endpoint could swap the skill payload underneath you.

</Accordion>

<Accordion title="Removing a source removes its rules too">

`remove` strips every `asset_policy.{skill,mcp}.registry` rule whose `Reason="registry:<id>"`. The intent is "the registry is the source of truth for these rules; deleting the registry deletes the rules". Use `--keep-cache` if you want to preserve the on-disk manifest for a future re-add.

</Accordion>

<Accordion title="My MCP scanner / skill scanner is not installed">

The skill scanner is an unconditional runtime dependency. If it is missing,
affected skill scans fail and those entries are marked `error`. The MCP scanner
is declared only on Python 3.11 and newer; any Python 3.10 runtime, including a
managed POSIX install that selected 3.10, legitimately omits it. When the MCP
SDK is unavailable, MCP entries are fetched but remain `pending` because no
verdict is computed.

Do not repair a packaged runtime with `pip`. Use the
[supported install or repair path](/docs/get-started/install), then rerun
`defenseclaw registry sync --all`. Source contributors should run `uv sync`
from the checkout. Use Python 3.11 or newer when MCP scanning is required.

</Accordion>

</Accordions>
