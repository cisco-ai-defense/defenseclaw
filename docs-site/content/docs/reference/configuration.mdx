`~/.defenseclaw/config.yaml` is the source of truth for every decision an administrator makes. Setup commands, `defenseclaw config set` and the policy commands change it through one writer that validates before it writes; on a per-user install you can also edit it by hand. The running gateway validates the whole file on change and swaps in a new policy generation, so most changes need no restart; a change that does not validate leaves the previous generation running. The model behind this is on [Source of truth](/docs/reference/source-of-truth); the keys that need a restart are under [Reload without restart](#reload-without-restart).

The current schema is `config_version: 9`. `defenseclaw config reference --format json-schema` prints the schema of every section with allowed values, and `defenseclaw config validate` checks a file. A version 8 file (written by 0.8.5 to 0.8.10) is migrated in memory when the gateway loads it; see [Migrate to config version 9](/docs/reference/migrate-v9).

<Callout title="Windows layouts depend on the installer">
The Windows Setup package uses an embedded runtime and `defenseclaw-hook.exe`, without a `.venv`. The supported per-user `install.ps1` route manages a private `.venv` and generates hook scripts under the data home. See [Windows paths](/docs/get-started/windows/paths-troubleshooting) before locating or editing Windows state.
</Callout>

<Callout title="Managed computers">
On a Linux or macOS computer with the standalone enterprise package, `defenseclaw` offers users only `sandbox` commands, `help` and `--version` (every other command exits 2), and `defenseclaw-gateway` is not on their `PATH`. On Windows, `defenseclaw.exe` is the administrator's command. The `defenseclaw` and `defenseclaw-gateway` examples on this page are for a per-user install. The administrator edits the managed config and runs the packaged binary as root: `/opt/defenseclaw/bin/defenseclaw-gateway` on Linux, `/opt/cisco/defenseclaw/bin/defenseclaw-gateway` on macOS, and `defenseclaw.exe enterprise ...` from an elevated PowerShell on Windows. Apply a change with `enterprise <os> ensure`, check it with `enterprise <os> verify`, and use `policy digest` and `policy reload` on the gateway binary. See [Change the config](/docs/enterprise/lifecycle#change-the-config) and [Enterprise settings](#enterprise-settings-enterprise).
</Callout>

## On-disk layout

Where each file lives on macOS and Linux is under [What the install creates](#what-the-install-creates) and [Data](#data). Windows paths are on [Windows paths](/docs/get-started/windows/paths-troubleshooting). Only `config.yaml` and the assets it names by digest are policy. Everything else is one of three other kinds, and none of it is read back as input:

| Kind | Files | What to do |
| --- | --- | --- |
| Derived (rendered from `config.yaml`) | `custom-providers.json`, `hooks/<connector>-hook.sh`, the composed rule packs and compiled admission (the last two live in memory) | Never edit. Doctor reports drift. Regenerate with `defenseclaw doctor --fix` (providers) or `defenseclaw-gateway restart` (hook scripts). |
| Evidence (what was applied) | `config.generation.json`, `hook_contract_lock.json`, `migration-v9.json`, `config.yaml.v8.bak`, `data.json.migrated-v9` | Keep; they explain how the file got here. |
| Runtime state (what was seen or done) | `audit.db`, `doctor_cache.json`, `judge_bodies.db`, quarantine records, the AI-discovery inventory | Reported, never policy. |

`config.generation.json` records the generation counter, the SHA-256 of the file the writer last wrote, the actor and the reason. `config.yaml.lock` is the lock the Go and Python writers share. `hooks/`, `hook_contract_lock.json` and `connector_backups/` appear once a connector is set up; `backups/` holds the timestamped copies that commands such as `setup redaction` write before changing `config.yaml`. A `policies/rego/data.json` left over from an upgrade is ignored. `gateway.jsonl` exists only when an optional `kind: jsonl` destination explicitly uses that path.

`config.yaml`, `config.generation.json`, `audit.db` and `device.key` are created by `defenseclaw init` or `quickstart`, and the hook scripts by setting up an agent. Only `config.yaml` is policy; the hook scripts are derived from it. `installer/` is the installer that performed the current install (`defenseclaw rollback` uses it); on macOS and Linux its `binaries.sha256` lists the SHA-256 of each installed binary as it runs (`cd ~/.local/bin && shasum -a 256 -c ~/.defenseclaw/installer/binaries.sha256`); on Windows `installer\` holds only `install.ps1`. On macOS these differ from the binaries in the release archive, which the installer checks against `checksums.txt` and then signs ad hoc for this Mac. `previous/` is the install the last upgrade replaced. On Linux, `~/.local/bin` also holds `defenseclaw-sensor-helper` for the opt-in sandbox kernel feed. When the installer installs `uv` for you, `uv` and `uvx` are in `~/.local/bin` too.

On macOS and Linux the installer does not change `PATH`. If `~/.local/bin` is not on it, the installer prints the line to add to your shell profile.

### Data

In `~/.defenseclaw`, `%USERPROFILE%\.defenseclaw` on Windows, or `DEFENSECLAW_HOME` when set.

| Path | What it is | Edit it? |
| --- | --- | --- |
| `config.yaml` | Your configuration. | Use `defenseclaw config set` or the setup commands. The gateway applies a valid edit and keeps the previous policy if an edit is invalid; run `defenseclaw config validate` first when you edit by hand. |
| `config.generation.json` | Generation, SHA-256, actor and time of each write to `config.yaml`. | No. |
| `custom-providers.json` | Custom LLM providers, derived from `llm_providers`. | No. `defenseclaw doctor --fix` regenerates it. |
| `config.yaml.v8.bak`, `migration-v9.json` | Kept by the `config_version` 9 migration. | Read them. `defenseclaw config migrate --ack` marks the record read. |
| `.env` | Protected tokens and API keys. | No. Never print it. Use `defenseclaw keys`. |
| `audit.db` | The local audit database (SQLite). | No. Do not open it with a second writer or attach it to a ticket. |
| `gateway.log` | The gateway's output. | Read it locally; check excerpts before sharing. |
| `logs/install-*.log` | One log per install, upgrade or rollback. | Read it. |
| `logs/hook-failures.jsonl` | Hook delivery failures. | Read it locally; it can hold sensitive details. |
| `.venv/` | The Python environment the installer manages. | No. |
| `previous/` | The install the last upgrade replaced. | No. `defenseclaw rollback` swaps it back. |
| `hooks/` | Generated hook files and per-connector credentials. | No. Never print or copy them. |
| `backups/`, `connector_backups/` | Copies needed to restore agent files and earlier settings, including `config.yaml.before-redaction-*`. | No. They can contain credentials. |
| `quarantine/` | Quarantined skills and plugins. | No. Use `defenseclaw skill restore` or `plugin restore`. |
| `gateway.pid`, `watchdog.pid` | Records of the running gateway and watchdog. | No. |
| `gateway.jsonl` | Exists only when an optional `kind: jsonl` destination explicitly uses that path. | Manage it through [observability](/docs/observability). |

## Doctor cache

`~/.defenseclaw/doctor_cache.json` is the latest non-dry-run Doctor snapshot. The TUI reads it for the Overview panel instead of repeating network probes on every redraw.

```json
{
  "schema_version": 2,
  "captured_at": "2026-04-17T18:21:09Z",
  "mode": "repair",
  "outcome": "failed",
  "exit_code": 1,
  "passed": 12,
  "failed": 0,
  "warned": 1,
  "skipped": 2,
  "summary": {"passed": 12, "failed": 0, "warned": 1, "skipped": 2},
  "checks": [
    {"status": "warn", "label": "Splunk HEC", "detail": "queue depth 4200/5000"}
  ],
  "repair_summary": {
    "planned": 0,
    "applied": 1,
    "failed": 0,
    "blocked": 1,
    "manual": 0,
    "noop": 0,
    "declined": 0,
    "requires_confirmation": 0
  },
  "repairs": [
    {"repair_id": "doctor.gateway.service.reconcile", "state": "blocked"}
  ]
}
```

The top-level and `summary` counts keep their health-only meaning; `repair_summary` and `repairs` form a separate ledger, so a failed or blocked repair can fail the aggregate outcome without raising the health failure count. The CLI publishes the cache atomically after each non-dry-run Doctor run, including nonzero outcomes; `doctor --fix --dry-run` never writes it. The TUI marks snapshots older than 15 minutes stale. A missing cache is normal before the first Doctor run.

## config.yaml schema

Every block is optional, and setup commands preserve comments and unrelated hand edits. Do not copy every default into the file.

Before validating this example, make `GALILEO_API_KEY` and `SPLUNK_ACCESS_TOKEN`
available to the validation process from your credential store. The Galileo and
Splunk destinations below require them. Omit those destinations if you do not use
them. Validation is read-only and refuses an unresolved credential reference.

```yaml
config_version: 9             # current schema; `defenseclaw migrate` rewrites a v8 file (the old file stays as config.yaml.v8.bak)

claw:
  mode: claudecode             # the primary connector; setup aliases select this with --connector.
                               # With several connectors active it names the primary one
                               # (see guardrail.connectors below). It is mirrored to the
                               # OTel resource attr `defenseclaw.claw.mode` only while a
                               # single connector is active.

gateway:
  host: 127.0.0.1              # upstream agent gateway host (OpenClaw/ZeptoClaw fleet link)
  port: 18789                  # upstream agent gateway port
  fleet_mode: auto             # auto | enabled | disabled: when to dial host:port (see below)
  api_port: 18970              # gateway REST API port (hooks + TUI dial this)
  api_bind: ""                 # REST API bind override; normally 127.0.0.1 when empty
  config_reload:
    mode: hot                  # hot | restart; omitted means hot
  watcher:                     # install watcher for new skills, plugins and MCP servers
    enabled: true
    skill:
      enabled: true
      take_action: true        # apply the admission actions (quarantine/block) to a rejected new skill; false = alert only
      dirs: []                 # non-empty replaces the connector's own skill folders
    plugin:
      enabled: true
      take_action: true        # same for new plugins (admission.plugin)
      dirs: []
    mcp:
      take_action: true        # block a rejected new MCP server in the connector's MCP config

# One observability graph owns collection, local history, routing, redaction,
# sampling, metrics policy and every destination (see Reference > Observability).
observability:
  resource:
    attributes:
      service.name: defenseclaw-gateway
      deployment.environment.name: production
  trace_policy:
    sampler: parentbased_always_on
    semantic_profile: defenseclaw-genai-rich-v1
  metric_policy:
    export_interval_seconds: 60
    temporality: delta
  local:
    path: ~/.defenseclaw/audit.db
    judge_bodies_path: ~/.defenseclaw/judge_bodies.db
    retention_days: 7          # default rolling window; larger values are deliberate overrides
  # Omit defaults/buckets for full-fidelity collection. List only deliberate
  # overrides; a route cannot resurrect a signal disabled at collection.
  buckets:
    diagnostic:
      collect: {logs: false, traces: false, metrics: false}
    model.io:
      redaction_profile: content
  redaction_profiles:
    soc:
      extends: sensitive
      detectors: [pii, credentials, secrets]
      field_classes:
        content: detect
        evidence: detect
        path: hash
        credential: remove
  destinations:
    - name: local-observability
      kind: otlp
      protocol: grpc
      endpoint: 127.0.0.1:4317
      network_safety: {allow_private_networks: true}
      # Omitted send/routes means every bucket and all OTLP capabilities:
      # logs, traces, and metrics. Profile resolves per bucket; model.io uses
      # content above and every other omitted bucket inherits none.
    - name: galileo
      kind: otlp
      preset: galileo
      protocol: http/protobuf
      endpoint: https://api.galileo.ai/otel/traces
      batch: { scheduled_delay_ms: 1000 }
      headers:
        Galileo-API-Key: {env: GALILEO_API_KEY}
        project: defenseclaw
        logstream: production
      # Keep send/routes omitted for the compiler-owned traces-only route whose
      # event_names equal the generated available Galileo family membership.
      # Explicit send/routes replace that filter and express operator intent.
    # More optional destinations join the same graph. Splunk HEC is logs-only.
    - name: org-splunk
      kind: splunk_hec
      endpoint: https://splunk.example.com/services/collector/event
      token_env: SPLUNK_ACCESS_TOKEN
      index: defenseclaw
      send:
        signals: [logs]
        buckets: [compliance.activity, security.finding, enforcement.action]
        redaction_profile: soc

# Top-level LLM block, written by `defenseclaw setup llm`. Every component
# without its own llm block reads it. `setup llm --role judge` writes
# guardrail.judge.llm instead; the role is a command option, not a key.
llm:
  provider: anthropic          # anthropic | openai | bedrock | vertex_ai | azure | custom
  model: claude-sonnet-4-6
  api_key_env: DEFENSECLAW_LLM_KEY
  base_url: ""                 # optional override; LiteLLM picks a default per provider. For an OpenAI-style provider (openai, openai-compatible, vllm, lm_studio) a bare host such as https://host gets /v1 added, so the judge, doctor and the scanners all call https://host/v1/chat/completions; a URL with a path is used as written
  instance_name: ""            # binds to an llm_providers.custom entry; required with provider: custom
  region: ""                   # generic regional hint (Bedrock / Vertex); provider-specific sub-blocks below take precedence
  # forward_custom_headers: copy inbound agent HTTP headers to the upstream LLM
  # provider (default on). A blocklist (proxy-hop, auth, host, X-DC-*,
  # X-DefenseClaw-*, W3C trace context), RFC 7230 validation and 64-header /
  # 32 KiB caps apply regardless.
  forward_custom_headers: true

  # Provider sub-blocks: only the one matching `provider` is consulted.
  bedrock:
    region: us-east-1
    auth_mode: iam_credentials # api_key | iam_credentials | profile | instance_role
    access_key_env: AWS_ACCESS_KEY_ID
    secret_key_env: AWS_SECRET_ACCESS_KEY
    session_token_env: AWS_SESSION_TOKEN
    profile_name: ""
    inference_profile: us.     # optional model-id prefix
    deployment_aliases: {}     # alias -> model-id, populated by --bedrock-deployment

  vertex:
    project_id: acme-prod-vertex
    region: us-central1
    auth_mode: service_account # service_account | adc | workload_identity
    service_account_json_env: GOOGLE_APPLICATION_CREDENTIALS

  azure:
    endpoint: https://my-resource.openai.azure.com
    api_version: "2024-10-21"
    auth_mode: api_key         # api_key | managed_identity
    deployment_aliases: {}     # model -> deployment, populated by --azure-deployment-alias

  # Inline TLS posture for self-signed or internal endpoints; doctor warns
  # when both are set.
  tls:
    ca_cert_pem: ""            # PEM bundle inlined from --tls-ca-cert-file
    insecure_skip_verify: false

# Optional semantic model classifier for proxy-mode OpenAI Chat Completions.
# Routing-only edits are validated by config reload but activate on gateway
# restart. Omit `remote` to run the pinned, loopback-only Docker sidecar.
routing:
  enabled: false
  version: "0.3.0"            # the only tested managed-sidecar contract
  port: 8080
  algorithm: static
  # remote: {endpoint: https://router.example.com}  # sends prompt content
  models:
    - name: fast              # classifier alias; unique within this catalog
      provider: openai
      model: gpt-5.4-mini
      base_url: https://api.openai.com
      api_key_env: OPENAI_API_KEY
      capabilities: [general]
  signals:
    keywords:
      - name: code-request
        keywords: [debug, implement, refactor]
        operator: OR
  decisions:
    - name: code
      priority: 100
      conditions: [{type: keyword, name: code-request}]
      model_refs: [fast]
    - name: default           # an unconditional decision is the fallback
      priority: 1
      model_refs: [fast]

guardrail:
  enabled: true
  connector: claudecode        # actively enforced connector
  mode: action                 # observe | action (default observe)
  scanner_mode: local          # local | remote | both (default both)
  rule_pack: default           # default | strict | permissive, or a guardrail.custom_packs name (guardrail use-pack)
  custom_packs: {}             # pack directories pinned by digest; `guardrail use-pack` adds an entry, for example:
  #   acme-hardened:           # select it with rule_pack: acme-hardened
  #     path: /etc/acme/defenseclaw/packs/acme-hardened
  #     digest: sha256:<64 hex digits of the pack files>
  rules:                       # layered on the selected pack in memory; no files are written
    protections: []            # built-in use-case packs, for example database-destruction-protection
    enable: []                 # rule IDs, as the pack spells them (SEC-AWS-KEY, exec.remote_ip_download_execute_same_artifact)
    disable: []
    severity_overrides: {}     # RULE-ID: CRITICAL | HIGH | MEDIUM | LOW (any case)
    suppressions: []           # {id, finding_pattern, entity_pattern, reason}
    sensitive_tools: []        # {name, result_inspection, judge_result, min_entities_for_alert}
  block_at: ""                 # CRITICAL | HIGH | MEDIUM | LOW; empty -> the rule pack's level
  alert_at: ""                 # same values; never above block_at
  cisco_trust_level: full      # full | advisory | none: how far a Cisco AI Defense verdict can escalate
  port: 4000                   # guardrail proxy port
  block_message: ""            # custom; empty -> default
  detection_strategy: regex_judge  # default; regex_only | regex_judge | judge_first
  detection_strategy_prompt: ""      # per-lane override; empty -> detection_strategy
  detection_strategy_completion: regex_only  # default for tool results and completions; regex_judge also sends them to the judge
  detection_strategy_tool_call: ""   # per-lane override; empty -> detection_strategy

  # judge.llm omitted: the judge inherits the top-level llm block.
  judge:
    enabled: false
    model: anthropic/claude-sonnet-4-6
    api_base: ""
    api_key_env: DEFENSECLAW_LLM_KEY
    llm: {}                    # same shape as top-level `llm:` above
    trace: false               # log judge prompts and responses (debugging); refused on a managed device

  hilt:
    enabled: false
    min_severity: HIGH         # CRITICAL, HIGH, MEDIUM or LOW, any case (empty: HIGH)

  # Multi-connector overlay: each key is a hook connector carrying a subset of
  # the guardrail knobs above; unset fields inherit guardrail.*. Proxy
  # connectors (openclaw, zeptoclaw) cannot appear here. Managed by
  # `defenseclaw setup <connector>` and `guardrail ... --connector X`.
  connectors:
    codex:
      enabled: true            # pointer field: omit = inherit (enabled); false = explicitly off
      mode: action             # observe | action; inherits guardrail.mode when unset
      hook_fail_mode: closed   # open | closed; inherits guardrail.hook_fail_mode
      block_message: ""        # custom; inherits guardrail.block_message
      rule_pack: strict        # inherits guardrail.rule_pack
      block_at: HIGH           # inherits guardrail.block_at, then the rule pack's level
      hilt:
        enabled: true
        min_severity: HIGH
    claudecode:
      mode: observe            # only logs; everything else inherits the global default

  # Identity-based profiles (see Guardrail profiles below); the strictest applies.
  profiles:
    contractors:
      mode: action
      block_at: MEDIUM
      hilt: {enabled: true, min_severity: HIGH}
  profile_assignments:        # the strictest applies; keys AND, values OR
    - profile: contractors
      match: {groups: ["contractors@corp.example.com"]}   # or "CORP\\Contractors" on Windows
  default_profile: ""          # "" keeps the guardrail.* settings above

ai_discovery:
  ide_inventory: all           # all | ai_only | off
  include_user_principal: false
  signature_packs: []          # pack files to load; only listed packs load (see the table below)
  trusted_ad_child_domains: []   # child AD domains whose users are verified on Linux

# What happens to a skill, MCP server or plugin by scan severity.
admission:
  defaults: {}                 # scan_on_install, allow_list_bypass_scan, actions, scanner_overrides, first_party_allow_list
  skill: {}                    # per-type overrides of the same keys
  mcp: {}
  plugin: {}

# The only block and allow list. `defenseclaw skill|mcp|plugin|tool block` writes here.
asset_policy:
  skill: {denied: [], allowed: []}
  mcp: {denied: [], allowed: []}
  plugin: {denied: [], allowed: []}
  tool: {denied: [], allowed: []}

# Scanner model (see Scanners below).
scanners:
  skill_scanner:
    policy: quiet              # quiet | strict | balanced | permissive | low-noise | custom
    fail_on_severity: HIGH     # the blocking gate
    review_queue_min: MEDIUM   # the warn band starts here
  mcp_scanner:
    analyzers: []              # [] = automatic

# Custom LLM providers; custom-providers.json is derived from this block.
llm_providers:
  custom: []
  ollama_ports: []

update:
  check: true                  # the once-a-day "new release available" notice
  channel: stable              # the only channel
  source: ""                   # "" = the official GitHub releases, else an https mirror

# Notifier webhooks remain separate from telemetry routing.
webhooks:
  - name: oncall-slack
    type: slack
    enabled: true
    url: https://hooks.slack.com/services/T000/B000/XXX
    # secret_env: WEBHOOK_HMAC_KEY   # optional HMAC key variable, for type: generic
    min_severity: HIGH
```

### Other top-level keys

Defaults from the loader. Omitted keys take these values.

| Key | Default | What it does |
| --- | --- | --- |
| `data_dir` | `~/.defenseclaw` | The data directory. `DEFENSECLAW_HOME` relocates it. Restart required. |
| `audit_db`, `judge_bodies_db` | `<data_dir>/audit.db`, `<data_dir>/judge_bodies.db` | The audit store and the retained judge bodies. |
| `quarantine_dir`, `plugin_dir`, `policy_dir` | `<data_dir>/quarantine`, `plugins`, `policies` | Quarantined files, connector plugins, policy assets. |
| `environment` | detected (`macos`, `windows`, `linux`, ...) | Stamped on every record. Restart required. |
| `tenant_id`, `workspace_id`, `discovery_source` | empty | Identity stamped on every record. Restart required. |
| `deployment_mode` | empty | `managed_enterprise` on a managed device. Restart required. |
| `claw.mode` | `openclaw` | The primary connector. With several active it names the first; the OTel attribute `defenseclaw.claw.mode` is set only while a single connector is active. |
| `claw.home_dir`, `claw.config_file` | `~/.openclaw`, `~/.openclaw/openclaw.json` | Where the OpenClaw install is looked up. |
| `claw.workspace_dir` | empty | Set by `setup <connector> --workspace`; scopes hooks to one folder ([Per-connector files](#per-connector-files)). |
| `gateway.host`, `gateway.port` | `127.0.0.1`, `18789` | The upstream agent gateway (OpenClaw and ZeptoClaw fleet link). |
| `gateway.fleet_mode` | `auto` | `auto`, `enabled` or `disabled`: when to dial `host:port` ([OpenClaw fleet link](#openclaw-fleet-link)). |
| `gateway.token_env` | `DEFENSECLAW_GATEWAY_TOKEN` | The variable that holds the sidecar API token ([Keys](/docs/reference/keys)). |
| `gateway.api_port`, `gateway.api_bind` | `18970`, empty | The sidecar REST API. Empty `api_bind` binds `127.0.0.1` ([Gateway API](/docs/reference/gateway-api#bind-address)). |
| `gateway.device_key_file` | `<data_dir>/device.key` | The device key. |
| `gateway.auto_approve_safe` | `false` | Auto-approve safe requests from the upstream gateway. |
| `gateway.reconnect_ms`, `gateway.max_reconnect_ms` | `800`, `15000` | Reconnect backoff to the upstream gateway. |
| `gateway.approval_timeout_s` | `30` | Seconds to wait for an approval. |

### Rule packs, rules and thresholds

These keys are allowed at the global level, in `guardrail.connectors.<connector>`,
in `guardrail.profiles.<profile>` and in a profile's connector entries. The
concept pages explain how they combine: [Rules](/docs/policies/rules) and

| --- | --- | --- |

| `guardrail.custom_packs.<name>` | none | A rule-pack directory pinned by digest: `path` and `digest` (`sha256:` plus 64 hex digits, printed by `defenseclaw guardrail validate-pack`). | `guardrail.cisco_trust_level` | `full` | How much a Cisco AI Defense verdict counts. `full`: as much as a local finding. `advisory`: a verdict that only Cisco AI Defense reached is downgraded to an alert, never a block. `none`: Cisco AI Defense results are ignored when choosing the action. |

tool calls, hook prompts, and proxy prompts, completions and tool calls alike.

`guardrail.connectors.<connector>`, the application protection overlay, the


names the pack, for example `(source: pack-default:default)`.

### Admission

`admission` decides what happens to a skill, MCP server or plugin by scan
severity. `admission.defaults` applies to every type; `admission.skill`,
`admission.mcp` and `admission.plugin` override it field by field. There is no
`admission.tool`: a tool is only blocked or allowed by name, in `asset_policy`.
The policy page explains the actions and the matching rules:
[Admission](/docs/policies/admission).

| Key | Default | Meaning |
| --- | --- | --- |
| `admission.<type>.scan_on_install` | `true` | Scan a new asset when it is installed. |
| `admission.<type>.allow_list_bypass_scan` | `true` | An asset on the allow list skips the scan. `false` scans it anyway. |
| `admission.<type>.actions.<severity>` | see below | One entry per severity: `critical`, `high`, `medium`, `low`, `info`. A shorthand (`block`, `quarantine`, `warn`, `allow`) or the exact triple `{install, file, runtime}`. |
| `admission.<type>.scanner_overrides.<scanner>` | `{}` | The same severity map for the findings of one scanner, keyed by its name (`skill-scanner`, `mcp-scanner`, `plugin-scanner`, `codeguard`, and the ClawShield names). VirusTotal and the other analyzers run inside the skill scanner, so they use the `skill-scanner` key. At most 32 scanners. |
| `admission.<type>.first_party_allow_list` | built in | Assets that count as first party: `{name, source_path_contains, reason}`, matched when the name is equal and the path contains one of the entries as whole path components. Unset inherits; an empty list clears it. |

The shorthands are `block` (do not install, runtime disable), `quarantine`
(do not install, quarantine the files, runtime disable), and `warn` and `allow`
(install, runtime enabled; they differ only in the verdict).

Each severity resolves in this order, first match wins: `admission.<type>`,
for skills the scanner gate (`scanners.skill_scanner.fail_on_severity` and
`review_queue_min`), `admission.defaults`, and the built-in policy. The
built-in policy quarantines `critical` and `high`, warns on `medium`, `low` and
`info`, except that balanced MCP servers warn on `high`, `medium` and `low` as
well. Secure Client keeps its separate admission actions. The built-in first-party lists name the `codeguard` skill and the
`defenseclaw` plugin. A severity nothing covers fails closed.

### Block and allow lists

`asset_policy` is the only block and allow list. `defenseclaw skill block`,
`mcp block`, `plugin block`, `tool block` and their `allow` and `unblock`
partners write `asset_policy.<type>.denied` and `allowed` through the config
writer, and the running gateway applies the change without a restart. On a
managed standalone device those commands are refused: add the entry to
`asset_policy` in the admin config. Quarantine, restore, disable and enable are
runtime state, not entries here.

| Key | Default | Meaning |
| --- | --- | --- |
| `asset_policy.skill.denied`, `allowed` | `[]` | Entries `{name, connector, reason, source_path_contains}`. An empty `connector` covers every connector. |
| `asset_policy.mcp.denied`, `allowed`, `asset_policy.plugin.denied`, `allowed` | `[]` | The same entries, plus the matchers `url`, `command`, `args_prefix` and `transport` for MCP servers. |
| `asset_policy.tool.denied`, `allowed` | `[]` | `{name, connector, reason}`. A tool is matched by name (and connector) when an agent calls it. |

The other `asset_policy` keys (`enabled`, `mode`, `default`, `registry`,
`registry_required`, `registry_empty_action` and `runtime_detection`) govern
deny-by-default and approved-catalog rules, not the explicit lists. They are
described in [Admission](/docs/policies/admission#enabled-and-mode) and
[Registries](/docs/scanning/registries).

### OpenClaw fleet link

The gateway dials the OpenClaw or ZeptoClaw gateway at `gateway.host` and `gateway.port` only when there is one to reach. `gateway.fleet_mode: enabled` always dials and `disabled` never does. With `auto`, the default:

- the `openclaw` and `zeptoclaw` connectors dial;
- `codex` and `claudecode` dial only when `gateway.host` is not loopback;
- every other connector, and an install with no connector, does not dial.

`claw.mode` defaults to `openclaw` for older configs, so an install that never picked a connector names OpenClaw without having it. When only that default names OpenClaw (`guardrail.connector` and `guardrail.connectors` are empty) and OpenClaw is not installed, the gateway and CLI resolve no agent connector; with a loopback `gateway.host` and `fleet_mode` unset or `auto`, the gateway does not dial. OpenClaw counts as installed when an `openclaw.json` exists at `claw.config_file` or in `claw.home_dir`, or an `openclaw` binary is on `PATH` or in `/usr/local/bin`, `/opt/homebrew/bin`, `~/.npm-global/bin` or `~/.local/bin`. Then `defenseclaw-gateway status` shows the Gateway subsystem `DISABLED` with `OpenClaw gateway off (OpenClaw is not installed)`, doctor reports `OpenClaw gateway: off (OpenClaw is not installed)`, the TUI and Mac app show the same text, and `OPENCLAW_GATEWAY_TOKEN` is not required. The gateway checks at start: restart it after installing OpenClaw, or set `fleet_mode: enabled`.

When `guardrail.connectors` lists agents, the active connector comes from that roster. An older `claw.mode` default does not add OpenClaw to it.

### Routing and observability behavior

The `routing` block affects OpenClaw and ZeptoClaw only on the proxy's OpenAI-compatible Chat Completions path. `defenseclaw keys list` discovers each non-empty `api_key_env`; the classifier never receives the key value. See [Semantic routing](/docs/guardrail/semantic-routing).

Omissions compile to an explicit effective policy; inspect it with `defenseclaw config show --effective --section observability` and `defenseclaw observability plan`. Destination kinds, buckets, routes and redaction are on [Observability](/docs/observability).

- With `observability: {}`, all 14 buckets collect logs, traces and metrics, local SQLite stores all collected logs unredacted, and no remote destination exists.
- An enabled destination without `send` or `routes` takes every bucket, every signal it supports, and profile `none`. A logs-only kind sends all logs; a general OTLP kind sends logs, traces and metrics. The Galileo preset generates one traces-only `capability-default` route restricted to its available family membership.
- An explicit `send` or `routes` block replaces the generated route. A selected nonmember of the Galileo family is rejected as `unsupported_shape` and reported through destination failure accounting.
- Destinations are independent fan-out legs; one failing does not stop another. For advanced routes the first matching route wins per destination and signal, and an unmatched record is not delivered. Selectors AND across fields and OR within one: `buckets`, `sources`, `connectors`, `actions`, `event_names`, `min_severity`. Collection happens first, so routing cannot recreate a disabled signal.
- Exactly one generated local SQLite destination is mandatory. It is configured only through `observability.local`, cannot be disabled or filtered, and keeps `retention_days` (default 7; `0` retains forever and warns about capacity). The same window bounds AI discovery history in `<data_dir>/inventory.db`.

### Destination transport and queue limits

| Limit | Value |
| --- | --- |
| Destinations | at most 64, names unique after canonical normalization |
| Advanced `routes` per destination | at most 256 |
| Queue (queue-backed destinations) | default 2,048 records and 67,108,864 bytes; bounds `1..65536` records and `4198400..268435456` bytes. JSONL and console accept only these queue fields |
| Batch (Splunk HEC, HTTP JSONL, OTLP) | default at most 512 records and 8,388,608 encoded bytes, 5,000 ms delay, 10,000 ms attempt timeout. Count `1..8192` and not above queue count; bytes `4263936..67108864`; delay `1..600000` ms. Galileo's omitted delay is 1,000 ms. Prometheus is pull-based and rejects `batch` |

When a queue overflows, the newest enqueue is dropped; older work, the mandatory SQLite store and sibling destinations stay intact. Transient or ambiguous acknowledgements retry the same immutable projection and record ID, so remote delivery is not exactly once.

### Config reload mode

`gateway.config_reload.mode` controls what happens after a valid change:

| Mode | Behavior |
| --- | --- |
| `hot` | Default. Reload, validate, diff and reconcile in the running gateway. |
| `restart` | Validate first, then use a fresh gateway process only for edits that cross a restart boundary (listener, topology, storage). Hot-reloadable fields, observability destinations included, still reconcile in process. A daemon launches `defenseclaw-gateway restart`; a service-supervised foreground run exits cleanly for its supervisor. Changing only this mode does not restart. |

In `hot` mode a change to a restart-required key is not rejected: the gateway keeps that key's running value, logs `[config] restart the gateway to apply <key>; the rest of the change applies now`, and applies everything else. The storage paths (`data_dir`, `observability.local.path`, `observability.local.judge_bodies_path`) and `deployment_mode` cannot be kept that way: the gateway refuses that reload, and every later one, until it restarts. `/health` shows `last_reload_error`, and an `/enforce` write answers `applied: false`. Changing `gateway.config_reload.mode` itself needs a restart.

The LLM block, regional Bedrock, Vertex and Azure backends and how doctor validates them are on [LLM providers](/docs/guardrail/unified-llm-key).

## OpenShell sandbox settings

The `openshell:` block configures NVIDIA OpenShell 0.1 sandboxes, the [`defenseclaw sandbox`](/docs/reference/sandbox-cli) commands. You rarely edit it by hand: `sandbox setup` writes `enabled`, `harnesses` and `upstream_telemetry`, `sandbox enable` and `disable` keep `wrappers` in step with your shell rc files, `sandbox policy allow` and `block` edit the egress lists, and "always" answers are saved to `egress.unblocked` or `egress.block`. Pack contents, layering and admin limits are on [Sandbox policy](/docs/sandboxes/policy-packs).

<Callout title="Where sandboxes run">
Sandboxes run on Linux and on Apple-silicon Macs, with the DefenseClaw and OpenShell gateways running as your own user. On a Mac they are OpenShell MicroVMs that mount no host folders, so `openshell.workdir.mode` is always `copy` there. A standalone `managed_enterprise` install runs them for each signed-in person under the policy in `openshell.admin` and each guardrail profile ([Sandboxes on managed computers](/docs/enterprise/sandboxes)). On Windows, an Intel Mac and a Secure Client profile `/health` reports the `sandbox` subsystem as `disabled`.
</Callout>

The selected sandbox policy pack supplies every default, the keys below override it, `sandbox run` options override those, and `openshell.admin` clamps the result. Keys the pack governs have no loader default, so an unset key follows the pack: `profile`, `yolo`, `workdir.mode`, `workdir.max_upload_mb`, `egress.ports`, `egress.large_upload_mb`, `egress.block_large_uploads`, `egress.feed` and `mcp.import`. The mask, unmask, block and allow lists add to the pack's lists. Some settings exist only in a pack: the approvals mode, the review list, `mcp.blocked_tools`, `mcp.project_servers`, `hooks.on_tamper`, and `hooks.on_silence` with `hooks.silence_after`.

```yaml
openshell:
  enabled: false               # true starts the sandbox runtime; sandbox setup sets it
  binary: openshell            # the upstream openshell CLI
  gateway:
    name: ""                   # OpenShell gateway registration; "" = the active one
    workspace: ""              # OpenShell workspace; "" = default
  ingress_port: 0              # sandbox hook ingress; 0 = gateway.api_port + 1
  egress_port: 0               # DefenseClaw egress proxy; 0 = gateway.api_port + 2
  pack: ""                     # "" = open; a built-in, a name under pack_dir, or an absolute path
  pack_dir: ~/.defenseclaw/policies/sandbox   # default <data_dir>/policies/sandbox; managed standalone: <policy_dir>/sandbox
  profile: ""                  # "" follows the pack; open | balanced | strict
  yolo: null                   # null follows the pack; true | false
  llm: auto                    # model credential a run shares; see below
  keep_headless: false         # true keeps a --prompt run's sandbox
  trusted_ca_bundle: ""        # PEM file of CAs sandboxes also trust (a TLS-inspecting proxy's root)
  workdir:
    mode: ""                   # "" follows the pack; mount | copy
    masks: []                  # secret-file globs added to the pack's masks
    unmask: []                 # project globs that stay visible despite a mask
    max_upload_mb: 0           # copy-mode size limit; 0 follows the pack
    git_depth: 200             # history depth of the copy-mode clone
    on_exit: ask               # ask | keep | undo
    undo_ignored:
      enabled: false           # true: undo restores these directories (Linux mount mode)
```

**Host patterns** in `egress.block`, `egress.allow`, `egress.unblocked`, `admin.egress_block`, `admin.egress_allow_only` and a pack's egress lists are a host name, `*.<host>` (every subdomain, not the host), an IP address, or a CIDR prefix such as `198.51.100.0/24`. Addresses compare by value, so `2001:db8::1`, its uncompressed spelling and an IPv4-mapped spelling match one entry. A bare `*`, schemes, ports, paths, wildcards inside a name, and host names whose last label does not start with a letter (`127.1`, `0x7f000001`) are refused. Matching ignores case and a trailing dot. Only `admin.egress_block` widens a host name (`example.net` blocks its subdomains too); every other list matches exactly. Lists hold at most 4096 entries.

**Project globs** (`workdir.masks`, `workdir.unmask`, `sandbox run --unmask`, a pack's masks) are relative to the project folder with forward slashes. Absolute paths, `~`, drive letters, backslashes and `..` are refused. Lists hold at most 1024 entries.

**Names** in `harnesses`, `wrappers`, `image.harness_versions` and `admin.allowed_harnesses` start with a letter or digit, then letters, digits, `.`, `_` and `-`, up to 128 characters. An `image.harness_versions` key cannot contain `.`.

Built-in packs, custom pack format and loading rules are on [Sandbox policy](/docs/sandboxes/policy-packs).

### Admin keys

`openshell.admin` holds the administrator's limits. Every key is optional; an unset key adds no limit, and the `allow_*` switches restrict only when `false`. Each is explained with examples on [Sandbox policy](/docs/sandboxes/policy-packs).

```yaml
openshell:
  admin:                     # every key is optional
    required_pack: ""        # its profile, yolo, workdir mode, MCP import, feeds and ports are floors
    required_pack_digest: "" # sha256:<hex> pins the required pack's content
    min_profile: ""          # strict > balanced > open
    allow_yolo: null         # null = no constraint; false forbids
    allow_mount: null
    allow_host_ports: null
    allow_unblock: null      # also governs approve-always, user allow entries, turning the feed off
    allow_learn_mode: null
    allowed_harnesses: [claudecode, codex]   # nonempty; leave the key out for no limit
    egress_block: []         # always blocked, never unblockable
    egress_allow_only: [api.example.com]     # nonempty; forces an allowlist profile
    block_large_uploads: false # true: every sandbox's large uploads to new hosts are cut
    require_copy_for: []     # absolute or ~/ path globs that must run in copy mode
    max_resources: {cpu: "", memory: ""}
    locked: []               # keys run options may not loosen
```

| Key | Values | Effect |
| --- | --- | --- |
| `required_pack` | Pack reference, like `pack` | Every run uses this pack, and its profile, skip-permissions default, workspace mode, MCP import, blocklist feed, and proxy ports are floors. |
| `required_pack_digest` | `sha256:` and 64 lowercase hex digits | Pins the required pack's content: the digest `defenseclaw sandbox pack show` reports. Needs `required_pack`. |
| `min_profile` | `open`, `balanced`, `strict` | The loosest profile allowed. |
| `allow_yolo` | `true`, `false`, `null` | `false` keeps every harness's permission prompts. |
| `allow_mount` | `true`, `false`, `null` | `false` forces copy mode and refuses every host folder mount. |
| `allow_host_ports` | `true`, `false`, `null` | `false` refuses every host port. |
| `allow_unblock` | `true`, `false`, `null` | `false` refuses unblocks and approve-always, ignores saved unblocks and the allow entries of users and of custom packs they chose, and keeps the blocklist feed on. A one-time approval then can't reach a feed-listed or private-network destination. |
| `allow_learn_mode` | `true`, `false`, `null` | `false` refuses learn mode. |
| `allowed_harnesses` | Harness names, at least one | Only these harnesses may run. Leave the key out for no limit: an empty list is refused. |
| `egress_block` | Host patterns | Always blocked, for every sandbox. Nothing unblocks or approves them. A host name also blocks its subdomains (`example.net` covers `www.example.net`). |
| `egress_allow_only` | Host patterns, at least one | Leave the key out for no limit: an empty list is refused. The only hosts any sandbox may reach. Raises the profile to at least `balanced`. Entries match exactly: list `*.<host>` for subdomains. |
| `block_large_uploads` | `true`, `false` | `true` turns the large-upload block on for every sandbox (see `egress.block_large_uploads`) and keeps its report on: a pack's `large_upload_mb: 0` gets 25 MiB, and a threshold above 25 MiB (a pack's or `egress.large_upload_mb`) is lowered to 25 MiB, or to the required pack's own when that is higher. An unblock still lifts it for one host unless `allow_unblock` is `false`. |
| `require_copy_for` | Path globs, at most 1024 | Projects that must run in copy mode. |
| `max_resources.cpu`, `max_resources.memory` | Same formats as `resources` | Ceilings for every sandbox. |
| `locked` | Up to 16 of `pack`, `profile`, `yolo`, `workdir.mode`, `workdir.unmask`, `mcp.import`, `mcp.host_ports`, `resources` | Keys whose configured value run options may not loosen. |

Every loosening `openshell.admin` refuses is reported as "blocked by your organization's DefenseClaw policy: `<key>`", and the same limits gate runtime actions such as unblocking a destination or opening a host port. In a `managed_enterprise` install the admin block is authoritative; elsewhere it is enforced but advisory, because you can edit the file. `sandbox policy explain` and `sandbox doctor` say which applies.

### Validation and reload

The configuration schema rejects unknown keys in every `openshell` block. DefenseClaw also
refuses to load a `config.yaml` whose `openshell` values break these rules:

- `ingress_port` and `egress_port` must differ when both are set;
- when `enabled` is `true`, the effective ingress and egress ports must differ
  from each other, from `gateway.api_port`, and from `guardrail.port`. A
  derived port that would pass 65535 (a `gateway.api_port` of 65534 or higher)
  must be set explicitly;
- enum values, port ranges, host patterns, globs, names, and CPU and memory
  quantities must be valid, and size and depth values must not be negative;
- `admin.required_pack_digest` must be a well-formed digest and needs
  `admin.required_pack`, and every `admin.locked` entry must be a lockable key.

The checks don't open pack files, so a missing or broken custom pack named in
`pack` or `admin.required_pack` isn't reported when the config loads.
`sandbox policy show` reports it, and so does the next `sandbox run`;
`sandbox pack validate` checks a pack file on its own.

The gateway reloads the `openshell` block in place, with either
`gateway.config_reload.mode`. A change that fails these checks is rejected,
and the running config stays in place. A reload re-resolves the egress policy
of every running sandbox, so changes to the egress keys, the large-upload
threshold included, reach them within seconds.
Turning `enabled` on or off, or moving `ingress_port` or
`egress_port` while `enabled` is `true`, restarts the API listener inside the
running gateway.

## `guardrail.connectors` (several connectors)

A single gateway can enforce guardrail policy for several **hook** connectors at once. Each connector that's active gets a `guardrail.connectors.<name>` block; the gateway resolves policy per connector and falls back to the global `guardrail.*` values for anything a block leaves unset.

| Per-connector key | Type | Inherits when unset |
| --- | --- | --- |
| `enabled` | bool pointer — omit = inherit (on); `false` = explicitly off (drops it from the active set, removes its hooks) | on |
| `mode` | `observe` \| `action` | `guardrail.mode` |
| `hook_fail_mode` | `open` \| `closed` | `guardrail.hook_fail_mode` |
| `block_message` | string | `guardrail.block_message` |
| `rule_pack` | a preset (`default`, `strict`, `permissive`) or a `guardrail.custom_packs` name | `guardrail.rule_pack` |
| `block_at` | `CRITICAL` \| `HIGH` \| `MEDIUM` \| `LOW` (any case) — lowest severity that blocks | `guardrail.block_at`, then the rule pack's level |
| `alert_at` | same values — lowest severity that alerts; never above the block level | `guardrail.alert_at`, then the rule pack's level |
| `hilt` | `{ enabled, min_severity }` | `guardrail.hilt` |


With more than one connector active, `claw.mode` and `guardrail.connector` keep naming the primary connector (the first in alphabetical order unless setup keeps the existing one), and the gateway leaves the OTel attribute `defenseclaw.claw.mode` off. Manage these blocks with `defenseclaw setup <connector>` (choose **Add**) and `defenseclaw guardrail ... --connector X` ([Multi-connector](/docs/guardrail/multi-connector)).

| `managed_hooks_only` | `enforce` \| `preserve` | `enforce` |
| `foreign_hooks` | `remove` \| `report` \| `allow` | `remove` |
| `higher_precedence_sources` | `fail` \| `warn` | `fail` |

The standalone lifecycle on Linux and macOS also requires `config_version: 9` (a `config_version: 8` file is migrated when it is applied),
`enterprise.profile: standalone` if you set it, and `data_dir` set to exactly

you set `gateway.api_bind` or `gateway.api_port`, they must be `127.0.0.1` and
`18970`. Connectors are enabled by `guardrail.connectors`, as in any other
config; see [Choose the agents to protect](/docs/enterprise/configuration#choose-the-agents-to-protect).

## Custom LLM providers (`llm_providers.custom`)

Custom-provider instances are defined once in `config.yaml` under `llm_providers.custom`, so the same instance definition can be shared across roles (agent, judge). A role selects one with `instance_name`; **the role wins and the instance fills blanks**. `defenseclaw setup provider add` writes these entries and `setup provider remove` deletes them; you can also edit `llm_providers` with `defenseclaw config set` or by hand.

```yaml
llm_providers:
  custom:
    - name: acme-internal-bedrock
      base_provider_type: bedrock
      base_url: https://llm.internal:8443
      domains: [llm.internal]
      env_keys: [ACME_BEDROCK_KEY]
      allowed_requests: [chat, embedding]
      available_models: [us.anthropic.claude-sonnet-4-6]
      request_path_overrides:
        chat: /openai/v1/chat/completions
      tls:
        ca_cert_file: /etc/acme/ca.pem       # a file, not inline PEM
        insecure_skip_verify: false
      bedrock:
        region: us-east-1
        auth_mode: iam_credentials
        access_key_env: AWS_ACCESS_KEY_ID
        secret_key_env: AWS_SECRET_ACCESS_KEY
        session_token_env: AWS_SESSION_TOKEN
        inference_profile: "us."
        deployment_aliases:
          fast: us.anthropic.claude-haiku-4-5-20251001-v1:0
  ollama_ports: [11434]
```

An entry carries only the sub-block (`bedrock`, `vertex` or `azure`) matching its `base_provider_type`; `defenseclaw doctor` warns about family mismatches and unknown `auth_mode` values. Auth modes are the same as on `setup llm` (`api_key` / `iam_credentials` / `profile` / `instance_role` for Bedrock; `service_account` / `adc` / `workload_identity` for Vertex; `api_key` / `managed_identity` for Azure). Other keys an entry accepts are `profile_id` (an OpenClaw auth-profile ID) and `extra_headers`. `ollama_ports` lists extra loopback ports to treat as Ollama.

The `domains` array drives the gateway's URL → instance lookup: when an inbound request URL (set on `X-DC-Target-URL` by fetch-interceptor agents, or recorded in the connector snapshot for native binaries) matches one of the listed hosts, the resolver applies this entry's TLS, `base_url` and sub-block posture. An entry that declares `base_url` should also list the matching host in `domains`.

A `custom-providers.json` marked `_derived_from` is rendered from this section on config writes. Do not edit it: the gateway does not read its edits back, `defenseclaw doctor` reports drift in the **Custom-provider overlay** row, and `defenseclaw doctor --fix` regenerates it. An unmarked overlay with `request_overrides` is a **live input** the gateway still merges ([Custom providers](/docs/reference/migrate-v9#custom-providers)).

## Environment variables

Every variable DefenseClaw reads, with defaults, is on [Environment variables](/docs/reference/env-vars). `DEFENSECLAW_HOME` relocates the data directory and `DEFENSECLAW_LLM_KEY` is the unified LLM key. On a managed standalone device some variables are ignored or may only tighten a setting ([Managed hosts](/docs/reference/env-vars#managed-hosts-and-the-environment)).

There is no `DEFENSECLAW_GATEWAY_BIND`, `DEFENSECLAW_DATA_DIR` or `DEFENSECLAW_LOG_LEVEL`. Configure the sidecar API with `gateway.api_bind` and `gateway.api_port`, the guardrail proxy with `guardrail.host` and `guardrail.port` (`gateway.host` and `gateway.port` are the upstream agent gateway). For extra diagnostics set a variable from [Debug / verbose logging](/docs/reference/env-vars#debug--verbose-logging), such as `DEFENSECLAW_SIDECAR_DIAG=1`, in the gateway's environment and restart it.

**Proxy variables.** The telemetry exporters (OTLP, Galileo, Splunk HEC, HTTP JSONL) follow `HTTPS_PROXY` and `NO_PROXY` from the gateway's environment; `enterprise.network.https_proxy` takes precedence, and loopback destinations connect directly. The proxy URL must be `http(s)://host[:port]`; with a user name or password the gateway logs a warning and the exporters connect directly. Restart the gateway from a shell that has the variables set. Whenever a proxy variable is set, the CLI and gateway add the instance-metadata endpoints (`169.254.169.254`, `169.254.170.2`, `fd00:ec2::254`) to `NO_PROXY`.

## Per-connector files

`defenseclaw setup <connector>` writes these agent-side files from `config.yaml`. They are derived: change the setting in `config.yaml`, not the file. Hook scripts under `~/.defenseclaw/hooks/` carry a `# defenseclaw-derived:` header. Doctor warns `stale generated script` when a script is from an older build or bakes a different fail mode, naming the command that regenerates it. A script edited by hand, or copied from another build, fails the `Hook runtime files` row (`changed since setup`) and its freshness row warns `a generated script is not the one setup rendered`; `defenseclaw doctor --fix` renders it again.

| Connector | File DefenseClaw mutates |
| --- | --- |
| OpenClaw | `~/.openclaw/openclaw.json`, `~/.openclaw/extensions/defenseclaw/` |
| ZeptoClaw | `~/.zeptoclaw/config.json` |
| Claude Code | `~/.claude/settings.json` |
| Codex | `~/.codex/config.toml` |
| Cursor | `~/.cursor/hooks.json` |
| Devin (Devin CLI and Devin Desktop's Devin Local) | `~/.config/devin/config.json` or `<workspace>/.devin/hooks.v1.json` |
| GitHub Copilot CLI | `~/.copilot/hooks/defenseclaw.json` by default; `<workspace>/.github/hooks/defenseclaw.json` with `--workspace` |
| Antigravity | `~/.gemini/config/hooks.json`; Google documents no configuration-home environment override, and DefenseClaw owns only this global registration. Antigravity also discovers `<workspace>/.agents/hooks.json`, which DefenseClaw does not patch to avoid duplicate ownership. |
| Hermes | `~/.hermes/config.yaml` on macOS/Linux or `%LOCALAPPDATA%\hermes\config.yaml` on native Windows (`$HERMES_HOME/config.yaml` when `HERMES_HOME` is set) |
| Kiro | `~/.kiro/hooks/defenseclaw.json` (Kiro IDE and `kiro-cli --v3`), `~/.kiro/agents/defenseclaw.json` (Kiro CLI 2.x) and `~/.kiro/settings/cli.json`; a workspace copy under `<workspace>/.kiro/hooks/` with `--workspace` |

Before the first mutation, a backup record is stored at `~/.defenseclaw/connector_backups/<connector>/<logical-name>.json`. It binds the connector, logical name and absolute target path, and holds the pristine bytes, permissions, pristine hash and post-setup hash. Teardown (or `--disable`) restores the pristine bytes only when the current file still matches the recorded identity; if it drifted, teardown removes only DefenseClaw-owned entries and keeps unrelated edits.

Hook connectors default to global scope. `claw.workspace_dir` is empty unless you pass `--workspace`; GitHub Copilot CLI then uses it for `.github/hooks/defenseclaw.json` and workspace-local component discovery. Re-run `defenseclaw setup <connector>` without `--workspace` to return to global scope. The workspace is one value for the whole install, so `setup <connector> --workspace` refuses while other connectors are configured; use `defenseclaw setup guardrail --workspace <dir>` to scope every connector to one folder.

Every hook setup writes the resolved path contract to `~/.defenseclaw/hook_contract_lock.json`. Its `locations` block records the pinned workspace, hook config file, generated script, and the MCP, skills, rules, plugins and agents surfaces DefenseClaw scans. `defenseclaw doctor` compares the lock against the files the active SDK can load.

## Reload without restart

A running gateway applies `config.yaml` changes by itself. One watcher sees the file (and the rule pack and Rego files it refers to), builds a new policy generation off the hot path and swaps it in atomically. A change that fails to build (an unknown rule ID, a pack whose digest no longer matches) keeps the old generation, shows `last_reload_error` in `/health`, fails the **Policy** row in `defenseclaw doctor` and records a `config.reload.rejected` event. Invalid YAML does the same, except that doctor stops at the **Config validation** row with the line and column and shows no **Policy** row until the file parses.

Only process-level keys need `defenseclaw-gateway restart`. A write that touches one prints the command, and the gateway keeps that key's running value until you restart it:

```text
Set guardrail.hook_self_heal (config generation 5, sha256 b0eecf44591d).
Effective policy digest: sha256:4254f65d36b3d7af4e4704a12570e2a4a1e0e5a4063a58d27a18953f5376a8f2
Restart the gateway to apply guardrail.hook_self_heal: defenseclaw-gateway restart
```

| Restart-required key | Why |
| --- | --- |
| `data_dir`, `observability.local.path`, `observability.local.judge_bodies_path` | Storage identity: the files the process opened at start |
| `gateway` (the listener, API port and credentials; except `gateway.watcher.*` and the `gateway.config_reload` keys other than `mode`) | The listeners and credentials the process owns |
| `guardrail.host`, `guardrail.port`, `guardrail.enabled`, `guardrail.connector`, `guardrail.scanner_mode`, `guardrail.retain_judge_bodies` | The guardrail listener, whether it runs, and start-up settings |
| `guardrail.hook_self_heal`, `guardrail.hook_self_heal_debounce_ms` | The hook guard |
| `claw`, `agent`, `routing`, `plugin_dir` | Paths, identity, the model router and the connector plugins, captured at start |
| `deployment_mode`, `enterprise.profile`, `enterprise.network`, `enterprise.openshell` | The deployment boundary |
| `fleet.enabled`, `fleet.mqtt_broker_url`, `fleet.mqtt_require_tls`, `fleet.ota_key_env`, `fleet.emergency_key_env`, `fleet.device_key_env`, `fleet.mqtt_user_env`, `fleet.mqtt_pass_env` | MQTT connections and signing keys |
| `environment`, `tenant_id`, `workspace_id`, `discovery_source` | Identity stamped on every record from start |

Every other key is hot, including `guardrail.mode`, `guardrail.hook_fail_mode`, thresholds, rule packs and rules, `admission`, `asset_policy`, `scanners`, `llm_providers`, `policy_dir`, `quarantine_dir`, `observability.destinations` and `update`. The effective policy digest is stamped on `/health`, `/status` and every decision event; `defenseclaw-gateway policy digest` computes it from the file on disk, and the **Policy** row of `defenseclaw doctor` compares it with what the gateway applied ([Policy generation and digest](/docs/reference/cli#policy-generation-and-digest)).

`defenseclaw-gateway policy reload` asks the running gateway to rebuild the generation now, for scripts and for assets the watcher may not see. Connector wiring (hook scripts, agent files) is not re-applied by a reload: run `defenseclaw-gateway restart` or `defenseclaw setup <connector>`. Both commands belong to the Go gateway binary; the Python CLI has no `gateway` group.
