Reference for the [Antigravity connector](/docs/connectors/antigravity). The connector is hook-only: Antigravity contacts its model provider directly, and its documented lifecycle hooks send local events to the authenticated DefenseClaw gateway. Google's [install page](https://antigravity.google/docs/cli/install) documents native `agy` clients for Windows, macOS and Linux, and its [CLI releases](https://github.com/google-antigravity/antigravity-cli/releases) list the current version.

## Install surface

### Platform status

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw installs the portable `antigravity-hook.sh` runtime and writes the five documented handlers to `~/.gemini/config/hooks.json`. |
| Native Windows x64 | **Supported** | The native x64 `agy.exe` client. A system Windows PowerShell launcher starts the protected `defenseclaw-hook.exe` for each registered event. Google's minimum is Windows 10 64-bit. Windows ARM64 is not supported. |

### Windows

The process chain is `agy.exe` → system Windows PowerShell 5.1 → `defenseclaw-hook.exe` → loopback gateway. The registered command uses `-EncodedCommand`, which keeps paths with spaces out of Antigravity's command tokenizer. The script starts `defenseclaw-hook.exe` with .NET `Process.Start`, passes stdin and stdout through, waits and exits with its status. Under Constrained Language mode (WDAC or AppLocker) it runs the binary with the call operator instead. Enforcement does not depend on the exit status.

The vendor installer (`irm https://antigravity.google/cli/install.ps1 | iex`) puts `agy.exe` under `%LOCALAPPDATA%\agy\bin` and verifies the manifest SHA-512. Authentication uses Windows Credential Manager for secure token profiles, with browser authentication as the fallback. DefenseClaw discovery accepts only the token-bound Known Folder form of this path, applies its trusted ACL boundary, and checks a stable no-follow SHA-512 across the version probe. It claims no vendor signer pin. Setup writes to `%USERPROFILE%\.gemini\config\hooks.json`. Google documents no configuration-home override. Setup keeps a predecessor custom path only as internal custody for exact restoration and migration. The contract lock is `%USERPROFILE%\.defenseclaw\hook_contract_lock.json`.

### Repair and doctor

`defenseclaw doctor` passively validates the exact five-event mixed schema and 30-second timeouts, each event's native `--event` binding, the protected `defenseclaw-hook.exe` PE target and contract lock, connector-scoped gateway authentication and runtime freshness, and stale, malformed, foreign, missing or inconsistent registrations. Doctor never executes command text read from `hooks.json`. Run `defenseclaw setup antigravity` again to repair, using the same guarded backup and rollback path as first setup. Teardown restores the pre-Setup file when unchanged. If you edited it, teardown removes only DefenseClaw's current and legacy commands, keeps other hooks, disables cached launchers and checks that no registration remains.

### Configuration boundary

Setup, repair and removal write only `~/.gemini/config/hooks.json`. MCP commands you run, such as `defenseclaw mcp set`, edit `~/.gemini/config/mcp_config.json`. DefenseClaw never edits `~/.gemini/settings.json`. It writes hooks only to the global file, to avoid duplicate global and workspace evaluation.

| Surface | Paths |
| --- | --- |
| Hooks and MCP | `~/.gemini/config/hooks.json`, `~/.gemini/config/mcp_config.json`, `<workspace>/.agents/hooks.json`, `<workspace>/.agents/mcp_config.json` |
| Agents, skills, plugins | `~/.gemini/config/agents`, `skills/<skill>/SKILL.md`, `plugins/<plugin>/rules`, and `<workspace>/.agents/{agents,skills,plugins,rules}` |
| Rules | `~/.gemini/GEMINI.md`, `<workspace>/.agents/rules`, legacy `<workspace>/.agent/rules`, plugin `rules/*.md`. Read from bounded, stable bytes without following links. |

Rules and agents (standalone and plugin-contained) are discovery-only. Enterprise, managed, Team, ProgramData, cloud-dashboard, MDM and organization policy surfaces are outside the connector contract and unverified.

### OpenShell sandbox

DefenseClaw builds an Antigravity overlay image. Nothing on your host changes.

| Item | Detail |
| --- | --- |
| Tier | User. agy reads global hooks from `~/.gemini/config/hooks.json`, and the reviewed 1.2.x build has no managed hook location. The image seeds the file and keeps a root-owned copy under `/usr/local/lib/defenseclaw/antigravity/`. The launcher restores it before every start, and refuses to start when the path is not a regular file. |
| Workspace hooks | agy also loads `<workspace>/.agents/hooks.json`. The launcher refuses to start when that file reuses a `defenseclaw-antigravity-*` key. Other workspace hooks load beside DefenseClaw's. |
| Fail closed | agy enforces only a synchronous `PreToolUse` `{"decision":"deny"}`. The sandbox hook prints it on every failure and names the reason: policy service unreachable or server error, refused request (HTTP 400), reply without a verdict, or missing binding token. |
| Known gaps | The agent can edit `hooks.json`, or start a second agy with another `HOME`, from a tool call. DefenseClaw sees that call first, and hook-silence detection is the backstop. Command rules judge `run_command` (in the directory its `Cwd` names) and `send_command_input` (as shell input). A script the agent writes and runs is judged by the command that starts it. |
| Install pin | agy 1.2.12 from the tarball Google's manifest names, checked against the manifest SHA-512, which DefenseClaw pins per architecture (arm64, x86_64). The build refuses a version without a pinned download or below `>=1.1.8`. |
| Model access | The `defenseclaw-gemini` provider profile sends `GEMINI_API_KEY` as `x-goog-api-key` to `generativelanguage.googleapis.com`. The launcher selects agy's `gemini` provider in `~/.gemini/antigravity-cli/settings.json`, and the key skips Google sign-in. Signing in with a Google account inside a sandbox is untested. |
| First-run screens | The image completes agy's onboarding: DefenseClaw accepts the [Google Antigravity CLI Terms of Service](https://antigravity.google/terms) on your behalf with data sharing off. The data-collection box is never ticked, `/settings` shows Enable Telemetry off, and the launcher trusts the working directory. A start without `GEMINI_API_KEY` still asks how to sign in. Delete `~/.gemini/antigravity-cli/cache/onboarding.json` in the sandbox to see the screens again. |
| Launch flags | Skip-permissions adds `--dangerously-skip-permissions`. `--safe` drops it in every form agy accepts. A headless run is `agy -p <prompt>`; pass `-- -p "TEXT"` to `sandbox run`. |
| Other traffic | Apart from the model, a mock run reached `antigravity-unleash.goog` (feature flags) and `play.googleapis.com` (usage logging). Enable Telemetry off does not stop either. The egress proxy logs both. Block them with `openshell.egress.block` if required. |
| Status | Verified end to end through the daemon on a Gemini-API mock: hooks reached the ingress with OpenShell substituting the key, a rule-blocked command was refused with the rule's reason passed to the model, and egress went through the proxy, including a blocklisted host that a sandbox-scoped unblock let through. The hook-fire probe also passed. A real Gemini key and a Google sign-in are untested. |

DefenseClaw's hook contract covers `agy` `>=1.1.8`. Google's [changelog](https://antigravity.google/changelog) records the changes that matter: v1.0.8 corrected the shared `~/.gemini/config/hooks.json` path, v1.0.10 made PowerShell the Windows default shell, v1.0.15 fixed Windows output, v1.1.1 fixed workspace hook loading, v1.1.7 stopped disabled plugins from running hooks, and v1.1.8 is the floor for the five-event contract. Later versions run as untested newer versions until a release changes the hook schema ([version policy](/docs/reference/apis/hook-contracts#version-policy)).

### Hook schema

All handlers are synchronous with a 30-second timeout. The event name is not in Antigravity's stdin, so DefenseClaw binds each registration to a trusted `--event` argument and forwards it to the gateway in a local header, without rewriting the stdin captured for audit.

| Event | Registration shape | Stdin beyond common metadata | DefenseClaw stdout |
| --- | --- | --- | --- |
| `PreInvocation` | direct handler list, matcher ignored | `invocationNum`, `initialNumSteps` | `{}` or `injectSteps` with `ephemeralMessage` |
| `PreToolUse` | matcher group with nested `hooks` | `toolCall{name,args}`, `stepIdx` | required `decision`; `deny` is the hard block |
| `PostToolUse` | matcher group with nested `hooks` | `stepIdx`, optional `error` | `{}` |
| `PostInvocation` | direct handler list, matcher ignored | `invocationNum`, `initialNumSteps` | `{}` or `injectSteps`; `terminationBehavior` is not used |
| `Stop` | direct handler list, matcher ignored | `executionNum`, `terminationReason`, `error`, `fullyIdle` | required `decision`; DefenseClaw uses `allow` |

Common stdin fields are `conversationId`, `workspacePaths`, `transcriptPath` and `artifactDirectoryPath`. The transcript roots are `~/.gemini/antigravity` (app) and `~/.gemini/antigravity-cli` (CLI). The on-disk registration mixes two schemas:

```json
{
  "defenseclaw-antigravity-pretooluse": {
    "PreToolUse": [
      { "matcher": "*", "hooks": [ { "type": "command", "command": "<event-bound native command>", "timeout": 30 } ] }
    ]
  },
  "defenseclaw-antigravity-stop": {
    "Stop": [ { "type": "command", "command": "<event-bound native command>", "timeout": 30 } ]
  }
}
```

Claude Code fields such as `systemMessage`, `additionalContext` and `permissionDecision` are not part of this connector's output.

## Verdict mapping

`observe` records policy findings without blocking on those findings. When the gateway is not running, a per-user install in the default or permissive policy lets `PreToolUse` run with one warning, and the strict policy and a managed install in the default fail mode `closed` deny it ([gateway outage table](/docs/reference/apis/capability-matrix#gateway-outage)). `action` may deny or ask on policy findings only at `PreToolUse`. The [official hooks documentation](https://antigravity.google/docs/hooks) defines `PreToolUse` as a synchronous pre-execution hook whose stdout carries one of `allow`, `deny`, `ask` or `force_ask` in `decision`. DefenseClaw sends `{ "decision": "deny", "reason": "policy denied" }` for a hard block and `{ "decision": "force_ask", "reason": "operator confirmation required" }` for native confirmation. This synchronous `PreToolUse` decision is the only hard-blocking claim for the connector.

## Native ask

Only `PreToolUse` supports native ask. DefenseClaw sends `force_ask`, which always prompts. It never sends `ask`, because `ask` honors a cached "Always Allow" grant and the call could run without a prompt. A headless `agy -p` run cannot prompt and denies the call; the audit log still records `confirm`. DefenseClaw does not claim the response overrides Antigravity's permission-bypass flags.

## Fail mode

Antigravity does not document non-zero hook exit status as enforcement, so DefenseClaw does not advertise connector-wide fail-closed support. A gateway that is not running follows the policy tier on a per-user install, as above. Every other failure, an authentication or decoding failure or an unusable answer, denies `PreToolUse` with `decision: "deny"`. On a managed host the administrator's fail mode decides an outage: `closed`, the default, denies it, and `open` gives the event's no-op answer. Antigravity itself may run a call when the hook times out or cannot start. A T7 stopped-hook drill blocked in its tested build, but that is not a vendor timeout-deny contract. Standalone status and verify warn `hook_process_fail_open` and set `security_complete: false` while Antigravity is enabled. Under Secure Client the hook stays open. Other events keep their documented non-blocking shapes. DefenseClaw does not claim it can override Antigravity's own permission bypass.

## Limits

- The only hard block is the synchronous `PreToolUse` `deny`. Non-zero exit status is not documented as enforcement.
- DefenseClaw does not claim it can override Antigravity's own permission bypass.
- Enterprise, managed, Team, ProgramData, cloud-dashboard, MDM and organization policy surfaces are outside the connector contract and unverified.
- Windows ARM64 is not supported.
