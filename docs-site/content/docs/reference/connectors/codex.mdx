Reference for the [Codex connector](/docs/connectors/codex). Codex talks to `api.openai.com` or the ChatGPT backend directly. DefenseClaw observes host activity through Codex's hooks. Isolated OpenShell images also use Codex's [native OpenTelemetry exporter](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry). Secure Client and the OpenShell sandbox use a notify bridge. Per-user and standalone installs on the host do not register a notify bridge or native exporter. No proxy is involved.

On a per-user install, an explicitly saved `guardrail.hook_fail_mode` takes precedence over the selected tier. See the [gateway outage table](/docs/reference/apis/capability-matrix#gateway-outage) and [Fail modes](/docs/reference/configuration/fail-modes).

### Platform status

| Platform | Status | Connector path |
| --- | --- | --- |
| macOS and Linux | **Supported** | Portable command hooks; native OTel only in isolated OpenShell. |
| Native Windows x64 | **Supported** | A system PowerShell bridge starts the protected `defenseclaw-hook.exe` for each registered event; host native OTel is disabled. |

### Setup details

Host setup removes earlier DefenseClaw native exporter blocks and revokes their scoped tokens because Codex cannot verify the account behind the loopback listener. An existing Codex process can retain the old configuration; quit and reopen Codex after an upgrade. The isolated OpenShell exporter still uses the gateway's `/v1/{logs,metrics,traces}` endpoints. Do not print or copy old exporter headers.

Redaction follows the v8 bucket and profile policy: edit `observability.destinations[].routes[].selector.buckets` and `observability.redaction_profiles`, then follow [Redaction](/docs/reference/observability/redaction/). The alias options are in the [quick-alias reference](/docs/reference/commands/guardrail-setup#aliases).

On native Windows, DefenseClaw writes each event and contract into `%CODEX_HOME%\config.toml` and marks the hooks trusted there, because Codex on Windows does not read hooks from `managed_config.toml`. The registered command runs system Windows PowerShell with `-EncodedCommand`, which starts `defenseclaw-hook.exe` synchronously with inherited handles and the bound `--event` and `--hook-contract`. No POSIX shell or WSL is involved. On managed Windows, the enumerator enrolls Codex installed with npm, the official `install.ps1` at its default location, or WinGet. A relocated `CODEX_HOME`, or another folder that discovery finds but cannot enroll, is reported as `agent_unprotected` ([Enrollment](/docs/enterprise/configure/enrollment/#how-users-and-agents-are-found)). Managed enrollment publishes hooks in `%ProgramData%\OpenAI\Codex\requirements.toml`. The per-user `managed_config.toml` is read only to clean up older registrations.

### Inventory surfaces

DefenseClaw follows Codex's own layouts, not Claude Code's `.mcp.json`.

| Asset | Sources |
| --- | --- |
| Skills | `.agents/skills` from the working directory to the repository root, `$HOME/.agents/skills`, and `$CODEX_HOME/skills` (`/etc/codex/skills` too on Unix). `CODEX_HOME` does not redirect personal `.agents/skills`. Children of `$CODEX_HOME/skills/.system` are vendor-bundled: listed but never scanned, blocked, disabled or quarantined. A `.system` folder elsewhere is not exempt. Linked or reparse-point roots are rejected. |
| MCP | `[mcp_servers.*]` in project `.codex/config.toml` layers, closest first, then `$CODEX_HOME/config.toml`. The exact URL-only `openaiDeveloperDocs` entry in the user config is vendor-bundled (`bundled: true`, never scanned). A same-named project entry or any added field is not exempt. Codex's generated `node_repl` stays scan-eligible. |
| Custom agents | `.toml` files in project `.codex/agents/` and `$CODEX_HOME/agents/`. Inventory checks the required `name`, `description` and `developer_instructions` fields without copying instruction text into the AIBOM. |
| Rules | `*.rules` under `rules/` beside each active config layer. |
| Memories | `$CODEX_HOME/memories/`. `$CODEX_HOME/history.jsonl` is a separate transcript-history file and is not reported as a memory store. |
| Plugins | Local `source.path` entries from repository and personal `.agents/plugins/marketplace.json`, the lower-precedence `.claude-plugin/marketplace.json`, and installed copies observed under `$CODEX_HOME/plugins/cache/`. Codex does not promise that cache layout, so Git, URL and npm sources are not claimed to land there. |

Codex activates project `.codex/` layers only for trusted projects. Inventory reports project entries as `trust_required` and does not infer the trust decision.

### OpenShell sandbox

`defenseclaw sandbox run codex` runs Codex in an OpenShell sandbox ([macOS](/docs/how-to/sandboxes/set-up-on-macos), [guide](/docs/how-to/sandboxes/run-an-agent)).

| Item | Detail |
| --- | --- |
| Tier | Managed. Hooks are in root-owned `/etc/codex/requirements.toml`, which pins `allow_managed_hooks_only` and `features.hooks` on. Root-owned `/etc/codex/managed_config.toml` turns off the update check, analytics and remote-reaching features, sends OTel to DefenseClaw, and pins `BASH_ENV`, `ENV` and the loader variables to empty. Hooks fail closed with a per-sandbox token that never goes on a command line. |
| Notify bridge | `managed_config.toml` sets `notify` to the root-owned `/usr/local/lib/defenseclaw/hooks/codex-notify.sh`. After each turn it posts Codex's turn JSON to the gateway's `/api/v1/codex/notify` with the per-sandbox token, which it reads from the environment, never from its command line. It only records and never blocks; an unreachable gateway is ignored. Codex passes the turn JSON as its argument, so processes in the sandbox can read it from the process list. |
| Startup tip | The Codex TUI fetches a tip from `raw.githubusercontent.com` around the egress proxy. OpenShell refuses it and triage rejects the drafted rule (`harness_background_fetch`). It is not counted as a blocked site. |
| Skip permissions | On by default (`open` and `balanced` packs): `--dangerously-bypass-approvals-and-sandbox`. `--safe` or the `strict` pack keeps approvals with `sandbox_mode="danger-full-access"` and `approval_policy="untrusted"`. A headless `--safe` run cannot ask and refuses those commands. `requirements.toml` refuses the `never` policy, and `--yolo`, `--full-auto` and `--ask-for-approval never` are dropped. |
| Sign-in | `--llm auto` shares `OPENAI_API_KEY` (or `CODEX_API_KEY`), or else the key `codex login --with-api-key` stored in `~/.codex/auth.json`. A ChatGPT sign-in is not shared. The sandbox gets a placeholder valid only at `api.openai.com`. `--llm bedrock`, and `auto` when neither is set, shares `AWS_BEARER_TOKEN_BEDROCK` for a custom provider on the Bedrock Mantle OpenAI route in `--bedrock-region`, with multi-agent and web search off. A Bedrock run uses `openai.gpt-5.5` unless you pass `-- -m MODEL`. |
| Per-sandbox settings | Each sandbox gets its own read-only `managed_config.toml` and `requirements.toml`. They pin the model provider and define the MCP servers brought from your setup. Unless the pack sets [`mcp.project_servers: allow`](/docs/reference/sandboxes/policy/), only those servers are allowed. `--no-mcp` leaves yours behind. |
| MCP gap | Codex matches an allowed server by command only and merges a repository's `[mcp_servers.<name>]` table key by key. DefenseClaw leaves such a server behind and names it at start. |
| Image | Codex 0.146.0 by default, replacing the base image's older one. A version without a reviewed Linux hook contract is refused. Verified against a mock model with hostile config, and in a live run that honored a deny with a Bedrock Mantle model. |

Each hook request must match the registered event and its stdin `hook_event_name`. The gateway also compares the event and contract ID with the protected contract lock and rejects mismatches or tampering. Controls marked v3/v4 need Codex `0.133` or later: v3 covers `0.133` to `0.144`, v4 covers `0.145` and later. They do not apply to v1 and v2.

## Verdict mapping

In action mode each event answers with its own official response.

| Event | DefenseClaw response |
| --- | --- |
| `SessionStart` (`>=0.133`) | `continue: false` ends the turn before another model request. The matcher includes `startup`, `resume`, `clear` and `compact`. |
| `PostToolUse` | `decision: "block"` cannot undo the finished tool. In interactive use the reason replaces the tool result fed to the next loop. In code mode the tool promise rejects. |
| `SubagentStop` (`>=0.133`) | `decision: "block"` continues the subagent flow. It does not end the subagent. |
| `PreCompact` (`>=0.133`) | `continue: false` stops before compaction. |
| `PostCompact` (`>=0.133`) | `continue: false` stops after compaction has completed. |
| `Stop` | `decision: "block"` prevents stopping and continues with the reason as a new prompt. |
| `SessionEnd` (`>=0.145`) | Observation only. Output cannot steer Codex, and the hook has a three-second host maximum. |

Codex loads a skill without a hook of its own. DefenseClaw refuses a skill on `asset_policy.skill.denied` when it is selected as `$name` and when a tool call reads its folder ([where a denied skill is refused](/docs/reference/scanning/admission/#where-a-denied-skill-is-refused)).

## Native ask

Codex has no native ask surface (Can ask is 0 on every contract). A confirm verdict is recorded and alerted with `raw_action` preserved. The TUI can review the event but cannot resume it.

## Fail mode

Fail closed when the running hook cannot reach the gateway: yes, except on a per-user install in the default and permissive policies, which lets the call run with one warning while the gateway is not running; the strict policy blocks it ([gateway outage table](/docs/reference/apis/capability-matrix#gateway-outage)). A managed administrator can select `open` for a gateway outage, and the managed default is `closed`. Codex itself treats a hook process failure or timeout as non-blocking. Setup registers `PreToolUse` with a 30-second timeout, but Codex has no reviewed on-timeout deny setting. A standard user who kills or stops the hook before it sends a request can make a tool run without a pre-tool audit row. Managed `status` and `verify` warn `hook_process_fail_open` and set `security_complete: false`; OS application control or EDR that protects the hook process is needed to prevent it. Settings and edge cases are in [Fail modes](/docs/reference/configuration/fail-modes).

When a hook fails closed because DefenseClaw cannot decide, `Stop`, `SubagentStop` and `SessionEnd` are not blocked. A blocked stop would only make Codex try again. Codex ends the turn, and the next prompt or tool call is blocked until the gateway is back ([Stop and session-end events](/docs/reference/configuration/fail-modes#stop-and-session-end-events)).

## Limits

- A `PostToolUse` block cannot undo the finished tool, and `SessionEnd` is observation only. A post-tool hook may still record a call after a missed `PreToolUse`, but it may itself be stopped or absent.
- Controls marked v3 or v4 need Codex 0.133 or later.
- Codex activates project `.codex/` layers only for trusted projects. Inventory reports project entries as `trust_required` and does not infer the trust decision.

### Troubleshooting details

| Symptom | Cause and fix |
| --- | --- |
| Hooks do nothing | `codex features disable hooks` (or `[features] hooks = false`). Run `codex features enable hooks`. |
| Codex refuses to load `config.toml` ("missing field command") | DefenseClaw `command` lines were deleted by hand, leaving `[[hooks.*]]` entries. The self-heal, `defenseclaw setup codex --yes` and `defenseclaw doctor --fix` restore them. To stop guarding Codex, run `defenseclaw guardrail disable --connector codex`. |
| Notify entry changed or deleted (Secure Client only) | Under Secure Client, the top-level `notify` entry is DefenseClaw's turn-complete bridge. The self-heal writes it back about a second later (500 ms debounce) or at the next 30-second check. A notifier you set yourself is kept and still run by the bridge. `defenseclaw doctor` warns on the **Codex notify** row when the gateway is stopped. |
| 401 right after rotating a model key | Codex's shared app-server daemon keeps the environment it started with. Run `codex app-server daemon restart` from a shell with the new key. DefenseClaw's hooks are not involved. |
| `doctor` warns about rejected OTLP attempts after an upgrade | The daemon keeps the old telemetry credential. Run `codex app-server daemon restart`. The **Native OTLP credentials** row clears 24 hours after the last refused attempt. |
| First prompt of a new session recorded twice | Codex 0.156 starts a second internal session during the first turn, with its own session id. It fires `SessionStart`, `UserPromptSubmit` and `Stop` for the same prompt. Two rows differ in `defenseclaw.session.root.id`. Count prompts by session and turn id. |
| Connections to OpenAI when the gateway starts (Windows) | Each gateway start or restart with the Codex connector enabled runs Codex's app-server once to read its effective requirements. It connects to OpenAI (for example chatgpt.com) and can reach your model provider. |
| Hooks fail after a Codex update (Windows) | Setup records the Codex executable's path and SHA-256. An update changes it, so doctor fails the **Hook contract** and **Codex hooks** rows with `policy-blocked: selected Codex executable no longer matches protected Setup evidence`. Run `defenseclaw setup codex --yes`. |

**Behind an HTTP proxy.** Hooks reach the gateway on 127.0.0.1 and ignore proxy variables. Managed Linux and macOS setup retains a marked `NO_PROXY` block for cloud instance metadata and container credentials. Host setup does not install a native exporter.
