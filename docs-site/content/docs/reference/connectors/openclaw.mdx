Reference for the [OpenClaw connector](/docs/connectors/openclaw). It is the only connector that ships a first-party plugin in this repository (`extensions/defenseclaw/`). The plugin owns the OpenClaw-side wiring. The gateway and CLI own everything else.

## Install surface

### Platform status

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw hosts the required guardrail proxy and installs the first-party plugin. Subprocess policy is shell shims on both. |
| Native Windows x64 | **Unsupported** | DefenseClaw is hook-only on Windows, while the OpenClaw connector requires the guardrail proxy. There is no supported WSL, Docker, VM or mixed workaround. |

### Setup defaults

`defenseclaw setup openclaw` is the dedicated alias. It delegates to the shared guardrail setup and exposes the common options, not every `setup guardrail` flag ([quick-alias reference](/docs/reference/commands/guardrail-setup#aliases), [full guardrail setup](/docs/features/guardrail)). The flags in the user page set the connector, mode, optional HITL and optional rule pack. Everything else uses the shipped defaults ([Defaults](/docs/reference/policy/defaults)).

| Knob | Value when omitted | Flag to override |
| --- | --- | --- |
| Scanner backend | `local` (bundled regex packs, no key) | `--scanner-mode local\|remote\|both` |
| Rule pack | unset, built-in baseline | `--rule-pack default\|strict\|permissive` |
| LLM judge | off (regex-only triage) | `--judge-model <model>` plus `--judge-api-key-env` |
| Detection strategy | `regex_judge` if the judge is on, else regex-only | `--detection-strategy regex_only\|regex_judge\|judge_first` |
| HITL | off | `--human-approval` plus `--hilt-min-severity` |
| HITL minimum severity | `HIGH` when `--human-approval` is on | `--hilt-min-severity low\|medium\|high\|critical` |
| Gateway outage | `closed`: no hooks, so a call is blocked while the gateway is down; `status`, the setup summary and `guardrail fail-mode` all show it | not configurable (`guardrail.hook_fail_mode` does not apply) |
| Proxy port | `4000` | `--port <int>` |
| Block message | empty (built-in copy) | `--block-message "<text>"` |
| Redaction | v8 bucket and profile policy (`none` for fresh v8) | Edit `observability.destinations[].routes[].selector.buckets` and `observability.redaction_profiles` ([Redaction](/docs/reference/observability/redaction/)) |

Recipes:

```bash
# Pilot: nothing blocks. Run for at least a week before promoting.
defenseclaw setup openclaw --mode observe --rule-pack permissive --restart

# Action with human approval. HIGH can pause for approval, CRITICAL still blocks.
defenseclaw setup openclaw --mode action --human-approval --hilt-min-severity high --restart

# Strict: block MEDIUM and above, alert on LOW.
defenseclaw policy activate strict
defenseclaw setup openclaw --mode action --rule-pack strict --restart
```

Human approval needs OpenClaw 2026.3.28 or later. The OpenClaw that `install.sh` installs (2026.3.24) has no plugin approvals, so setup refuses `--human-approval` there and changes nothing. Upgrade OpenClaw first (`npm install -g openclaw@2026.3.28` or later), or set up without human approval.

For a second-pass LLM judge, export a key and add `--detection-strategy regex_judge --judge-model <model> --judge-api-key-env DEFENSECLAW_LLM_KEY`. Latency and cost depend on the model.

#### Bedrock on OpenClaw 2026.5.12 and later

From 2026.5.12 OpenClaw no longer bundles the Amazon Bedrock provider. A Bedrock model in `openclaw.json` then needs the external plugin, or every model call fails with `No API provider registered for api: bedrock-converse-stream`. `defenseclaw setup openclaw` warns when the plugin is missing, disabled or not in `plugins.allow`.

```bash
openclaw plugins install @openclaw/amazon-bedrock-provider   # adds amazon-bedrock to plugins.allow
openclaw gateway restart
```

#### Bedrock through a VPC endpoint

When `bedrock-runtime.<region>.amazonaws.com` resolves to an AWS PrivateLink (VPC interface) endpoint, the proxy refuses the private address and every turn fails. The agent shows `DefenseClaw refused a private LLM endpoint; if you trust it, run: defenseclaw guardrail allow-private-upstream <host>`, and `defenseclaw doctor` warns with a **Private upstream** row. Allow the endpoint. The command restarts a running gateway.

```bash
defenseclaw guardrail allow-private-upstream bedrock-runtime.us-east-1.amazonaws.com
```

#### Gateway on another port

`defenseclaw setup openclaw` reads the OpenClaw gateway port from `openclaw.json` (`gateway.port`). If you onboard OpenClaw on another port later, run `defenseclaw setup openclaw` again or `defenseclaw setup gateway --port <port>`.

### Files

| What | Path |
| --- | --- |
| Allow and load entries | `~/.openclaw/openclaw.json` |
| Plugin | `~/.openclaw/extensions/defenseclaw/` (`openclaw.plugin.json`, `package.json`, `dist/index.js`) |
| Hook scripts | `~/.defenseclaw/hooks` |

DefenseClaw limits its OpenClaw-tree changes to `extensions/defenseclaw/` and its managed entries in `openclaw.json`. Backups are byte for byte and hash-checked. Teardown restores the file, or removes only DefenseClaw's entries when the file drifted.

Proxy connector: not gated by a hook contract version.

| --- | --- |

### Transport coverage

The plugin patches `globalThis.fetch`, Node `https.request`, `http.request` and `http.get`, the global Undici dispatcher, and the Undici copy OpenClaw ships. A matching request is redirected through the guardrail proxy.

| Transport | Redirected through the proxy when | Unclassified request |
| --- | --- | --- |
| `globalThis.fetch` | The destination is a known provider, or the method, path and readable body form a recognized LLM request shape. | Passes through and emits egress passthrough telemetry. |
| `https.request` | The destination is a known provider or its path has a recognized LLM suffix. | Passes through and emits egress passthrough telemetry. |
| `http.request` and `http.get` | Its non-safe destination has a recognized LLM path, including supported known or local-provider paths. | Passes through without guaranteed passthrough telemetry. |
| Undici global dispatcher | Its non-safe destination is a known provider or has a recognized LLM path. | Passes through without guaranteed passthrough telemetry. |
| Undici copy that OpenClaw ships | Same rule as the global dispatcher. OpenClaw sends model requests through an SSRF-guarded fetch that gives Undici a dispatcher of its own, which skips every layer above. | Passes through without guaranteed passthrough telemetry. |

Raw sockets, custom transports and libraries that bypass every patched entry point are outside the boundary. An egress event proves the plugin observed a transport branch, not that the request was proxied and inspected.

OpenClaw `>=2026.6.8` is the range that first required the Undici dispatcher layers. `defenseclaw doctor` fails the **OpenClaw interception** row when the plugin's sentinel self-test, which never leaves the host, cannot prove a rewrite onto the guardrail proxy, even if `/health` returns 200. The gateway pairs each model call OpenClaw completes with a proxy hop of its own. Doctor fails the row when the latest call took no hop, and warns when an earlier one did not but the calls after it did. Counts restart when `defenseclaw-gateway` restarts. If turns succeed while doctor says traffic is not intercepted, restart OpenClaw so the plugin reloads, then rerun doctor. Confirm a real `INCOMING REQUEST` delta in `gateway.log` only when that log can grow.

### Correlation headers

There is no `X-DefenseClaw-Correlation-Id` header. Depending on available context, plugin requests use `X-DefenseClaw-Run-Id`, `X-DefenseClaw-Session-Id`, `X-DefenseClaw-Trace-Id`, `X-DefenseClaw-Agent-Id`, `X-DefenseClaw-Agent-Name`, `X-DefenseClaw-Policy-Id`, `X-DefenseClaw-Agent-Instance-Id` and `X-DefenseClaw-Sidecar-Instance-Id`. The HTTP client identifies itself with `X-DefenseClaw-Client`. Optional fields are omitted when OpenClaw supplies no context. The fetch interceptor mints a fresh trace ID for each intercepted LLM call and reuses the most recent tool context for run and session attribution. The sidecar can echo sticky agent and sidecar instance IDs so later requests converge on the same identities.

### Protocol range

The gateway client speaks the OpenClaw WebSocket handshake across protocol v3 to v4. On connect it sends `minProtocol: 3` and `maxProtocol: 4`. OpenClaw returns the negotiated `hello-ok` protocol plus its supported methods and events. Protocol v4 installs work, and the v3 challenge-response device flow is kept for older endpoints.

## Verdict mapping

The gateway answers allow, alert, confirm or block. In action mode a block stops the tool and a confirm becomes OpenClaw's `requireApproval`. Allow and alert let the tool run. For model calls, the guardrail proxy checks the request before it forwards it and the response before it returns it.

## Native ask

For a `confirm` verdict in action mode the plugin returns OpenClaw's `requireApproval` object with `timeoutBehavior: "deny"`. OpenClaw applies the decision. The plugin's `onResolution` callback only logs it. It sends no separate "resolve approval" request to the gateway.

OpenClaw shows the request in its Control UI (`openclaw dashboard`) and on chat channels that forward `/approve`. `openclaw tui` and local `openclaw chat` do not show it, so a call that needs approval there is denied when the request times out (`gateway.approval_timeout_s`, 30 s by default). The plugin then logs `<tool> was denied: nobody answered its approval request` with where to answer, and setup with `--human-approval` and the doctor **Human approval** row say the same. OpenClaw is the only connector with plugin-mediated approval in its chat origin. Other native-ask connectors use their own host UI. See [Human approval](/docs/features/guardrail) for the per-connector matrix.

## Fail mode

OpenClaw is a proxy connector with no hooks. While the gateway is down, requests are blocked whatever `guardrail.hook_fail_mode` says. `guardrail fail-mode` lists it as `closed (proxy-backed, no hooks ...)`. See [Fail modes](/docs/reference/configuration/fail-modes).

## Limits

- Native Windows is unsupported: the connector needs the guardrail proxy, which DefenseClaw does not host on Windows.
- Raw sockets, custom transports and libraries that bypass every patched entry point are outside the boundary.
- OpenClaw does not run in an OpenShell sandbox. OpenShell support is pending in the [capability matrix](/docs/reference/apis/capability-matrix).

### Subprocess policy

The policy is `shims` on every platform. Setup installs PATH shims for `curl`, `wget`, `ssh`, `nc`, `pip` and `npm` that send each invocation to the gateway's tool-inspection endpoint before running the real binary. They inspect those command paths only and give no syscall, filesystem or network isolation.

OpenClaw does not run in an OpenShell sandbox. The legacy standalone sandbox that ran it as a separate Linux user was removed. A host that still carries it removes what it left by hand ([remove a retired standalone sandbox](/docs/how-to/sandboxes/run-an-agent/)). OpenShell support for OpenClaw is pending in the [capability matrix](/docs/reference/apis/capability-matrix).
