Every connector implements one Go interface, defined in [`internal/gateway/connector/connector.go`](https://github.com/cisco-ai-defense/defenseclaw/blob/main/internal/gateway/connector/connector.go). Each connector reports only the capabilities its agent offers, so proxy routing, hooks, subprocess wrapping, telemetry and approval support differ per agent. Use the [capability matrix](/docs/reference/apis/capability-matrix) to compare them and the [hook contracts](/docs/reference/apis/hook-contracts) page for supported agent versions.

## The interface

| Method | Runs | Purpose |
| --- | --- | --- |
| `Name`, `Description` | Always | Identify the connector. |
| `ToolInspectionMode`, `SubprocessPolicy` | Always | Report how tool calls are inspected and whether setup installs PATH shims. |
| `Setup` | When an agent is wired in | Back up the agent config and add DefenseClaw's hooks, plugin or provider entries. |
| `Teardown` | When an agent is taken out | Restore the config, or remove only DefenseClaw's entries. |
| `VerifyClean` | After `Teardown`, and before another connector's `Setup` | Fail with a list of leftover hooks, env files, config patches or shims. |
| `Authenticate` | On each request | Accept or refuse the caller. |
| `Route` | On each proxied LLM request | Read the request signals the proxy needs. |
| `SetCredentials` | At gateway boot | Give the connector the gateway token and master key. |

Two optional interfaces cover the rest. `HookEndpoint` lets a connector declare its hook route, for example `/api/v1/codex/hook`, which the gateway's API server registers when it starts. `NotifyEndpoint` does the same for an auxiliary notify bridge. Cursor and the other hook-only connectors share `hook_only.go`. Other connectors have a file of their own, such as `claudecode.go`, `codex.go` and `devin.go`.

## Hook and proxy paths

| | Hook connector | Proxy connector |
| --- | --- | --- |
| Data path | The agent talks to its upstream directly. | The agent's model calls go through the guardrail proxy (port 4000 by default). |
| Enforcement | Only the events the selected hook contract declares as blocking. | Request and response policy in the proxy, plus tool-call checks. |
| Several at once | Yes, each with its own posture under `guardrail.connectors.<name>`. | No. A proxy connector owns the traffic plane. |
| OS | Linux, macOS, Windows | Linux, macOS |
