Reference for the [Amp connector](/docs/connectors/amp). DefenseClaw installs a dependency-free TypeScript policy plugin into Amp's user plugin directory. Amp's docs call these system plugins, but they are per user, not machine-wide. The plugin sends `session.start`, `agent.start`, `tool.call`, `tool.result` and `agent.end` to the local gateway. Amp waits for `tool.call` before running the tool, and `tool.result` can replace unsafe output before the model sees it. Amp talks to its own model provider directly. See Amp's [manual](https://ampcode.com/manual) and [plugin API](https://ampcode.com/manual/plugin-api).

## Install surface

### Platform status

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | The policy plugin is installed in Amp's user plugin directory, `~/.config/amp/plugins`. |
| Native Windows x64 | **Supported** | `defenseclaw setup amp` installs the same plugin under `%USERPROFILE%\.config\amp\plugins` and limits it to your account with a user-only ACL. |

### Setup details

`--workspace` sets the workspace for the whole DefenseClaw install. It inventories
that repository's `.amp/settings.json` or `.jsonc`, `.amp/plugins`, skills, checks,
guidance, MCP servers and custom agents. If that change would move configured peer connectors
to a different scope, setup refuses and changes nothing. Use it on a single-Amp
install, or keep global protection with `defenseclaw setup amp` without `--workspace`.
Global setup governs tool calls and inventories user and managed surfaces.

The plugin is owner-only (private permissions, or the Windows user-only ACL) and
holds a connector-scoped token. Setup preserves an existing file, teardown restores
it, and a user-modified managed file is never silently removed. Connector removal refuses before saving while the bridge is modified;
preserve your edits, run `defenseclaw setup amp --yes --restart`, then retry removal.

Plugin lists, scans and the AIBOM treat the file as connector configuration. `defenseclaw plugin remove`, `disable`, `block` and `quarantine` refuse `defenseclaw --connector amp`, because Amp runs unguarded without it. The built-in `admission.plugin.first_party_allow_list` entry for `defenseclaw` matches the Amp bridge only at `.config/amp/plugins/defenseclaw.ts` ([first-party assets](/docs/reference/scanning/admission/#first-party-assets)).

Headless runs: `amp -x "your prompt" --plugin-ready-timeout 30`. Without the flag a turn can begin before plugins load. The three session and agent callbacks stay observe-only, and `defenseclaw doctor` reports this caveat.

Amp executes project and user plugin TypeScript, including top-level code, when each plugin loads. DefenseClaw does not sandbox, disable or govern that initialization. Amp does not define the order of handlers across plugins, so DefenseClaw cannot guarantee it sees another plugin's final input or that a sibling cannot change the outcome. In action mode `doctor` warns when it finds other `.ts` plugins. It never runs them and never removes them.

### Observability

Amp has no documented customer native-OTLP exporter and its plugin API gives no W3C `traceparent`. DefenseClaw produces canonical hook logs, metrics and spans from the five events, authenticated with the connector-scoped token. Correlation uses only IDs Amp reports: the thread ID, the `agent.start` message ID, and `toolUseID`. Agent 360 discovers `connector=amp` and shows sessions, turns, tools, outcomes, approvals and enforcement attempts. Galileo receives only canonical spans that satisfy the `galileo-rich-v2` profile. The plugin reports a custom agent's name, display label and declared model, or a built-in agent's mode, when available. That is not a stable agent ID, model request ID, trace context or parent link. Where a view needs an agent identity, DefenseClaw derives a per-session root identity and marks its lineage inferred. It never invents provider or model identity, request IDs, a trace parent or a parent-subagent link.

Amp and DefenseClaw must run on the same host with the gateway reachable over loopback. Amp Orbs run remotely, do not load a local plugin and are not covered.

### Enterprise standalone profile

The guardian writes the managed plugin into each enrolled user's `~/.config/amp/plugins/defenseclaw.ts` (or `%USERPROFILE%\.config\amp\plugins\defenseclaw.ts`) and repairs it when the user changes it. Amp has no machine-wide plugin location, so coverage is advisory against a user who sets out to avoid it.

- Amp loads plugins from the `amp/plugins` folder under `XDG_CONFIG_HOME` (default `~/.config`). A session started with `XDG_CONFIG_HOME` or `HOME` pointing elsewhere does not load the plugin (`amp plugins list` shows only Amp's own). Its tool calls are not inspected or logged, the guardian never repairs that session, and status and verify keep reporting the user's Amp ready. `DEFENSECLAW_*` overrides do not turn the plugin off.
- Amp does not define plugin order.

To reduce this, prefer agents DefenseClaw governs through machine policy (Claude Code, Codex, Cursor, GitHub Copilot, OpenCode), and use application control so users start Amp only through an administrator-owned launcher that resets `XDG_CONFIG_HOME` and `HOME`. See R1 and R3 in the [threat model](/docs/enterprise/plan/threat-model#residual-risks).

### OpenShell sandbox

Amp cannot run in a sandbox yet. The image is **unverified**, so `defenseclaw sandbox run amp` refuses it. Amp needs an account API key (`AMP_API_KEY`) for every run and stops at the account check before any agent turn. It has no local or bring-your-own model endpoint, so the mock-model check cannot pass. The unverified image stays (see the [Cursor note](/docs/reference/connectors/cursor#openshell-sandbox) on `image list` and `image prune`).

| Item | Detail |
| --- | --- |
| Tier | User. Amp loads plugins only from `~/.config/amp/plugins` and a project's `.amp/plugins`. The plugin lives in the image home (`/sandbox/.config/amp/plugins/defenseclaw.ts`), where the agent can edit it. The launcher points Amp at that home, drops variables that load other plugins or settings, and refuses `--settings-file`. DefenseClaw reports a sandbox whose hooks go silent. |
| Skip permissions | Would start with `--dangerously-allow-all`. `--safe` keeps prompts and drops it. |
| Sign-in | The account API key only. The `defenseclaw-amp` profile binds `AMP_API_KEY` to `ampcode.com` (not tested live). `sandbox run` has no `--llm` choice for Amp. |
| Image | Amp 0.0.1785334225-g9abe75, with the npm registry integrity and the native binary's SHA-256 checked. The plugin loads before any server call and fails closed. Hooks reaching DefenseClaw and blocking still need a run with a key. |

| Contract | Agent versions | Hook script | Events | Can block | Can ask |

| `amp-plugin-v1` | `>=0.0.1785334225` | `v2` | 5 | 2 | 2 |

| Contract | Events registered | Block events | Ask events |
| --- | --- | --- | --- |
| `amp-plugin-v1` | `session.start`, `agent.start`, `tool.call`, `tool.result`, `agent.end` | `tool.call`, `tool.result` | `tool.call`, `tool.result` |

| Fact | Value |
| --- | --- |
| Hook script | `amp-plugin.ts` |
| Hook config paths | `~/.config/amp/plugins/defenseclaw.ts`, `%USERPROFILE%\.config\amp\plugins\defenseclaw.ts` |
| Response field | `` |
| Native OTLP | no |
| W3C traceparent | no |
| Fail closed | yes |

The contract is `amp-plugin-v1`, plugin script `v2`. DefenseClaw pins the normalized Amp build `0.0.1785334225` as its contract snapshot and certification floor. Amp does not declare that build as the upstream minimum.

## Verdict mapping

| Amp event | DefenseClaw role | Enforcement |
| --- | --- | --- |
| `session.start` | Start thread and session correlation | Observe only |
| `agent.start` | Record the turn and prompt context | Observe only |
| `tool.call` | Inspect tool name and input before execution | Allow, reject or native confirm |
| `tool.result` | Inspect status and output after execution, before model delivery | Preserve, withhold or replace, or native confirm |
| `agent.end` | Close the turn and record its status | Observe only |

Amp documents no `session.end` and no separate subagent events. Oracle, Task launchers, MCP tools and plugin-defined tools are governed at their parent `tool.call`. If Amp emits events from a child thread, DefenseClaw enforces that child's calls under its thread ID and invents no parent-child edge. For a `confirm` decision, the plugin calls Amp's confirmation UI only when the thread is active in the foreground. Denial, a background thread or unavailable UI rejects a pending call or withholds a pending result. On a per-user install, gateway delivery failures follow the effective hook fail mode. Fail-closed applies once the plugin has loaded, and a killed or stopped check blocks the call.

## Native ask

Amp can ask in the active foreground thread during `tool.call` and before a `tool.result` reaches the model. Denial, a background thread or unavailable plugin UI rejects the call or withholds the result rather than allowing it silently.

## Fail mode

Fail closed: yes. On a per-user install, an invoked plugin in mode `closed` blocks supported calls on a gateway delivery failure; mode `open` can let an eligible call run. The unset mode is `closed` outside Secure Client. On a managed standalone host, the administrator's `open` applies only to a classified gateway outage; refusals and unusable answers block in every fail mode. With `foreign_hooks: remove` on Linux and macOS, During a classified gateway outage under administrator `open`, a gateway-backed guarded call can proceed only with fresh, trusted process and session records showing no block; otherwise it blocks. Windows Amp keeps a local guard record, and its managed plugin blocks a gateway outage in every fail mode, including with `foreign_hooks: report` or `allow`. Settings and edge cases are in [Fail modes](/docs/reference/configuration/fail-modes) and [Gateway outages](/docs/enterprise/configure/foreign-hook-guard#gateway-outages).

## Limits

- Amp documents no `session.end` and no separate subagent events.
- Amp does not define the order of handlers across plugins, so DefenseClaw cannot guarantee it sees another plugin's final input.
- Amp Orbs run remotely, load no local plugin and are not covered.
- Amp has no machine-wide plugin location, so enterprise coverage is advisory against a user who sets out to avoid it.
- Amp cannot run in an OpenShell sandbox yet.
