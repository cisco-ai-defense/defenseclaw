Reference for the [ZeptoClaw connector](/docs/connectors/zeptoclaw), the second proxy connector. DefenseClaw rewrites `~/.zeptoclaw/config.json` providers to point at the local guardrail proxy. Every request is inspected on its way out and every response on its way back.

## Install surface

### Platform status

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw hosts the required guardrail proxy. Subprocess policy is shell shims on both. |
| Native Windows x64 | **Unsupported** | ZeptoClaw publishes macOS and Linux builds, and the integration requires the guardrail proxy, which DefenseClaw does not host on Windows. There is no supported WSL, Docker, VM or mixed workaround. |

### Setup defaults

Before setup: no hook connector may be configured (ZeptoClaw is proxy-backed; setup refuses with "cannot run next to hook connectors" unless you pass `--replace`, which replaces them), and `~/.zeptoclaw/config.json` must define at least one provider (otherwise the gateway fails with `no usable providers found` and setup rolls back).

`defenseclaw setup zeptoclaw` is the dedicated alias. It delegates to the shared guardrail setup and exposes the common options, not every `setup guardrail` flag ([quick-alias reference](/docs/reference/commands/guardrail-setup#aliases), [full guardrail setup](/docs/features/guardrail)). The proxy is in the data path in both modes. Everything not set by a flag uses the shipped defaults ([Defaults](/docs/reference/policy/defaults)).

| Knob | Value when omitted | Flag to override |
| --- | --- | --- |
| Scanner backend | `local` (bundled regex packs, no key) | `--scanner-mode local\|remote\|both` |
| Rule pack | unset, built-in baseline | `--rule-pack default\|strict\|permissive` |
| LLM judge | off (regex-only triage) | `--judge-model <model>` plus `--judge-api-key-env` |
| Detection strategy | `regex_judge` if the judge is on, else regex-only | `--detection-strategy regex_only\|regex_judge\|judge_first` |
| HITL | off | `--human-approval` plus `--hilt-min-severity` |
| HITL minimum severity | `HIGH` when `--human-approval` is on | `--hilt-min-severity low\|medium\|high\|critical` |
| Hook fail mode | current config; `closed` on a fresh install | `defenseclaw guardrail fail-mode <open\|closed>` |
| Proxy port | `4000`, or the free port `init` chose when another account holds 4000 (it says so, for example 4090) | `--port <int>` |
| Block message | empty (built-in copy) | `--block-message "<text>"` |
| Redaction | v8 bucket and profile policy (`none` for fresh v8) | Edit `observability.destinations[].routes[].selector.buckets` and `observability.redaction_profiles` ([Redaction](/docs/reference/observability/redaction/)) |

```bash
# Pilot: nothing blocks. Run for at least a week before promoting.
defenseclaw setup zeptoclaw --mode observe --rule-pack permissive --restart

# Action with human approval. HIGH can produce a raw confirm action, CRITICAL still blocks.
defenseclaw setup zeptoclaw --mode action --human-approval --hilt-min-severity high --restart

# Strict: block MEDIUM and above, alert on LOW.
defenseclaw policy activate strict
defenseclaw setup zeptoclaw --mode action --rule-pack strict --restart
```

For a second-pass LLM judge, export a key and add `--detection-strategy regex_judge --judge-model <model> --judge-api-key-env DEFENSECLAW_LLM_KEY`. ZeptoClaw has no native ask, so a confirm takes its immediate fallback with `raw_action` preserved. The TUI and audit log can review it but cannot approve and resume it. See [Human approval](/docs/features/guardrail).

<Callout title="Treat local event history as sensitive data">
The mandatory database is configured by `observability.local` (by default `~/.defenseclaw/audit.db`) and retains seven days on a fresh configuration. Set `observability.local.retention_days` to the reviewed retention period and limit host access to the DefenseClaw data directory. A global `observability.defaults.redaction_profile` or a bucket `redaction_profile` also governs SQLite. A destination or route profile governs only that export trust boundary. Verify the effective result with `defenseclaw config show --effective --section observability` and `defenseclaw observability plan`. See [Redaction](/docs/reference/observability/redaction) and [Observability](/docs/features/observability/). Retention removes eligible rows and frees their pages for SQLite reuse, but the file does not shrink automatically.
</Callout>

On a fresh v8 configuration the local profile is `none`, so registered prompt, response, tool, path and identifier fields can stay full fidelity. A global or bucket profile can redact the local projection, and optional destinations receive their own projection.

### Files

| What | Path |
| --- | --- |
| Providers and private endpoints | `~/.zeptoclaw/config.json` (`providers.*.api_base`, `safety.allow_private_endpoints`) |
| Hook scripts | `~/.defenseclaw/hooks` |

`safety.allow_private_endpoints` is set to `true` so the rewritten `api_base` (a 127.0.0.1 URL) is accepted.

## Hook events

Proxy connector: not gated by a hook contract version.

## Verdict mapping

The guardrail proxy inspects every request on its way out and every response on its way back, in both modes. There are no hook events to map.

## Native ask

ZeptoClaw has no native ask surface. A confirm takes its immediate fallback with `raw_action` preserved. The TUI and audit log can review it but cannot approve and resume it.

## Fail mode

ZeptoClaw is a proxy connector with no hooks. While the gateway is down, requests are blocked whatever `guardrail.hook_fail_mode` says. See [Fail modes](/docs/reference/configuration/fail-modes).

## Limits

### Model limits

ZeptoClaw 0.9.2 sends `max_tokens` on its OpenAI-style chat requests. The Bedrock `gpt-5.6-luna` model refuses that parameter (HTTP 400, `unsupported_parameter`) and accepts `max_completion_tokens`, so a ZeptoClaw agent cannot use it through the Bedrock OpenAI route until ZeptoClaw sends the newer parameter. This is the model's and the agent's request shape, not a DefenseClaw block. Pick a model that accepts `max_tokens`, such as one served through an OpenAI-compatible route.

### Subprocess policy

The policy is `shims` on every platform. Setup installs seven PATH shims, for `curl`, `wget`, `ssh`, `nc`, `ncat` (a link to the `nc` shim), `pip` and `npm`, that send each invocation to the gateway's tool-inspection endpoint before running the real binary. They give no syscall, filesystem or network isolation. ZeptoClaw does not run in an OpenShell sandbox. Support is pending in the [capability matrix](/docs/reference/apis/capability-matrix).
