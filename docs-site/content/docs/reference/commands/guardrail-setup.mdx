`defenseclaw setup guardrail` sets the connector, mode, scanner, judge, human approval and rule pack, then restarts the gateway. Run it interactively the first time; re-run it with flags and `--non-interactive` for scripts and CI. To build a command in the browser, use the [command generator](/docs/how-to/agents/generate-a-setup-command).

```bash
defenseclaw setup guardrail \
  --non-interactive \
  --connector claudecode \
  --mode observe \
  --scanner-mode local \
  --detection-strategy regex_only \
  --restart
```

`--non-interactive` (aliases `--accept-defaults` and `--yes`) skips every prompt; missing flags fall back to the wizard defaults. The judge stays off until you pass `--judge-model`. The saved detection strategy defaults to `regex_judge`, but with the judge off only the regex lane runs.

## Prompt-flag mapping

Each row is one wizard prompt, with the default that Enter selects and the flag to use in scripts.

| Prompt (default) | Flag, or how to script it |
| --- | --- |
| **Which agent framework are you using?** *(first setup only; suggests an agent it finds)* | `--connector` / `--agent`: `claudecode`, `codex`, `cursor`, `devin`, `copilot`, `hermes`, `antigravity`, `opencode`, `amp`, `kiro`, `openclaw`, `zeptoclaw`. |
| **Enable guardrail?** *(Y)* | Implied by running setup. `--disable` turns the guardrail off. |
| **Select mode** *(observe on first setup, then the current mode)* | `--mode observe\|action`. `observe` records; `action` enforces. |
| **Hook failure behavior** *(`closed` on per-user installs)* | Per-user setup runs failed inspections closed. `--fail-mode open` is refused. A managed administrator may set outage-open in the managed config. |
| **Human approval for risky actions?** *(action mode only; current setting)* | `--human-approval` / `--no-human-approval`. |
| **Approval minimum severity** *(if HITL is on; HIGH)* | `--hilt-min-severity high\|medium\|low\|critical`, matched case-insensitively. |
| **Select engine** *(local)* | `--scanner-mode local\|remote\|both`. The wizard offers only local and remote; pass `both` to run the two together. |
| **API endpoint / API key env var name / Timeout** *(remote scanner only)* | `--cisco-endpoint`, `--cisco-api-key-env`, `--cisco-timeout-ms`. Defaults come from the existing `cisco_ai_defense` config. |
| **Add LLM judge on top of rule scanning?** *(action mode only; current setting)* | `--judge-model` turns the judge on. `--detection-strategy regex_only` turns it off; there is no `--no-judge` flag on this command. |
| **Use this LLM for the judge?** *(Y, when an LLM is already configured)* | `--judge-provider`, `--judge-model`, `--judge-api-key-env`; `--inherit-llm` or `--inherit-from guardrail\|scanners.skill\|scanners.mcp\|scanners.plugin` copies another LLM block. To start from the saved judge settings, use `defenseclaw setup llm --role judge --inherit-from guardrail.judge`. |
| **How should DefenseClaw use the LLM?** *(proxy connectors only)* | `--llm-role judge_only\|judge_and_agent`. Hook connectors always get `judge_only`; see [Hook-based vs proxy-based connectors](/docs/reference/configuration/llm-providers#hook-based-vs-proxy-based-connectors). |
| **Configure fallback models?** *(N)* | No flag. Set `guardrail.judge.fallbacks` (a list of model ids) in `~/.defenseclaw/config.yaml`. |
| **Configure advanced options?** *(N)* | Opens the next two prompts. |
| **Guardrail proxy port** *(4000)* | `--port`. Used by the proxy connectors; hook connectors bind no proxy. |
| **Use a custom block message?** *(action mode only)* | `--block-message`. |

For the remote Cisco AI Defense scanner, an unset or empty
`cisco_ai_defense.enabled_rules` sends no `config.enabled_rules` list; the AI
Defense connection's own policy applies. A nonempty operator list is sent in
the order configured.

On a multi-connector install, `--connector <name>` scopes this setup run to that
connector. When `--block-message` is passed without `--connector`, setup treats
it as broad operator intent: it updates the shared block message and reconciles
the active connector overrides, so no connector keeps stale block text.

<Callout type="warn">
Per-user hook failure behavior is closed. A managed administrator sets an outage-open choice in managed `config.yaml`. Judge fallback models live in `guardrail.judge.fallbacks` in `config.yaml`.
</Callout>

<Callout title="Redaction has its own workflow">
Telemetry redaction is configured per destination with `defenseclaw setup redaction`, not by this command. See [Redaction](/docs/reference/observability/redaction).
</Callout>

## Connector resolution

When you omit `--connector`, DefenseClaw resolves it in this order:

1. The `--connector` flag.
2. The `guardrail.connector` an earlier setup run saved.
3. The `<data_dir>/picked_connector` hint, written by `install.sh --connector ...` and by connector setup.
4. Otherwise pass `--connector`. The interactive wizard suggests an agent it finds on this machine; the non-interactive path does no detection.

## Recipes

<Tabs items={['Observe', 'Action', 'HITL', 'Judge', 'Bedrock judge']}>

<Tab value="Observe">

```bash
defenseclaw setup guardrail --non-interactive --connector claudecode --mode observe --scanner-mode local --restart
```

Findings go to the audit database. Nothing blocks.

</Tab>

<Tab value="Action">

```bash
defenseclaw setup guardrail --non-interactive --connector claudecode --mode action --scanner-mode local --rule-pack default --restart
```

With the `default` pack, CRITICAL blocks, HIGH and MEDIUM alert, LOW is allowed.

</Tab>

<Tab value="HITL">

```bash
defenseclaw setup guardrail --non-interactive --connector claudecode --mode action --rule-pack default \
  --human-approval --hilt-min-severity high --restart
```

HIGH findings are eligible for confirmation. CRITICAL still blocks. See [which agents can ask](/docs/features/guardrail#which-agents-can-ask).

</Tab>

<Tab value="Judge">

```bash
defenseclaw keys set DEFENSECLAW_LLM_KEY

defenseclaw setup guardrail --non-interactive --connector claudecode --mode action \
  --detection-strategy regex_judge \
  --judge-model anthropic/claude-sonnet-4-20250514 \
  --judge-api-key-env DEFENSECLAW_LLM_KEY --restart
```

Regex runs first and the judge adjudicates what regex flags. `--detection-strategy judge_first` flips the order. Hook connectors are judged only in action mode; `--judge-hook-connectors` chooses which. A judge verdict goes through `block_at` and `alert_at` like a rule finding.

</Tab>

<Tab value="Bedrock judge">

```bash
defenseclaw setup guardrail --non-interactive --connector claudecode --mode action \
  --detection-strategy regex_judge \
  --judge-provider bedrock \
  --judge-model us.anthropic.claude-sonnet-4-6 \
  --judge-bedrock-region us-east-1 \
  --judge-bedrock-auth-mode iam_credentials \
  --judge-bedrock-access-key-env AWS_ACCESS_KEY_ID \
  --judge-bedrock-secret-key-env AWS_SECRET_ACCESS_KEY \
  --judge-bedrock-inference-profile us. --restart
```

Use `--judge-provider vertex_ai` with the `--judge-vertex-*` flags, or `--judge-provider azure` with the `--judge-azure-*` flags. For a self-signed endpoint add `--judge-tls-ca-cert-file`. If the settings are already on a custom provider entry, `--judge-instance-name <name>` inherits them; role-level flags win field by field. See [LLM providers](/docs/reference/configuration/llm-providers/).

</Tab>

## Aliases

Each connector has a setup alias that runs `setup guardrail --connector <id>` with a smaller, connector-oriented flag set. The hook aliases start in observe mode and never proxy model traffic. OpenClaw and ZeptoClaw run the guardrail proxy regardless of mode.

| Agent | Id | Alias | Class |
| --- | --- | --- | --- |
| Claude Code | `claudecode` | `defenseclaw setup claude-code` | Hook |
| Codex | `codex` | `defenseclaw setup codex` | Hook |
| Cursor | `cursor` | `defenseclaw setup cursor` | Hook |
| Devin | `devin` | `defenseclaw setup devin` | Hook |
| GitHub Copilot CLI | `copilot` | `defenseclaw setup copilot` | Hook |
| Antigravity | `antigravity` | `defenseclaw setup antigravity` | Hook |
| Hermes | `hermes` | `defenseclaw setup hermes` | Hook |
| OpenCode | `opencode` | `defenseclaw setup opencode` | Hook (JS bridge) |
| Amp | `amp` | `defenseclaw setup amp` | Policy plugin |
| Kiro | `kiro` | `defenseclaw setup kiro` | Hook |
| OpenClaw | `openclaw` | `defenseclaw setup openclaw` | Proxy |
| ZeptoClaw | `zeptoclaw` | `defenseclaw setup zeptoclaw` | Proxy |

On a host with another connector already configured, an alias asks whether to **Add** the new connector or **Replace** the old one. Add is the default, also under `--yes`. Pass `--replace` to switch. Only the aliases add a connector to the roster: `setup guardrail --connector <name>` tunes a connector already on it and refuses one that is not, with `No changes made` and the alias that adds it. `defenseclaw setup remove <connector>` retires one.

An alias selects the connector, wires its hook or plugin, writes `config.yaml`, the connector roster and the `picked_connector` hint, and restarts the gateway unless `--no-restart`.

## Per-connector overrides

One gateway enforces several hook connectors. Each connector has an optional block under `guardrail.connectors.<name>` in `~/.defenseclaw/config.yaml`. An unset field inherits the global `guardrail.*` value, so a block carries only what differs. Proxy connectors (OpenClaw, ZeptoClaw) cannot be multi-connector peers: they own a proxy listener, so only one runs at a time.

```yaml title="~/.defenseclaw/config.yaml"
guardrail:
  enabled: true
  mode: action
  hook_fail_mode: closed
  rule_pack: default
  connectors:
    codex:
      mode: action
    claudecode:
      mode: observe
      hilt:
        enabled: true
        min_severity: HIGH
```

The fields you can override per connector mirror the global guardrail knobs:

| Field | Meaning | Inherits when unset |
| --- | --- | --- |
| `enabled` | Per-connector on/off switch (`guardrail disable --connector X`). Drops it from the active set and removes its hooks; re-enable restores it with no re-prompt. | enabled |
| `mode` | `observe` (log only) or `action` (enforce). | global `guardrail.mode` |
| `hook_fail_mode` | Per-user hooks run closed even if an older config saved `open`. A managed administrator may choose `open` for verified gateway connection outages; invalid or incomplete answers still block. | global `guardrail.hook_fail_mode` |
| `hilt` | `{ enabled, min_severity }` — per-connector human-in-the-loop policy. | global `guardrail.hilt` |
| `block_message` | Custom block text shown to this connector's agent. | global `guardrail.block_message` |
| `rule_pack` | The rule pack this connector scans against: a preset or a `guardrail.custom_packs` name. | global `guardrail.rule_pack` |
| `rules` | Rule customisation layered over this connector's pack: `protections`, `enable`, `disable`, `severity_overrides`, `suppressions`, `sensitive_tools`. See [Rules and custom packs](/docs/reference/policy/rules). | the global `guardrail.rules` only |
| `block_at` | Lowest severity that blocks: `CRITICAL`, `HIGH`, `MEDIUM` or `LOW`. | global `guardrail.block_at`, then the rule pack's level |
| `alert_at` | Lowest severity that alerts, same values; never above the block level. | global `guardrail.alert_at`, then the rule pack's level |


`claw.mode` and `guardrail.connector` name the active connector on a single-connector install. With several connectors they keep naming one primary connector: the existing one when you add a connector, otherwise the first name in sorted order. Read the full roster from `guardrail.connectors`, `defenseclaw status` or `defenseclaw guardrail status`. While more than one connector is active, the gateway leaves out the process-level `defenseclaw.claw.mode` resource attribute; use the per-event `connector` metric label or the `defenseclaw.connector.source` span attribute.

Set any override with `--connector`:

```bash
defenseclaw guardrail fail-mode closed --connector codex
defenseclaw guardrail hilt on --min-severity HIGH --connector claudecode
defenseclaw guardrail block-message "Codex policy blocked this" --connector codex
defenseclaw guardrail block-at CRITICAL --connector codex
defenseclaw guardrail use-pack strict --connector codex
defenseclaw guardrail rule disable CMD-REVSHELL-NC --connector codex
defenseclaw guardrail disable --connector codex
defenseclaw guardrail enable  --connector codex
```

`--connector X` writes only that connector's override. Unscoped writes are the broad path: `fail-mode`, `hilt` and `block-message` also reconcile active connector posture so an old override does not keep the old value. On a single-connector install `--connector` is rejected.

### CLI contract: read vs write

| Commands | Scope | How to narrow |
| --- | --- | --- |
| `defenseclaw status`, `defenseclaw doctor`, bare `defenseclaw guardrail status`, bare `guardrail fail-mode` / `hilt` / `block-message`, `skill list`, `mcp list`, `plugin list`, `tool list`, `tool status`, `codeguard status` | **Read — fans out to every active connector.** Identical layout whether one or N are wired. | `guardrail status --connector X`, `skill list --connector X`, `mcp list --connector X`, `plugin list --connector X`, `tool list --connector X`, and `tool status --connector X` narrow where supported. |
| `alerts` | **Read — recent decisions across connectors by default.** | `alerts --connector X` filters to events attributed to one connector. |
| `guardrail enable` / `disable` / `fail-mode` / `hilt` / `block-message` (with an argument) | **Guardrail write — scoped or broad.** `--connector X` writes one connector override. Omit `--connector` for the broad path: enable/disable is global; fail-mode, HITL, and block-message update active connector posture. | `--connector X` to target a specific connector. |
| `skill`, `mcp`, `plugin`, and `tool` policy verbs (`block`, `allow`, `unblock`, plus runtime verbs such as `disable` / `enable` where supported) | **Asset-policy write — broad fallback by default, connector-scoped when requested.** Bare writes apply across matching configured connector copies or the unscoped fallback tier for that asset family. | `--connector X` writes or clears only that connector's scoped state. |
| `mcp set` / `mcp unset`, `skill install`, `plugin remove`, `codeguard install` / `install-skill` | **Config/install write — all configured/active connectors by default.** | `--connector X` writes or removes only one connector's source. |
| `skill scan` / `mcp scan` / `plugin scan` / `aibom scan` | **Scan — configured/active connectors by default.** | Positional target and `--connector X` narrow where supported. |

### The firewall stays global

Per-connector policy is a guardrail concept. The egress firewall is not per-connector: DefenseClaw compiles one `firewall.yaml` into the host-wide pf/iptables filter and merges each active connector's allowed hosts into one allowlist at boot. Those rules see network attributes, not the connector label, so they cannot attribute a connection to one of several agents.

### Protected-file write proof

The write proof checks command text before a tool runs. It does not see what child programs write. A write inside a script, interpreter or shell built-in that the command only names cannot be fully checked from the command text. A rule that needs the complete action cannot block that inner write; an eligible rule about the complete outer argument list can still block the call in action mode. For protected files, use a sandbox or file permissions as an additional control.
