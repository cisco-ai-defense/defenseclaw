## Where CEL fits

<Flow
  direction="TB"
  caption="How a CEL rule turns a tool call into an action. Static tool block and allow lists are checked before this. If a CEL expression errors or runs out of budget, that rule falls back to its regex pattern."

The connector's authenticated hook route, or a trusted inspect call, decides that a request is a tool call. A payload cannot mark itself as structured. DefenseClaw parses the arguments into private `ActionFacts` and exposes them to CEL as one typed variable, `f`. Each rule takes exactly one route: its CEL expression when the arguments are fully parsed, or its own regex `pattern` when they are not. Both routes produce the finding defined in the YAML. A finding changes the action only when DefenseClaw's own code holds complete proof for that same rule ID and the connector can block. A regex match on its own is recorded as detection-only.
