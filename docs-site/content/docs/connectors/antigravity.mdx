DefenseClaw registers five hook handlers in Antigravity's global `hooks.json`. This is a hook connector: Antigravity talks to its model provider directly and no proxy is involved.

## Platform support

<ConnectorSupport id="antigravity" />

## Set up

On a new install, run `defenseclaw init --connector antigravity` first. Until DefenseClaw is initialized, `defenseclaw setup antigravity` stops with `DefenseClaw is not initialized — run 'defenseclaw init' first.`

Install `agy` from Google's [install guide](https://antigravity.google/docs/cli/install) and sign in. Then run:

```bash
agy --version
defenseclaw setup antigravity                 # first setup defaults to observe
defenseclaw setup antigravity --mode action   # deny or ask at PreToolUse
```

A re-run without `--mode` keeps the current mode. On Windows, run the same
commands in PowerShell. Sign-in still goes through Windows Credential Manager
or Google's browser flow.

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` passes the **Antigravity hooks** row.


## What it can block or ask

<HookEventsList connector="antigravity" />

- In action mode `PreToolUse` can deny a tool call or ask you first, using Antigravity's own `decision` field. The ask always prompts, even when you chose "Always Allow" before.
- `PreInvocation` and `PostInvocation` can only add context. `PostToolUse` only observes. `Stop` is always allowed.
- Observe mode records policy findings without blocking on those findings. When the gateway is not running, the default and permissive policies let the call run with one warning and strict denies `PreToolUse`; every other hook failure denies it ([gateway outage table](/docs/reference/apis/capability-matrix#gateway-outage)).

## Files it changes

| What | Where |
| --- | --- |
| Hook registrations | `~/.gemini/config/hooks.json` (Windows: `%USERPROFILE%\.gemini\config\hooks.json`) |
| Hook program, macOS and Linux | `~/.defenseclaw/hooks/antigravity-hook.sh` |
| Hook program, Windows | `defenseclaw-hook.exe` through a system PowerShell launcher |
| Contract lock | `~/.defenseclaw/hook_contract_lock.json` |

Setup backs up `hooks.json` and keeps unrelated hooks. It writes only the global file, never the workspace one.

## Limits

- Only the synchronous `PreToolUse` decision is a hard block. Antigravity does not document a non-zero hook exit as enforcement, so there is no connector-wide fail-closed. In fail mode `closed`, the default, a gateway failure denies `PreToolUse`; Antigravity itself still runs a call when the hook times out or cannot start.
- DefenseClaw cannot override Antigravity's own permission bypass.
- Windows ARM64 is not supported.
- Enterprise, Team and organization policy surfaces are outside this connector.

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

With the default gateway restart, disabling removes DefenseClaw's hook
registrations from Antigravity's global file and preserves your other
Antigravity settings. `defenseclaw guardrail enable` restores DefenseClaw's
hooks. To remove the connector, run
`defenseclaw setup remove antigravity --yes` (add `--force` if it is the last
one).

On a multi-connector install, add `--connector antigravity` to `guardrail disable` and `guardrail enable` to change only this agent.
