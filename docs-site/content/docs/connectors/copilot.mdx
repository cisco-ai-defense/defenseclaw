The GitHub Copilot CLI connector wires DefenseClaw into [Copilot CLI hooks](https://docs.github.com/copilot/) globally under `~/.copilot/hooks/` by default, with an optional workspace mode for `<workspace>/.github/hooks/`. Native ask is supported on `preToolUse`, so HITL approvals surface inside the agent UI.

## Platform support

| Platform | Status | Connector path |
| --- | --- | --- |
| macOS and Linux | **Supported** | Global or workspace command hooks using the portable DefenseClaw hook. |
| Native Windows x64 | **Supported** | Copilot's official `powershell` hook field synchronously invokes the protected `defenseclaw-hook.exe`; `preToolUse` supports native ask. Provider authentication is required. Not yet tested against the official client. |

## Setup

<Tabs items={['macOS / Linux', 'Windows']}>
  <Tab value="macOS / Linux">

```bash
defenseclaw setup copilot
defenseclaw setup copilot --workspace /path/to/repo
```

DefenseClaw writes the global hook by default. Pass `--workspace` only when the
repository should carry its own `.github/hooks/defenseclaw.json` file.

  </Tab>
  <Tab value="Windows">

```powershell
defenseclaw setup copilot
defenseclaw setup copilot --workspace 'C:\path\to\repo'
```

Copilot selects the registration's official `powershell` field. That field
starts the stable `defenseclaw-hook.exe` synchronously with inherited
stdin/stdout, waits for completion, and propagates its exit code. DefenseClaw
does not require Bash or WSL. Normal GitHub provider login is still required;
WSL, Git Bash, Cygwin, MSYS, Docker, and VM workarounds are outside the native
connector path.

  </Tab>
</Tabs>

By default this is **global/user-scoped**: DefenseClaw writes hook entries into `~/.copilot/hooks/defenseclaw.json`. Pass `--workspace /path/to/repo` only when you intentionally want repo-local `<workspace>/.github/hooks/defenseclaw.json` wiring. **There is no proxy-enforcement path** for Copilot CLI — blocking happens hook-side only through the documented `preToolUse`, `permissionRequest`, `agentStop`, and `subagentStop` responses. `postToolUseFailure` is advisory-only and can add recovery context after the tool has already failed. Native ask is supported on `preToolUse`, so HITL approvals surface inside the agent UI for that surface.

`setup copilot` is the Copilot alias for the shared guardrail setup. It
defaults to observe mode and can join an existing hook-connector roster when
you choose **Add**.

- For the alias flags, see [shared alias flags](/docs/setup/guardrail/aliases#shared-flags).
- For recipes, the wizard, the judge and the full flag list, see [Guardrail setup](/docs/setup/guardrail).

Copilot-specific differences:

- `--workspace` (or `--workspace-dir`) opts into repo-local `.github/hooks`.
  Without it, setup writes the global `~/.copilot/hooks` and clears
  `claw.workspace_dir`.
- If `COPILOT_HOME` is set, DefenseClaw uses that official Copilot
  configuration root instead of `~/.copilot` for hooks, MCP, skills, and
  agents.
- With `--mode action --human-approval`, `preToolUse` shows a native ask for an
  eligible confirm verdict. Confirm findings on other events use a
  non-pausing audit and alert fallback.
- Copilot has no fail-closed hook transport. `--fail-mode closed`, missing
  auth, timeouts, and malformed responses cannot make an unavailable hook
  block the agent.
- The gateway requires the exact event-specific registration header and never
  infers the Copilot event from stdin fields.
- To add the LLM judge, run `defenseclaw setup guardrail --connector copilot`
  with `--detection-strategy regex_judge --judge-model <provider/model>
  --judge-api-key-env DEFENSECLAW_LLM_KEY --judge-hook-connectors copilot`.

<Callout type="warning">
Global setup is the default because DefenseClaw is intended to govern the operator environment, not one repo at a time. Use `--workspace` only for a repository that must carry its own hook file.
</Callout>

### Inventory surfaces

With an explicitly pinned workspace, inventory follows Copilot's documented
precedence instead of the DefenseClaw daemon's current directory.

- **Agents.** DefenseClaw reads `.github/agents` and `.claude/agents` at each
  ancestor through the Git root. Only `.md` and `.agent.md` files are agents,
  with the full suffix removed for identity. The Copilot CLI 1.0.77 built-in
  agent IDs are inventoried as immutable rows, and local custom files cannot
  shadow them.
- **Agent order.** GitHub's custom-agent reference and plugin-reference
  diagram disagree about load order. DefenseClaw follows the custom-agent
  reference: project and ancestor first, `.github` before `.claude` at each
  level.
- **MCP servers.** Inventory reads `.mcp.json` and `.github/mcp.json` at each
  ancestor, then the personal `mcp-config.json`, preserving name precedence.
  Workspace MCP needs folder trust, or
  `GITHUB_COPILOT_PROMPT_MODE_WORKSPACE_MCP=true` in untrusted prompt mode.
- **Skills.** Inventory covers the immediate `.github`, `.agents`, and
  `.claude` locations, inherited parent `.github/skills`, personal
  `~/.agents/skills`, and `COPILOT_SKILLS_DIRS` entries.
- **Plugins.** Read-only plugin inventory uses
  `copilot plugins list --kind plugin --json`. DefenseClaw does not use it to
  install, enable, disable, or remove plugins.

These are declarations, not proof of live activation. Plugin-contributed,
built-in, organization, and remote agents, skills, and MCP servers are not
expanded from private or remote stores.

## Hook capabilities

<HookEventsList connector="copilot" />

<Callout type="info">
Copilot CLI supports native ask on documented `preToolUse` hooks. The approval prompt surfaces inside the agent UI, not the DefenseClaw TUI.
</Callout>

On native Windows, Copilot selects the hook's official `powershell` field.
DefenseClaw's prepared contract invokes a managed `copilot-hook.ps1`
byte-stream adapter. The adapter reads Copilot's JSON from console stdin,
launches the stable `defenseclaw-hook.exe` runtime without a console and with
explicitly redirected standard handles, waits for completion, and writes the
runtime's decision back to Copilot unchanged. It normalizes Windows
PowerShell 5.1's leading encoding marker and uses UTF-8 without a BOM for the
child streams. It does not require Bash or WSL.

Copilot documents optional OpenTelemetry traces and metrics. DefenseClaw does
**not** configure that native exporter: no Copilot OTel environment variables or native-exporter
credentials are written. Connector telemetry remains derived from
authenticated hook events and then flows through the ordinary DefenseClaw v8
audit, alert, webhook, and configured export destinations.

<Callout type="warn">
GitHub's Copilot CLI 1.0.76 release notes state that per-path sandbox denials cannot be enforced on Windows. Hook enforcement remains event-specific; do not treat Copilot's Windows sandbox as per-path filesystem containment.
</Callout>

## In an OpenShell sandbox

`defenseclaw sandbox run copilot` runs GitHub Copilot CLI in an NVIDIA
OpenShell sandbox on Linux, or on a Mac with Apple silicon in a MicroVM of its
own that works on a copy of your folder ([macOS](/docs/setup/sandbox#macos)):
the agent sees only your project folder, and DefenseClaw hooks gate every tool
call. The
[sandbox guide](/docs/setup/sandbox) covers setup, the session and every flag.
The first run builds the Copilot CLI image;
`defenseclaw sandbox image build copilot` builds it ahead of time.
`defenseclaw sandbox setup` builds the images of the harnesses in
`openshell.harnesses` (Claude Code and Codex by default), and its `--harness`
replaces that list, so name every harness you want:
`defenseclaw sandbox setup --harness claudecode --harness codex --harness copilot`.

- **Managed tier.** The hooks are in the root-owned policy document
  `/etc/github-copilot/policy.d/50-defenseclaw.json`, and the managed settings
  admit only managed hooks, so a user `disableAllHooks` and user or repository
  hooks change nothing. The hooks fail closed and authenticate with a
  per-sandbox token. The image pre-extracts the pinned CLI into a root-owned
  package cache that the launcher pins, so a newer package planted in the
  agent's home cannot replace the running CLI.
- **Skip-permissions.** On by default (the `open` and `balanced` packs):
  Copilot CLI starts with `--yolo`. `--safe`, or the `strict` pack, keeps its
  prompts and drops `--yolo`, `--allow-all` and `--allow-all-tools` from the
  arguments you pass. A safe headless run (`--prompt`) still adds
  `--allow-all-tools`, because Copilot's non-interactive mode refuses to run
  without tool approval.
- **Model sign-in.** `sandbox run` uses Copilot's bring-your-own-provider
  mode. `--llm auto` (the default) shares `ANTHROPIC_API_KEY` from your shell
  as Copilot's provider key for the Anthropic Messages API (pick a model with
  `-- --model <model>`); `--llm bedrock`, and `auto` without it, shares a
  short-term Amazon Bedrock API key from `AWS_BEARER_TOKEN_BEDROCK` for the
  Bedrock Mantle Anthropic
  endpoint (default model Claude Haiku 4.5). OpenShell holds the secret, and
  the sandbox gets a placeholder that works only at that endpoint. Both run
  Copilot in offline mode, which skips GitHub sign-in, telemetry, web tools,
  the GitHub MCP server and updates. Copilot's own models through a
  Copilot-entitled GitHub token (`COPILOT_GITHUB_TOKEN`) have no `--llm`
  choice.
- **MCP servers.** DefenseClaw brings your MCP servers along into Claude Code
  and Codex sandboxes only.
- **Ctrl-Z.** Copilot CLI suspends itself by signalling its process group,
  which the OpenShell sandbox refuses, and no shell in the sandbox could
  resume a stopped job either. DefenseClaw resumes Copilot at once, also at a
  `sandbox connect --shell` prompt: Copilot shows its own `✗ Error: kill
  EPERM` and keeps working, and the terminal's title (and a desktop
  notification, where the terminal shows them) says at once `[defenseclaw]
  Ctrl-Z cannot suspend a harness in an OpenShell sandbox: it keeps
  running`. Once Copilot exits, the terminal shows Copilot's own "has been
  suspended. Use `fg` to resume." line, which DefenseClaw cannot keep off
  the screen, followed by `defenseclaw: Ctrl-Z cannot suspend a harness in
  an OpenShell sandbox (the sandbox refuses the signal): it keeps running,
  and there is nothing to bring back with fg.`
- **Interactive hook latency.** In the interactive TUI, every hook waits for
  Copilot's full 30-second hook timeout, even though DefenseClaw answers in
  milliseconds. A prompt takes about a minute to reach the model, and a tool
  call about a minute and a half. The verdict is still applied, and the launch
  banner says so. This is a limit of the OpenShell sandbox and Copilot CLI,
  not of the hooks. Headless runs are not affected: use
  `defenseclaw sandbox run copilot --prompt "PROMPT"` or
  `defenseclaw sandbox connect NAME --prompt "PROMPT"`. DefenseClaw does not
  shorten the timeout, because Copilot allows a tool call whose hook timed
  out.
- **Image.** The sandbox image ships Copilot CLI 1.0.88.

## Disable

```bash
defenseclaw guardrail disable --connector copilot --yes
```

`--connector` turns off only Copilot on a multi-connector install. On a
single-connector install, run `defenseclaw guardrail disable --yes`. To remove
the connector from the config, use `defenseclaw setup remove copilot`; see
[Quick aliases](/docs/setup/guardrail/aliases).

Teardown restores the exact pre-Setup hook document when its managed copy is
unchanged. If an operator edits the file after Setup, DefenseClaw removes only
its recognized handlers and preserves foreign entries, unknown events, and
the rest of the file. The same custody rule applies to the pinned workspace
hook file.
