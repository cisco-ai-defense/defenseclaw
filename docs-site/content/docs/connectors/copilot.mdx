DefenseClaw installs a hook file that Copilot CLI runs on its lifecycle events. This is a hook connector: Copilot talks to GitHub directly and no proxy is involved.

## Platform support

<ConnectorSupport id="copilot" />

## Set up

```bash
defenseclaw setup copilot
defenseclaw setup copilot --workspace /path/to/repo
```

On Windows, use PowerShell and a Windows path such as `'C:\path\to\repo'`. Hooks are global by default. `--workspace` writes them into one repository instead and pins the workspace for the whole install. Setup refuses it once another connector is configured. To scope every connector to a repository, run `defenseclaw setup guardrail --workspace /path/to/repo`.

Interactive setup asks for the mode, whether to add to or replace an existing connector roster, and whether to add an LLM judge. For scripts, pass `--yes --mode observe` (or `--mode action`).

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` reports no failed check for it.


## What it can block or ask

<HookEventsList connector="copilot" />

- `preToolUse` can ask you first. The approval appears inside Copilot CLI.
- `permissionRequest`, `agentStop` and `subagentStop` can return a deny or block.
- `postToolUseFailure` is advisory. It can add recovery context after the tool failed.
- Copilot CLI has no hook that can stop a prompt. A matching prompt reaches the model and the alert reads `detected in the prompt (cannot block)`. Tool-call rules still block.

## Files it changes

| What | Where |
| --- | --- |
| Global hooks | `~/.copilot/hooks/defenseclaw.json` (or under `$COPILOT_HOME`) |
| Workspace hooks (only with `--workspace`) | `<workspace>/.github/hooks/defenseclaw.json` |
| Hook program, macOS and Linux | `~/.defenseclaw/hooks/copilot-hook.sh` |
| Hook program, Windows | `%USERPROFILE%\.local\bin\defenseclaw-hook.exe` (one-line install) or `%LOCALAPPDATA%\DefenseClaw\HookRuntime\defenseclaw-hook.exe` (Setup installer) |

Teardown restores the exact earlier file when DefenseClaw's copy is unchanged. Otherwise it removes only its own handlers.

## Limits

- Copilot runs a call when its hook times out or cannot start. Every other failure DefenseClaw sees (gateway down, unusable answer, missing token, oversized input) is denied in fail mode `closed`, the default, and the reason names the next step. With fail mode `open` the call runs, is recorded in `~/.defenseclaw/logs/hook-failures.jsonl` and is reported as a `guardrail-degraded` alert when the gateway starts again. Under Secure Client the hook stays open.
- DefenseClaw does not configure Copilot's own OpenTelemetry exporter. Telemetry comes from hook events.
- Copilot's Windows sandbox does not enforce per-path denials. Do not rely on it for filesystem containment.
- The VS Code Local harness reads its own hook format. The enterprise profile covers it; see the reference.

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

This keeps Copilot's settings. Turn it back on with `defenseclaw guardrail enable`. To remove the connector, run `defenseclaw setup remove copilot --yes` (add `--force` if it is the last one).

On a multi-connector install, add `--connector copilot` to `guardrail disable` and `guardrail enable` to change only this agent.
