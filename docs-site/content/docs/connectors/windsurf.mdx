The Windsurf connector wires DefenseClaw into the official
[Cascade hooks](https://docs.devin.ai/desktop/cascade/hooks) surface so every
prompt, code read, code write, command run, and MCP tool call can be scored
before it lands. Windsurf is now named Devin Desktop; the official download
page states that the IDE and settings remain available through the rename.

## Setup

```bash
defenseclaw setup windsurf
```

<Callout type="warning">
Windsurf setup is supported on macOS and Linux. Native Windows x64 setup is
available as a preview, but it is not yet certified for release.
</Callout>

`setup windsurf` is the dedicated Windsurf alias. It uses the shared guardrail
setup backend and wires hooks against `~/.codeium/windsurf/hooks.json`.
DefenseClaw discovers existing MCP, global rules, `.devin/rules` and legacy
Windsurf rule surfaces. When a workspace is explicitly pinned, inventory also
includes its documented `.windsurf/skills` and `.agents/skills` roots.
DefenseClaw never auto-creates workspace configuration. **There is no
proxy-enforcement path** — blocking happens hook-side via Cascade's
`pre_user_prompt`, `pre_read_code`,
`pre_write_code`, `pre_run_command`, and `pre_mcp_tool_use`. Windsurf has no
native ask surface, so confirm verdicts use its non-pausing fallback with
`raw_action` preserved for audit.

### Native Windows x64 preview

The native Windows implementation is available as a preview. Install the
official [Devin Desktop/Windsurf Windows x64 build](https://devin.ai/download)
for the same signed-in user, then run this from PowerShell or cmd:

```powershell
defenseclaw setup windsurf --mode observe
defenseclaw doctor
```

Setup binds the Windows Profile Known Folder explicitly and manages only
`<bound-profile>\.codeium\windsurf\hooks.json`. That exact profile root is
persisted for repair, upgrade, reconciliation, and uninstall. DefenseClaw does
not inherit a maintenance process's `USERPROFILE`, guess from the data
directory, or inspect another user's configuration.

Windsurf runs the documented `powershell` hook field through
`powershell -Command`. DefenseClaw writes no `command` fallback. The generated
native PowerShell adapter forwards JSON stdin and stdout/stderr, waits for the
exact packaged `defenseclaw-hook.exe`, and propagates its exit status,
including blocking exit `2`. This path uses no Bash, Git Bash, Cygwin/MSYS,
WSL, Docker, or VM.

Packaged Windows and interactive official-client validation remain release
gates. Do not treat preview availability as certification.

#### What `setup windsurf` actually does

The table highlights convenience options rather than the complete alias
surface. The alias also accepts `--mode`, `--rule-pack`, `--fail-mode`,
approval, block-message, add/replace, workspace, and rule-pack-directory
options. See the [quick-alias reference](/docs/setup/guardrail/aliases); use
[full guardrail setup](/docs/setup/guardrail) for scanner, detection-strategy,
and judge-provider configuration.

| Flag | Default | What it does |
| --- | --- | --- |
| `--yes / -y` | off | Skip the confirmation prompt. |
| `--restart / --no-restart` | `--restart` | Bounce `defenseclaw-gateway` after applying changes so the new hooks wire in. |
| `--with-local-stack / --no-local-stack` | `--no-local-stack` | Also run `setup local-observability up`; follow the command's printed gateway-restart step after it writes the export destination. |

The alias defaults Windsurf to observe mode and can join an existing hook-connector roster when you choose **Add**. To tune Windsurf after install, keep using [`defenseclaw setup guardrail --connector windsurf`](/docs/setup/guardrail) — see the variations below.

#### Common variations — pick the recipe that fits your phase

<Tabs items={['Standard', 'Local stack', 'Add scanning rigor', 'Hook-side enforcement']}>

<Tab value="Standard">

```bash
defenseclaw setup windsurf
```

Confirms once, wires the hooks against `~/.codeium/windsurf/hooks.json`, and restarts the gateway. Findings flow to mandatory SQLite event history and the TUI; configured v8 destinations receive only the buckets/signals their routes select. No traffic is intercepted and no requests are blocked. Pass `--yes` to skip the confirmation in CI.

</Tab>

<Tab value="Local stack">

```bash
defenseclaw setup windsurf --yes --with-local-stack
```

Same as standard but also runs `setup local-observability up` so Prom/Loki/Tempo/Grafana come up locally for ad-hoc dashboards. That command writes the export destination after the alias has already restarted the gateway, so run its printed `defenseclaw-gateway restart` step before expecting exports. See [Local observability](/docs/observability/local-observability).

</Tab>

<Tab value="Add scanning rigor">

```bash
export DEFENSECLAW_LLM_KEY='replace-with-your-key'

defenseclaw setup windsurf                                # base alias first
defenseclaw setup guardrail \
  --connector windsurf \
  --rule-pack strict \
  --scanner-mode local \
  --detection-strategy regex_judge \
  --judge-model anthropic/claude-sonnet-4-20250514 \
  --judge-api-key-env DEFENSECLAW_LLM_KEY \
  --judge-hook-connectors windsurf \
  --restart
```

The alias selects Windsurf; the follow-up `setup guardrail --connector windsurf` swaps in the strict rule pack, keeps scanning local, and turns the LLM judge on as a second-pass adjudicator on regex-flagged events. Configure the remote scanner separately through [full guardrail setup](/docs/setup/guardrail), which validates its endpoint and API-key environment variable.

</Tab>

<Tab value="Hook-side enforcement">

Windsurf has no proxy enforcement, but its pre-action hooks can enforce
directly:

```bash
defenseclaw setup windsurf --mode action
```

With `mode=action`, the five declared pre-hooks block when policy returns
`block`. A `confirm` verdict uses Windsurf's non-pausing fallback because the
agent has no native ask surface.

The vendor hook transport has no generic fail-closed error: exit `2` is the
only blocking status and applies only to the five documented pre-hooks; every
other exit proceeds. DefenseClaw's `fail_mode: closed` deliberately maps its
own adapter availability failures to that vendor-defined exit `2` on those
five pre-hooks. It cannot make any post-hook block. Of the post-hooks, only
`post_cascade_response` and `post_cascade_response_with_transcript` run
asynchronously. Restricted Mode disables hooks entirely.

</Tab>

</Tabs>

## Hook capabilities

<HookEventsList connector="windsurf" />

<Callout>
Windsurf has no native human-approval surface. Confirm verdicts use an immediate fallback with `raw_action` preserved; operators can review them in the TUI or audit log, but cannot approve and resume them there.
</Callout>

<Callout type="warning" title="Know the vendor enforcement limits">
Only `pre_user_prompt`, `pre_read_code`, `pre_write_code`,
`pre_run_command`, and `pre_mcp_tool_use` can block, and only with exit `2`.
Every other exit proceeds. Post-hooks cannot block; only
`post_cascade_response` and `post_cascade_response_with_transcript` run
asynchronously. Restricted Mode disables all hooks.
</Callout>

## Subprocess policy

`none` — Windsurf executes commands inside its own runtime; DefenseClaw observes via the `pre_run_command` hook rather than the openshell sandbox.

## Disable

```bash
defenseclaw guardrail disable --connector windsurf --yes
```
