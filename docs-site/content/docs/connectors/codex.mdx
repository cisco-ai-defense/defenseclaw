DefenseClaw writes hooks into Codex's `config.toml`. Host setup removes native OpenTelemetry exporters installed by earlier releases: Codex cannot verify which local account holds a stopped gateway's TCP port. Isolated OpenShell images retain native telemetry. On an ordinary host install, per-user and standalone enterprise installs do not register a notify bridge; only Secure Client does. Codex in an OpenShell sandbox (`defenseclaw sandbox run codex`) is the exception: the sandbox image installs `codex-notify.sh` and sets `notify` in its managed config. This is a hook connector: Codex talks to OpenAI directly and no proxy is involved.

## Set up

On a new install, run `defenseclaw init --connector codex` first. Until DefenseClaw is initialized, `defenseclaw setup codex` stops with `DefenseClaw is not initialized — run 'defenseclaw init' first.`

```bash
defenseclaw setup codex                # first setup defaults to observe: record only
defenseclaw setup codex --mode action  # block on policy hits
```

A re-run without `--mode` keeps the current mode. On Windows, run the same
commands in PowerShell. Quit and reopen Codex afterwards.
After upgrading from an earlier release, quit all running Codex processes and reopen them so they stop using any old exporter configuration.

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` passes the **Codex hooks** row.


## What it can block or ask

<HookEventsList connector="codex" />

- In action mode `PreToolUse` and `PermissionRequest` can deny a call before the tool runs.
- `UserPromptSubmit`, `PostToolUse`, `Stop` and (on newer Codex versions) the session, subagent and compaction events can also block. Each answers in its own way: `PostToolUse` cannot undo the finished tool, and `Stop` blocks by continuing the turn.
- Codex has no native ask. A confirm verdict becomes an alert with the original action kept. You can review it in audit or the TUI, but not resume the call.
- Codex loads skills without a hook of their own. DefenseClaw refuses a denied skill when you select it as `$name` or when a tool call reads its folder.

## Files it changes

| What | macOS and Linux | Windows |
| --- | --- | --- |
| Hooks; removal of older native telemetry | `$CODEX_HOME/config.toml` (default `~/.codex`) | `%CODEX_HOME%\config.toml` |
| Hook program | `~/.defenseclaw/hooks/codex-hook.sh` | `%USERPROFILE%\.local\bin\defenseclaw-hook.exe` (one-line install) or `%LOCALAPPDATA%\DefenseClaw\HookRuntime\defenseclaw-hook.exe` (Setup installer) |
| Connector credentials | `~/.defenseclaw/hooks` | `%USERPROFILE%\.defenseclaw\hooks` |
| Proxy bypass for cloud credentials | `$CODEX_HOME/.env` (managed, marked block) | not written |

Teardown restores the backup, or removes only DefenseClaw's entries.

## Limits

- `codex features disable hooks` keeps the entries but runs none of them. DefenseClaw raises a guardrail-degraded alert, `defenseclaw status` shows DEGRADED and `defenseclaw doctor` fails the **Codex hooks** row. Run `codex features enable hooks`.
- If DefenseClaw's `command` lines are deleted from `config.toml`, Codex may start and run without DefenseClaw hooks. `defenseclaw doctor` reports the missing commands; run `defenseclaw setup codex --yes` or `defenseclaw doctor --fix` to repair them, then restart Codex.
- Hosted tools, file reads and `write_stdin` have no complete hook coverage. On Windows each gateway start runs Codex's app-server once, which contacts OpenAI.
- After you rotate a model key, or after an upgrade, run `codex app-server daemon restart`. The daemon keeps the environment and telemetry credential it started with.
- Codex's own command check can refuse `rm -f` and `rm -rf` cleanups, and Codex runs a tool when its pre-tool hook is stopped or times out. Both are Codex limits. See [Known limits in 1.0.4](/docs/troubleshooting/known-limits#codex).

## On a managed computer

The per-user commands on this page do not run on a computer with a standalone enterprise install. On Linux and macOS, `defenseclaw` there offers only `sandbox` commands, `help` and `--version`: anything else prints "This computer is managed; only `defenseclaw sandbox` commands are available here." and exits 2. On native Windows, `defenseclaw` is the administrator's command: it refuses `setup codex` and `setup remove`, and has no `guardrail` group. Protected requirements pin `[features] hooks = true`, so `codex features disable hooks` writes the user's config but hooks stay on. On standalone Linux and macOS, the guardian also removes that conflicting user preference during reconciliation; while it remains, Codex can reject an unrelated project trust write.

The per-user files in [Files it changes](#files-it-changes) are not used there. The hooks are in Codex's machine requirements file and run the administrator's hook program:

| | Hooks | Hook program |
| --- | --- | --- |
| Linux | `/etc/codex/requirements.toml` | `/opt/defenseclaw/bin/defenseclaw-hook` |
| macOS | `/etc/codex/requirements.toml` | `/opt/cisco/defenseclaw/bin/defenseclaw-hook` |
| Windows | `C:\ProgramData\OpenAI\Codex\requirements.toml` | `C:\Program Files\Cisco\DefenseClaw\bin\defenseclaw-hook.exe` |

`enterprise policy verify` prints both. On Windows its first line names the hook program:

```text
Standalone machine agent policy (hook binary C:\Program Files\Cisco\DefenseClaw\bin\defenseclaw-hook.exe)
```

and the `codex` row names the requirements file:

```text
codex        machine_policy  covered      lock=enforce  foreign_hooks=remove  owned=10 foreign=0
    file:      C:\ProgramData\OpenAI\Codex\requirements.toml
```

The administrator manages Codex in the managed `config.yaml` under `guardrail.connectors.codex` (`{}` adds it, `enabled: false` removes it). Apply the change as in [Change the config](/docs/enterprise/operate/lifecycle#change-the-config), then check it with `enterprise policy verify` ([Machine policy](/docs/enterprise/configure/machine-policy#inspect-export-and-verify)).

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

With the default gateway restart, disabling removes DefenseClaw's hooks and
OpenTelemetry entries from Codex's config and preserves your other Codex
settings. `defenseclaw guardrail enable` restores DefenseClaw's hooks and
telemetry entries. To remove the connector, run
`defenseclaw setup remove codex --yes` (add `--force` if it is the last one).

On a multi-connector install, add `--connector codex` to `guardrail disable` and `guardrail enable` to change only this agent.
