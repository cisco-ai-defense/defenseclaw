The `devin` connector wires DefenseClaw into the native
[Devin CLI lifecycle-hook surface](https://docs.devin.ai/cli/extensibility/hooks/overview).
Devin continues to contact its model provider directly; DefenseClaw does not
proxy its model traffic.

<Callout type="info" title="One connector for Devin CLI and Devin Desktop">
Use `devin` for both Devin CLI and Devin Desktop. If an older DefenseClaw
release protected Devin Desktop under its previous product name, upgrading
moves that configuration to `devin` and removes the hook entries DefenseClaw
wrote for the old app. See
[Upgrade → Renamed and removed connectors](/docs/get-started/upgrade#renamed-and-removed-connectors).
</Callout>

## What this connector protects

| Surface | Protected | Why |
| --- | --- | --- |
| Devin CLI | **Yes** | DefenseClaw registers the `devin-hooks-v1` contract in the Devin CLI hook config. |
| Devin Desktop, **Devin Local** agent (the default for new tabs) | **Yes, per vendor documentation** | [Devin Local](https://docs.devin.ai/desktop/devin-local) shares the agent harness, config file, and hooks with Devin CLI, so the same hook registration applies. DefenseClaw has not yet recorded a live Devin Desktop validation run. |
| Devin Desktop, legacy **Cascade** agent | **No** | Cascade uses a separate hook contract that this connector does not register. New Devin Desktop conversations never start on Cascade, but existing Cascade conversations still run unprotected. |
| Cloud Devin sessions | **No** | Cloud execution does not run local hooks. |

The supported hook contract is pinned to Devin CLI `3000.4.25` on Windows,
macOS, and Linux. This is source-reviewed compatibility evidence. Authentic
official-client validation metadata remains empty and `live=false`.

## Platform support

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | The native `devin-hooks-v1` contract manages user hooks under `~/.config/devin` or an explicitly pinned project hook document. |
| Native Windows x64 | **Supported** | Setup admits only the current user's exact Devin CLI `3000.4.25` executable at its official LocalAppData path with a valid `Exafunction, Inc.` Authenticode signer. DefenseClaw adds no Bash or WSL dependency; Devin's own Windows hook runner invokes the protected native hook executable directly. |

Use `--mode action` only after reviewing observed events and policy findings.
The connector can join an existing hook-connector roster. After setup, restart
any open Devin CLI session and reopen Devin Desktop tabs so they load the new
hooks.

### Native Windows admission

Native Windows Setup accepts only the current user's official CLI at
`%LOCALAPPDATA%\devin\cli\bin\devin.exe`. The executable must be a regular,
non-reparse file, report exactly `3000.4.25`, have a valid Authenticode chain,
and be signed by `Exafunction, Inc.`. Setup does not trust a different
PATH-resolved `devin.exe`.

Devin evaluates hook commands through its own Bash execution path on Windows.
DefenseClaw therefore registers the protected `defenseclaw-hook.exe` as a
Bash-safe direct command. This preserves the hook JSON streams and blocking
exit code without a PowerShell decode boundary. DefenseClaw does not install
or add Bash, WSL, Docker, a VM, Git Bash, Cygwin/MSYS, or a proxy dependency.

## Configuration custody

DefenseClaw manages only the documented Devin-native hook locations. Devin CLI
and Devin Desktop's Devin Local agent read the same files:

- Windows user hooks: `%APPDATA%\devin\config.json`, nested under `hooks`;
- macOS/Linux user hooks: `~/.config/devin/config.json`, nested under `hooks`;
- project hooks: `<workspace>/.devin/hooks.v1.json`, where the hook map is the
  whole JSONC document.

Existing foreign hook groups and JSONC content are preserved. Devin also loads
hooks from `.claude/` settings for compatibility; DefenseClaw does not claim or
modify those locations.

## Lifecycle and enforcement

The `devin-hooks-v1` contract registers exactly eight events:

| Event | DefenseClaw role |
| --- | --- |
| `PreToolUse` | Inspect tool input before execution; action mode can return top-level `decision: "block"`. |
| `PostToolUse` | Inspect `tool_response`; completed work cannot be undone. Additional context may be returned. |
| `PermissionRequest` | Action mode can return a block decision; DefenseClaw does not claim native resumable ask. |
| `UserPromptSubmit` | Inspect the prompt before the turn; action mode can block or return additional context. |
| `Stop` | Action mode can return a block decision through the documented hook response. |
| `PostCompaction` | Observe the compaction summary. |
| `SessionStart` | Observe lifecycle and optionally return additional context. |
| `SessionEnd` | Observe lifecycle teardown. |

Top-level `decision` and `reason` carry allow/block results.
`hookSpecificOutput` is event-tagged; DefenseClaw emits `additionalContext`
only for `UserPromptSubmit`, `SessionStart`, and `PostToolUse`. Exit `2`
blocks, while every other hook error fails open. Restricted Mode disables
hooks and agents entirely.

Devin publishes `session_id` and per-turn `prompt_id`, but no stable per-tool
invocation ID. Cross-event tool pairing is therefore detection-only. A
`confirm` finding remains available in audit but cannot pause and resume in
the DefenseClaw TUI.

## Local customization surfaces

Read/write MCP custody is limited to the canonical user and project
`mcp_config.json` files. Higher-precedence local compatibility files may be
read for effective inventory but are not rewritten. Skills and rules are
discovered from the documented `.devin` and `.agents` roots, including
`AGENT.md`, `AGENTS.md`, and `AGENTS.local.md` where applicable. Inventory
also reads the pre-rename Devin Desktop rule and skill locations that the
vendor still loads (see Cognition's
[memories and rules](https://docs.devin.ai/desktop/cascade/memories) and
[skills](https://docs.devin.ai/desktop/cascade/skills) documentation).
Setup never installs anything there; `defenseclaw skill quarantine` and
`restore` can move a flagged skill out of and back into those folders, as for
any other skill folder. Traversal is bounded and does not follow links or
reparse points.

Devin plugins are closed beta, so DefenseClaw does not advertise plugin setup
or enforcement. The separate `devin acp` entry point is cataloged for the
shared [ACP guard](/docs/acp-guard), but it has not completed official-client
testing and is not part of this hook contract. Cloud Devin execution, proxy
transport, native OTLP, sandboxing, egress control, and managed higher-layer
policy are also outside this connector's support boundary.

## Upgrading an older Devin Desktop install

Upgrades migrate the previous Devin Desktop connector automatically; you do
not need to edit files by hand. The details, including what DefenseClaw removes and what it
leaves alone, are in
[Upgrade → Renamed and removed connectors](/docs/get-started/upgrade#renamed-and-removed-connectors).

## Disable

```bash
defenseclaw guardrail disable --connector devin --yes
```
