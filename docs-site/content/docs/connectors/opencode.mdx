DefenseClaw supports **OpenCode V2 only**. Its dependency-free plugin default-exports an `id` and `setup(ctx)`, registers awaited `execute.before` and `execute.after` callbacks, and rejects a blocked call before OpenCode executes it. OpenCode sends model traffic directly to its provider; this connector does not proxy that traffic.

## Platform support

<ConnectorSupport id="opencode" />

V2 support is currently a preview. Native allow/block callbacks have been checked on macOS arm64. Native Linux and Windows vendor-CLI certification remains unrecorded.

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | V2-only preview contract `>=2.0.0,<2.2.0`, reviewed at 2.0.0 and 2.1.4. Native callback validation currently covers macOS arm64. |
| Native Windows x64 | **Supported** | V2-only preview; direct native execution with the official `@opencode/cli` package or the protected current-user `SST.opencode` WinGet executable. The installed version must be V2. Mixed WSL/native paths, Desktop sidecars, other packages and ARM64 are outside the native Windows contract. |

## Setup

Install OpenCode V2 first. If npm installed V1, remove that old package before installing V2; the two releases use the same `opencode` command. Follow the [vendor migration guide](https://opencode.ai/v2/docs/migrate-v1/).

```bash
npm uninstall -g opencode-ai
npm install -g @opencode/cli@2
```

On a new DefenseClaw install, run `defenseclaw init --connector opencode` first. Until initialized, setup stops with `DefenseClaw is not initialized — run 'defenseclaw init' first.`

```bash
defenseclaw setup opencode                # first setup defaults to observe: record only
defenseclaw setup opencode --mode action  # reject blocked calls before execution
```

A re-run without `--mode` keeps the current mode. Restart OpenCode afterwards, including after upgrading from V1. Setup replaces only DefenseClaw-owned artifacts and refreshes the contract lock. Legacy artifact names remain recognizable for cleanup; no V1 factory or V1 runtime contract is shipped.

### Check it

```bash
defenseclaw status
defenseclaw doctor
```

The connector appears under **Agents** with its mode. `IDLE` is normal until OpenCode starts and loads the plugin.

### Version contract

| Installed version | What setup does |
| --- | --- |
| OpenCode V1 or another detected non-V2 major | Refuses before activation in observe and action mode, including with the exploratory drift override. Install V2 and rerun setup. |
| `>=2.0.0,<2.2.0` | Uses `opencode-hooks-v2`, bridge generation `v7`. |
| A newer V2 minor | Per-user setup uses the same V2 contract with an untested-version warning. Strict profiles retain their exact reviewed range. |
| Not readable | Existing unversioned policy applies: observe warns; action refuses without an explicit exploratory override. This does not provide a V1 implementation. |

The plugin follows the [official V2 migration guide](https://opencode.ai/v2/docs/build/plugins/migrate-v1) and the API at [V2.0.0](https://github.com/anomalyco/opencode/tree/63f7ceecbed2d7d9a627518d935dd963b9d4ac9f/packages/plugin) and [dev/2.1.4](https://github.com/anomalyco/opencode/tree/f669c46c9604ea3d70b8a7ed1f0c10f3a5ac1f61/packages/plugin). It imports only Node built-ins and requires no OpenCode SDK package at runtime.

## Files DefenseClaw will modify

A per-user install writes the owned `defenseclaw.js` into `OPENCODE_CONFIG_DIR/plugins/`, or `~/.config/opencode/plugins/` by default. OpenCode V2 auto-discovers the file. DefenseClaw does not edit the per-user `opencode.json` to register it.

Managed standalone installs publish `<install root>/share/opencode/index.js` and register its directory. Configured V2 local plugins must name a directory containing `index.js`; a configured single-file path is not a V2 registration. Reconciliation removes owned legacy file references and preserves unrelated settings.

On native Windows, the npm image is `%APPDATA%\npm\node_modules\@opencode\cli\bin\opencode.exe`. The admitted WinGet path is `%LOCALAPPDATA%\Microsoft\WinGet\Packages\SST.opencode_Microsoft.Winget.Source_8wekyb3d8bbwe\opencode.exe`. DefenseClaw verifies the native executable selection and package identity before setup. Neither a mutable npm command wrapper nor a WSL executable supplies that authority.

## Hook capabilities

| Contract | Reviewed range | Bridge | Events | Block surfaces | Native ask |
| --- | --- | --- | --- | --- | --- |
| `opencode-hooks-v2` | `>=2.0.0, <2.2.0` | `v7` | 8 | 1 | 0 |

| Contract | Events | Block events | Ask events |
| --- | --- | --- | --- |
| `opencode-hooks-v2` | `defenseclaw.plugin.loaded`, `session.created`, `session.status`, `session.idle`, `session.error`, `session.deleted`, `tool.execute.before`, `tool.execute.after` | `tool.execute.before` | none |

Before awaiting a verdict, the V2 adapter detaches and deeply freezes the inspected input and freezes the event. A later hook cannot substitute an uninspected tool or argument. Session location and MCP identity come from bounded local V2 API calls; invalid context is refused and action mode rejects ambiguous MCP identity.

A blocked call returns its reason through the rejected tool Promise. V2 server plugins have no V1 TUI toast API; advisory notices use host logs. There is no native hook-side approval dialog. A confirm verdict is advisory rather than a native ask.

The after hook preserves V2 `status`, structured `output`, `content` and metadata. Errors are failures. A shell result proves success only when completed with exit zero; a running background command is not completed success. After-hook findings cannot undo an already executed side effect.

Session events are observe-only telemetry. The adapter maps native `session.execution.*` events to the gateway's status, error and idle events, resolves location-less events against the session, and disposes subscriptions and registrations on unload.

See the [gateway outage table](/docs/connectors/capability-matrix#gateway-outage) for each installation mode's outage behavior.

## Local surfaces

V2 accepts compatible existing configuration syntax as well as native V2 fields. DefenseClaw reads both when resolving plugins, skills, agents, commands and MCP inventory. Retaining that data compatibility does not admit a V1 runtime.

Native V2 plugin entries use `plugins`; MCP servers use `mcp.servers`. Relative paths are resolved only against an explicit workspace. Managed policy and JSONC handling preserve unrelated operator settings.

## Enterprise deployments

Per-user, managed standalone and Secure Client plugin variants all use the V2 entrypoint. The existing account and service verification boundaries remain in their respective transports. A detected V1 installation must be upgraded before connector activation.

Managed standalone setup uses the administrator-owned shared plugin and the existing foreign-hook guard. Old file identities remain solely to migrate or remove installations written by an earlier DefenseClaw release.

### On a managed computer

Per-user setup and guardrail commands refuse on a standalone enterprise Linux or macOS host. An administrator adds `guardrail.connectors.opencode: {}` to the managed `config.yaml`, applies it through the [enterprise lifecycle](/docs/enterprise/lifecycle), and runs `enterprise policy verify`. DefenseClaw registers the V2 plugin directory in OpenCode's managed config (`/etc/opencode/opencode.json` on Linux). Set `guardrail.connectors.opencode.enabled: false` in the managed configuration to disable it. See [Machine policy](/docs/enterprise/machine-policy) for platform paths and deployment steps.

## In an OpenShell sandbox

The image pin is OpenCode V2.1.4 from the official `@opencode/cli` package. Package integrity and the native binary digest are checked; Linux x64 uses the baseline binary rather than adding an AVX2 requirement. The V1 base-image package and its startup SDK-record workaround are removed. Interactive runs use `--standalone`; headless runs use `run --standalone`. The launcher refuses `--server` because an external server does not use this sandbox's managed plugin.

The previous V1 live sandbox certification does not certify V2. The V2 image remains unverified and unselectable until a fresh OpenShell ingress, block and egress verification succeeds. Existing V1 image records no longer resolve to a supported OpenCode contract.

## Limits

- Only V2 is supported. Neither an old V1 factory nor the drift override enables a detected V1 runtime.
- This plugin inspects tool calls and outcomes; it does not intercept raw model traffic.
- Server-plugin logs replace V1 toast behavior; native approval is not provided.
- Native Linux/Windows vendor-CLI certification and V2 OpenShell live certification are not claimed by this preview.

## Disable

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

With the default gateway restart, disabling removes DefenseClaw's plugin file. This preserves your other OpenCode settings. `defenseclaw guardrail enable` reinstalls DefenseClaw's plugin. To remove the connector, run `defenseclaw setup remove opencode --yes` (add `--force` if it is the last one). If you modified the plugin, `guardrail disable` and `setup remove` refuse before saving configuration, and the gateway is left as it was; `defenseclaw doctor` reports the change. Preserve your edits, run `defenseclaw setup opencode --yes --restart` to restore the managed plugin, then retry. Restart OpenCode afterwards.

On a multi-connector install, add `--connector opencode` to `guardrail disable` and `guardrail enable` to change only this agent.

No V2 hook or subscription starts when the plugin is not loaded.
