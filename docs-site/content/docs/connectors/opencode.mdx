DefenseClaw installs one plugin file in OpenCode's plugin directory. The plugin sends each tool call to the gateway before it runs and throws if the verdict is a block. OpenCode talks to its model provider directly and no proxy is involved.

## Platform support

<ConnectorSupport id="opencode" />

## Set up

```bash
defenseclaw setup opencode                # observe (default): record only
defenseclaw setup opencode --mode action  # block on policy hits by throwing
```

On Windows, run the same commands in PowerShell. Restart OpenCode afterwards. Until it starts, `defenseclaw status` shows OpenCode as `IDLE`, which is normal.

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` reports no failed check for it.


## What it can block or ask

<HookEventsList connector="opencode" />

- In action mode `tool.execute.before` blocks a tool call by throwing an error. The TUI shows a notice, and the model gets the reason.
- `tool.execute.after` only records the result. The tool has already run.
- OpenCode has no hook that stops a prompt. A matching prompt reaches the model. Tool-call rules still block.
- There is no native ask. A confirm verdict runs the call and shows a warning notice with the severity and reason.

## Files it changes

| What | Where |
| --- | --- |
| Plugin | `$OPENCODE_CONFIG_DIR/plugins/defenseclaw.js` (default `~/.config/opencode/plugins/defenseclaw.js`; Windows `%USERPROFILE%\.config\opencode\plugins\defenseclaw.js`) |

Setup also writes a connector-scoped token sidecar under `~/.defenseclaw/hooks`. Per-user plugins use the account-owned `defenseclaw-gateway` native helper to verify the connected listener; Secure Client plugins use the administrator-owned native helper to verify the protected gateway service. The helper sends the token and tool event only on that verified connection. `opencode.json` is not edited. Restart OpenCode after an upgrade so it loads the repaired plugin.

## Limits

- Setup refuses an OpenCode older than the supported range. A newer one runs as an untested newer version.
- On Windows only the WinGet `SST.opencode` package and the npm `opencode-ai` package are accepted, run natively. WSL is not part of the contract.
- A listener owned by another local account receives no credential or tool event; `tool.execute.before` blocks with an unverified-listener reason, including under Secure Client. Per-user host hooks fail closed on gateway failure. A managed administrator can choose outage-only open.
- A project plugin that loads after DefenseClaw's can change the arguments. In action mode the bridge then refuses to allow the call.
- Running OpenCode with `--pure` turns external plugins off, and DefenseClaw sees nothing.

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

This keeps OpenCode's settings. Turn it back on with `defenseclaw guardrail enable`. To remove the connector, run `defenseclaw setup remove opencode --yes` (add `--force` if it is the last one). If you modified the plugin, removal refuses before saving configuration. Preserve your edits, run `defenseclaw setup opencode --yes --restart` to restore the managed plugin, then retry removal. Restart OpenCode afterwards.

On a multi-connector install, add `--connector opencode` to `guardrail disable` and `guardrail enable` to change only this agent.
