Connectors are the adapter layer between agent frameworks and DefenseClaw.
They share one Go interface, but each connector advertises only the
capabilities its agent actually exposes. Proxy routing, lifecycle hooks,
custom policy callbacks, component discovery, CodeGuard, subprocess wrapping,
native telemetry, and approval support therefore vary by connector.

## Pick your agent

| Agent | Integration | Where DefenseClaw enforces |
| --- | --- | --- |
| [Claude Code](/docs/connectors/claudecode) | Hook | Native lifecycle hooks; native ask at `PreToolUse` |
| [Codex](/docs/connectors/codex) | Hook | Native lifecycle hooks plus native OTLP |
| [Cursor](/docs/connectors/cursor) | Hook | Native user hooks; confirm verdicts stay alerts |
| [GitHub Copilot CLI](/docs/connectors/copilot) | Hook | Native lifecycle hooks; native ask at `preToolUse` |
| [Devin CLI and Devin Desktop](/docs/connectors/devin) | Hook | Native Devin hooks shared by the CLI and Devin Local |
| [Kiro](/docs/connectors/kiro) | Hook, plus optional [ACP](/docs/acp-guard) | Kiro IDE and Kiro CLI hook configs |
| [Amp](/docs/connectors/amp) | Plugin hook | `tool.call` and model-bound `tool.result` |
| [Antigravity](/docs/connectors/antigravity) | Hook | `PreToolUse` only |
| [Hermes](/docs/connectors/hermes) | Hook | Native Hermes hooks |
| [OpenCode](/docs/connectors/opencode) | Hook | Awaited `tool.execute.before` |
| [OpenHands](/docs/connectors/openhands) | Hook | Native OpenHands hooks |
| [OmniGent](/docs/connectors/omnigent) | Custom policy | Six in-process policy phases (`ALLOW`, `ASK`, `DENY`) |
| [OpenClaw](/docs/connectors/openclaw) | Proxy | Model requests and responses, plus `before_tool_call` |
| [ZeptoClaw](/docs/connectors/zeptoclaw) | Proxy | Model requests and responses |

- **Proxy connectors** route model traffic through the DefenseClaw proxy.
- **Hook connectors** wire into the agent's native lifecycle hooks; the agent
  talks directly to its model provider.
- The [ACP guard](/docs/acp-guard) is a separate path for native ACP entry
  points. [Connector compatibility](/docs/connectors/compatibility) lists the
  versioned hook contracts.

<Callout type="info">
**One gateway, many hook connectors.** A single DefenseClaw gateway can serve several hook connectors at once, each with its own guardrail posture under `guardrail.connectors.<name>` — pick **Add** (not Replace) when you run a second `setup <connector>`. Proxy connectors (OpenClaw, ZeptoClaw) bind a listener and own the traffic plane, so they can't be multi peers. See [Multi-connector](/docs/setup/guardrail/multi-connector).
</Callout>

## Platform support

Each connector page covers its macOS/Linux and native Windows setup, paths,
dependencies, and enforcement limits. **Supported** means the connector is
available through the ordinary setup path.

| Connector | macOS / Linux | Native Windows x64 | Important Windows boundary |
| --- | --- | --- | --- |
| [Claude Code](/docs/connectors/claudecode) | **Supported** | **Supported** | Direct executable hooks; Git for Windows is optional and WSL is outside the native contract. |
| [Codex](/docs/connectors/codex) | **Supported** | **Supported** | Event-bound system PowerShell bridge to the packaged hook executable plus native OTLP; no resumable native ask response. |
| [Kiro](/docs/connectors/kiro) | **Supported** | **Supported** | Regular connector: workspace-scoped native hooks in `.kiro/hooks` for Kiro IDE and `kiro-cli --v3`, a CLI 2.x agent config for bare `kiro-cli`, plus optional ACP via the shipped stdio guard. |
| [Amp](/docs/connectors/amp) | **Supported** | **Supported** | Owner-only TypeScript system-policy plugin; no shell hook or native OTLP exporter. |
| [Cursor](/docs/connectors/cursor) | **Supported** | **Supported** | Managed PowerShell adapter; DefenseClaw does not enable Cursor's native ask response. |
| [Devin CLI and Devin Desktop](/docs/connectors/devin) | **Supported** | **Supported** | Exact same-user CLI `3000.4.25` hook admission. Devin Desktop's default Devin Local agent shares the CLI hooks; its legacy Cascade agent is not covered. The separate native `devin acp` entry point is cataloged for the shared guard, while cloud Devin, proxy, and native OTLP remain excluded. |
| [GitHub Copilot CLI](/docs/connectors/copilot) | **Supported** | **Supported** | Uses Copilot's PowerShell hook field; upstream Windows sandboxing cannot enforce per-path denials. |
| [Antigravity](/docs/connectors/antigravity) | **Supported** | **Supported** | Native PowerShell launcher; only `PreToolUse` can block or ask. |
| [Hermes](/docs/connectors/hermes) | **Supported** | **Supported** | Direct executable hook is shell-free, but Hermes' own terminal tool depends on its bundled Git Bash. |
| [OpenCode](/docs/connectors/opencode) | **Supported** | **Supported** | Direct Windows execution is supported; only awaited `tool.execute.before` can block. |
| [OmniGent](/docs/connectors/omnigent) | **Supported** | **Supported — native degraded** | Server/SDK policy path only; terminal wrappers and filesystem/network/L7 sandbox parity are unavailable. |
| [OpenHands](/docs/connectors/openhands) | **Supported** | **Unsupported** | OpenHands CLI requires WSL, and DefenseClaw has no WSL connector path. |
| [OpenClaw](/docs/connectors/openclaw) | **Supported** | **Unsupported** | Its DefenseClaw integration requires the guardrail proxy, which native Windows does not host. |
| [ZeptoClaw](/docs/connectors/zeptoclaw) | **Supported** | **Unsupported** | Its DefenseClaw integration requires the guardrail proxy and upstream publishes macOS/Linux builds. |

Connectors that earlier releases shipped under other names, or that were
removed, are listed with migration steps in
[Upgrade → Renamed and removed connectors](/docs/get-started/upgrade#renamed-and-removed-connectors).

## Approvals

Native ask is event-specific: OpenClaw (`before_tool_call`), Claude Code
(`PreToolUse`), Copilot CLI (`preToolUse`), Antigravity (`PreToolUse` only),
Amp (`tool.call` and model-bound `tool.result`), and OmniGent's three
pre-action phases. Other confirmation verdicts use the connector's documented
fallback. See [HITL](/docs/hitl) for the per-event matrix.

## OpenShell sandbox

`defenseclaw sandbox run <harness>` runs a coding agent in an NVIDIA OpenShell
sandbox; see the [sandbox guide](/docs/setup/sandbox). DefenseClaw builds
sandbox images for these harnesses:

- **Run today:** [Claude Code](/docs/connectors/claudecode#in-an-openshell-sandbox),
  [Codex](/docs/connectors/codex#in-an-openshell-sandbox),
  [OpenCode](/docs/connectors/opencode#in-an-openshell-sandbox),
  [GitHub Copilot CLI](/docs/connectors/copilot#in-an-openshell-sandbox),
  [Kiro CLI](/docs/connectors/kiro#in-an-openshell-sandbox),
  [Hermes Agent](/docs/connectors/hermes#openshell-sandbox),
  [OpenHands](/docs/connectors/openhands#openshell-sandbox),
  [OmniGent](/docs/connectors/omnigent#openshell-sandbox) and
  [Antigravity](/docs/connectors/antigravity#openshell-sandbox).
- **Cannot run yet:** [Amp](/docs/connectors/amp#in-an-openshell-sandbox),
  [Cursor Agent](/docs/connectors/cursor#in-an-openshell-sandbox) and
  [Devin CLI](/docs/connectors/devin#in-an-openshell-sandbox) need a vendor
  account before any agent turn, so their images have not passed
  DefenseClaw's hook check.

OpenClaw and ZeptoClaw do not run in a sandbox. The
[capability matrix](/docs/capability-matrix#i-want-to-run-the-agent-in-an-openshell-sandbox)
shows each harness's image pin, hook tier and verification.

## How a connector is structured

<Flow
  direction="TB"
  caption="Every connector implements the same Go interface; individual methods may report that an agent does not support that capability."
>
  <Node id="setup" kind="connector">{`Setup(ctx, opts)\nwrite hook scripts,\nback up agent files,\nregister routes`}</Node>
  <Node id="auth" kind="connector">{`Authenticate(r)\nverify gateway token`}</Node>
  <Node id="route" kind="connector">{`Route(r, body)\nextract upstream + model\n+ stream + headers`}</Node>
  <Node id="teardown" kind="connector">{`Teardown(ctx, opts)\nrestore agent files`}</Node>
  <Node id="verify" kind="connector">{`VerifyClean(opts)\nno residual artifacts`}</Node>
  <Edge from="setup" to="auth" />
  <Edge from="auth" to="route" />
  <Edge from="route" to="teardown" />
  <Edge from="teardown" to="verify" />
</Flow>

The interface is defined in [`internal/gateway/connector/connector.go`](https://github.com/cisco-ai-defense/defenseclaw/blob/main/internal/gateway/connector/connector.go); each per-connector file (`claudecode.go`, `codex.go`, `cursor.go` via `hook_only.go`, ...) implements it.
