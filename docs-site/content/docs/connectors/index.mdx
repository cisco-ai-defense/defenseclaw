A connector is how DefenseClaw guards one coding agent. **Hook** connectors register with the agent's own hooks or plugin, and the agent keeps talking to its model provider directly. **Proxy** connectors send the agent's model traffic through the DefenseClaw guardrail proxy.

Connectors are the adapter layer between agent frameworks and DefenseClaw. They share one Go interface, but each connector advertises only the capabilities its agent actually exposes. Proxy routing, lifecycle hooks, subprocess wrapping, telemetry and approval support therefore vary by connector.

Where an agent cannot ask, a confirm verdict becomes an alert with the original action kept. You can review it in audit or the TUI, but you cannot resume the call. The [capability matrix](/docs/connectors/capability-matrix) has the full per-connector detail, and [Human approval](/docs/guardrail) has the per-event matrix.

One gateway can serve several hook connectors, each with its own posture under `guardrail.connectors.<name>`. Choose **Add**, not Replace, when you run a second `setup <connector>`. Proxy connectors own the traffic plane and cannot be combined this way. See [Multi-connector](/docs/guardrail/multi-connector).

## OpenShell sandbox

`defenseclaw sandbox run <harness>` runs a coding agent in an NVIDIA OpenShell sandbox. The [sandbox guide](/docs/sandboxes/first-session) has setup and every command.

- **Run today:** [Claude Code](/docs/connectors/claudecode), [Codex](/docs/connectors/codex), [OpenCode](/docs/connectors/opencode), [GitHub Copilot CLI](/docs/connectors/copilot), [Kiro](/docs/connectors/kiro), [Hermes](/docs/connectors/hermes#openshell-sandbox) and [Antigravity](/docs/connectors/antigravity#openshell-sandbox).

OpenClaw and ZeptoClaw do not run in a sandbox.

## How a connector is structured

Every connector implements one Go interface, defined in [`internal/gateway/connector/connector.go`](https://github.com/cisco-ai-defense/defenseclaw/blob/main/internal/gateway/connector/connector.go). Each connector reports only the capabilities its agent offers, so proxy routing, hooks, subprocess wrapping, telemetry and approval support differ per agent. Use the [capability matrix](/docs/connectors/capability-matrix) to compare them and the [hook contracts](/docs/connectors/compatibility) page for supported agent versions.

| Method | Runs | Purpose |
| --- | --- | --- |
| `Name`, `Description` | Always | Identify the connector. |
| `ToolInspectionMode`, `SubprocessPolicy` | Always | Report how tool calls are inspected and whether setup installs PATH shims. |
| `Setup` | When an agent is wired in | Back up the agent config and add DefenseClaw's hooks, plugin or provider entries. |
| `Teardown` | When an agent is taken out | Restore the config, or remove only DefenseClaw's entries. |
| `VerifyClean` | After `Teardown`, and before another connector's `Setup` | Fail with a list of leftover hooks, env files, config patches or shims. |
| `Authenticate` | On each request | Accept or refuse the caller. |
| `Route` | On each proxied LLM request | Read the request signals the proxy needs. |
| `SetCredentials` | At gateway boot | Give the connector the gateway token and master key. |

Two optional interfaces cover the rest. `HookEndpoint` lets a connector declare its hook route, for example `/api/v1/codex/hook`, which the gateway's API server registers when it starts. `NotifyEndpoint` does the same for an auxiliary notify bridge. Cursor and the other hook-only connectors share `hook_only.go`. Other connectors have a file of their own, such as `claudecode.go`, `codex.go` and `devin.go`.

### Hook and proxy paths

| | Hook connector | Proxy connector |
| --- | --- | --- |
| Data path | The agent talks to its upstream directly. | The agent's model calls go through the guardrail proxy (port 4000 by default). |
| Enforcement | Only the events the selected hook contract declares as blocking. | Request and response policy in the proxy, plus tool-call checks. |
| Several at once | Yes, each with its own posture under `guardrail.connectors.<name>`. | No. A proxy connector owns the traffic plane. |
| OS | Linux, macOS, Windows | Linux, macOS |
