OpenClaw is the connector DefenseClaw was designed against. DefenseClaw ships a
first-party TypeScript plugin for it. The plugin routes recognized LLM provider
requests and their responses through the guardrail proxy. It also sends
OpenClaw's `before_tool_call` events to the DefenseClaw gateway. Coverage
depends on which Node transport sent the request; see
[Transport coverage](#transport-coverage).

## Platform support

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw hosts the required guardrail proxy and installs the first-party OpenClaw plugin. Subprocess policy is shell shims on both. |
| Native Windows x64 | **Unsupported** | DefenseClaw is hook-only on Windows, while the OpenClaw connector requires the guardrail proxy. |

## Setup

<Tabs items={['macOS / Linux', 'Windows']}>

<Tab value="macOS / Linux">

```bash
defenseclaw setup openclaw --mode observe --restart
defenseclaw setup openclaw --mode action --human-approval --rule-pack default --restart
```

</Tab>

<Tab value="Windows">

<Callout type="warning" title="Native Windows setup is unsupported">
DefenseClaw does not host the guardrail proxy on Windows, so it cannot install
or enforce the OpenClaw connector there. There is no supported WSL, Docker,
VM, or mixed native/POSIX workaround; run the connector on macOS or Linux.
</Callout>

</Tab>

</Tabs>

`setup openclaw` is the OpenClaw alias for the shared guardrail setup. The proxy
is always in the data path: `--mode observe` records without blocking, and
`--mode action` enforces.

- For the alias flags, see [shared alias flags](/docs/setup/guardrail/aliases#shared-flags).
- For recipes, the wizard and the full flag list, see [Guardrail setup](/docs/setup/guardrail).

OpenClaw-specific differences:

- Proxy aliases have no `--fail-mode` flag. Use `defenseclaw guardrail fail-mode <open|closed>`.
- The proxy listens on port `4000` by default. Change it with `--port <int>`.
- To add the LLM judge, pass `--detection-strategy regex_judge --judge-model <provider/model> --judge-api-key-env DEFENSECLAW_LLM_KEY`.
- Redaction follows the v8 bucket and profile policy. Edit `observability.destinations[].routes[].selector.buckets`
  and `observability.redaction_profiles`, then follow [Redaction → Verify policy](/docs/reference/redaction#verify-policy).

DefenseClaw limits its OpenClaw-tree changes to `extensions/defenseclaw/` and
its own allow and load entries in `openclaw.json`. It stores a hash-checked
backup of `openclaw.json` before editing. Teardown restores the file, or
removes only DefenseClaw entries when the file has changed since setup.

## Hook capabilities

The proxy can block inspected fetch requests, fetch responses, and tool calls.
The bundled plugin provides native approval for `before_tool_call`, including
chat-origin sessions.

### HITL through the OpenClaw plugin

OpenClaw has a native, plugin-mediated approval flow in its chat origin. The
operator approves or denies without leaving OpenClaw.

- For an action-mode `confirm` verdict, the plugin returns OpenClaw's
  `requireApproval` object with a deny-on-timeout policy.
- OpenClaw applies the decision.
- The plugin's `onResolution` callback logs the result. It does not send a
  separate resolve request to the gateway.

Other native-ask connectors, such as Amp and Claude Code, use their own host
approval UI instead of a plugin. Connectors and hook events without native ask
apply their documented fallback. Their events stay visible in audit and
`defenseclaw tui`, but the TUI cannot resume the original call. See
[HITL](/docs/hitl) for the per-connector matrix.

### Transport coverage

The plugin patches `globalThis.fetch`, Node `https.request`, `http.request` and
`http.get`, and the global Undici dispatcher. A matching request is redirected
through the guardrail proxy, where DefenseClaw can inspect its request and
response. The match and passthrough boundaries are transport-specific:

| Transport | Redirected through the proxy when | Unclassified request behavior |
| --- | --- | --- |
| `globalThis.fetch` | The destination is a known provider, or the method, path, and readable body form a recognized LLM request shape | Passes through and emits egress passthrough telemetry. |
| `https.request` | The destination is a known provider or its path has a recognized LLM suffix | Passes through and emits egress passthrough telemetry. |
| `http.request` / `http.get` | Its non-safe destination has a recognized LLM path, including supported known or local-provider paths | Passes through without guaranteed passthrough telemetry. |
| Undici global dispatcher | Its non-safe destination is a known provider or has a recognized LLM path | Passes through without guaranteed passthrough telemetry. |

Raw sockets, custom transports, and libraries that bypass all patched entry
points are outside this inspection boundary. An egress event proves that the
plugin observed a transport branch; it does not mean the request or response
was proxied and inspected.

### Check interception

OpenClaw 2026.6.8 and later can send provider traffic through undici or
embedded runtimes that skip a fetch-only patch. The plugin runs a sentinel
self-test that never leaves the host, and `defenseclaw doctor` reports the
result as **OpenClaw interception**.

- Doctor fails that row when the self-test cannot prove a rewrite onto
  `:4000`, even if `/health/liveliness` returns 200.
- If agent turns succeed while doctor says traffic is not intercepted, restart
  OpenClaw so the plugin reloads, then rerun doctor.

### Correlation headers

Plugin requests use the shared DefenseClaw header vocabulary, as context
allows: `X-DefenseClaw-Run-Id`, `X-DefenseClaw-Session-Id`,
`X-DefenseClaw-Trace-Id`, `X-DefenseClaw-Agent-Id`,
`X-DefenseClaw-Agent-Name`, `X-DefenseClaw-Policy-Id`,
`X-DefenseClaw-Agent-Instance-Id` and `X-DefenseClaw-Sidecar-Instance-Id`. The
HTTP client also sends `X-DefenseClaw-Client`. There is no
`X-DefenseClaw-Correlation-Id` header.

- Optional fields are omitted when OpenClaw has not supplied their context.
- The fetch interceptor mints a fresh trace ID for each LLM call and reuses the
  latest tool context for run and session attribution.
- The gateway can echo sticky agent and sidecar instance IDs, so later requests
  share the same runtime identities.

### Protocol compatibility

The gateway client speaks the OpenClaw WebSocket handshake for protocols v3 and
v4. It sends `minProtocol: 3` and `maxProtocol: 4`, and OpenClaw returns the
negotiated protocol in `hello-ok`. Protocol v4 installs work, and v3 endpoints
keep the challenge-response device flow.

### Subprocess policy

The policy is `shims` on every platform. Connector setup installs PATH shims
for `curl`, `wget`, `ssh`, `nc`, `pip`, and `npm` that send each invocation to
the gateway's tool-inspection endpoint before running the real binary. Shims
inspect those command paths only; they do not provide syscall, filesystem, or
network isolation.

## Sandbox

OpenClaw does not run in an OpenShell sandbox. See the
[capability matrix](/docs/capability-matrix) for sandbox support by connector.
A host that still carries the removed standalone OpenClaw sandbox should run the
[legacy cleanup](/docs/setup/sandbox) first.

## Disable

```bash
defenseclaw guardrail disable --connector openclaw --yes
```

`--connector` turns off only OpenClaw on a multi-connector install. On a
single-connector install, run `defenseclaw guardrail disable --yes`. Teardown
restores `~/.openclaw/openclaw.json` from the backup, removes the plugin
entries, and stops the proxy. To remove the connector from the config, use
`defenseclaw setup remove openclaw`; see [Quick aliases](/docs/setup/guardrail/aliases).
