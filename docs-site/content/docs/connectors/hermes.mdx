DefenseClaw adds hooks to the default profile's `config.yaml` and approves exactly those hook commands. This is a hook connector: Hermes talks to its model provider directly and no proxy is involved.

## Platform support

<ConnectorSupport id="hermes" />

## Set up

```bash
defenseclaw setup hermes                # observe (default)
defenseclaw setup hermes --mode action  # block on policy hits
```

On Windows, run the same commands in PowerShell. Interactive setup asks for the mode, whether to add to or replace an existing connector roster, and whether to add an LLM judge. For scripts, pass `--yes --mode observe` (or `--mode action`).

Then reload or restart every Hermes host. Hermes registers hooks in each running process, so restarting the DefenseClaw gateway does not reload them. Until you reload, setup and doctor report `pending_reload`.

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` reports no failed check for it.


## What it can block or ask

<HookEventsList connector="hermes" />

- Only `pre_tool_call` can block, and only when the hook returns valid block JSON.
- Hermes has no hook that stops a prompt. A matching prompt reaches the model. Tool-call rules still block.
- Hermes has no native ask. A confirm verdict is recorded and alerted, and the hook returns nothing. The standalone enterprise profile blocks it instead.
- The other registered events are audit only.

## Files it changes

| What | Where |
| --- | --- |
| Hooks | `$HERMES_HOME/config.yaml`, `hooks` block (Windows default `%LOCALAPPDATA%\hermes\config.yaml`) |
| Approvals | `shell-hooks-allowlist.json` in the same folder |
| Hook program, macOS and Linux | `~/.defenseclaw/hooks/hermes-hook.sh` |
| Hook program, Windows | `%USERPROFILE%\.local\bin\defenseclaw-hook.exe` (one-line install) or `%LOCALAPPDATA%\DefenseClaw\HookRuntime\defenseclaw-hook.exe` (Setup installer) |

## Limits

- The connector covers the default profile only. Named-profile homes and multiplex gateways are rejected.
- Hermes runs the call when a hook times out or cannot start. In the supported releases it blocks only on a valid block answer and, from Hermes 0.21, on exit code 2.
- Hermes runs every hook registered for an event, in order. A hook added after DefenseClaw's can change a command DefenseClaw already checked.
- `hermes --safe-mode`, or a `HERMES_HOME` without the `hooks` block, runs with no DefenseClaw hook.
- A host that is not reloaded keeps its old state, also after you turn the connector off.

## On a managed computer

The per-user commands on this page do not run on a computer with a standalone enterprise install. On Linux and macOS, `defenseclaw` there offers only `sandbox` commands, `help` and `--version`: anything else prints "This computer is managed; only `defenseclaw sandbox` commands are available here." and exits 2. On native Windows, `defenseclaw` is the administrator's command: it refuses `setup hermes` and `setup remove`, and has no `guardrail` group. Hermes is protected per user: the guardian writes the hooks and exact approvals into each enrolled account's Hermes config.

The administrator manages Hermes in the managed `config.yaml`. `guardrail.connectors.hermes: {}` adds it for the accounts that [enrollment](/docs/enterprise/configure/enrollment) selects, the connector's `mode` and `hook_fail_mode` tune it, and `guardrail.connectors.hermes.enabled: false` removes it. Apply the change as in [Change the config](/docs/enterprise/operate/lifecycle#change-the-config), then check it with `enterprise <os> verify --json` (on Windows add `--profile standalone`; see [Operations](/docs/enterprise/operate/operations)). Read `connectors.hermes.hooks_installed` and `targets`. On Linux and macOS these summarize the last reconcile; check the current files with `enterprise hooks verify --json` as root. `enterprise policy verify` checks machine-policy connectors only. See [Managed verification](/docs/reference/connectors/hermes#managed-verification).

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

This keeps Hermes's settings. Turn it back on with `defenseclaw guardrail enable`. To remove the connector, run `defenseclaw setup remove hermes --yes` (add `--force` if it is the last one). Then reload every Hermes host.

On a multi-connector install, add `--connector hermes` to `guardrail disable` and `guardrail enable` to change only this agent.
