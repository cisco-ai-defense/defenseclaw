DefenseClaw installs a TypeScript policy plugin in Amp's user plugin directory. Amp waits for the plugin's verdict on each tool call and each tool result. Amp talks to its model provider directly and no proxy is involved.

## Platform support

<ConnectorSupport id="amp" />

## Set up

On a new install, run `defenseclaw init --connector amp` first. Until DefenseClaw is initialized, `defenseclaw setup amp` stops with `DefenseClaw is not initialized — run 'defenseclaw init' first.`

```bash
defenseclaw setup amp                                  # first setup defaults to observe, global
defenseclaw setup amp --mode action                    # enforce calls and results
defenseclaw setup amp --workspace /path/to/repo        # also inventory the repository
```

A re-run without `--mode` keeps the current mode. On Windows, use a Windows
path. The plugin is per user in every case.
`--workspace` sets the workspace for the whole DefenseClaw install, including
Amp's project inventory. Use it on a single-Amp install: if it would move peer connectors
from their current scope, setup refuses and changes nothing. On a multi-connector
install, run `defenseclaw setup amp` without `--workspace` for global protection.

For headless runs, give Amp time to load plugins:

```bash
amp -x "your prompt" --plugin-ready-timeout 30
```

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` reports no failed check for it.


## What it can block or ask

What a gateway outage does to an Amp call, per install and fail mode, is in the [gateway outage table](/docs/reference/apis/capability-matrix#gateway-outage).

<HookEventsList connector="amp" />

- `tool.call` runs before the tool. DefenseClaw can allow it, reject it or ask through Amp's confirmation UI.
- `tool.result` runs before the output reaches the model. DefenseClaw can keep it, withhold or replace it, or ask. It cannot undo a side effect.
- `session.start`, `agent.start` and `agent.end` are observed only.
- A prompt has no hook, so a matching prompt reaches the model. Tool-call rules still block.
- Ask works only for the active foreground thread. A background thread or missing UI rejects the call instead of allowing it.

### Rejected command display

In the tested Amp 0.0.1790798464 build, a policy-rejected shell call can still have
a checked, collapsed **Ran 1 command** summary. This counts an attempted tool
call; the command did not execute. Expand the tool result to see **Tool rejected
by plugin** and the DefenseClaw policy reason. The matching DefenseClaw audit
block and absent command output confirm the rejection. The plugin sends Amp
`reject-and-continue` with that reason before execution; Amp's [plugin API](https://ampcode.com/docs/plugin-api)
does not provide a field for changing the collapsed summary.

## Files it changes

| What | Where |
| --- | --- |
| Plugin | `~/.config/amp/plugins/defenseclaw.ts` (Windows `%USERPROFILE%\.config\amp\plugins\defenseclaw.ts`) |

It holds a connector-scoped token and is limited to your account. Setup keeps an existing file, and teardown restores it.

## Limits

- Amp runs plugin code, including top-level code, when it loads. DefenseClaw does not sandbox that code, and Amp does not define the order of several plugins' handlers. In action mode `defenseclaw doctor` warns about other `.ts` plugins.
- Without `--plugin-ready-timeout`, a headless turn can start before the plugin loads, and no plugin can govern events before it loads.
- The plugin is in a folder you own. A session started with another `XDG_CONFIG_HOME` or `HOME` does not load it.
- Amp Orbs run remotely and are not covered.
- Amp cannot run in an OpenShell sandbox yet.

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

With the default gateway restart, disabling removes DefenseClaw's plugin file.
This preserves your other Amp settings. `defenseclaw guardrail enable`
reinstalls DefenseClaw's plugin. To remove the connector, run
`defenseclaw setup remove amp --yes` (add `--force` if it is the last one). A
modified bridge makes `guardrail disable` and `setup remove` refuse before
saving configuration, and the gateway is left as it was; `defenseclaw doctor`
reports the change. Preserve your edits, run
`defenseclaw setup amp --yes --restart`, then retry. Relaunch Amp afterwards.

On a multi-connector install, add `--connector amp` to `guardrail disable` and `guardrail enable` to change only this agent.
