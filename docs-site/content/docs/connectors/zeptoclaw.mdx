DefenseClaw rewrites the provider `api_base` values in `~/.zeptoclaw/config.json` to the local guardrail proxy. Every request is checked on the way out and every response on the way back. This is a proxy connector.

## Platform support

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw hosts the guardrail proxy. |
| Native Windows x64 | **Unsupported** | ZeptoClaw publishes no native Windows build, and the connector needs the guardrail proxy, which DefenseClaw does not host on Windows. |

## Set up

On a new install, run `defenseclaw init --connector zeptoclaw` first. Until DefenseClaw is initialized, `defenseclaw setup zeptoclaw` stops with `DefenseClaw is not initialized — run 'defenseclaw init' first.`

```bash
defenseclaw setup zeptoclaw --mode observe --restart
defenseclaw setup zeptoclaw --mode action --rule-pack default --restart
```

The proxy is in the data path in both modes. Observe records policy findings without blocking on those findings; a gateway outage still stops proxied requests. Action enforces policy. Run `defenseclaw doctor` to check the result.

## Check it

```bash
defenseclaw status
```

The agent appears under **Agents** with its mode. `defenseclaw doctor` reports no failed check for it.


## What it can block or ask

<HookEventsList connector="zeptoclaw" />

- The proxy can block a checked request, a checked response and a tool-call payload.
- ZeptoClaw has no native ask. A confirm verdict takes an immediate fallback with the original action kept. Audit and the TUI can show it but cannot resume it.

## Files it changes

| What | Where |
| --- | --- |
| Providers and private-endpoint setting | `~/.zeptoclaw/config.json` (`providers.*.api_base`, `safety.allow_private_endpoints`) |
| Subprocess shims | on `PATH` (`~/.defenseclaw/shims`), for `curl`, `wget`, `ssh`, `nc`, `ncat`, `pip` and `npm` |

`safety.allow_private_endpoints` is set to `true` so ZeptoClaw accepts the `127.0.0.1` address.

## Limits

- The shims inspect those seven commands only. They give no syscall, filesystem or network isolation.
- ZeptoClaw 0.9.2 sends `max_tokens`, which the Bedrock `gpt-5.6-luna` model refuses. Pick a model that accepts it.
- The local event database keeps seven days of prompts and responses by default. Treat it as sensitive data and set `observability.local.retention_days` (see the reference).
- ZeptoClaw does not run in an OpenShell sandbox.

## Turn it off

For a per-user, single-connector install:

```bash
defenseclaw guardrail disable --yes
```

To drop the connector from the configuration, run `defenseclaw setup remove zeptoclaw --yes`. If ZeptoClaw is the last connector, removal refuses because the gateway would enforce nothing. To deliberately remove that last connector, run:

```bash
defenseclaw setup remove zeptoclaw --yes --force
```

Turn it back on by running the Set up command again, for example `defenseclaw setup zeptoclaw --restart`. Leaving out `--mode` keeps the mode you saved before disabling the guardrail. `defenseclaw guardrail enable` turns ZeptoClaw back on only when `guardrail.model` is set (`defenseclaw setup guardrail`); otherwise it stops with `Cannot enable: guardrail.model is not set.`

ZeptoClaw is proxy-backed and cannot run next to hook connectors. While any hook connector is configured, `defenseclaw setup zeptoclaw` refuses and changes nothing; `defenseclaw setup zeptoclaw --replace` removes the hook connectors and sets up ZeptoClaw in their place.
