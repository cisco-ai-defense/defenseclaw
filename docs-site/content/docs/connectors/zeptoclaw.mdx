ZeptoClaw is the second proxy connector. DefenseClaw rewrites the providers in
`~/.zeptoclaw/config.json` to point at the local guardrail proxy. Every request
is inspected on its way out, and every response on its way back.

## Platform support

| Platform | Status | Notes |
| --- | --- | --- |
| macOS and Linux | **Supported** | DefenseClaw hosts the required guardrail proxy. Subprocess policy is shell shims on both. |
| Native Windows x64 | **Unsupported** | ZeptoClaw publishes macOS/Linux builds, and its DefenseClaw integration requires the guardrail proxy that DefenseClaw does not host on Windows. |

## Setup

<Tabs items={['macOS / Linux', 'Windows']}>

<Tab value="macOS / Linux">

```bash
defenseclaw setup zeptoclaw --mode observe --restart
defenseclaw setup zeptoclaw --mode action --rule-pack default --restart
```

</Tab>

<Tab value="Windows">

<Callout type="warning" title="Native Windows setup is unsupported">
DefenseClaw does not host the guardrail proxy on Windows, and ZeptoClaw does
not publish a native Windows build for this integration. There is no supported
WSL, Docker, VM, or mixed native/POSIX workaround; run the connector on macOS
or Linux.
</Callout>

</Tab>

</Tabs>

`setup zeptoclaw` is the ZeptoClaw alias for the shared guardrail setup. The
proxy is always in the data path: `--mode observe` records without blocking,
and `--mode action` enforces.

- For the alias flags, see [shared alias flags](/docs/setup/guardrail/aliases#shared-flags).
- For recipes, the wizard and the full flag list, see [Guardrail setup](/docs/setup/guardrail).

ZeptoClaw-specific differences:

- Proxy aliases have no `--fail-mode` flag. Use `defenseclaw guardrail fail-mode <open|closed>`.
- The proxy listens on port `4000` by default. Change it with `--port <int>`.
- To add the LLM judge, pass `--detection-strategy regex_judge --judge-model <provider/model> --judge-api-key-env DEFENSECLAW_LLM_KEY`.
- ZeptoClaw has no native ask surface, so `--human-approval` confirm verdicts
  take their immediate fallback. See [HITL](/docs/hitl).
- Redaction follows the v8 bucket and profile policy. Edit `observability.destinations[].routes[].selector.buckets`
  and `observability.redaction_profiles`, then follow [Redaction → Verify policy](/docs/reference/redaction#verify-policy).

<Callout title="Treat local event history as sensitive data">
The mandatory database is configured by `observability.local` (by default,
`~/.defenseclaw/audit.db`) and retains seven days on a fresh configuration. Set
`observability.local.retention_days` to the reviewed retention period and limit
host access to the DefenseClaw data directory. A global
`observability.defaults.redaction_profile` or a bucket
`redaction_profile` also governs SQLite; a destination or route profile governs
only that export trust boundary. Verify the effective result with
`defenseclaw config show --effective --section observability` and
`defenseclaw observability plan`. See [Redaction](/docs/reference/redaction) for
the resolution order and [Observability](/docs/observability#local-history)
for retention behavior. Retention removes eligible rows and makes their pages
available for SQLite reuse, but the database file does not shrink automatically.
</Callout>

`safety.allow_private_endpoints` is set to `true` so the rewritten api_base (a 127.0.0.1 URL) is accepted.

## Hook capabilities

The proxy can block inspected requests, responses, and tool-call payloads.

<Callout>
ZeptoClaw has no native ask surface. Confirm verdicts take an immediate fallback with `raw_action` preserved so operators can review the original request in the TUI or audit log; neither surface can resume it.
</Callout>

### Subprocess policy

The policy is `shims` on every platform. Connector setup installs PATH shims
for `curl`, `wget`, `ssh`, `nc`, `pip`, and `npm` that send each invocation to
the gateway's tool-inspection endpoint before running the real binary. Shims
inspect those command paths only; they do not provide syscall, filesystem, or
network isolation.

## Sandbox

ZeptoClaw does not run in an OpenShell sandbox. See the
[capability matrix](/docs/capability-matrix) for sandbox support by connector.

## Disable

```bash
defenseclaw guardrail disable --connector zeptoclaw --yes
```

`--connector` turns off only ZeptoClaw on a multi-connector install. On a
single-connector install, run `defenseclaw guardrail disable --yes`. To remove
the connector from the config, use `defenseclaw setup remove zeptoclaw`; see
[Quick aliases](/docs/setup/guardrail/aliases).
