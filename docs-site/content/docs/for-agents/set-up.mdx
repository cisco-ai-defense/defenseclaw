You are an AI agent. Install DefenseClaw for the current user and set up the coding agents on this computer in observe mode. Run each step, compare with the expected output, and follow the "if it differs" branch.

## Hard rules

1. Observe first. Never switch an agent to action mode, change a fail mode, disable a connector or edit `config.yaml` by hand without the user's yes to that exact change.
2. Never print a key, token or the contents of `.env`.
3. Stop on a managed computer: if a command prints `This computer is managed` or `This device is managed` (exit `2` or `3`), or `defenseclaw status --json` shows `"deployment_mode": "managed_enterprise"`, tell the user to contact their administrator.

## Steps

1. Check the OS and CPU.

   ```bash
   uname -sm
   ```

   Expected: `Darwin arm64`, `Linux x86_64` or `Linux aarch64`. On Windows, use PowerShell and expect an x64 system.
   If it differs: `Darwin x86_64` is an Intel Mac. Stop and tell the user it is unsupported. Windows on ARM64 and x86 are also unsupported.

2. Check whether DefenseClaw is already installed and whether the computer is managed.

   ```bash
   defenseclaw status --json
   ```

   Expected on a clean computer: `command not found`. Go to step 3.
   If it prints `This computer is managed`: stop (rule 3).
   If it prints JSON: read `deployment_mode`. `managed_enterprise` means stop (rule 3). Otherwise DefenseClaw is already installed; skip to step 4.

3. Install. This is the official one-line installer; tell the user what you run.

   ```bash
   curl -LsSf https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.sh | bash -s -- --connector none
   ```

   On Windows PowerShell:

   ```powershell
   & ([scriptblock]::Create((irm https://github.com/cisco-ai-defense/defenseclaw/releases/latest/download/install.ps1))) -Connector none
   ```

   `--connector none` installs without picking an agent; step 4 sets up every agent it finds.
   Expected: the installer ends with `Next: defenseclaw init`. Open a new shell if it says `~/.local/bin` is not on `PATH`, then run `defenseclaw --version` (expect `defenseclaw, version X.Y.Z`).
   If it fails, exit `1` means not installed (an upgrade puts the previous install back) and `2` an unknown option. Report the last lines of the output; do not retry in a loop.

4. Set up the agents in observe mode.

   ```bash
   defenseclaw init --non-interactive --yes --observe-all
   ```

   Expected: a first-run report like this one (a terminal shows `✓` where a script sees `OK`):

   ```text
     OK Configured connectors: claudecode, codex

     DefenseClaw First-Run
     status=ready connectors=2 profile=observe
     …
     OK Guardrail  2 connectors: claudecode=observe, codex=observe
     OK Sidecar  …
   ```

   If `status=partial` or `needs_attention`: the report names the cause (for example an agent that is not installed). Continue to step 5 and include it in your report. For one agent only, use `defenseclaw quickstart --connector <name>`.

5. Check health.

   ```bash
   defenseclaw doctor --json
   ```

   Expected: `"outcome": "healthy"` (or `"warning"`) and `"exit_code": 0`. `"outcome": "failed"` comes with `"exit_code": 1`.
   If it differs: list each check with `"status": "fail"` and its `"remediation"`. Do not apply `--fix` without the user's yes; you may show `defenseclaw doctor --fix --dry-run`.

6. Check the gateway and the agents.

   ```bash
   defenseclaw status --json
   ```

   Expected: `sidecar.running` is `true`, and each entry in `connectors` has `"mode": "observe"`.
   If the sidecar is not running, ask the user before running `defenseclaw-gateway start`.

7. Tell the user to restart each agent so it loads the hooks.

## Report

Reply with:

- Installed: version, OS and CPU.
- Agents set up and their mode.
- `doctor` outcome and each failing check with its remediation.
- What you did not do, and what needs the user's yes (for example action mode: `defenseclaw guardrail mode action --connector <name>`).
