DefenseClaw can export to an existing telemetry stack, but the bundled local
stack gives you a loopback-only environment for development and evaluation.

For the full deep-dive on flags, dashboards, and tear-down, see [Observability → Local stack](/docs/observability/local-observability).

## What you get

## Run it

<Steps>

<Step>

### Bring up the stack

```bash
defenseclaw setup local-observability up
```

Docker Compose starts the OTel Collector, Prometheus, Loki, Tempo, and
Grafana, all bound to `127.0.0.1`. The
[reference page](/docs/observability/local-observability#what-it-brings-up)
lists the images and ports.

</Step>

<Step>

### Check the destination

`up` also writes a `local-observability` destination to `config.yaml`. A
running gateway picks it up without a restart, and active agent sessions keep
running. Confirm that it is reachable:

```bash
defenseclaw setup observability list
defenseclaw observability destination test local-observability
```

</Step>

<Step>

### Open Grafana

Visit [http://localhost:3000](http://localhost:3000) and sign in as `admin`
with the password stored in
`~/.defenseclaw/observability-stack/.grafana-admin-password`. The setup
summary tells you if your stack uses anonymous access instead; see
[Grafana access](/docs/observability/local-observability#bring-it-up).

Open **Dashboards → DefenseClaw → DefenseClaw — Overview**. The
[Grafana dashboard catalog](/docs/observability/grafana-dashboards) explains
what each of the 16 boards is for.

</Step>

<Step>

### Generate one real event

Dashboards fill only from real traffic; the destination test above does not add
events. Use a connected agent for one turn, for example ask Claude Code or Codex
to list the files in a folder. Shortly afterwards, **Hook Connectors** shows the
connector's hook calls and **Agent identity → Runtime Agent Directory** lists
the agent. Click its **Agent ID** to open [Agent360](/docs/observability/agent360).

</Step>

<Step>

### Tear it down

```bash
defenseclaw setup local-observability down
```

Stops the containers while preserving their named volumes and the configured
destination. Your audit DB is untouched. To stop the stack and disable the
destination in config, use:

```bash
defenseclaw setup local-observability down --disable-config
```

Use `reset --yes` only when you also intend to delete the stack's
Prometheus/Loki/Tempo/Grafana data.

</Step>

</Steps>

## When to graduate to your own stack

The local stack is for building intuition. For production, replace each component with the equivalent in your existing telemetry estate:

- Prometheus → your metrics platform (Datadog, New Relic, Honeycomb, ...).
- Loki → your log aggregator (Splunk, Datadog Logs, ...).
- Tempo → your tracing backend (Honeycomb, Tempo, Jaeger, ...).
- Grafana → whatever your team already uses for dashboards.

Add your collector as another destination, and DefenseClaw's signals land
alongside the rest of your telemetry:

```bash
defenseclaw setup observability add otlp \
  --name engineering \
  --endpoint otel.example.com:4317 \
  --protocol grpc
```

Destinations live under `observability.destinations` in `config.yaml`; see
[Observability](/docs/observability#destination-capabilities-and-fan-out) for
routing and redaction, and the
[configuration reference](/docs/reference/configuration) for every field.
