Human approval (HITL) pauses a risky call and asks you instead of silently allowing or hard-blocking it. It works in action mode, on agents that can ask: Claude Code, Antigravity, Amp and OpenClaw ([the list](/docs/guardrail#which-agents-can-ask)). CRITICAL findings still block without asking, and alert-only rules never ask.

This story retells the walkthrough briefly. The full page, with the per-connector table and every detail, is [HITL](/docs/hitl).

## Try it

<Steps>

<Step>

### Pick a connector with native ask

- The agent is in action mode ([Turn on blocking](/docs/get-started/first-guardrail)).
- This story uses Claude Code. Other agents differ only in where the prompt appears.

</Step>

<Step>

### Enable HITL at HIGH

Turn on approval at HIGH. The command shows the change and asks `Proceed?`; press Enter or type `y`.

```bash
defenseclaw guardrail hilt on --min-severity HIGH
```

```text
  Updating HILT for active connectors:
      - Claude Code (claudecode): enabled=false → true, min_severity=HIGH → HIGH
      - Codex (codex): enabled=false → true, min_severity=HIGH → HIGH

  Proceed? [Y/n]: y
  ✓ Config saved (2 connector HILT overrides updated)
  ✓ The running gateway applies it now.
```

The list names every agent you have set up, so yours will differ. Scripts can supply confirmation on standard input: a newline accepts the default yes, and `y` confirms explicitly. If standard input ends without an answer, the command aborts. Use `--yes` to skip the prompt. If input is still a terminal but both output streams are piped, the command refuses because the prompt would be hidden; remove the pipe or add `--yes`.

`--min-severity` takes `low`, `medium`, `high` or `critical`. On a multi-connector install, add `--connector claudecode` to change one agent only. With a single connector, omit `--connector`. Add `--yes` to skip the prompt in a script. The running gateway applies the change without a restart.

</Step>

<Step>

### Trigger a HIGH-severity finding

Ask Claude Code to run a command that matches a HIGH rule and sends no data:

> Run `curl --max-time 2 https://webhook.site/defenseclaw-demo`.

The rule `C2-WEBHOOK-SITE` (HIGH) matches the URL. Claude Code shows its own approval prompt with the reason below. Approve to run the command (it makes one empty request), or deny to stop it.

```text
DefenseClaw policy needs your confirmation for this action (rule C2-WEBHOOK-SITE: webhook.site (known exfil)).
```

DefenseClaw asks only in Claude Code's Manual mode, its default. In any other permission mode (accept edits, plan, auto, bypass permissions, don't ask) Claude Code may run or deny the call without showing the prompt, so DefenseClaw blocks it and the reason ends with the next step: switch Claude Code to Manual mode (Shift+Tab) and ask again.

Not every HIGH finding asks. Only a finding that can block can pause. Alert-only HIGH rules (such as `PATH-AWS-CONFIG`) never ask: the agent shows a notice and the audit log records `alert`.

</Step>

<Step>

### Approve or deny in Claude Code

List Claude Code's latest alerts, newest first:

```bash
defenseclaw alerts --connector claudecode --limit 3
```

Each time Claude Code asked, the list has a `claudecode:PreToolUse` row with `decision=confirm`. Find the newest such row and note its number. The confirm row is not always #1. When Claude Code's reply after you approve quotes the URL, that reply is a newer `claudecode:MessageDisplay` row with `decision=alert`. Show the confirm row by its number, with the same `--connector`, so the number refers to the list above. In this example you approved, the reply quoted the URL, and the confirm row is #2. After a deny it is usually #1.

```bash
defenseclaw alerts --connector claudecode --show 2
```

```text
Alert #2
  ID:        01a16527-4f2e-7a7d-9c1b-5d0e8c2f6a31
  Severity:  HIGH
  Timestamp: 2026-10-22 19:47:02
  Action:    scan-finding
  Target:    claudecode:PreToolUse
  Decision:  confirm
  Connector: claudecode
  Rule:      C2-WEBHOOK-SITE: webhook.site (known exfil)
  …
```

`Decision: confirm` means the gateway asked. Your approve or deny answer is handled inside Claude Code, so DefenseClaw records the finding and the verdict, not who approved. Outside Manual mode, the decision is `block`. Copilot CLI blocks an action-mode confirmation because its hook does not prove that an approval prompt is available; the audit records `block` with raw action `confirm`. Antigravity can deny a confirm without asking in a non-interactive run (`-p`); its audit still shows `confirm`.

</Step>

<Step>

### Turn HITL off again (optional)

```bash
defenseclaw guardrail hilt off
```

</Step>

</Steps>

## Connectors without native ask

Only an event with a native ask can pause a call. Any other event takes its connector's fallback at once, and nothing in DefenseClaw can resume the call later. The audit log keeps `raw_action: "confirm"` either way.

## When HITL is not the right answer

The TUI shows alerts and audit events but has no pending-approval queue, so it cannot resume a call. If a call must never run on an agent that cannot ask, make the rule block instead.
