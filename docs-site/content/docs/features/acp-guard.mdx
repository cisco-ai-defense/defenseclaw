The ACP guard sits between an editor that speaks the Agent Client Protocol (ACP), such as Zed or JetBrains, and the coding agent it runs. The editor keeps its normal agent experience. Every message between the two passes through DefenseClaw policy first.

## How it works

- Fresh `defenseclaw acp setup` writes a `DefenseClaw · <agent>` entry that starts `defenseclaw-acp`. On Linux, macOS and Windows, `defenseclaw setup acp` adopts an existing direct picker entry in place, keeping its name and `env` without adding a duplicate for that adopted key. Later `acp setup` updates entries DefenseClaw can identify for that pair. Run `acp verify` and inspect the editor's picker for any other entry that can launch the agent directly or through a copied guard. Remove such entries in the editor.
- The guard checks prompts, agent output, permission requests, file and terminal calls, and vendor extensions.
- It talks only to the gateway on a loopback address. Each request is encrypted and each verdict is authenticated, so another process on the port cannot read content or fake a verdict.
- Setup starts in observe mode: it records findings and does not block on them. In observe mode the guard still refuses a message it could not check when the profile's `fail_mode` is `closed`, and on a managed computer unless the administrator set `fail_mode: open`. Add `--activate` for action mode.
- In action mode a blocked prompt ends that turn, and the editor shows the reason as an agent message.
- Policy is set per editor and agent pair through [profiles](/docs/reference/apis/acp-guard#configuration), so one editor can enforce on one agent and observe another.

## Supported agents

`defenseclaw acp catalog` prints the list. Only agents with their own ACP mode are guarded. Other connectors are guarded through their [hooks](/docs/connectors).

| Agent | Entry point | Status |
| --- | --- | --- |
| Kiro | `kiro-cli acp` | Tested with Zed |
| Cursor | `agent acp` | Cataloged |
| OpenCode | `opencode acp` | Cataloged |
| Hermes | `hermes acp` | Cataloged |
| GitHub Copilot CLI | `copilot --acp --stdio` | Cataloged |
| Devin | `devin acp` | Cataloged |

Zed is tested. JetBrains is cataloged. A cataloged entry point matches the vendor's documentation; it does not mean DefenseClaw tested that editor and agent together.

## What it does not do

- It does not stop an agent entry the editor launches without `defenseclaw-acp`. `defenseclaw acp detect` lists those entries.
- It can only withhold what the agent sends. An agent that runs its own tools may already have run a step when its output is blocked. Keep the agent's connector hooks in action mode next to the guard to stop a step before it runs.
- An organization-wide "only these agents" rule also needs IDE policy and operating-system application control.

## Managed computers

`defenseclaw acp setup` is for a per-user install. On an enterprise managed computer an administrator enrolls each user, editor and agent with `defenseclaw-gateway enterprise acp enroll`, and the user then runs the setup command it reports. The administrator tools are `enroll`, `verify` and `revoke`. Secure Client deployments are not covered.
