DefenseClaw collects each event once and builds one record from it. Log records are stored in local history. Every record, logs, traces and metrics, goes to the destinations you add: an OpenTelemetry (OTLP) collector, Splunk, Galileo, a file, or a webhook. Each destination picks the buckets it wants and applies its own redaction.

## How it works

- **Buckets.** Every record belongs to one of 14 buckets, such as `security.finding`, `enforcement.action` or `model.io`. You can turn off collection per bucket. The full list is in the [reference](/docs/reference/observability#buckets).
- **Local history.** A SQLite database in the DefenseClaw data directory keeps every collected log, 7 days by default. It cannot be turned off or filtered. A small set of content-free compliance events is always written, even when you turn off collection for their bucket.
- **Destinations.** With no destination configured, nothing leaves the computer. An enabled destination with no filter receives every bucket and every signal its kind supports. Adding a second destination adds a second copy. It is not a failover.
- **Independent delivery.** Each destination has its own bounded queue, retry and health. A slow or failing destination does not block agents or other destinations.
- **Redaction.** DefenseClaw redacts a record once, per destination, before it is sent. Four built-in profiles run from `none` (the default) to `strict`. See [Redaction](/docs/reference/observability/redaction).

<Callout type="warn" title="The default sends full content">
With no redaction profile, an enabled destination receives prompts, responses, tool arguments, file paths and identifiers as recorded. Choose a profile before you send to anything outside your trust boundary.
</Callout>

## What it does not do

- It does not keep traces or metrics locally. Local history holds logs; traces and metrics exist only at the destinations you send them to.
- It does not replace the audit log. For logs, local history is the durable record; destinations are copies.
- It does not backfill. Records that a destination missed while it was down or while the gateway restarted are not resent. Export the local history if you need them.
- Dashboards add no redaction of their own. They show what the destination received.
- Webhook alerts to Slack, PagerDuty or Webex are a separate feature. They notify; they do not export telemetry.

## Check your setup

```bash
defenseclaw setup observability list
```

```text
  Observability destinations
  --------------------------
  NAME                     KIND         STATE     SIGNALS                BUCKETS  POLICY               REDACTION

  engineering              otlp         enabled   logs,traces,metrics    14       capability_default   unredacted (none)

  Plan digest: 9cf948dc…
```

`defenseclaw observability plan` shows the same policy per bucket and signal.
