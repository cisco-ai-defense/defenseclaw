AI Discovery answers two questions. What AI is installed on this machine? And what actually ran, and where did it send data? The first answer comes from an inventory scan. The second comes from three runtime planes inside the gateway.

## Installed or ran

| Question | Answered by | Needs the gateway |
| --- | --- | --- |
| Which agents are installed? | `defenseclaw agent discover` | No |
| What AI is on the machine (agents, CLIs, local models, MCP servers, skills, packages, desktop apps)? | The continuous scan, read with `defenseclaw agent usage` | Yes |
| Which agent assets exist, with provenance? | `defenseclaw aibom scan` | No |
| Which IDE plugins does each user have? | `defenseclaw agent ide-plugins` | Yes |
| What ran, and who did it talk to? | The runtime planes | Yes |

The inventory proves presence, not activity. A detected component may be dormant. A process that ran but is not in the inventory is the case only the runtime planes see.

## The three runtime planes

| Plane | Watches | Needs |
| --- | --- | --- |
| A, inference heartbeat | Sustained CPU in a scriptable runtime, or memory large enough to hold model weights | Nothing for your own processes |
| B, shadow egress | Which process sends data to which AI provider, with the DNS answer that names the peer | Elevated rights for other users' processes |
| C, agent actions | Process, file and identity events that descend from an AI agent | Root and Full Disk Access on macOS, capabilities on Linux, audit policy on Windows |

A new configuration turns on A and B. Plane C is opt-in. Every plane reports what it cannot see instead of showing a clean host. Per-OS grants and detail: [AI Discovery reference](/docs/reference/scanning/ai-discovery#runtime-planes).

## Where the data goes

- The gateway keeps every scan in the local audit database. This is always on.
- It exports `ai_discovery`, `ai_component.*` and `ai.runtime.*` records to your observability destinations: Grafana, Splunk or any OTLP destination.
- It never sends discovery results to Galileo.
- On managed enterprise devices it also reaches the AI Defense destination, if configured.

## Privacy

- Environment variable names are recorded, never values.
- File paths leave the host as hashes. Raw paths need `ai_discovery.store_raw_local_paths: true`.
- Model discovery reads file headers and small metadata files, never model weights or document contents.
- The IDE plugin scan reads small metadata files only and runs per user. `ai_discovery.ide_inventory` limits it to AI plugins or turns it off.
- Runtime planes read process arguments. Those are classified as content, so each destination's redaction profile decides whether they leave the host.
