DefenseClaw scans every skill, MCP server and plugin before an agent can use it. A scan gives a severity. Your admission settings turn that severity into an action: allow it, warn, or block and quarantine it. Block and allow lists you write always come first.

- **When it runs.** The gateway's install watcher checks a skill, plugin or MCP server when it appears in a watched folder or when an agent adds it. A rescan runs every 60 minutes and whenever the asset or the scanner settings change. The CLI runs the same check on demand.
- **What a verdict does.** The defaults quarantine CRITICAL and HIGH skills, warn on MEDIUM, and allow the rest. A rejected skill or plugin moves to a quarantine folder and is disabled. A rejected MCP server stays where it is and its tool calls are refused.
- **When the scanner fails.** A scan that errors or cannot run counts as rejected. Admission fails closed.
- **Blocked tool calls.** Agent hooks refuse a denied skill, plugin or MCP tool even if the install watcher never saw it.
- **A judge reads what the rules flag.** Both scanners use the LLM judge when a model and key are set (`DEFENSECLAW_LLM_KEY`). Set one up; the rules alone miss most malicious assets.

## Skills

A skill is a bundle of instructions an agent follows. The skill scanner checks `SKILL.md` and bundled files for prompt injection, dangerous shell and Python calls, and untrusted binaries. Findings at HIGH or above quarantine the skill. Findings from MEDIUM up to that line warn and go to the review queue.

```text
defenseclaw skill scan --path ~/code/risky-skill
```

See [Scan a skill](/docs/how-to/scanning/scan-a-skill). Settings: [Scanners](/docs/reference/scanning/scanners#skill-scanner).

## MCP servers

An MCP server lists tools an agent can call. The MCP scanner reads each tool's name, schema and description, and flags tools whose behavior does not match what they claim. DefenseClaw scans a server when you add it with `defenseclaw mcp set`, when an agent adds it, and on every rescan. Until a new server has a verdict, the Claude Code and Codex hooks refuse its tool calls.

See [Scan an MCP server](/docs/how-to/scanning/scan-an-mcp-server).

## Plugins

Plugins go through the same admission check. Plugin scanning runs from `defenseclaw plugin scan` and from the install watcher. Settings use `admission.plugin` and the `plugin-scanner` override key. Block and allow lists work the same way as for skills.

## What it does not do

- It does not scan tools. Nothing installs a tool, so tools have name lists only.
- It does not stop a process that is already running. A block stops tool calls and new installs; use `disable` or `quarantine` for a running asset.
- A local MCP scan starts the server as you. Scan only servers you would run.
- Admission belongs to the device. Rules can be scoped to a connector, not to a user or group.
