`defenseclaw setup guardrail` sets the connector, mode, scanner, judge, human approval and rule pack, then restarts the gateway. Run it interactively the first time; re-run it with flags and `--non-interactive` for scripts and CI. To build a command in the browser, use the [command generator](/docs/command-generator).

The guardrail checks what your agent is about to do (a prompt, a shell command, a tool call) against rules, and answers allow, alert, ask you, or block. It runs in the gateway. The agent's hook only carries the question and the answer.

The picker's "never block" covers policy findings. With the `strict` and `managed-strict` packs, observe still blocks an agent that changes DefenseClaw's own files, such as a copy into `~/.defenseclaw` (rule `tamper.detector_state_write`); the default and permissive packs raise a HIGH alert and do not block it. See [Packs and modes](/docs/guardrail/packs-and-modes).

## Same setup, no prompts

```bash
defenseclaw setup guardrail \
  --non-interactive \
  --connector claudecode \
  --mode observe \
  --scanner-mode local \
  --detection-strategy regex_only \
  --restart
```

`--non-interactive` (aliases `--accept-defaults` and `--yes`) skips every prompt; missing flags fall back to the wizard defaults. The judge stays off until you pass `--judge-model`. The saved detection strategy defaults to `regex_judge`, but with the judge off only the regex lane runs, so the setup summary and `guardrail status` show the strategy that runs: `regex_only`.

The tree below shows Claude Code on Linux and macOS. On Windows the registered

`setup guardrail` saves `config.yaml`. The `picked_connector` hint in `~/.defenseclaw` is written by the connector aliases (`defenseclaw setup <connector>`) and by `install.sh --connector`, not by `setup guardrail`. The gateway writes the connector files when it starts: for Claude Code, the hook scripts under `~/.defenseclaw/hooks/` and the hook entries in `~/.claude/settings.json`. A hash-checked backup is stored before edits; teardown restores the file or removes only the DefenseClaw-owned entries. The [connector pages](/docs/connectors) list the files each agent uses.

## Verify it worked

```bash
defenseclaw doctor
defenseclaw status
defenseclaw guardrail status
defenseclaw alerts --limit 25
```

`status --json` is for automation. `guardrail status` shows the resolved posture of each connector. `alerts --connector <name>` filters, `--show <n>` prints one alert and `--json` prints the list as JSON. Which commands prompt and which are flag-only is in the [interactive vs non-interactive matrix](/docs/reference/cli).

A call that was blocked, or should have been: [Why was this blocked?](/docs/guardrail/why-blocked) and [Fix a false block](/docs/guardrail/false-blocks). A guardrail that does not load or does not check: [Fix setup problems](/docs/guardrail/setup-problems). The protected-file write proof is on [Protected files](/docs/guardrail/protected-files).
