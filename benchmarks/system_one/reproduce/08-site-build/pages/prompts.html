Prompts

The prompt contract

Every model saw the same three-part request: an instruction variant, a question variant and a context variant. {{fig:proto.instructions}} instructions × {{fig:proto.questions}} questions × {{fig:proto.contexts}} contexts. All of the text below is verbatim from the protocol JSONs in this repository.

Model choice: question format moves block-only F1 further, in absolute terms, than any model-against-model gap at a single format — the same OpenJev weights score {{fig:q.q2.alone}} on Q2 and {{fig:q.q3.alone}} on Q3, while the widest model-against-model gap at one format is {{fig:fmt.m.diff}} (at {{fig:fmt.m.who}}). As a ratio the model gap at {{fig:fmt.m.who}} is larger, {{fig:fmt.m.ratio}}×. Either way, fix the question before comparing models.

Instantiated prompts are withheld. The 33 files of filled-in prompts each embed a corpus row: the user request, the tool call and its arguments. Every corpus involved is download-only or aggregate-only. This page publishes the templates and one synthetic instantiation. No real request, tool call or argument value appears anywhere on this site.

Request shape

One request carries three fields. state holds the context variant, questions holds the question variant, and the instruction variant is prepended as the policy. The whole state is capped at {{fig:proto.maxbytes}} bytes so every variant is measured under the same budget.

Question variants

The question variant fixes the answer schema, and the schema fixes how an action is derived. Q0, Q2 and Q4 answer a disposition directly. Q1 and Q3 answer only booleans, and the action is derived from them.

{{ui:questions}}

Q1 and Q3 derive an action from booleans with no answer-type guard. A provider that answers the same Nouls as a yes/no Choice emits <name>.yes keys instead of <name>.true, every lookup defaults to zero, and the branch returns ("allow", 1.0) with no error code. The worked example is on examples. The Q1 audit over {{fig:fo.rows}} scored rows found {{fig:fo.fired}} rows where it fired. Summed across every audited arm the count is {{fig:failopen.fired}} of {{fig:failopen.rows}}; the Q3 arm’s headline probe is also zero, but the two Q1-specific probes were not run on it.

Context variants

Ten recipes over the same 200-case pilot. C0 through C7 are the production ladder; CR, CS, CF, CA and CD are diagnostics.

{{fig:ctx.settled}}

What the context ladder shows. Adding the request alone (C0 to C1) raises both recall and the false-positive rate ({{fig:ctx.C0.recall}} to {{fig:ctx.C1.recall}} and {{fig:ctx.C0.fpr}} to {{fig:ctx.C1.fpr}}). Across the rest of the production ladder, C1 to C7, both end lower — C7 reaches the ladder’s lowest false-positive rate at {{fig:ctx.C7.fpr}} and gives up recall to get there ({{fig:ctx.C7.recall}}) — but not at every step: C3’s false-positive rate ({{fig:ctx.C3.fpr}}) is above C2’s ({{fig:ctx.C2.fpr}}), and C7’s recall is above C3’s ({{fig:ctx.C3.recall}}).

  • CF, the 64-event upper bound, beats no rung of the production ladder. It scores {{fig:ctx.CF.f1}}, the same F1 as C3 on three events; of the ten recipes it beats only CD ({{fig:ctx.CD.f1}}). More history is not the missing input.
  • CD, redaction, collapsed. Stripping argument values raises the false-positive rate to {{fig:ctx.CD.fpr}}. The model cannot tell a bounded write from an exfiltration once the values are gone.
  • CA, ActionFacts, matched C0. {{fig:ctx.CA.f1}} against {{fig:ctx.C0.f1}}, with the event log replaced by a structured effect summary.
