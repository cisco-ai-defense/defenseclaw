Deploy

How to run the cascade once the middle tier is chosen: which routing rule, which threshold, in what order, on what traffic, enforced at what granularity, and what it costs. Everything on this page uses OpenJev as the small model unless a panel names another.

Recommended: rules → OpenJev → Gemma 4 judge, {{term:two_sided}} at 0.30, with {{term:escalate}}: block-only F1 {{fig:lb.casc_esc.f1}} at block FPR {{fig:lb.casc_esc.fpr}}, judge called on {{fig:s2.twosided.llm}} of cases. The cascade as it runs today, which short-circuits on an advisory rule confirm, scores {{fig:s2.shortcircuit.f1}}. The routing, threshold, cost and tier-order panels below are measured on that version, because the escalating version was scored only in the policy re-analysis. Four settings were run: {{fig:thr.list}}. The slider snaps to them; nothing in between was measured. Traffic mix: when to drop the judge

The Broad comparison is {{fig:s2.benign.scorable}} benign. Real coding traffic is closer to the Production-weighted corpus, {{fig:s3.benign.scorable}} benign. At that mix precision dominates F1, and a judge that escalates uncertain cases adds more false blocks than true ones.

Enforce per tool call, not per session

{{chart:per_event}}

Same model, same threshold. Stopping the one flagged call instead of the whole session costs 2.7× to 5.1× less benign work across the four measured model-and-corpus pairs: on the Broad comparison, 16 benign tool calls blocked against 13 whole benign sessions killed.

Serving cost and latency

Recorded provider spend over every run on this site is {{fig:spend.api}}: {{fig:spend.jev}} for hosted Jev 1.13.0 ({{fig:spend.jev.paidtok}} input tokens at {{fig:spend.jev.rate}} per million, the one rate every priced manifest records) and {{fig:spend.gemma4}} for the Gemma 4 judge, whose large-stage runs logged no cost, so its true Bedrock spend is higher by an unknown amount. The self-hosted models ran on one g6e.12xlarge (published on-demand rate $12.90 per hour); its uptime is not recorded, so no GPU total is stated.

The small model emits one token per call, so serving time is all prefill: there is no decode phase to speed up and input tokens are the whole cost. The latencies below come from a saturated GPU running a batch to completion; the long tail is queueing, and any in-line deployment needs a timeout policy.

Prefix caching does not pay for this workload. {{fig:px.under}} of {{fig:px.calls}} measured prompts are shorter than one {{fig:px.block}}-token cache block. Padding prompts to the block boundary cost +86.68% input tokens. A finer cache match unit raised hit rates but slowed the server: on the 120-prompt probe by {{fig:px.serial.slower}} serially and {{fig:px.concurrent.slower}} at four concurrent requests, and on the 200-case benchmark workload by 0.72% of wall clock. Putting the static part of the prompt first costs nothing.

Recommendations

Twelve recommendations. Confidence: high means reproduced and gated; medium means measured once or with a stated confound.
#RecommendationEvidenceConfidence
1Enforce per tool call, not per session.2.7×–5.1× less benign work destroyed at identical recall (above).high
2Use a single-disposition question (Q2, or Q4) for anything that blocks; never the boolean-probe formats Q1 and Q3.Block-only F1 {{fig:q.q2.alone}} against {{fig:q.q1.alone}} and {{fig:q.q3.alone}}; Q1 and Q3 fail open on a malformed answer (Risks).high
3Set the escalation threshold per surface to save judge calls.{{fig:surf.esc.action.gemmagain}} points fewer judge calls on one-shot actions at unchanged F1.qualified
4Treat a rule-engine confirm as a floor and keep evaluating.{{fig:s2.shortcircuit.f1}} → {{fig:s2.escalate.f1}} block-only F1, same false blocks and judge-call rate.high
5At production traffic, run rules → small model with no judge, once recommendation 6 is in place.{{fig:s3.twosided.f1}} → {{fig:s3.so.f1}} block-only F1 at zero judge cost (above).high
6Make the disposition on a small-model failure configurable, defaulting to confirm, with a timeout.{{fig:fault.allow.total}} of 28 injected failure classes end with the call allowed (Risks).high
7Decide explicitly whether to accept the short-circuit loss of two-sided routing.Of the 1,346 cases the judge wanted to escalate and the small model allowed, 32 are graded unsafe (2.38%); two-sided routing discards at most that set (Risks).medium
8Author the mined deterministic rules, starting with shell-history tampering.96.2% of the small model’s confident blocks match no rule; that cluster is grade A throughout ({{fig:rule.history.events}} events).medium
9Fix the two provenance defects in the dataset lock.One disabled source was normalised into the intent corpus; one entry pins a paper, not a revision (Method).high
10Do not use the serves-the-request score (Lane B) as a standalone gate.It flags {{fig:tb.laneb.oj}} of benign tool calls and {{fig:tb.laneb.oj.traj}} benign coding sessions (Risks).high
11Do not invest in prefix caching or prompt padding.+86.68% input tokens for padding; slower serving with a finer match unit (above).qualified
12Do not reinstate Von 1.0.1.Block-only F1 {{fig:von.f1}} against {{fig:von.floor}} for blocking everything on the same pilot, at a {{fig:von.p50.lo}}–{{fig:von.p50.hi}} median per case on CPU.high
