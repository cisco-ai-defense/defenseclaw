Evidence artifacts

The analysis JSONs every figure is drawn from are held privately and are available on request. Each number on this site carries its file and key path, in the form outputs/….json :: key.path, so a figure can be traced to its artifact by whoever holds it. Each path names the artifact that holds the figure.

None of the derived evidence is approved for training, synthetic generation, teacher context, distillation or redistribution.

Withheld corpus. The proof-verified compromise corpus behind the headline reversal carries redistribution: aggregate-only in the dataset lock and license: unresolved in its own manifest, which records that the upstream repository ships no LICENSE file. Publication is restricted to “local evaluation only”. This site reports rates, counts and intervals for it, and publishes no case, request, tool call or description from it. There is no upload inventory for that corpus on disk, so the licence statement rests on the source catalogue.

The carve-out the aggregate-only rule carries. One table on this site publishes per-case structure: the disagreement queue on compare. Each of its {{fig:exp.rows}} rows is {{fig:exp.ints}} small integers indexing code tables printed beside it — truth grade, surface, event count, source dataset, four votes and a verdict — and the rows collapse to {{fig:exp.distinct}} distinct tuples. No case_id, no request, no tool call, no argument value and no free-form rationale appears in it, and no row of it comes from the aggregate-only or local-evaluation-only corpora. Coded contingency data carrying no identifier and no text is permitted under the rule; this paragraph states that permission so the rule and the payload agree.

The one upload inventory that does exist is the s1-n1000 screening stage’s. Settled-file discipline

Long provider runs write predictions incrementally, so without a gate an analysis can read a file still being written. Four rules prevent that.

  1. Gate on completion and hash. Two provenance forms are accepted, and nothing else. Either a prediction file has a .meta.json that says complete: true and its on-disk SHA-256 equals the manifest’s recorded prediction_sha256; or it is a merge of files that each satisfy that rule, and the analysis that reads it records the merged hash and the merge as byte-reproduced. Two files on this site take the second form — outputs/s2/openjev-q1.jsonl and outputs/s2/openjev-q3.jsonl, whose halves each carry complete: true and whose merged hashes are recorded in q1-vs-q2-vs-q3.json :: merge.merged_sha256.

    The fourth-model intent analysis prints both hashes for both arms, sha256 matches meta: True for each, then GATE PASSED: True. One in-flight run was scored only after settling, against a recorded hash.

  2. Reproduce before extending. Every analysis re-derives at least one already published number through its own code path before emitting a new one, and prints the comparison.

    The four-model intent analysis re-scores the earlier single-model result from scratch, identical cell for cell across all four unit/lens grids and all ten scopes. The question-comparison analysis reproduces two published files byte for byte by SHA-256.

  3. New paths only. No existing scorecard, prediction file, manifest or scorer was modified by any analysis here. Re-analyses write to new filenames alongside.
  4. Publish the integrity counters. Every analysis prints row counts, error rows, unparsable rows, duplicate (case_id, event_index) pairs, rows missing probabilities, the case-set intersection between arms, and the events-per-case histogram.

Site build

One Python script, no third-party libraries: numpy, matplotlib and pandas are not in the evaluation venv. It reads the analysis JSONs, renders every chart as hand-written inline SVG, and substitutes values into the page templates. The stylesheet is inlined per page in a <style> block, because a Space served through an authenticated wrapper answers 401 for a separate subresource request. Every SVG element carries its own fill / stroke / font-size, so no chart colour depends on a CSS class; the verifier re-checks the charts with the style block stripped.

  • {{fig:assertions}} assertion checks. Each is a (file, key path, expected value) triple. If an artifact disagrees with an asserted figure, the build prints the mismatch and writes nothing.
  • Unresolved-token check. Any {{fig:…}} or {{chart:…}} placeholder that has no value aborts the build.
  • Label-fit check. Every axis label’s rendered width is estimated against its gutter; an overflow aborts the build.
  • Payload guard. Before upload every file is scanned for the evaluation-only corpus’s identifiers, CJK text, raw case ids and credential-shaped strings; a hit aborts it.
  • Source under every chart. Each figure names the artifact and key path it came from and carries a Table view of every plotted value.

The build writes _build-figures.json alongside the pages: every substituted value, the artifacts read, and the assertion count.
