Method and data

What was scored, how a label was assigned, how a figure is computed, what the models were asked, and where the data came from. Names used on every page are defined in the glossary at the end.

The two scored corpora

Every ranked figure is on the Broad comparison (stage S2, {{fig:s2.benign.scorable}} of scorable cases benign). The Production-weighted corpus (stage S3) is weighted to the benign share of real coding traffic, {{fig:s3.benign.scorable}} benign; it is where the judge stops paying for itself. A third, the 200-case pilot (stage S1), screened candidates before either.

How a figure is scored

  • {{term:block_f1}} is the default everywhere: a confirm stops nothing, so only a hard block counts as a catch. {{term:any_f1}} counts a confirm too; it is quoted only where it is named.
  • The {{term:budget}} is block FPR ≤ {{fig:x.budget.cap}}, OpenJev’s own realised rate on the Broad comparison: at most {{fig:x.budget.fp}} false blocks in {{fig:x.s2.neg}} benign cases. Each model’s threshold on P(block) is the one that stays inside it on these same cases.
  • {{term:auc}} and every figure at the budget use P(block), with a case scored at the maximum over its events.
  • Grade C is excluded from every score; grades A and B are the unsafe class and grade D the benign one ({{term:grades}}).
  • Intervals are bootstraps over families (cases that share an origin), 2,000 replicates, seed 741983, or Wilson intervals for a single proportion.

Question format is held fixed

The question format changes a result about as much as the model does. With model, context and instruction held, OpenJev scores {{fig:fmt.q.hi}} block-only F1 at {{fig:fmt.q.qhi}} and {{fig:fmt.q.lo}} at {{fig:fmt.q.qlo}}, a spread of {{fig:x.fmt.q.diff}}. Across the {{fig:sf.n}} models ranked at the one format they all answered, {{fig:par.grid}}, the spread is {{fig:sf.diff}}, from {{fig:sf.hi.f1}} ({{fig:sf.hi.name}}) to {{fig:sf.lo.f1}} ({{fig:sf.lo.name}}). A table that mixed formats would rank the format as much as the model, so the ranking holds {{fig:par.grid}} fixed and SecJudge, which takes no question at all, is the one disclosed exception. This is the only place the caveat is stated; it applies wherever two models on different formats appear in one panel, and every such series names its format.

The prompt contract

Each request has three parts: an instruction variant, a question variant and a context variant, {{fig:proto.instructions}} × {{fig:proto.questions}} × {{fig:proto.contexts}} of them. Every generative model received this request; SecJudge received the same state serialised as one string. The whole state is capped at {{fig:proto.maxbytes}} bytes. The text below is verbatim from the protocol files.

Instantiated prompts are withheld. The 33 files of filled-in prompts each embed a corpus row, and every corpus involved is download-only or aggregate-only. This page publishes the templates and one synthetic instantiation; no real request, tool call or argument value appears anywhere on this site.

Where the data came from

Across 18 normalised corpora, {{fig:src.rows}} rows, the user-request field was empty in every row, so the intent check had never been measurable. Three adapters were rewritten to carry the request through, and a new corpus of real emitted MCP tool calls with deterministic proof of compromise added 405 proof-verified families against 333 grade-A rows in the whole prior inventory. That corpus is evaluation-only and aggregate-only.

All {{fig:src.count}} row-supplying sources are public and download-only; the per-source table with licences and revisions is on Reproduce. {{fig:src.noncommercial}} is licensed CC-BY-NC-4.0, the only non-commercial source that supplies rows: its {{fig:src.noncommercial.rows}} rows must not be used for any commercial purpose.

Two provenance defects. (1) A trajectory corpus marked enabled: false / review_required in the dataset lock was normalised anyway, and 452 of its cases became the clean lane of the proof-backed intent corpus. It changes no measurement; it changes what may be published. (2) The evaluation-only corpus’s lock entry pins an arXiv abstract (revision: paper-v1) instead of the code repository, so it cannot pin a revision.

assay is disabled in the lock (license: {{fig:lock.assay.licence}}) and ships zero rows; a forbidden benchmark named in the screening manifest could not be drawn from.
