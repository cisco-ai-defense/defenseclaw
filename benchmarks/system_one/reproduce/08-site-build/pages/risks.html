Risks

What goes wrong around the model: failures that resolve to allow, benign work flagged as unsafe, answers that change on replay, and the cases where the deciders disagree.

  1. {{fig:fault.allow.total}} of 28 injected provider and parse failures end with the tool call allowed; {{fig:fault.silent}} of them raise no error at all.
  2. Two question formats, Q1 and Q3, fail open on a malformed answer with no error code.
  3. The promotion gate advanced a candidate that errored on every diagnostic request.
  4. Resume validation accepts a stored decision flipped to allow.
  5. The serves-the-request score flags {{fig:tb.laneb.oj.traj}} benign coding sessions as a standalone gate.

Failure handling

Twenty-eight failure classes were injected against a local mock: refused and reset connections, timeouts, HTTP 429, 500, 502, 503 and 422, truncated bodies, invalid or duplicate JSON, missing, wrong or extra answer keys, out-of-range probabilities, wrong value types and a deliberate silent allow.

{{chart:faults}}

{{fig:fault.allow}} classes write an error row and the cascade allows anyway; {{fig:fault.silent}} answer in the wrong shape and are allowed with no error code; {{fig:fault.other}} are partially degraded; {{fig:fault.notscorable}} crashes the runner on a non-finite token count and writes no prediction file. With the judge behind the small model every all-allow class becomes confirm instead, because all {{fig:judge.closed}} of the judge’s own injected failure modes answer confirm. Without the judge, which is the recommendation at production traffic, the allow is what ships.

Q1 and Q3 fail open

Q0, Q2 and Q4 answer with a disposition, and a value outside the vocabulary returns action = "error". Q1 and Q3 derive an action from eight boolean slots with probabilities.get(name, 0), so a response that parses but carries no signal becomes allow at confidence 1.0 with no error code. That is indistinguishable from a confident correct allow, and no scorer downstream can see it.

A malformed Q1 answer, traced through derive_action() in benchmarks/scripts/benchmark_run_system_one.py. The answer is a synthetic illustration.

The guard that closes it:

if not any(key.endswith(".true") for key in probabilities):
    return "error", 0

It never fired in the measured runs: {{fig:fo.fired}} of {{fig:failopen.rows}} scored rows across {{fig:failopen.arms}} audited runs. The defect is latent, and Q1 and Q3 also block too rarely to be used for enforcement (Method). A second, smaller defect: when two dispositions tie to within {{fig:tie.eps}}, the winner was whichever key the provider emitted first; the fix resolves the tie toward the higher severity.

Resume validation

Long runs resume from a partial prediction file. Of {{fig:fault.tamper.total}} tampers probed, {{fig:fault.tamper.accepted}} were accepted (counting the untampered control): {{fig:fault.tamper.list}}. The run then reports complete. The validator checks which request each row answers, not what the answer was. A resumed run also keeps its predecessor’s errored rows unless --resume-retry-errors is passed.

The serves-the-request score as a gate

The Q4 format returns a second score, serves_intent (“does this still serve the user’s request?”), called Lane B here. As a standalone gate at its nominal 0.5 threshold it flags {{fig:tb.laneb.oj}} of benign events for OpenJev and {{fig:tb.laneb.dg}} for DiffusionGemma, {{fig:tb.laneb.ratio.span}} each model’s own full-decision rate, and {{fig:tb.laneb.oj.traj}} and {{fig:tb.laneb.dg.traj}} of the {{fig:tb.traj}} sessions. On OpenJev the score never exceeds {{fig:tb.si.oj.max}} on any benign event, so no threshold separates the traffic. This corpus has no unsafe cases, so the recall cost of a lower threshold is unmeasured.

Repeatability

Three byte-identical replays of each model over {{fig:flip.openjev.events}} events. Flips only happen on events flagged in at least one replay, so the rate that matters is over those: {{fig:flip.flagged.per_model}}. Jev 1.13.0 was replayed {{fig:cross.jev.all.runs}} times in all, and over all of them its rate rises to {{fig:flip.jev.deep.flagged}}; more replays can only find more flips, so OpenJev’s zero is a zero over three. DiffusionGemma’s confidence differs on every event across replays even where its action does not.

Where the deciders disagree

OpenJev, DiffusionGemma, the Gemma 4 judge and the rules disagree on {{fig:s2.disagree}} of the Broad comparison ({{fig:s3.disagree}} of the Production-weighted corpus). All {{fig:adj.queue}} disputed Broad cases went to an independent model, {{fig:adj.model}}, blinded to the four votes. It is one model’s opinion, not ground truth, and it is permissive: it allows {{fig:adj.permissive}} of the cases the corpus grades unsafe. Agreement with it is weaker evidence than the raw rate suggests.

The cost of two-sided routing. 1,346 cases are ones the judge wanted to escalate and the small model allowed. The adjudicator agrees with discarding 89.08% of them, but 32 are independently graded unsafe, 2.38% (Wilson 1.69%–3.34%), a loss that does not depend on the adjudicator. Whether that is acceptable is recommendation 7 on Deploy.

The disagreement queue

Every disputed case, filterable by vote pattern, grade, surface and verdict.

Metadata only, and the one table of per-case rows on this site. Each row is {{fig:exp.ints}} small integers into the code tables beside it: truth grade, surface, event count, source dataset, the four votes and the verdict. The tool call, the user request, the adjudicator’s written reason and apparent_task, and the corpus case_id are withheld; every row of the source files is download-only. The {{fig:exp.rows}} rows collapse to {{fig:exp.distinct}} distinct tuples and carry no identifier and no corpus text, and none comes from an aggregate-only or local-evaluation-only corpus. The aggregate-only rule carries an explicit carve-out for coded contingency data of exactly this kind; the rule and its carve-out are stated together.
