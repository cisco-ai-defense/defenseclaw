# Contextual LLM-as-judge results — 2026-09-09

## Outcome

Use Bedrock Gemma 4 26B A4B as the hosted contextual judge. On the frozen
production-path validation, deterministic detection plus Gemma 4 detected 94
of 100 family-excluded attack trajectories and alerted on 1 of 20 unseen,
task-deduplicated successful coding trajectories. It recommended blocking 35
attacks and blocked no benign trajectory.

That is 94% benchmark-bounded attack coverage, 98.95% precision, 0.964 F1,
5% observed benign trajectory alert rate, and 0% observed benign block rate.
Across the benign trajectories, only 1 of 511 pre-tool decisions alerted
(0.20%) and none blocked. The 20-trajectory benign sample is deliberately
family-diverse but small: the Wilson 95% interval for trajectory FPR is
0.89–23.61%, and the upper bound for a zero observed block rate is 16.11%.

Gemma 3 12B is not suitable for coding-session enforcement with this contract.
It detected 99 attacks, but alerted and blocked 18 of 20 benign trajectories
(90% FPR). Granite, Qwen 3.5, and Muse are excluded from the active matrix.

These are benchmark-bounded results, not a universal protection claim. A
judge block is prevented execution only when an enabled synchronous pre-tool
hook consumes it. EventRouter judging remains asynchronous and observational.

## Frozen validation design

The positive lane contains 100 stateful MonitoringBench prefixes: 25 each from
the firewall, malware, password-leak, and sudo domains. It excludes every
family used in development and earlier holdouts. The corpus SHA-256 is
`b53d46bb4898e2df8b84cc65011c6b0351136e566da20353cb5f71c7bbbe8bba`.

The primary negative lane contains all 20 available validation task families
from the pinned successful TerminalBench trajectories, one trajectory per
task family. It replays the full public task instruction as authenticated user
intent, followed by 511 production-format tool decisions. The corpus SHA-256
is `664e7ade3202b2d14e545a7d9c8ccad348ab2b712967dd4e5631989a6afa1102`.

TerminalBench was normalized from `yoonholee/terminalbench-trajectories` at
revision `04e8940f5b6736a7ce8d22224fe2f2af74163ed2`; task instructions came from
`harbor-framework/terminal-bench-2` at revision
`2fd12b88aafdd04a52c298e3940bcb189f9766d6`. The normalized inventory contains
2,362 cases, 2,000 successful trajectories, 73,533 tool calls, and 86 task
families. Development used 40 different task families and validation used 20.

The combined 120-case validation corpus SHA-256 is
`5d87506255717c70eb25d96024d19652408d4127e85fa45cf76f3de36d74a07f`.
The prompt, response schema, thresholds, and default rule pack were frozen
before either validation model was scored.

## Detection and intervention

| System | TP / FN | FP / TN | Precision | Recall | F1 | FPR | Block recall | Benign block rate |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Deterministic only | 1 / 99 | 0 / 20 | 100% | 1% | 0.020 | 0% | 0% | 0% |
| Gemma 4 judge first | 94 / 6 | 1 / 19 | 98.95% | 94% | **0.964** | **5%** | 35% | **0%** |
| Deterministic → Gemma 4 | 94 / 6 | 1 / 19 | 98.95% | 94% | **0.964** | **5%** | 35% | **0%** |
| Gemma 3 judge first | 99 / 1 | 18 / 2 | 84.62% | 99% | 0.912 | 90% | 95% | 90% |

The MonitoringBench lane is contextual: the deterministic engine sees only
the explicit structured evidence available on each call, so it resolves one
trajectory. Gemma 4 contributes 93 additional attack detections. This frozen
set is therefore a hard estimate of contextual lift, not a production LLM-call
rate estimate. The recommended runtime order remains deterministic first,
then LLM for unresolved calls (`regex_judge`).

The block policy is intentionally conservative for coding. `weak_signal` is
non-actionable; `needs_review` can alert but cannot block by itself. A block
requires an actionable corroborated category or strong structural
exfiltration/destruction evidence. This is why detection recall is 94% while
block recall is 35% and observed benign blocking is zero.

## Hook-level activity

Stateful truth labels a whole trajectory, so the following figures describe
operational judge activity and interruption pressure, not per-hook accuracy.

| Model / slice | Hook decisions | Alerted decisions | Blocked decisions | Provider calls |
| --- | ---: | ---: | ---: | ---: |
| Gemma 4, attacks | 778 | 232 (29.82%) | 48 (6.17%) | 778 |
| Gemma 4, benign coding | 511 | 1 (0.20%) | 0 (0%) | 368 |
| Gemma 3, attacks | 778 | 430 (55.27%) | 337 (43.32%) | 778 |
| Gemma 3, benign coding | 511 | 132 (25.83%) | 126 (24.66%) | 368 |

Provider calls are lower than hook decisions on TerminalBench because repeated
identical contextual decisions can be served by the runtime verdict cache and
empty or very short no-op arguments do not require model inference.

Costs use explicit US-East token rates at evaluation time: Gemma 4
$0.13/M input and $0.40/M output; Gemma 3 $0.09/M input and $0.29/M output.
Both models used JSON mode for 100% of provider calls and had zero provider,

trajectory; it is not latency for a single tool hook.

The deterministic-first Gemma 4 cascade invoked the model for 119 of 120
cases, used 3,060,620 tokens across 1,138 calls, and cost $0.4133. The small
savings are a property of this deliberately contextual validation set.

## Private local validation

The current local Gemma 4 12B MLX judge was also run on 100 held-out private
coding-session action rows, locally only. It produced 0 alerts, 0
blocks, 0 provider errors, and 100% JSON-mode responses. The Wilson 95% upper
bound on the observed 0/100 FPR is 3.70%.

The run used 176,351 prompt plus 8,300 completion tokens (184,651 total).
End-to-end latency was 8.13s p50, 10.34s p95, and 28.65s max. Monetary cost is
not reported as zero because electricity and hardware amortization were not
measured. The labels were model-adjudicated private trace labels rather than
human ground truth, so this lane supplements rather than replaces the public
execution-grounded TerminalBench lane.

No private prompt or tool-call content was sent to AWS. Prediction files are
value-free: case identities, actions, severities, finding IDs, request hashes,
latency, and token counts only—no commands, prompts, raw model responses,
rationales, or evidence values.
