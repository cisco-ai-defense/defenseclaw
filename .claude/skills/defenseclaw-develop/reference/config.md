# Config: add or change a setting end to end

Open this when: you add, rename, remove or change the default of a key in config.yaml, add an environment variable, or touch the config writer or reload path.

`config.yaml` (config_version 9) is the only source of administrator decisions. Hook scripts, custom-providers.json and managed machine policy are derived from it. `config.generation.json` and `migration-v9.json` are evidence, not policy.

## Requirements

IDs live only in `reference/checklist.md`. These rows add detail and carry no IDs.

| Declare every new key in the closed JSON schema first. ## Checklist: adding a key

1. Add it to the schema. 2. Add Go struct field and default. 3. Add Python field and default. 4. Decide hot or restart and edit both lists. 5. If it is a secret, store a reference. 6. If it replaces an old key, add a migration and a refusal message. 7. Add `config get` provenance. 8. Update `configuration.mdx`. 9. Run `make check`, `pytest cli/tests/test_config*.py`, `go test ./internal/config/...`.

## Where it lives

- Schema: `schemas/config/v8/` (the directory name is v8 but holds the v9 shape; do not create a v9 directory).
- Go: `internal/config/`, `internal/config/configwrite/`, `internal/envvars/`, `internal/gateway/config_manager.go`.
- Python: `cli/defenseclaw/config.py`, `config_writer.py`, `migrations.py`, `cli/defenseclaw/commands/cmd_config.py`.
- Docs: `docs-site/content/docs/reference/configuration.mdx`, `source-of-truth.mdx`, `env-vars.mdx`.

## How to verify

`go test ./internal/config/... ./internal/envvars` then `pytest cli/tests/test_config.py cli/tests/test_cmd_config.py cli/tests/test_config_writer.py` then `make check`. Test the writer and loader with a UTF-8 BOM, CRLF line endings, a `~` path and a byte-identical re-apply.

## Common mistakes

- Editing `restartKeys` on one side only. No automatic parity test exists.
- Hand-editing generated reference, telemetry or env-var docs.
- Relying on viper state between loads: the loader resets viper on every load.
- Adding a field named `api_key`, `token` or `password` that holds a literal.
- Testing only the happy path and not the retired-key message.
- Treating a prose mention of a `DEFENSECLAW_` name as free; the coverage test counts it.
