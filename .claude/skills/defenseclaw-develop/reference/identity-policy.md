# Policies, guardrails, rule packs, identity and profiles

Open this when: you change admission policy (Rego), guardrail rules or rule packs, guardrail profiles, profile assignments, directory or identity sources, agent identity IDs, or anything that reports a user's effective policy.

There are two separate layers. Admission (skills, MCP servers, plugins) runs in OPA Rego behind `internal/policy/engine.go`, with a Go twin used only when OPA fails. Guardrail rule packs hold trusted tool-call CEL rules with regex fallbacks, judge prompts and suppressions. Identity-based policy is `guardrail.profiles` plus ordered `profile_assignments` plus `default_profile`.

## Requirements: identity, profiles, privacy

IDs live only in `reference/checklist.md`. These rows add detail and carry no IDs.

| Rule | Why | How to check | Evidence |
|---|---|---|---|
| A profile may carry only fields that can vary by subject. `enabled` and `hook_fail_mode` are rejected in profiles. A new profile field joins the validator, the derivation precedence, the digest view and the Python twin. | A field missing from the digest view keeps the same digest after a change. | `go test ./internal/config -run GuardrailProfile`; `pytest cli/tests/test_guardrail_profiles.py` | `internal/config/guardrail_profiles.go` (`@sym:validateProfiles`, `@sym:guardrailPolicyDigestView`) |
| The policy digest is deterministic: canonical JSON, sorted keys, fixed field order, a version field, and no secrets. Test stability, API-key independence and change on edit. | The digest is stamped on decisions and telemetry. | `go test ./internal/config -run Digest` | `internal/config/guardrail_profiles_test.go` |
| Only verified identity selects a profile: the kernel-verified uid/SID or per-user credential and the directory facts resolved for it. Never use headers, hook payloads, env or claimed session facts. Mark each new fact verified or claimed; claimed is attribution only. | A client-supplied identity lets a user pick a looser profile. | `go test ./internal/gateway -run GuardrailProfile` | `internal/useridentity/directory.go`, `internal/gateway/guardrail_profile.go`, `internal/gateway/guardrail_profile_test.go` |
| No lenient fallback in matching. A failed or partial directory lookup refuses a request when an assignment needs the missing fact, with that fact named in `refused_reason`. If no assignment needs it, only a proven uid/SID or other proven match, or the default, may apply. A stale name selects nobody. Compare names with the `useridentity` helpers and warn on assignments that select nobody. | A failed lookup that lands in a looser profile is a bypass. | `go test ./internal/gateway ./internal/useridentity` | `internal/useridentity/principal.go`, `internal/gateway/guardrail_profile_warnings.go` |
| Profiles are rejected under the Secure Client integration, which serves none of the identity routes. | That profile's behavior must stay unchanged. | `go test ./internal/config ./internal/managed ./internal/gateway -run SecureClient` | `internal/managed/profile.go`, `internal/gateway/api.go` |
| Effective-policy visibility is own-only for users and admin-only for everything else. Any endpoint, status field, health block or telemetry attribute naming a policy, profile, digest, assignment, group or account is gated server-side (loopback plus gateway token, or privileged peer). Test each caller class. | A health or status field that names another account's policy, group or digest discloses it to every local user. | `go test ./internal/gateway -run 'PolicyBlockOnlyToAnAdministrator\|PolicyPrivacy\|ProfileExplain'` | `internal/gateway/guardrail_profile.go`, `internal/gateway/health_policy_privacy_test.go` |
| Sandbox sections and OpenShell admin settings in profiles may only tighten: false wins, stricter minimum profile, intersect allow lists, union required and blocked egress, contradictions are errors. `default_profile` must be at least as strict as every assigned profile in examples. | A request whose assignment needs an unconfirmed directory fact is refused and names the fact. The default applies only when no assignment needs it. | `go test ./internal/config -run 'Tighten\|Sandbox'` | `internal/config/openshell_tighten.go`, `internal/config/identity_examples_test.go` |
| A new identity source reads the OS only (NSS, SSSD, account APIs, directory join state). It never calls an IdP API or holds identity credentials. Add the value to `useridentity.Directory` and the schema enum, mark facts, state per-OS limits, and test per platform. | The product promise is no IdP calls. | `go test ./internal/useridentity ./internal/unixidentity`; `GOOS=windows go vet ./internal/useridentity` | `internal/useridentity/`, `docs-site/content/docs/enterprise/identity/authentication.mdx` |
| Agent identity IDs stay pure and deterministic (SHA-256 over machine id, verified user, connector, gateway-resolved config root). Never change a namespace constant or input without a migration. | Assignments match agents by ID; a change orphans them and breaks audit trails. | `go test ./internal/agentidentity` | `internal/agentidentity/agentidentity.go` |
| State the per-OS and per-IdP limits of any new identity feature in the docs page and the doctor output. | An undocumented per-OS limit makes a group assignment silently match nobody. | read the docs diff | `docs-site/content/docs/enterprise/identity/sources.mdx`, `packaging/identity/` |

## How to verify

`make rego-test`, `go test ./internal/policy ./internal/guardrail ./internal/config ./internal/gateway ./internal/useridentity`, `pytest cli/tests/test_scanner_rulepack.py cli/tests/test_guardrail_profiles.py`, `make check`. For privacy, call each endpoint as an ordinary user, an admin and a hook-authenticated caller.

## Common mistakes

- Changing Rego and forgetting the Go fallback.
- Raising a regex finding to blocking without a same-rule proof.
- Adding a profile field without the digest view.
- Matching names with plain string equality instead of the normalizing helpers.
- Showing a group or other account name in a health or status response.
- Editing a pack file but not its pinned digest, or adding a component type the digest skips.
